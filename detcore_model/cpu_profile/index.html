The virtual CPU a guest sees (https://github.com/rrnewton/hermit/issues/4243).

Structs§

HostXstate
The facts a v3 guest’s CPUID and xstate answers are built from. For a host-derived machine they are captured once at startup on a host that passed the qualification, and bound into a recording so that replay refuses a host where any of them differs. The synthetic HostXstate::fixed_guest instead describes the fixed KVM machine: its vendor and signature are the presented identity, not a captured host’s, so a recording binding made from it does not by itself identify the real host class; bind that separately before such facts enter a recording or a qualification cache key.

Structs§

Bitmap
The per-task file grammars (stat, status, comm, fdinfo, io, sched, statm) live in reverie-proc-grammar, a pure leaf crate with no backend knowledge; re-exported here so Detcore consumes them without declaring a reverie-* dependency of its own (the backend-abstraction commandment in detcore/Cargo.toml; a direct dependency plus a checker allowlist entry for this one pure crate is the named follow-up). Which fields are rewritten, and to what, is Detcore policy and stays in Detcore. A CPU/node bitmap as bitmap_string prints it: comma-separated 32-bit groups, most significant first, each group zero-padded to its digit width (8 for full groups, fewer for a partial top group).

MountInfoRow
The mountinfo grammar lives in reverie-proc-grammar (single grammar owner since Slice 2 S2-R1; this S2-D1 switch ends detcore-model’s last reverie-procfs edge). The legacy identity-bearing row shape is kept here so producers and consumers keep one path and change nothing: raw_device is computed with libc::makedev at this conversion exactly as the former procfs shim did, and grammar refusals map to None. The seed-mount exclusion and mount-identity provenance rules below are Detcore policy and stay.

exclude_ephemeral_host_seed_mounts
Drop the rows is_ephemeral_host_seed_mount classifies from raw mountinfo contents, keeping every other row, newline included, in its original order. Detcore’s guest-read capture, Detcore’s fdinfo mnt_id capture and hermit-cli’s launch-time identity capture all use this one filter, so they agree on the guest mount membership.
is_ephemeral_host_seed_fields
is_ephemeral_host_seed_mount for a row already split into its mountpoint and filesystem type (fields 5 and 9).
is_ephemeral_host_seed_mount
True for one ephemeral host FUSE seed mount row in /proc/<pid>/mountinfo grammar: filesystem type fuse.squashfuse_ll and a mount point whose last path component is a host seed name, <hex>-seed-<seed>-ns-<digits>, where <seed> is a non-empty run of ASCII letters, digits, _ and -.
mount_identity_provenance_is_well_formed
Whether captured mount-identity provenance is well formed: the namespace order names each raw mount ID once, and the assignment order numbers each raw ID once and names raw 0 only where the namespace order does (an fdinfo zero is the anonymous class and is never numbered). Detcore’s mount-ID pool accepts exactly these, and a producer that hands provenance to a backend without a second capture checks them first.
mount_ids_are_ordered_subset
Whether every visible mount ID occurs once and in the same relative order as the producer-captured namespace.

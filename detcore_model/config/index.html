Constants§

CONFIG_FINGERPRINT_ENV
N.B. we don’t want to specify two different notions of “default”, so we use the Clap instance above. Environment variable carrying the coordinator’s fingerprint to an out-of-process plugin: detcore::config_wire_fingerprint, which extends config_wire_fingerprint with Detcore’s global RPC definitions.
DEFAULT_BACKEND_CAPABILITIES
The capabilities a Config has before the host prepares it for the backend that runs it: ptrace’s, the backend Detcore’s own tests use, except that eight facts stay off (supports_blocked_wait_signal_interruption and the four split out of it, which set_kernel_signal_facts clears together, delivers_preemption_timer_events, runs_guest_code_between_injections, reports_sigreturns). Until supports_blocked_wait_signal_interruption, delivers_preemption_timer_events and runs_guest_code_between_injections became backend capabilities they were Config fields that only the host set, for the backend it had selected, and were false otherwise; a configuration nobody prepared keeps that behaviour, and the four readings of the first with it. A configuration nobody prepared cannot know that sigreturns are reported, so that is off too (the DBT runtime’s standalone fallback starts from these). reports_kernel_child_exit_signals keeps ptrace’s value, as reports_child_exit_publication does: it took over the child-exit ledger’s gates from that field, so such a configuration behaves as before. The host copies the running backend’s own answer over all of these before a run.
LITEINST_CONFIG_FINGERPRINT_ENV
Environment variable carrying the coordinator’s fingerprint (detcore::config_wire_fingerprint, which extends config_wire_fingerprint with Detcore’s global RPC definitions) to the in-guest LiteInst runtime (libdetcore_liteinst.so), which checks it before it decodes the configuration the coordinator sends. Without the check, a runtime built from another tree fails with a bare decoding error that names neither build (https://github.com/rrnewton/hermit/issues/3986). The runtime removes it once checked, as it removes its DETLOG variables: the value is zeroed in the environment block and the variable is unset, so the fingerprint never reaches the guest.
MAX_SCHEDULER_TURN_COST
The largest --scheduler-turn-cost accepted, in virtual nanoseconds, both before and after the clock multiplier scales it: one second per scheduler turn.
MAX_VIRTUAL_CPUS
The most CPUs --virtual-cpus presents: the bits of the 128-bit mask Detcore’s sched_getaffinity answers with, whose highest CPU is the kernel_max (127) it reports.
RECOMMENDED_CHAOS_TIMESLICE_RANGE
The range used by --chaos-timeslice-draw=run when no range is given. One microsecond to 200 milliseconds spans fine preemption windows and the ordinary maximum. Plain --chaos keeps its fixed maximum: fine draws can cost much more, so this discovery mode remains explicit.

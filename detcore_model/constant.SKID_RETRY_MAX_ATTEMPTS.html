pub const SKID_RETRY_MAX_ATTEMPTS: u32 = 5;
Expand description

Attempts a test harness gives a Hermit run refused only for a typed PMU skid overshoot (exit HERMIT_POLICY_REFUSAL_EXIT, cause=skid-overshoot): one initial attempt plus four skid retries. In the manifest runner the attempts past the generic retry bound are additionally wall-bounded to that bound’s lifecycle, so this count never widens an enclosing node timeout.

A skid refusal measures the host’s PMU interrupt latency under load, not the guest (https://github.com/rrnewton/hermit/issues/1845), so its budget is separate from every generic retry budget (nextest’s own retries, the manifest runner’s per-cell retry). Every harness that retries such a refusal spells the bound from this one constant — the integration-test helper, the manifest runner’s skid budget and the nextest CPU wrapper’s retry credits (bound − 1) — instead of keeping a copy each. Exhausting it is a distinct infrastructure verdict (SKID-INFRA), never a test failure.

It lives here for the reason HERMIT_POLICY_REFUSAL_EXIT does: the integration tests, hermit-verify and the manifest-plan runner all depend on detcore-model, and on no common test crate.

pub fn loader_v2_rejection(attempt: &AttemptResult) -> bool
Expand description

Whether attempt is a loader rejection the v2 retry exists for (issue 5476): the guest loader refused the x86-64-v2 CPU before the guest ran. Three shapes of retained verification report show it. In the first two the run ends with the loader’s own exit 127, beside the loader’s fatal ISA line (LOADER_V2_SIGNATURE) in this attempt’s own captured output:

  • a typed first_run_rejected with guest exit 127, with the line in the attempt’s stdout or stderr: verify stopped after a first run whose disposition its --verify-allow refused;
  • a matched comparison in which both compared runs exited 127, with the line in the attempt’s stderr: a cell that declares a non-zero guest disposition runs with --verify-allow=failure, which admits the loader’s exit, so verify ran the guest twice and compared the runs. Only a match counts. Two refused runs that diverged differ in Hermit’s own work before exec, a determinism failure the retry must not hide.

The third is Hermit’s typed refusal in place of that exit. Where Hermit watches the program interpreter (the ptrace backend; not KVM, where guest threads are not host tasks), it refuses the run at the loader’s exit_group(127) and exits 122 itself:

  • a typed run_failed of run 1 with failure policy_refusal, with Hermit’s refusal of an x86-64-v3 program interpreter’s abort on the x86-64-v2 CPU as a line of the attempt’s stderr (LOADER_V3_ON_V2_REFUSAL_PREFIX). The report’s own detail names no cause, so the line is the evidence of which refusal it was. Only that refusal counts: another policy refusal (an x86-64-v3 admission refused for the host’s XCR0, say), an interpreter that names another level, or one refused under another profile is no loader rejection of the v2 CPU. A chaos pair admits its second run whatever the first exited, and the report is still run 1’s refusal.

Both halves come from retained typed evidence, never from the row’s reason text, and from the same attempt: a guest that merely prints the line without such a report earns no retry, and such a report without the line is an ordinary guest failure.

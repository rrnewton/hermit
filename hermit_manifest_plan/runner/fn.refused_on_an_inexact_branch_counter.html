pub fn refused_on_an_inexact_branch_counter(cell: &SelectedCell) -> bool
Expand description

Whether the hermit binary refuses cell where it reports no exact_branch_counter, as RunOpts::refuse_strict_with_inexact_branch_counter does (hermit-cli/src/bin/hermit/run.rs): the run is --strict, its backend arms the PMU preemption timer (strict_run_arms_the_preemption_timer: ptrace, e9patch and kvm), and it has a maximum timeslice, the condition of RunOpts::reads_the_branch_counter.

Verify and chaos cells always pass --strict to run, and replay cells to record start, which refuses in the same way (https://github.com/rrnewton/hermit/issues/3810). A custom cell passes it when its arguments before any -- say so, unless they also select --namespace-only (alias --lite), which arms no branch counter. A naked cell runs no hermit.

The timeslice is the one hermit resolves from the flags the cell passes (SelectedCell::strictness, MaxTimeslice::from_options), so every spelling hermit reads as no timer leaves the cell unrefused: disabled or 0, after = or as the next argument, under --max-timeslice or its alias --preemption-timeout. Without a timeslice Detcore uses no branch count (Reverie still sets the counters up), so Hermit does not refuse the run (https://github.com/rrnewton/hermit/issues/4291). A verify cell at the relaxed strictness level passes --max-timeslice=disabled (RELAXED_LEVEL_ARGS) unless its recipe names its own timeslice, which the relaxed level then leaves in place. KVM has no relaxed form (pmu_clock_backend), so a KVM cell is refused exactly when the flags it declares leave it a timeslice.

Files that carry a pin a floor-based check compares against the floor. A target that changes one is refused this kind: its pin checks would compare a new pin against E while bindings elsewhere in the tree (for example the LiteInst cache keys that check-reverie-pin.rs greps the whole tree for) could have been added by E..M. Such a target is validated against the real current main instead. Same pattern forms as the floor-sensitive list.

The floor-sensitive list itself is one of these. The parent reads the list from the target’s tree, the one input the target controls, so a target that rewrote it (to README, say) could have the proof accept an E..M that edits the validation DAG. A target that touches the list is validated against the real current main instead.

Expand description

The rows the history gate accepts without an approval line, because an import dropped it (SquashedApproval). The list is closed and holds no patterns: each entry is one row, held to its exact text in every version from the commit where it entered. So any row added later, entering at another commit, or differing in any version since it entered still needs its line.

The 0.5.5 import squashed the public history into one fbsource commit and copied none of its KVM-Gap-Approval: lines. On the GitHub export that commit is 1c24fe3aa964d51c246de92d022d30cc3ddf6dba, which introduced the deadline_slice_cap ledger, so its two approved rows entered there with no line binding their approval: the coordinator’s commit that filed dev-hermit minibeads dh-j7ocf. In rrnewton/hermit’s own history the rows entered with their lines, so this list is never consulted there.

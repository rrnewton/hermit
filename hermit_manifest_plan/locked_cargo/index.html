Module locked_cargo 

Source
Expand description

No validation step may rewrite a committed Cargo.lock.

Cargo rewrites a stale lock file in place unless the call carries --locked or --frozen. The lock freshness gate, pre.cargo_lock, reads the lock file in the same checkout the other nodes build in, and no node waits for it, so one unlocked cargo build that ran before it would rewrite a stale committed lock file and the gate would then pass. Every Cargo call of a validation node that resolves a workspace therefore carries one of the two flags, and a stale lock file fails the run at its first Cargo call, in a full run and in a focused one alike (https://github.com/facebookexperimental/hermit/issues/112).

cargo_calls finds the cargo calls in a node’s shell command, including calls nested in quoted strings: the pinned-root wrapper’s payload, bash -c scripts and command substitutions. script_cargo_calls does the same for a script a node runs. The tests refuse an unlocked call in the committed DAG or in the scripts its nodes run unless UNLOCKED_CARGO_EXCEPTIONS names its node or script with the reason. stale_lock_twin runs one call’s exact arguments in a fixture workspace whose committed lock file is stale. This module’s tests apply it to the first Cargo calls of every committed plan, and scripts/validate.rs’s tests apply it to those of its focused plans.

The scan reads every node command and a fixed list of scripts that nodes run (SCRIPTS in the tests). It discovers no scripts, so a Cargo call in any other program a node runs, whether a script, a Rust tool, a build script or a test, is not seen. Nor is a command that names Cargo through a variable ("$CARGO" build); no node command does that.

Nodes or scripts whose lock-resolving Cargo call cannot carry --locked or --frozen, by node tag or script path, each with the reason it cannot. Empty: every lock-resolving Cargo call of the committed DAG and of the scripts the tests scan carries one.

Module parity_outcomes 

Source
Expand description

Outcome parity against ptrace: for one finished run, every manifest cell whose outcome on a candidate backend differs from the same test and mode’s outcome on ptrace (test-harness parity outcomes).

This is coarser than crate::parity, which compares the verify logs of two passing runs message by message. Here a cell’s OUTCOME is its final row’s outcome in the run’s results.jsonl (PASS, FAIL, ERROR, …), or, when the run has no row for it, the manifest’s own status: disabled, not-selected (enabled, but full validation does not run it), no-mode (the test has no such mode), or not-run (full validation selects it, but this run has no row, as when one of its lanes did not run). A cell with no row on either side is never a difference.

The cells considered are every (test, mode) whose ptrace cell full validation selects, plus every (test, mode) for which the run has a row on any candidate backend. A baseline is this command’s own --json output: the differing cells, then every (test, mode) it considered. gate reports every cell that matched ptrace in the baseline and no longer does, which is the regression a step may not introduce, apart from the cells of tests and modes the baseline did not consider, which never matched.

§Adding a post-split DAG node (the ONE admission path)

ci/dag-source-ownership.json is the frozen pre-split source snapshot. Never edit it (or ORIGIN_SHA256) to admit a new node, and never fold a new bucket into an existing node’s step. Every validation-DAG node created after the first-party core split — rr, gVisor, and future e2e buckets — is admitted by adding one entry to POST_SPLIT_CORE_NODES below:

ⓘ
ExtensionNode {
    tag: "e2e.manifest_example",
    labels: &["full", "portable"],
    deps: &["gate.manifest", /* core or extension tags only */],
    populations: &["manifest_publishers"],
}

Rules (all fail-closed, each refusal names the node and dependency): the tag must not duplicate a frozen node or another extension node, and every dependency must be a frozen core node or another extension node. Dependencies on patching/dynamorio-owned nodes (crossed deps) are refused; new bucket steps therefore omit check.dbt_runtime_abi. Register every generated twin (_on_host, _buck) as its own entry. The admitted core population is then exactly frozen core tags ∪ extension tags (admitted_core_tags); anything else is refused as an extra node. Named-population membership (the contract’s named_populations, today only manifest_publishers) is declared the same way, per node, in populations; an undeclared extension node is never a member, and an unknown population name is refused.

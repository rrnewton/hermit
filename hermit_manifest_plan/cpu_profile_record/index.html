Module cpu_profile_record 

Source
Expand description

Which CPU profile each e2e cell’s Hermit runs presented, and the CI image they ran on.

With no profile named, Hermit presents x86-64-v3 where the run and host qualify and x86-64-v2 elsewhere, so a CI run must say which it got. Hermit already records that in each run’s manifest (cpu_profile: the profile, why, and a refusal’s words; inputs.host_drawn["cpu-profile"] when the host decided). The runner points every Hermit invocation of a cell at one data directory of the cell’s (stage_dir), asks every hermit run for a manifest (MANIFEST_ALWAYS_ARG), and moves that directory to the attempt’s own (data_dir) when the attempt’s process ends (retain_stage). It copies the choice out of those manifests into cpu-profile.json beside them (record_attempt), and combines the attempts of one result row (record_runs). Nothing is derived again: a run that left no manifest (one refused before it started, exit 122) or runs that disagree are recorded as unresolved, by name, never as a guessed profile.

The variable names a path that is the same for every attempt of a cell because a guest can see it: Hermit hands its own environment to the guest under its default --base-env=host, which a custom cell outside the hermetic lane runs with, and the runs a custom cell’s assertions compare are its attempts. Every other cell’s guest gets the runner’s fixed environment under --base-env=minimal.

Per run of the runner, cpu-profiles.jsonl holds one row per result row and ci-environment.json the CI image and the totals of final rows by profile and reason (Totals), beside results.jsonl. No existing reader opens either file. The last line the runner prints is Totals::summary.

The hermit run flag that writes a manifest for every run, reproducible or not. A flag rather than HERMIT_MANIFEST, so no variable of its own reaches a guest that inherits Hermit’s environment. record start --verify-run, which replay cells run, writes no manifest (REPLAY_WITHOUT_MANIFEST).

ci_image
The CI image of the environment the cells ran in, from /etc/os-release’s text: centos9, el10, or other:<ID>-<VERSION_ID>, with the fields it was read from.
data_dir
The data directory of attempt attempt of the cell whose directory is cell_dir: the manifests every Hermit run of that attempt wrote end up under it (retain_stage).
read_record
The record for the manifests under data_dir (*/manifest.json).
record_attempt
Writes data_dir/cpu-profile.json from the manifests there and returns the record. The file is written for every attempt that invoked Hermit, creating data_dir where no run did (a run refused before it started creates none), so its absence never stands for a profile. An unwritable file is reported in the record, never hidden.
record_result_row
The record of result row row (record_row) over every attempt the row ran, or None where none invoked Hermit (no attempt’s environment names DATA_DIR_ENV). The row’s own copy of the environment is its first attempt’s, so reading only that would record the first of a chaos row’s seeds or a custom row’s runs and none of the others.
record_row
The record of one result row of mode mode (record_runs). A replay row whose runs left no manifest says why: record start --verify-run writes none (REPLAY_WITHOUT_MANIFEST).
record_runs
The record of one result row, whose attempts ran as runs (each its label and data directory): record_attempt for each, so each attempt’s directory holds its own cpu-profile.json, then their manifests together, named <label>/<id>/manifest.json. A chaos row runs one attempt per seed and a custom row one per run.
reset_attempt
Before an attempt: removes a stage an interrupted attempt left and the attempt’s own data directory from an earlier run into the same result root, as the runner resets the attempt’s tmp, workdir and verify-run directories, so no earlier manifest is read as this attempt’s.
retain_stage
After an attempt’s process ends, however it ended: moves the stage, where the attempt’s Hermit runs wrote their manifests, to the attempt’s own data directory. Where no run created the stage (one refused before it started) there is nothing to move, and the record says so (record_attempt).
stage_dir
The directory every Hermit run of the cell whose directory is cell_dir writes its manifest into while an attempt runs (DATA_DIR_ENV): the same path for every attempt of the cell.

## Contract to preserve before deleting the H owner

At the fixed base, R `reverie-dbt/src/launcher.rs::StatsSink::drain` treats an absent file as a valid empty snapshot for its convenience API. H's former local `DbtStatsCapture` and `read_dbt_stats` apply stricter verification policy: distinguish missing from present-empty; reject malformed/truncated records; reject zero branch count, zero syscall count, or rewritten count greater than intercepted syscalls. The candidate keeps that H policy in `require_dbt_stats` while sharing capture and decoding. Protected evidence/FINAL, common run attribution and terminal-stdin refusal remain separate checks, in their existing order.

H live saved runs write the exact native records to `verify_run::DBT_STATS` (`dbt-stats.bin`); `verify_run.rs::conclude_dbt` reads them for offline comparison. The shared R reader therefore needs both actual presence and unchanged raw records, not just an aggregate. Preserve the old convenience result while allowing the strict H consumer to refuse. Neither the old reader nor aggregator has an identity-deduplication rejection; do not introduce one as an incidental test oracle. Physical `DispatchStats` measurement and protected-log transport are outside this slice.

## Committed ownership boundary and retained draft history

The active R API is `DbtStatsSink::{new, with_prefix, directory, configure, capture}` plus `backend_stats::DbtStatsCapture::{read, records, snapshot}`. R's default `new()` retains the existing `reverie-dbt-stats-` prefix and optional missing-to-empty convenience behavior.

The existing `output_with_detached_reader_and_global`, `output_with_inherited_stdin_and_global` and `status_with_global` calls remain unchanged. Tests configure the runner with a caller-owned sink, invoke those existing methods, assert output/Global return and the still-owned directory, then capture. The physical run body, cleanup, input pump, status/refusal ordering and `DbtPhysicalOutput` serialization are unchanged. Raw records do not cross a new IPC path; the saved-run writer borrows the captured original bytes at the old host completion point.

The earlier inside-container allocation, `_and_capture` Reader/Inherit/status APIs, `new_in('/tmp')` choice and raw-record IPC/serialization-test proposal are **superseded, unexecuted history**, retained in [draft-in-container-superseded](draft-in-container-superseded). The final regression checks the actual saved writer/shared reader instead, preserving the existing directory placement and physical return contract.

## First tests and what would constitute a real failure

The first checks select R's new `launcher::tests::stats_capture` module alongside the existing `stats_sink` and wire tests, then H's existing strict negatives before broad execution. The six committed R tests are:

- `stats_capture_distinguishes_missing_and_empty_and_cleans_its_directory`
- `stats_capture_retains_exact_record_order_after_decoding_and_cleanup`
- `stats_capture_keeps_read_failure_distinct_from_malformed_records`
- `reader_capture_keeps_output_and_global_when_stats_are_malformed`
- `inherited_input_capture_keeps_output_and_global_when_stats_are_missing`
- `status_capture_keeps_read_failure_after_physical_completion`

The three physical-call tests use the existing fake-drrun host fixture and deliberate exit 7, preserving the no-RPC-success refusal. They test component ownership and retained output/Global, not native DynamoRIO or Hermit cleanup/evidence integration. Native coverage comes only from the separately executed real CLI fixtures at their exact linked candidate.

- Missing and present-empty files must remain distinguishable even though the legacy convenience snapshots both contain zero images. A presence-loss regression must fail the new assertion; accepting an empty verification run is not the fix.
- Two unequal valid records must produce the expected sums/maxima **and the exact original concatenated bytes in original order**. Equal aggregates alone cannot prove saved-artifact preservation. No re-encoding, sorting or native wire change is required.
- Malformed magic/version, a trailing partial record and file-read failures retain failure behavior. Keep the existing native wire decoder as the one authority.
- Exercise the actual sink lifetime: the backing file remains available through capture/read/retention, then its owned temporary directory is removed when its owner is dropped. Do not test a copied implementation of the reader.
- Keep H's missing/empty/unreadable/inconsistent tests and diagnostics, run-1 refusal before run 2, run-2 attribution, branch/summary mismatch retention, and saved/offline `DBT_STATS` use. The existing `typed_stats_capture_aggregates_the_whole_process_tree` now checks unequal binary records through the actual `VerifyRunWriter` and shared offline reader, with exact bytes and the same strict snapshot. No new H test count is introduced by this extension.

This is an ownership deletion, not a claim that the old valid-input behavior was broken. Existing H negative cases already express the acceptance bar. A test failing to compile solely because a new API does not exist is not a behavioral failing-first result. Record any real failing test at its exact source; do not add a deliberately broken production stub or relabel a compiler failure as a semantics reproduction.

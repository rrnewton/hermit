                                        What the controls do

                                        Mute keeps the call open and keeps the agent's context; it only stops sending it your audio. Your phone will still show the microphone as in use, because the microphone really is still open — which is what lets unmuting drop you back into the same conversation rather than a new one. Muting and unmuting each send the agent a note saying the pause is deliberate, because withholding your audio looks to it exactly like you going quiet, and that is what makes it start asking whether you are still there. Whether it honours that note has not been tested against the live service yet. The call is billed while muted either way: what is metered is the conversation being open. Hang up ends the conversation. The vendor cannot resume a call once it has closed, so the next call is always a new one; the lines already on screen stay there because they are still your own record of what was said, and the transcript marks where one conversation ended and the next began. With Resuming turned on, this server reads the earlier lines back to the new call so it can carry on from them — that is a reconstruction from our side, not the same conversation, and the transcript seam says which of the two you got. Sound silences the agent's voice without silencing the agent: its replies keep arriving as text in the transcript. It keeps receiving that audio and throws it away rather than asking for a text-only conversation, because the response format is settled once when the conversation opens — switching it would mean closing and reopening the socket, and a reopened socket is a new conversation that remembers nothing. Silencing the agent must not cost you its memory. The message box at the bottom of the call's transcript is for writing to the agent, and it is always there — writing never changes the control bar, so the Voice/Channel switch stays where it is. During a call a message goes into the same conversation you are speaking in, so a typed turn and a spoken one land in the same transcript and the agent answers either one out loud. With nothing open, your first message starts a typed conversation and goes as soon as it is open; clicking into the box or typing in it opens nothing. A typed conversation never asks for the microphone, so there is no permission prompt and no in-use indicator, and there is no Talk or Sound button because there is no microphone to mute and no voice to silence — End chat ends it, and Talk is back for a spoken call. That is a different kind of conversation, chosen when it opens — not a call with two switches thrown, which is what it used to take. This page also asks the agent for a text-only response, but that is an override an agent's own settings can refuse; if it is refused the agent's audio is received and thrown away, the connection details say so, and nothing about the microphone changes. Whatever you have half-written stays in the box when you leave the screen or reload, until it is sent. Clear empties this screen only and never makes the agent forget anything. It asks twice, because it sits under your thumb and it cannot be undone. It also leaves the stored record on the server untouched, so the conversation comes back the next time you sign in — Forget stored conversations is the only control that erases that, and it leaves the screen alone in return.

                                        Keyboard

                                        On a computer the messages can be read and dealt with from the keyboard. The arrows, or j and k, move a ring from message to message; what a key does to "the selected message" it does to the one in the ring. The mouse moves the same ring: moving it over a message, or clicking one, selects that message, and the next key goes on from there. Only one message is ever lit, ringed solid in blue while it is unread and dashed in grey once it is read; marking it Done turns its ring grey as the ring moves on, and the Undo chip names it. A list that scrolls under a mouse you are not moving leaves the ring where the keys put it. A tap on a touch screen selects a message without lighting it. A key that types a character never acts while you are typing in a box: Esc and the Ctrl or Cmd chords do. Those single keys can be turned off under Keyboard in Settings. Nothing here starts a call, and Esc never marks anything read. Ctrl+S (Cmd+S on a Mac) goes to the message box from anywhere, the search box included, and so does Ctrl+Enter when you are not in a box; it used to open the search, which / and the magnifying glass still do.

                                        Microphone

                                        These are asked of the browser when the microphone opens, so a change applies to your next call, not the one in progress.

                                        Echo cancellation stops the agent hearing itself through your speaker and answering its own voice. Headphones solve this too; leave it on if you are on speakerphone.

                                        Noise suppression filters steady background noise — a fan, road noise, a room's hum.

                                        Automatic gain control amplifies quiet input. In a near-silent room it boosts small incidental sounds — a phone being set down — until they cross the speech threshold and get transcribed as words. Turn it off if you are getting phantom transcripts.

                                        Control bar

                                        The strip carrying the gear and the Voice/Channel switch. It can sit under the title at the top of the screen, or in the dock directly above the big buttons — bottom is the default, because that is where your thumb already is and because the header then costs no row at all. The gear is deliberately at the far left of it: it is the control you least want to hit by accident.

                                        Canned prompts

                                        What the prompt buttons say. Prompts in the control bar opens a tray of them above the bar; tapping one sends exactly this text into the live conversation, as though you had typed it, and puts the tray away. Emptying a field puts its default back rather than leaving a button that does nothing. All of them are greyed out when there is no call, because there is nothing for the sentence to reach — the tray still opens then, so you can see what they are.

                                        Sumry deliberately says recent messages and not "my unread messages since I last spoke". Read state and account identity depend on the configured chat service, and the bridge may post on your behalf. This prompt therefore asks about the recent messages available to the agent.

                                        Blockers makes the coding agent do work. It is not a question about the channel; it asks the voice agent to go and get the coding agent to report. It is drawn as an ordinary button rather than a warning: the cost is real, but a control that looks like a fault report is worse than one whose cost is stated here.

                                        Who is who in this channel

                                        The call transcript tells its two speakers apart by side, colour and corner. The channel can do the same, but only once it knows which account is which. A display name alone cannot reliably distinguish you, the bridge and the coding agent. The list sits inside Channels, under the channel picker, and shows everyone who has spoken in that channel, with what this page guessed shown in italics; change any of them and the channel is redrawn.

                                        The guesses, in the order they are tried: the account this bridge posts as is you — your own replies and anything your voice bot says go out through it, so they are your words even though a bot delivered them; a lone bot that is not this bridge is the coding agent; everyone else is another person or another bot. With two candidate bots the guess refuses rather than picking one. The guess is made per channel, so a bot that only ever speaks somewhere else cannot spoil the guess here.

                                        A choice, though, is about the account rather than the room: an account is the same account wherever it speaks, so choosing here applies in every channel it appears in, and you do not have to name your coding agent once per channel. Nothing here is sent anywhere: it is stored in this browser and affects only how the channel is drawn.

                                        The channel, and the inbox

                                        The channel view shows messages from Chat, rendered from a small, fixed markdown subset. Message text is written by other people and bots: it is escaped before anything else happens and is never treated as markup or as an instruction. Every line shows its author and its message id, so a message the agent describes can be checked against a real one — or shown not to exist.

                                        A message somebody has answered is dimmed. That is derived from the reply references on the answering messages — so it can only see answers that are loaded: a reply further back than you have walked is invisible, and a message can be dimmed later than it should have been, never earlier.

                                        A message that is itself a reply is set in from the left, with an arrow in the space beside it. When the message it answers is the one directly above, the arrow leaves the top of its left side and reaches up until it touches that message. When the message it answers is anywhere else, the arrow leaves the middle of its left side and slants away up to the left, touching nothing. Tap the arrow to go to the message it answers, which is lit for a moment: in this view if it is here, in All if it is in another part of the channel, and a few older pages back if it is not loaded yet. If it is further back than that, or gone, the status line says so. Back to reply takes you back to where you tapped.

                                        Reply says how many replies a message has once they are loaded: Reply (2), yours counted from the moment you press Send. Replies in a thread that point at no message are counted by the thread's chips instead. When a reply is not directly below, the message it answers has a small blue circle on its lower-left corner, the other end of the reply's arrow: tap it to go to the reply, and tap again for the next one.

                                        Quote reply. Select some of a message's words (drag over them, or double- or triple-click) and its Reply becomes Quote reply; where the row has no room for that without moving its words, it reads Quote. It opens the reply with those words at the top, each line starting >, then an empty line, and the box ready for the rest. It posts where Reply would; on Slack that is the message's thread. A draft you had started stays, under the quote, and a quote you leave untouched is not kept as a draft. Up to 1,000 characters are quoted: a longer selection is cut there and ends with “…”. On a computer, r on the selected message quotes the words selected in it; on a phone, select by pressing and holding, then tap Quote reply.

                                        N replies under a message gathers its replies, and the replies to those, directly beneath it, in time order, joined to it by one line, and leaves everything else where it was. Tapping a reply's arrow twice gathers the whole conversation it is in, under the first message of it that is loaded. Nothing is read or archived by it, and the message stays where it was on the screen. The × beside the line, or the pressed N replies, puts the replies back in time order; so do changing view or channel, and filtering from the search bar. Thread(N) opens a message's thread.

                                        On Main, a message whose thread holds unread replies says how many beside its N replies: M unread, which opens the thread at the first of them. Hide read and Collapse read keep that message in view, though it is read itself. It counts the replies this page holds; M+ unread means there may be more, and N new means the chat service reports replies this page has not loaded yet, which a tap reads.

                                        Archive is your own judgement, and it is recorded on the server — so it survives a different browser, a different device and a cleared cache. Swipe a row on a touch screen, or use the row's button on any device; swiping an archived row puts it back. By default an archived row stays where it is, greyed and drained of colour, so you can see what you have dealt with and change your mind.

                                        A reply you send marks what it answers Done, as its Done button would, with Undo to take it back. Only that message is marked, never the rest of its thread, and a send that fails marks nothing.

                                        The button beside Pace says what the list does with messages already read — archived, your own, or read automatically — and a tap moves it on to the next: Show read shows them greyed; Collapse read turns each run of two or more into one line, … 12 read messages …, which a tap opens, while keeping a thread's first message and the newest message in view; Hide read takes them out of the list entirely, which is what turns the channel from a log into a queue. A search, Links or whose messages opens every collapsed run, so nothing they match is behind a line; and while one is on, on a chat service with threads, Hide read steps aside too, so a read message that matches is shown, greyed — an old match is read by definition. Closing the search puts Hide read back.

                                        Searching. The magnifying glass filters the messages already loaded: every word you type has to be in a message for it to stay, and a quoted phrase has to be there whole. Each place a word is found is highlighted, the message's text, its header and its links included; a link found only by its address is outlined. A folded message whose match is further down says so under it, with a few words either side, and a tap opens it. Where the search leaves messages out between two it shows, a line says how many: … 12 unmatched messages ….

                                        Searching further back. Only what is loaded is searched, so while a search, Links or whose messages is on, the button at the head of the list says Search before Oct 3, the day the list reaches back to. Press it, or Enter in the search field — a phone keyboard's Search key — and it reads up to five older pages, for at most about fifteen seconds, stopping once three more messages match; meanwhile it says Searching… 2 of 5 · Stop, and pressing it stops. What it found is said under it, and the matches appear right below, the line above the first saying how many messages it skipped. Each press is one more search, never more on its own — and while a search, Links or whose messages is on, scrolling to the top of the list loads nothing by itself: this button, or Enter, is the way back, so a search cannot read a channel's whole history unasked. Main holds a thread's first message and none of its replies: in one column, a search nothing on Main matches offers Search All — thread replies too; in two columns, the cards on the right are found by what the thread's first message says and by the replies this page has loaded, and the thread selected there searches its own older replies.

                                        Days. A line above the first message of each day says which day it is — Today, Oct 12, Mon, Yesterday, Oct 11, Sun, or the date and weekday, Oct 3, Sat, with the year when it is not this one — by this device's clock and calendar, and it moves on at midnight by itself. Where messages are left out between two shown ones, by a filter or a collapsed run, the days they reach are said once, on that line: … 12 unmatched messages · Oct 3 – 5 …, or Oct 9 – Today. So a search that finds a few messages days apart shows each gap's days as one range, never a stack of lines.

                                        Yours, or theirs. The speech bubble left of Links in the search bar shows only your messages — with nothing typed, every prompt you wrote among the messages loaded — then only everyone else's, people and agents alike, then everyone's again; Shift+M does the same. Your messages are the ones drawn as yours, on the right. A message has to pass every filter in the bar: the search text, Links, Pinned and whose it is. On a chat service with threads Hide read steps aside while one of them is on, as Collapse read does, so your own messages show even when they count as read; on one without, Hide read still applies, and with your own messages counted as read it leaves none of yours to show.

                                        A filter keeps your place. Typing or clearing a search, closing it, turning Pinned or Links on or off, whose messages, the kinds of link under Links, and the read mode each leave the message you selected where it is on the screen — with nothing selected, the message at the top. So a pin found under Pinned and selected is still in front of you when the filter goes, among the messages around it; one older than anything loaded is fetched first, with Loading earlier messages… at the head of the list. When the new filter hides the message, the nearest one shown takes its place, and the status line says so. It stays put, new messages and all, until you scroll or do something in the list.

                                        Opening a thread takes you to its first unread message, already expanded, with the thread's first message above it when both fit. A thread with nothing unread opens on its newest message, as before.

                                        Two columns. On a desk, in a window at least 1000 pixels wide, the button with two panes beside the view picker puts Main on the left and a thread on the right. The view picker greys out: there is nothing left for it to choose. With no thread selected, the right column lists the channel's threads, newest activity at the bottom as in the channel, each as its name and summary when they have been summarised, or else its first message, three lines at most. A click on a card highlights it: it shows all of it, and every other card's edge and every other line between the columns go grey, until you click another card, the same one again, or press Esc. The card's N replies · M unread opens its thread, and so does →, on the highlighted card or the one the keys are on; ← comes back to the cards. Unread only beside its heading narrows the list to the threads with unread replies, and is remembered on this device. The search finds a card by its own words or by the replies already loaded for its thread, and says in replies on a card it found only there. A line in each thread's colour joins its first message on the left to its card on the right while both are on screen; the highlighted card, or else the message or card you select, draws its line even when the other end is off screen, pointing up or down to it, and if you stay on it for about a second and a half the other column scrolls that end into view. A thread's Thread(N), its N replies or M unread, the Threads screen and a card's N replies · M unread each select the thread on the right; a tap on a message still only opens or folds it. The × at the top of the right column goes back to the list. The search, Links and the read mode apply to both columns, and [ and ] move the keys between them. Reply and Quote reply open the reply box at the foot of the column you pressed them in, with the message you are answering edged in the accent where it stands; both columns stay on screen, and Send reply, Cancel or Esc puts the column back where it was. A reply that does not go says so on the status line, and that column's Newest reads Reply not sent until you go down to it and its Retry. A narrower window shows one column again, in the view you left it in, and keeps the choice for when the window is wide again; a reply you were writing moves to the reply screen with your words.

                                        When the configured chat provider supports it, the row's ⋯ menu offers Mark read in that service. It moves the chat service's own read marker for the whole space to that message, so the service's own app shows it as read. Read markers only move forward. This does not archive anything here; Done remains local and undoable.

                                        Your own messages

                                        A message posted on your behalf is one you dictated moments earlier, so it is already read by the only definition that matters. Leaving it in the queue would make the queue partly a record of things you said rather than things waiting for you.

                                        With this on they are greyed in the channel, collapsed under Collapse read and left out of the list under Hide read. It is not an archive: nothing is recorded on the server, there is nothing to undo, and turning it off brings every one of them straight back. Nothing here changes anything in the source chat service.

                                        Read automatically

                                        Some messages are only placeholders — a coding agent posting Working… while it works, with the real answer arriving later as a separate message. A message whose whole text matches one of these rules counts as read the moment it arrives: it is dimmed in the channel, left out of the list behind Hide read, never read aloud or passed to the voice agent as news, and not counted when the agent counts or summarizes a channel.

                                        Matching is deliberately simple, so a rule never hides more than you expect. The message's whole text must equal the rule, ignoring case, extra spaces, emphasis such as _italics_ or **bold** around it, and the difference between three dots and the single ellipsis character. A message that merely starts with the rule is a real message and is not matched. To match how a message starts instead, end the rule with *, as in Thinking*.

                                        Nothing is recorded per message: the rules are checked against each message as it reads now. A placeholder later edited into a real answer shows as unread again, and removing a rule brings back everything it matched. If a rule catches a message you wanted, Not noise on that row brings back just that one message. The rules are kept on the server and shared by every device you use; the voice agent cannot change them. Like Done, this is this app's own read state and changes nothing in the source chat service.

                                        Combining messages

                                        Chat services limit message length, so a client sending a long one may split it into parts. The next part can begin mid-sentence — often mid-word — and lands a fraction of a second after the first. With this on, messages from the same author within five seconds of each other are drawn as one, with a line break between them. A person almost never sends twice that fast.

                                        It is display only. Nothing is merged anywhere else: each part is still its own chat message with its own id, and this app still holds them that way. Marking a combined row as dealt with marks every message in it, reading it aloud reads all of it, and a row counts as dealt with only when all of its messages are — so a half-archived row shows as still waiting rather than hiding something you have not seen. A reply goes to the first message of the group, which is the one the rest is a continuation of.

                                        Turn it off to see the original messages, one row per message. That is worth doing when you are checking whether a specific message exists — press and hold a row to see every id it is showing.

                                        Rich headers

                                        Agents that post through one shared account often say who they are at the start of a message, in square brackets or parentheses, with a title and a time: [build-bot] Status, 9:05 PM ET. With this on, that first line moves into the message's header: the tag in quiet italics, the title in bold, and the time after an @. The rest of the message is the body.

                                        Where the header has room — on a wide screen — the pieces sit beside the time and the buttons. Where it does not, they become the first line of the message instead. Either way nothing is left out: every word of the first line is shown somewhere, and copying, searching and reading aloud use the message exactly as written.

                                        The server only lifts out what it is sure of: a tag in square brackets, or one in parentheses that the same author has used to start more than one message in the channel. Anything else is drawn as written. Turn this off to see every first line as it was written.

                                        Channels

                                        Everything in this group is about one channel — the one chosen at the top of it. Every other setting on the screen applies to the whole app.

                                        Adding a channel needs the channel ID supplied by this deployment. The chat connector must already have access to that channel in the chat service. The channel is read before it is accepted, so a mistyped id or a channel the bot cannot see is refused straight away rather than joining the list and failing later.

                                        Let this app post here is off unless you turn it on, and it is the one switch that widens what this app can say rather than what it can read. Leaving it off means the channel can be read and replied to from this app but is not somewhere the agent can be told to post.

                                        Any channel can be removed from your list here. One added here is forgotten. One that came from the server's configuration file is hidden instead, because the server never writes that file: it stays off your list across restarts, and Show again under Hidden channels puts it back. Adding it again from Browse or by its id does the same.

                                        What to call a channel

                                        Give a channel a name of your own. This app then uses it everywhere it would have shown the configured label — the picker, the channel summary, and the name the voice agent is given, so what you say out loud is what it was told.

                                        It is ours and local: it is kept on this server, the chat service is never told, the channel is not renamed there, and nobody outside this deployment sees it — the same standing as which messages you have dealt with. Clearing it puts the configured label back.

                                        It is also not something the agent can set. The agent is given the name and cannot choose it, because a model that renames the channels it also reports on can make its own reports unrecognisable.

                                        Reading width

                                        On a wide screen with a mouse, the transcript and the channel are held to a column rather than filling the window: a line of text stops being readable somewhere past ninety characters, and a maximised browser is twice that. Drag the edge of the column, or use the slider — they set the same thing. On a phone it does nothing, because there is no room for a column and no margin to put beside it.

                                        Resuming

                                        The vendor cannot resume a conversation once the connection closes. What this does instead is hand the new call a written record of the earlier one, so it can carry on from it. It is a reconstruction: a new conversation that has been told what happened, not the old one continued.

                                        It re-sends earlier conversation content to the voice vendor on every new call — your own speech, and any channel text the agent read out to you, which was written by other people. That is why it is off by default. The record is capped by the server; when it does not all fit, the oldest lines are dropped and both you and the agent are told the reconstruction is partial.

                                        Live messages

                                        When this server is set to watch the channel, new messages appear on their own rather than at the next refresh. A deployment can use bounded polling or push delivery from a provider adapter; Settings says which mode this server is using.

                                        Arriving messages during a call has three settings, on the bar as Read new and in Settings by name. Don't tell the agent leaves a call alone entirely. Briefly — the default — has the agent say in one sentence what arrived. In full has it read each message out word for word, which is what you want when the channel is the conversation and slow going when it is not. Both speaking modes send channel text to the voice vendor and spend conversation time. Replies this server posted are never sent back — otherwise the agent would hear its own answer and reply to it.

                                        A burst arriving at once becomes one spoken turn, not one per message. Messages that land within about a second of each other are collected and announced together, because a coding agent posting four lines in a row would otherwise interrupt four times and leave no gap to answer in.

                                        It only works while this page is open. The conversation socket belongs to this browser, not to the server, so closing the tab ends the relay even though the server keeps watching the channel.

                                        Only messages that arrive while the feed is connected are sent. When this page attaches to the channel it is first handed what the server already published, so the list catches up; that catch-up is never announced to the agent, because a burst of older messages read out as though they had just been said is worse than not hearing them at all. Anything that landed while the feed was reconnecting is on screen but was not spoken.

                                        How messages are said

                                        Before a message is read out — by the agent during a call, or by the tap-to-listen button — this server rewrites it for the ear. Markdown comes off, so **deploy** is not read as asterisk asterisk deploy asterisk asterisk. Timestamps become three hours ago instead of an ISO string read out character by character. Long numeric ids get a short name such as UID ending in 009, while a tag like D1234567890 becomes Diff ending in 890. The channel view still shows exactly what was typed; only the spoken form changes.

                                        UID and diff endings are stable across restarts. Hash codes still get short letter names that remain consistent while this server is running.

                                        It is on unless the operator turned it off, in this server's own configuration rather than here — the rewrite happens before a message reaches this page, and the voice agent's own tool calls never pass through this browser, so a switch on this screen could only govern one of the three paths. Turning it off is the control arm for tuning the agent's prompt: it makes every difference between two runs the prompt rather than this.

                                        Stored conversations

                                        This server keeps the transcript of each call in a database file on the machine it runs on, so a reload no longer loses the conversation. It is not encrypted: anyone with access to that machine's filesystem can read it, and it holds both your own speech and any channel text the assistant read out to you. Older conversations are dropped automatically once the server's retention limit is reached.

                                        Asking before the voice agent sends

                                        On, which is how this server ships, the voice agent never posts by itself. When you ask it to send something it drafts the message and reads it back in one fixed form — To lead team: on it, rebasing now. Send it? — and a card shows the exact text. Tap Send, or answer with a plain yes, yeah, yep, do it, go ahead, sure or please do — one word of filler such as yes please is fine. Send it works too, but not straight after the question, where it could be the agent's own voice. This page, not the agent, decides that you said yes: only as your very next answer after a read-back that you heard to the end without interrupting, only for the draft this call made, and only if the read-back was the card's text word for word with nothing added. If anything else was said in between, ask the agent to read it back again. Answering its question about sending, no, cancel, stop or wait withdraws the draft, and so does any answer that starts with one of them. Anything longer — "yes, and tell him I'm late" — sends nothing. Whenever you answer something like a yes, the page then tells the agent, and you, whether it was sent; a typed yes never sends.

                                        It cannot tell your voice from anyone else's: a passenger or the radio saying yeah straight after a read-back counts as you. A short word is also the easiest for speech recognition to mishear. Only plain words can be confirmed by voice: a draft with a mention, a link, a symbol such as + or #, an emoji, a time, or formatting such as strikethrough needs a tap, because a voice drops exactly those and the words alone would still match. The read-back names the channel, not the message a reply answers; the card shows that. Spoken yes needs echo cancellation on, so the agent's own Send it? is not heard as your answer.

                                        Off, the agent posts as soon as you ask, and tells you once the server says it was sent. There is no read-back and no card. That also means a chat message the agent reads could talk it into posting, which is why this is on unless you turn it off. The change applies to the server at once and to the agent from its next call — except an agent hosted by its voice provider whose prompt was pasted into the provider's console by hand. That one follows only if the provider lets this page replace its prompt; otherwise it needs the new prompt pasted again. Its approval for post_reply, set in the same console, is changed by hand either way. The line under the switch says which applies, from what the last call was given.

                                        Instructions for the voice agent

                                        Additional instructions are added to what the agent is told at the start of every call: how to address you, how long to talk, what to leave out. Save keeps them on the server, so every device and every later call has them. Empty the box and save to remove them.

                                        Edit the system prompt opens the base instructions themselves — the ones about summarising, reading aloud and treating chat text as untrusted — for you to change. Save keeps your copy; Restore the shipped prompt goes back to the one this server ships, and deletes your copy, so it asks for a second tap first. When a newer version of vibe-talk changes the shipped prompt, your copy does not change with it, and the line under the box says which version it was saved against. The shipped prompt tells the agent never to follow instructions found inside chat messages; take that out and a message it reads has more sway over it.

                                        Neither box can change what the agent is able to do. Whether it can send at all comes from the token it holds, and whether it asks first comes from the Sending switch; the server adds that part after your words, and enforces it whatever the prompt says.

                                        How your words reach the agent depends on the voice service. A voice bridge run with this server fetches the prompt as each call starts, so both reach its next call. A hosted agent is configured in its provider's console, so this page hands them over as the call starts: the whole prompt, if the agent's security settings allow the system prompt to be overridden; otherwise only the additional instructions, as a note at the start of the call, and your edited prompt does not reach it. The line under Instructions says which happened on the last call.

                                        An agent that allows its prompt to be replaced is given this server's prompt on every call, even with nothing of yours saved — the shipped one, with the send rules for the Sending switch — so the prompt in its provider's console is not used, and with only instructions saved the shipped prompt takes its place. That prompt is written for an agent that may send: give such an agent the write token, or one holding the read token is told it can send and is refused every time. An agent that does not allow it, with nothing of yours saved, starts exactly as it did before.

                                        Connection status

                                        What the current conversation is, what audio format it negotiated, and why the last one closed — including the close code, which is the one thing on this page written for whoever is debugging it rather than for you. It is a readout, not a setting, which is why it sits at the end.

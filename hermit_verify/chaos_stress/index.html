ChaosStressOpts
Verification utility for replaying preemptions under hermit This utility runs a guest program under “hermit run” and records schedules and preemptions. On the second run those recorded schedules are replayed via “hermit run” subcommand The outputs (stdout, stderr, log file, schedules) are captured and placed in a temporary directory allowing further inspection (if –keep-temp-dir is provided)

HERMIT_OUTCOMES 🔒
Hermit’s own outcomes that no guest produced, each the exit status from the allocation table in hermit-cli/src/lib.rs with the stderr marker that tells it apart from a guest choosing the same status. A run that ends in one of these says nothing about the guest.
SKID_ATTEMPTS 🔒
Attempts at one iteration while Hermit refuses its runs for PMU skid overshoot.
SKID_OVERSHOOT_REFUSAL_PREFIX 🔒
The prefix of the line Hermit prints when it refuses a run for PMU skid overshoot (classify_failure in hermit-cli/src/bin/hermit/main.rs).

Functions§

classify 🔒
Classify one finished hermit run by its exit status and stderr. Only the guest’s own outcome counts: a skid refusal is returned for a retry, and any other outcome of Hermit’s own (HERMIT_OUTCOMES) is an error, because counting it as the guest failing would report a race nobody found (https://github.com/rrnewton/hermit/issues/4490).
is_skid_refusal 🔒
Whether REFUSAL is the typed skid-overshoot refusal: a positive count, and Hermit’s HERMIT_SKID_OVERSHOOT report of the late interrupt beside it with no panic.

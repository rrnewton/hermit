The synchronous GlobalState failure hook takes the same scheduler mutex as grant/commit, closes an open tentative selection once, records terminal state, then sends the multiwaiter notification after unlocking. Startup, quiescence, and the selected request await can finish without another guest request. The daemon's post-await checks prevent a second undo, grant, timer processing, runqueue rotation or time advance after publication. Existing runqueue assertions and normal response paths remain.

Ordinary RPC admission and scheduler reacquisition after awaits use lock_rpc_scheduler(false). Publication winning that mutex leaves the ordinary callback pending for the backend failure subscription to drop. The helper releases the mutex on Pending and retains no guard across that suspension. It creates no Go, ThreadExited, errno or guest exit status as a fatal notification. The only terminal admission exceptions are consuming DeregisterThread and RobustListWakes. Their existing identity/accounting paths remain. New guarded non-scheduler metadata changes stay in the same mutex scope; exec reconnect clock reassignment and replay-history extraction now remain under the guard through their corresponding mutations. Read-only diagnostics and values have no guest-visible mutation; returned ordinary responses still pass the backend's failure check.

A constructed ThreadState now carries thread_start_entered without a serialization default. Actual handle_thread_start sets it before its first await. Root and every fork/thread construction explicitly reset it, while a successful exec continuation retains its existing state. Deregistration carries the value from its consuming owner. An absent scheduler registration is acknowledged before clock accounting only for a never-started owner or terminal cleanup; a started unknown owner on the ordinary path still violates the invariant. Sender and payload MmId assertions remain. Registered owner accounting is remembered even before a later peer fails, so consuming cleanup after failure cannot repeat it.

KVM's completion API now returns GlobalState on failure. The CLI consumes its scheduler cleanup before returning an anyhow context around the original typed backend error. Successful status, stdout, stderr and lifecycle timing behavior remain separate from fatal errors. Real negative syscall returns retain their existing conversion path in Reverie.

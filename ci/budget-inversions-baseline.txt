# Nodes whose declared wall budget is >= the kill of the job that runs them.
#
# EACH LINE IS A NODE THAT CAN NEVER FIRE ITS OWN TIMEOUT. The job's clock always
# wins, so the node is never named as the overrun; the lane reports only that
# "CI timed out". This file is the inventory of that condition as it stands, not
# permission for it.
#
# The guard (ci/test_harness.sh assert_node_budgets_fit_their_job_kill) fails on
# any inversion NOT listed here, and equally on any entry here that no longer
# inverts -- so the list can only shrink, and a fix must delete its line.
#
# HOW TO REMOVE A LINE, and this is a real decision rather than a formality:
#   * lower the node's wall in ci/dag/<lane>.json so it fits inside the job, which
#     may make a node that has always silently overrun start failing visibly --
#     that is newly EXPOSED, not newly broken; or
#   * raise that job's timeout-minutes, which is a cap increase and needs the
#     explicit approval that class of change requires.
# Both are CI policy calls. The guard deliberately does not choose.
#
# Format: <node> <declared>s >= <bound>s (<what bounds it>)

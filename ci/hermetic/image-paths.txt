#
# Each `PATH TARGET` line is an executable under /bin, /sbin or /usr/bin of the
# image and the /nix/store file it resolves to through every link. The
# planner's pinned-guest check reads the paths: every gating cell of a compat
# bucket that names one of these directories (or a bare program) must name a
# path listed here, so the gating corpus cannot quietly depend on a program
# the image lacks. /usr/bin is the curated set from guest-paths.txt; /bin and
# /sbin (a link to bin) are the image's Nix profile. Names that start with a
# dot are listed like any other (`shopt -s dotglob` in the recipe below), so
# an unlisted /usr/bin/.x is refused; the profile's /bin/.gzip-wrapped links
# to the ELF program that gzip's wrapper script runs. Dangling links (the
# profile's /bin/ld.so) are not listed. These three are the image's
# directories among the guest PATH, `/usr/local/sbin:/usr/local/bin:
# /usr/sbin:/usr/bin:/sbin:/bin` (GUEST_PATH_DIRECTORIES in
# ci/manifest-plan/src/compat_guest_root.rs); the image lacks the other three.
#
# Each `file: PATH TARGET sha256:HEX` line is a file whose bytes are recorded
# too: the image's dynamic loader and the libc beside it.
#
# The `tree: DIRECTORY sha256:HEX` line records the content digest of the
# image's whole /nix/store, where every TARGET lies: the sha256 of one line
# per entry, sorted bytewise, each ended by a newline: `PATH<TAB>x<TAB>SHA256`
# for a regular file with an execute bit, `PATH<TAB>f<TAB>SHA256` for another
# regular file, and `PATH<TAB>l<TAB>LINK-TARGET` for a symbolic link
# (tree_digest in ci/manifest-plan/src/compat_guest_root.rs).
#

# program that a workload arm tests for before falling back to an image path

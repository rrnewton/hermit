# Hermit 0.5.0

Hermit 0.5.0 improves Linux syscall compatibility for threaded programs,
shells, build tools and networked applications. These notes summarize changes
since `v0.4.1`. Ptrace remains the default and best-tested execution path;
individual KVM and in-guest paths have different capabilities and limitations.

## Signals, waits and process lifecycle

- Ptrace waits now distinguish signals that interrupt a call from signals that
  Linux ignores or holds. Timed `poll` and futex waits preserve their deadline
  across stop/continue and `restart_syscall`. Masked `pselect6`, `ppoll`,
  `epoll_pwait` and `epoll_pwait2` retain the temporary signal mask through the
  wait and its interruption. A signal arriving before the first mask probe
  restarts the call rather than leaking a spurious `EINTR` from `rt_sigaction`
  or `rt_sigprocmask`. See the
  [blocked-wait review](https://github.com/rrnewton/hermit/pull/3361),
  [deadline fix](https://github.com/rrnewton/hermit/issues/3358) and
  [mask-probe fix](https://github.com/rrnewton/hermit/issues/4526).
- Child exits produce one `SIGCHLD` with the child's exit information rather
  than duplicate notifications or the tracer's identity. On ptrace, a
  thread-directed guest `SIGCHLD` can interrupt gated waits and pipe calls;
  restartable pipe calls honor `SA_RESTART`. See
  [child notifications](https://github.com/rrnewton/hermit/issues/3895) and
  [wait interruption](https://github.com/rrnewton/hermit/issues/4273).
- A `vfork` parent becomes runnable when its child successfully executes a new
  image or exits. This lets tools such as `make -jN` start another job before
  the preceding job finishes; guest execution remains deterministically
  scheduled, rather than gaining parallel execution.
- Ptrace supports `PR_SET_CHILD_SUBREAPER` in the child-wait model, and
  guest-sent `SIGKILL` retires victims at a schedule-defined point. Process
  groups and sessions are modeled by shared Detcore state. KVM child-wait
  fixes preserve `waitid` copyout, interruption and child accounting. See
  [subreapers](https://github.com/rrnewton/hermit/issues/3997),
  [killed-process retirement](https://github.com/rrnewton/hermit/issues/3994)
  and [process identity](https://github.com/rrnewton/hermit/issues/4266).

## Futexes and virtual time

- Precise futex mode implements `FUTEX_REQUEUE`, `FUTEX_CMP_REQUEUE` and
  `FUTEX_WAKE_OP` instead of panicking. Wait admission and re-waiting use
  Linux's error precedence and return `EAGAIN` when the word changed.
  Robust-mutex waiters wake when a successful ptrace exec removes their owner.
  See the [futex implementation](https://github.com/rrnewton/hermit/pull/4020)
  and [robust-owner fix](https://github.com/rrnewton/hermit/issues/2082).
- Sequentialized run mode counts timerfd expirations on virtual time on
  supported paths, including ptrace and KVM. Ptrace `ITIMER_REAL` and
  observable POSIX timer signals coalesce missed periods as Linux does;
  POSIX deliveries retain `SI_TIMER`, timer values and overrun counts. See
  [timerfd](https://github.com/rrnewton/hermit/issues/1923),
  [interval timers](https://github.com/rrnewton/hermit/issues/4139) and the
  [POSIX timer review](https://github.com/rrnewton/hermit/pull/4491).
- `clock_gettime` and `clock_getres` reject unknown nonnegative clock IDs
  with `EINVAL`. `select` accepts positive microsecond fields larger than
  one second by folding them into seconds; `pselect6` continues to reject
  out-of-range nanoseconds.

## Files, directories and the guest machine

- With metadata virtualization enabled, `getdents` and `getdents64` serve a
  whole sorted directory snapshot, including listings spanning many buffers.
  `dup` and `fork` share its position, seek cookies identify the returned
  entries, and rewinding refreshes the snapshot. Copyout faults preserve
  complete directory records.
- Blocking opens of FIFOs created by the guest can yield while waiting for
  another guest to open the peer, avoiding a scheduler deadlock in shell
  pipelines. See the [FIFO fix](https://github.com/rrnewton/hermit/issues/2203).
  `splice` and `tee` return `EINVAL` under the default refusal policy so
  callers such as GNU grep can fall back to ordinary reads and writes.
- `--proc=minimal` is now the default; `--proc=standard` exposes a larger
  documented set. Omitted names return `ENOENT`. Detcore renders more of
  `/proc` from the guest model, including CPU information, uptime, mount
  tables, per-process executable links, auxiliary vectors and cgroups.
  `/proc/locks`, available at the standard level, filters lock rows using
  tracked guest ownership. CPU and NUMA topology report one virtual CPU and
  one node. See
  [procfs levels](https://github.com/rrnewton/hermit/issues/4266) and
  [shared procfs rendering](https://github.com/rrnewton/hermit/issues/4213).
- `statx(STATX_MNT_ID_UNIQUE)` now supplies a virtual unique-mount ID,
  allowing systemd's path resolution and package-install triggers to work.
  See the [systemd compatibility fix](https://github.com/rrnewton/hermit/issues/4519).

## Recording and replay

- `hermit run --record-networking=PATH` records outbound TCP traffic;
  `--replay-networking=PATH` replays the captured input offline and checks
  outbound bytes. This mode supports polling and selection of recorded
  sockets; it is distinct from full syscall recording.
- Full syscall recording now captures `accept`/`accept4`, `bind`, `listen`,
  `shutdown`, `epoll_ctl`, `epoll_pwait` and `epoll_pwait2`, including relevant
  output buffers and interruptions. Replay preserves `fcntl` query output,
  directory seeks and the bytes copied by `sendfile`. See
  [accepted connections](https://github.com/rrnewton/hermit/issues/3864),
  [Go file-open replay](https://github.com/rrnewton/hermit/issues/31),
  [masked epoll](https://github.com/rrnewton/hermit/issues/4086),
  [epoll_pwait2](https://github.com/rrnewton/hermit/issues/4088) and
  [sendfile](https://github.com/rrnewton/hermit/issues/4416).
- Verification seals shared invocation inputs before its two runs, rejects
  known determinism losses and failed log writes, and can identify a changed
  host input as the cause of a divergence. Use `--verify --verify-strict`
  for canonical full-observation comparison; ordinary `--verify` retains
  its less strict comparator.

## Known issues

- Reverie ptrace can miss the displaced leader's preceding EXIT status during
  a nonleader exec in the tool-hook-failure regression, leaving replacement
  cleanup pending before the expected failing hook is invoked.
  The regression test
  `ordinary_nonleader_exec_displaced_hook_failure_fences_replacement`
  failed at repetition 156 of a 200-attempt stress run on unchanged main, after
  155 passes. This pre-existing intermittent defect is not repaired in 0.5.0;
  passing candidate repetitions do not establish a fix.

## Migration and known limitations

The registry package boundaries below apply to the `release/0.5.0` branch.
Development main retains its existing Cargo package names and experimental
features; the release projection is not merged into main.

- The crates.io package remains `hermit-run` and installs the `hermit`
  executable. The Rust library keeps the `hermit` import name. `libhermit.so`
  now requires a source build of the separate `hermit-cdylib` package.
  DynamoRIO, e9patch and SaBRe third-party implementations are not bundled
  in the registry packages. LiteInst, in-guest-trap and native-exec are also
  outside this registry release: their development crates stay private, and
  the public Cargo features and dependencies that would select them are
  absent. `third-party-backends` enables only SaBRe/e9patch Rust glue, which
  requires separately supplied runtime artifacts. The default ptrace/KVM
  dependency graph does not require LiteInst or an unpublished `liteinst2`.

- Explicit `--strict` now requires `--epoch`, `HERMIT_EPOCH`, or an epoch
  supplied by a recording, and rejects `--seed-from=SystemRandom`. Preserve
  the epoch and seeds when reproducing a run. An explicit strict ptrace run
  refuses a branch counter that fails validation. Deterministic preemption
  continues to require usable hardware performance counters.
- The syscall recording format is `0x17e`. Recordings from 0.4.1 are not
  compatible; retain the old Hermit executable to replay them.
- The optional `--cpu-profile=x86-64-v3` is for qualified ptrace hosts.
  Replay binds the recording host's CPU and XSAVE facts. Qualification
  samples a fixed set of cases and cannot rule out every VM exit or firmware
  effect on extended register state. The default remains x86-64-v2. See
  [the profile's limits](../USER_GUIDE.md#the-x86-64-v3-cpu-profile).
- Priority-inheritance futexes remain unsupported. Some process-directed
  signal cases and timer transitions still end with a named refusal.
  KVM and in-guest paths do not inherit every ptrace signal or lifecycle
  guarantee merely because they use Detcore.
- Directory descriptors received through `SCM_RIGHTS` can still repeat
  entries ([known alias gap](https://github.com/rrnewton/hermit/issues/3722));
  snapshot allocation can fail with `ENOMEM`
  ([scratch-memory gap](https://github.com/rrnewton/hermit/issues/3723)).
  Virtual unique-mount IDs can be reused if Linux reuses a classic mount ID;
  `statmount` and `listmount` remain unsupported.
- Procfs coverage is still incomplete. Some allowed files retain kernel
  dependencies, and `/proc/locks` can omit guest locks when descriptor
  ownership is untrackable. Its filtering does not isolate lock operations
  on files shared with the host.
- Network-only recording is for outbound TCP clients, not UDP or listening
  servers. Unsupported operations are refused; it is not complete isolation
  from every host-network observation. Full syscall recording is the separate
  path for supported server workloads. A changing filesystem and external
  inputs still require explicit control for reproducibility.

The backend prerequisite of DetConfig::untrap_passthrough_syscalls: the ptrace backend, whose seccomp filter is what leaves the calls untrapped. KVM’s hypercall and the in-guest runtimes’ SIGSYS trap intercept syscalls their own way, which the mode has not been checked against. Detcore’s own admission (detcore::untrap_passthrough_admission) reads what a backend can do, never which backend it is, so this is decided here, where the library sees the built-in backend, by Detcore’s rule for a launch off ptrace (detcore::untrap_passthrough_off_ptrace): every launch reaches it in dispatch_backend or dispatch_output_backend, before Detcore’s admission and before the guest starts. hermit run’s validation asks it too, and KVM’s direct entry, hermit_run_kvm::run_detcore, asks Detcore’s rule itself.

Module vm_teardown

Handing KVM VM destruction to a longer-lived helper process.

Closing a VM fd waits out a kernel RCU grace period in kvm_destroy_vm (facebookexperimental/reverie#132), on whoever closes last. A short-lived CLI gains nothing by moving that close to another of its own threads: process exit closes every descriptor the threads have not reached, in the exiting process, and inside one CPU quota the deferred waits stop hiding under guest execution (measured; see the commit that added this module). So the binary instead spawns a small helper process (its own image re-executed in a private role, __hermit-vm-teardown-reap in the bin’s vm_teardown_helper module) before the container clone, and this sink passes each dropped backend’s duplicated vCPU and VM descriptors to it over a Unix socket with SCM_RIGHTS. The kernel takes the file references at sendmsg, so the backend’s own closes right afterwards only drop references and the helper’s closes are the destroys.

Ownership and lifetime, exactly:

  • The bin installs one sink per process, before the first container clone, through install_vm_teardown_sink. The container child inherits the installed sink and its socket at the clone; only the child adopts into it. The sink starts no threads in either process — a container clone copies none, and its callback return exits only the calling thread — so adopters count the helper’s acknowledgements themselves, as Inner::receive describes.
  • The helper serves until the socket reaches EOF — every sender copy closed, which happens when both the parent process and its container children have exited or been killed — then drains its queue and exits. Its bound past the run’s own exit is the drain: one bundle’s destroy per worker thread, every prior bundle having been destroyed or concurrently in flight since its adoption. If the helper dies at any point, the kernel closes the descriptors it holds in its own exit path, so every VM is still destroyed; later adoptions see the dead socket and fall back to the backend’s synchronous destroy (the sink’s duplicates close locally, then the backend’s own field drops are the last ones).
  • Adoption is bounded per adopting process: at most MAX_IN_FLIGHT_BUNDLES unacknowledged bundles are outstanding from it, and adoption blocks past that. A bundle keeps one guest memory’s pinned pages alive, so an unbounded backlog would be unbounded host memory; blocking degenerates to synchronous teardown under overload instead. Sequential container children sharing one helper can transiently sum to a few such bounds while the helper drains the previous child’s tail.

Nothing here is guest-visible: adoption happens from a backend’s drop, after every guest-visible effect of that exit was published on the dropping thread (see reverie-kvm’s teardown module). With no sink installed, run_kvm leaves every backend to destroy its VM synchronously, exactly as it did before this module.

ACK_BYTE
The helper’s per-bundle acknowledgement, sent after both closes.
BUNDLE_BYTE
The data byte accompanying one forwarded descriptor pair.
READY_BYTE
Sent once by the helper when its receive loop is running. Senders do not wait for it (the socket buffers bundles sent before the helper starts); it exists so tests and diagnostics can tell a live helper from a dead socket.

Functions§

install_vm_teardown_sink
Installs the process’s teardown sink on stream, the sender end of the socket to the helper process. The binary calls this once, before its first container clone, so the container child inherits the installed sink and its socket. Returns whether this call installed it; a later call drops its stream and changes nothing.
recv_vm_bundle
Receives one bundle sent by send_vm_bundle from fd. Ok(None) is a clean EOF before a bundle byte. A malformed message (wrong byte, truncated control data, a descriptor count other than two) is an error, and any descriptors it carried are closed before returning it: the helper treats that as fatal and exits, after which senders fall back to synchronous destroys.
send_vm_bundle
Sends one descriptor pair (vcpu first, mirroring the close order) with a BUNDLE_BYTE over stream. The kernel references both files for the receiver before this returns, so the caller may close its own copies immediately afterwards. MSG_NOSIGNAL: a dead helper must report EPIPE to the sender (which falls back to a synchronous destroy), never kill a running guest’s supervisor with SIGPIPE.
vm_teardown_sink
The installed teardown sink, for run_kvm to hand to each backend.
vm_teardown_sink_installed
Whether a teardown sink is installed in this process.

Module preemption_admission 

Source
Expand description

Refuse timer requests that the selected runtime cannot implement.

This is launch policy, not a timer implementation or a replacement for Detcore’s scheduling policy. Cooperative scheduling at existing guest events remains available without a preemption timer.

refuse_unqualified_annotated_launch
The library launches’ backstop for the same requirements, on the prepared configuration a backend is about to run: a library caller passes no command line, and its configuration reaches here unqualified. An annotated configuration must meet annotated_priority_replay_unqualified on the capabilities it carries. Its record is not reread here: Detcore refuses a record whose checkpoints disagree with the flag before any thread starts. Nothing is changed or forced.
refuse_unqualified_annotated_replay
Refuse to replay a callback-annotated priority history where its row ends cannot be honored: they are actual callback endpoints at exact RCB counts, guarded one RCB past each. The requirements are Config::annotated_priority_replay_unqualified’s, judged here on the command line’s configuration with the selected backend’s capabilities, so the refusal comes before input is read and names the backend. Without them a replay would neither reach nor bound those endpoints, and silently falling back to the legacy expiry would replay the wrong schedule. A record without checkpoints keeps its existing admission; this check never rewrites the configuration.

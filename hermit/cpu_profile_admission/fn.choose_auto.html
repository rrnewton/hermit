Expand description

The profile hermit run presents under auto for a program whose executable and interpreter ask for needs (resolve_auto) and whose C library beside a glibc interpreter does or does not declare x86-64-v3 (libc_v3, libc_needs_v3), for request:

  • x86-64-v3 for a program that declares it (declared), admitted afterwards as an explicit x86-64-v3 is, so a run that cannot carry it is refused;
  • where only the C library declares x86-64-v3, the same declared x86-64-v3 (its detail naming the C library) where this run presents a virtual CPU, so a backend or host that cannot carry x86-64-v3 refuses it by name instead of glibc refusing inside the guest; where the guest sees the host’s real CPU (AdmissionRequest::guest_sees_host_cpuid) the declaration does not decide, exactly as before it was read, and is recorded in the choice’s detail;
  • x86-64-v2 where request cannot carry x86-64-v3 (check_request);
  • otherwise the host’s answer, once per process: x86-64-v3 where admit passes, x86-64-v2 under a hypervisor without qualifying the host, and x86-64-v2 where the qualification refuses.

An Err is a malformed AUTO_HOST_TEST_ENV.

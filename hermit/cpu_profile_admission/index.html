Module cpu_profile_admission 

Source
Expand description

Admission for intercepted CPU profiles: v3 binds qualified host XSTATE facts; host-no-rdrand requires CPUID faulting without the v3 qualification.

Every class the v3 startup qualification cannot cover is refused by name. Neither nondefault profile, once named, silently falls back to v2 or native CPUID. auto, the default, presents x86-64-v2 where this run or host cannot carry x86-64-v3, and says why (choose_auto).

The probe costs seconds of CPU, and a replay on a different CPU, or of an altered recording, needs none of it to be refused. Returns the recorded facts.
qualify_host
The host half of admit, run once per process: the kernel, the every-bit CPUID check, the dynamic-feature refusal, the probe and the host facts. hermit host-capabilities --cpu-profile x86-64-v3 runs it alone. It always measures and never reads or writes the cache admit uses.
qualify_host_no_rdrand
Probe the Linux CPUID-faulting API in a child. Disabling CPUID in the tracer would also fault Rust’s and libc’s own feature detection, so only the forked child changes its state. After fork the child uses only libc syscalls and _exit, without allocation, locks or unwinding.
record_or_replay_request
The admission request of a recording or replay, which always runs on the ptrace backend with virtual CPUID.
refuse_unadmitted_launch
Refuses a nondefault profile launch that this process did not admit. Hermit’s library launch functions call this before any backend starts. Host mode requires its faulting proof and interception options; v3 also requires exactly the host facts admit bound after qualification and its floating-point register write ban.
resolve_auto
The named profile --cpu-profile auto resolves to for a guest program at host path program, with why (detcore::exec_record::auto_profile): from the declarations of the image it execs first and of that image’s program interpreter, where to_host gives the host path of a path as the guest names it, or None where a mount with no source hides it in the launch view: a hidden interpreter refuses, rather than reading the host file its mount target shadows. program is the program in the launch’s completed view (its mounts, binds and image rootfs already applied by the caller), and every script hop is mapped through to_host the same way. A script’s interpreter is followed as the kernel follows it (Detcore’s script_interpreter, the load_script rules: the line and the path end where the kernel ends them, at a newline and at a space, tab or NUL), through a bounded chain of scripts to the image the kernel would exec. Evidence is read strictly: a declaration beside a scan state that could not be decided refuses, rather than selecting from a lower bound. This chooses the profile before launch; Detcore’s check of each executed image and interpreter (Detcore::isa_refusal) is still what refuses a run whose actual objects need more, so a pathname read here can never admit one.
resolve_launch_auto
Resolve a configuration’s auto profile for a library launch of command (resolve_auto of the program it names, found as the launch finds it), before refuse_unadmitted_launch. hermit run and hermit record start resolve it earlier, before qualification; a configuration naming a profile is left as it is. A resolved x86-64-v3 is then admitted only as an explicit one is, so a library launch that never qualified the host refuses it by name.
under_hypervisor
Whether this host reports a hypervisor (CPUID leaf 1, ECX bit 31), where auto presents x86-64-v2 without qualifying the host.

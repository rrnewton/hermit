Bumped whenever the rewrite’s output for the same input can change. It is part of the overlay cache key, so a cached artifact from an older rewriter is never reused, and it is the algorithm identity a preemption record states for its run’s rewrite (crate::preemptions), so a replay under another version is refused rather than retiring other instructions. 3: only code is rewritten, as mapping tells it from data; none of the changes since 2 had bumped it, though the canonical shapes the refusal census added, the conditional compare-and-swap refusal, the direct-entry decoding and the positive allow-list each changed what the rewrite writes. 4: a sequence a known entry (the loader’s entry, a defined function symbol or an FDE start) points into is refused, as is a sub-word compare whose head is one. 5: literal loads of an FDE entry protect its instruction bytes from rewriting; only ADR address-taking can use the function-entry exemption. 6: literal readers in unknown executable ranges protect the bytes they reference, including bytes in other sections; only proven data is excluded from that scan. 7: so do the reads through an ADRP’s page or an ADR’s address: an access the instruction bounds protects those bytes, and any other use, or the address held where the scan stops, every executable byte. 8: a UDF #imm16 word, which traps and never branches, no longer refuses the image. 9: nor does a word of the SVE encodings, which hold no branch. 10: flag-setting read-modify-write loops retain the original ALU instruction after the LSE atomic so their outgoing flags are preserved. 11: literal and base readers in executable segment bytes no executable section covers protect the bytes they read, under their own refusal name, and direct branches out of those bytes count as branch targets. 12: a file whose executable section ends past the top of the address space is refused whole, and a relocation’s covered range saturates at the top instead of wrapping.

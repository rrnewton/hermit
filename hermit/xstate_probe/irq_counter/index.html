A per-thread count of the interrupts the probe thread takes, from the core PMU (https://github.com/rrnewton/hermit/issues/4243), condition C11).

The XINUSE probe’s reference trial is valid only if nothing saved and reloaded the thread’s FPU state inside it. Without a context switch, Linux does that only through kernel_fpu_begin in interrupt or softirq context, or in the task’s own syscall, so a trial that took no interrupt, no context switch and no syscall cannot contain a reload. This counter supplies the interrupt half of that certificate, and every property it rests on is checked rather than assumed:

  • the raw event is used only on CPU models whose perf tables document it;
  • it is opened pinned, so it is never time-shared, and every read checks that its time enabled equals its time running (both are cumulative, so equality at a read proves it counted for its whole enabled history);
  • a failed read is an error, never a value that could compare equal;
  • at startup its count over a spin must bind to the kernel’s own count of this CPU’s interrupts in /proc/interrupts.

Constants§

CALIBRATION_SLACK
A fixed allowance on top of the proportional one in calibration_verdict.
MIN_CALIBRATION_TICKS
The fewest local-timer interrupts a calibration must see, summed over its clean spins. CALIBRATION_SLACK is absolute, so this floor is what keeps the binding tight: at 190 interrupts the counter must see at least 180 of them, about 95%, when the reads around the spins take no time. (A single 70 ms spin sees about 70, where the slack alone would admit about 86%.) A tickless (nohz_full) CPU sees almost none, and there the binding says nothing.

Module sleep_registration_admission 

Source
Expand description

Refuse a queued-sleep registration rule the selected backend cannot honour.

First-pass registration (--sleep-registration=first-pass, and by default outside race search) parks every plain sleep as a timed waiter. The scheduler leaves a parked sleep alone for a signal Linux would not let end it only where it reads the sleeper’s signal mask and dispositions (Config::reads_sleeper_signal_state). Where it does not (DBT, SaBRe and LiteInst without the in-guest delivery gate, KVM), a child’s default-ignored SIGCHLD or a signal the sleeper blocks would end every such sleep with EINTR, which Linux never does. The default registers when chosen there. An explicit first-pass, or a replayed record that registered at the first pass, is refused here by name rather than replaced silently, so a run does what it was asked to and its record says what it did.

refuse_unreadable_first_pass_launch
Refuse a launch whose configuration registers queued sleeps at the first pass (detcore::preemptions::requests_first_pass_sleep_registration: the explicit option, or a replayed record’s rule) on a backend whose sleepers’ signal state the scheduler does not read, judged on the final configuration the backend is about to run. The default never asks for the first pass there (Config::queued_sleeps_registered_at_first_pass), and hermit record/replay never register at it, so neither is refused. This check never rewrites the configuration.

Bound metadata-audit concurrency by the CPU width the outer scheduler gave this gate.

gate.manifest is normally a one-core step. Running two audit children in that cgroup lets one child’s Cargo/cache work consume the quota while the other child’s source-current dagrun launcher waits on the shared cache lock. The launcher’s deliberately short wall-time self-test can then expire after almost no CPU time. dagrun exports the admitted width as CARGO_BUILD_JOBS at the final command boundary, so use that same authority rather than host-wide parallelism. Missing or malformed scheduler evidence stays serial; a gate explicitly granted two or more cores retains the measured two-worker path.

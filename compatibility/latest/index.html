Hermit makes Linux execution repeatable by controlling scheduling, time, and randomness. This scorecard compares its backends: determinism asks whether repeated runs agree, while parity asks whether a backend agrees with the reference ptrace backend. Each cell is one workload, execution mode, and backend; results distinguish passes, failures, and unmeasured cells. Totals may combine qualifying results from multiple runs; rebuilding this website does not rerun the tests. For context, start with the introduction to Hermit, or visit the README for setup and usage.

Parity (measured after determinism)

After the determinism checks, the retained verify log of each candidate backend whose inputs can be equalized with the ptrace reference's (kvm, liteinst, sabre, dbt, in-guest-trap) is compared with the ptrace reference log. A cell's credit is the matched prefix of the two logs over the longer one, in [0, 1]; only a complete match earns 1. The parity population is every test whose ptrace verify cell full validation selects, on every candidate backend. A cell whose ptrace reference left no usable golden log is outside it, never 0 credit; every other cell is in it, and a candidate that was not enabled, not selected, failed or left no usable log scores 0.

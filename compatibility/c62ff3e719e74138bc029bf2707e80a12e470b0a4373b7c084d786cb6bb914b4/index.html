Hermit compatibility scorecard

Current determinism, parity, and coverage evidence for Hermit's Linux execution backends.

Hermit makes Linux execution repeatable by controlling scheduling, time, and randomness. This scorecard compares its backends: determinism asks whether repeated runs agree, while parity asks whether a backend agrees with the reference ptrace backend. Each cell is one workload, execution mode, and backend; results distinguish passes, failures, and unmeasured cells. Latest selected measurement: Sep 29, 2026 · 9:17 PM EDT; latest history entry: Sep 29, 2026 · 10:23 PM EDT. Totals may combine qualifying results from multiple runs; rebuilding this website does not rerun the tests. For context, start with the introduction to Hermit, or visit the README for setup and usage.

How comparison evidence earns credit

Numerators count demonstrated comparisons, not generic Green labels. An absent or empty reference population is unavailable. Partial determinism uses the recorded first divergent scheduler turn and a complete same-commit ptrace execution; no missing measurement is inferred as partial. Parity requires explicit cross-backend evidence; partial parity additionally requires its authenticated divergence turn and a complete same-commit ptrace execution. A column with no supported observations is unavailable.

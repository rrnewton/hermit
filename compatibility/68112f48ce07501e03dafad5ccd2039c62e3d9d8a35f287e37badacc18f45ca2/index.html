Compatibility evidence

The Hermit container enables deterministic execution of guest Linux programs.

For more context, see the README and the high-level introduction in the blog post.

Hermit testing centers on a suite of test programs, each identified by a test ID. The central compatibility matrix is indexed by test ID × mode × backend. A mode selects deterministic execution, record/replay, or chaos concurrency testing. A backend identifies the Reverie implementation and the way it instruments the guest program.

This page reports the compatibility evidence recorded in the displayed snapshot; it is not a live status view.

Every count here comes from the single dated measurement run named in the provenance above, so it answers “what did that run measure?” and not “where is the project now?”. Backend work that landed after that run is not represented, and a backend whose coverage changed since then still shows the figure this run recorded. Comparing two dates means opening two snapshots and comparing them; no page on this site does that for you.

Read the result counts against the right denominator. Green and red are counted only over cells this run actually measured, which is a much smaller population than the manifest. Cells the run did not select are reported separately as never measured; they are not failures, and folding them in would understate the pass rate as badly as ignoring them would overstate it.

Hermit compatibility scorecard

Hermit is a reproducible container for Linux programs. It controls thread scheduling, time, and randomness so a program can run the same way again.

This scorecard shows which workloads have been tested and how Hermit’s execution backends compare. Determinism measures whether repeated runs agree; parity measures agreement with the reference ptrace backend. Each test cell is a workload, execution mode, and backend. The tables distinguish passing results, failures, and missing measurements. For context, start with the introduction to Hermit, or visit the README for setup and usage.

The totals combine qualifying results from multiple runs. History also retains other runs; rebuilding this website does not rerun the tests.

How comparison evidence earns credit

Numerators count demonstrated comparisons, not generic Green labels. An absent or empty reference population is unavailable. Partial determinism uses the recorded first divergent scheduler turn and a complete same-commit ptrace execution; no missing measurement is inferred as partial. Parity requires explicit cross-backend evidence; partial parity additionally requires its authenticated divergence turn and a complete same-commit ptrace execution.

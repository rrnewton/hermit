Explanation

600 tests × 19 cells per test = 11,400 cells in the manifest. The 19 are 3 modes (chaos, replay, verify) × 6 backends (dbt, in-guest-trap, kvm, liteinst, ptrace, sabre) + 1 naked/native.

Current policy can run 2,758 cells during normal validate testing and disables 6,185 combinations. Restrictions include unsupported modes or backends and test-specific limits. Measured results still count when a combination is disabled. 2,457 other cells have no conclusive result and are listed in the data audit. 2,758 + 6,185 + 2,457 = 11,400 manifest cells.

Overview counts use 4,199 cells from existing tests: 4,199 have a result and 0 have no usable measurement. Green means the test passed; red means it failed or timed out. Recorded results count regardless of whether the current CI policy runs the combination. Combinations with no usable result count here only if current policy runs them during normal validate testing. 2,457 other manifest cells have inconclusive or conflicting results; the data audit explains each omission.

How determinism is tested. Run the program twice under Hermit. Compare its guest syscall logs, recorded memory checks, outputs and exit status. The recorded details must match. A pass without this log comparison does not count as a determinism match.

Backend comparison. The determinism number of every backend uses the same 600 verify tests. These are the verify tests with a recorded ptrace result, including failures. Replay and chaos are shown in their own columns, each over its own cases (586 replay and 7 chaos), and are not part of the determinism number. Recorded comparisons count regardless of whether the current CI policy runs the combination. In the full-match column, failures and cases without a matching comparison earn no credit but stay in this shared denominator. This measures backend coverage of the reference tests.

0 ptrace test-and-mode cases use a reduced log comparison (comparator: stripped). They are excluded from every determinism denominator because they do not check for a bit-for-bit match.

With partial credit. Full matches earn one point. A diverging run can earn a fraction based on its first differing scheduler turn and the length of a complete ptrace run at the same commit. Missing measurements earn no credit. The table shows the total points as a decimal, divided by the same reference count.

Parity (measured after determinism)

Parity compares a backend's log with ptrace's after both pass the repeatability check. The compared backends are kvm, liteinst, sabre, dbt; their test inputs must match. A full log match scores 1. Otherwise, the score is the matching start of the logs divided by the length of the longer log. A cell without repeatable logs has no parity score and is excluded.

Hermit compatibility scorecard

Current determinism, parity, and coverage evidence for Hermit's Linux execution backends.

Hermit makes Linux execution repeatable by controlling scheduling, time, and randomness. This scorecard compares its backends: determinism asks whether repeated runs agree, while parity asks whether a backend agrees with the reference ptrace backend. Each cell is one workload, execution mode, and backend; results distinguish passes, failures, and unmeasured cells. Latest selected measurement: Sep 29, 2026 · 9:17 PM EDT; latest history entry: Oct 2, 2026 · 3:35 PM EDT. Totals may combine qualifying results from multiple runs; rebuilding this website does not rerun the tests. For context, start with the introduction to Hermit, or visit the README for setup and usage.

Parity (measured after determinism)

After the determinism checks, the retained verify log of each candidate backend whose inputs can be equalized with the ptrace reference's (kvm, liteinst, sabre) is compared with the ptrace reference log. A cell's credit is the matched prefix of the two logs over the longer one, in [0, 1]; only a complete match earns 1. A cell whose reference or candidate left no deterministic golden log has no parity: it is outside the mean and the floor, never 0 credit. The inputs of dbt cannot be equalized with the ptrace reference's, so dbt is not compared and none of its cells enters any mean or floor, per backend or in the total. This panel shows the ledger's committed parity summary after checking it against the parity records it summarizes; it is separate from determinism and recomputes no credit.

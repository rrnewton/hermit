Expand description

Real watcher and immutable-object authority, retained for a single birth.

§Safety

Implementations must retain the genuine pidfd/watch registration, accept only the exact same living birth and main thread, and recheck terminal watcher failure. matches_peer must compare the actual accepted peer pidfd to that retained birth. Qualification must independently bind the actual captured resume mask and the one-main-thread, childless preparation cut, the immutable admitted namespace, and the held target/bootstrap files. The runtime proof must exactly decode all carried counters, observer sequence and forwarding boundary, refusing unsupported patch state.

The installed proof and its admission adapter must protect the ticket and provisioned objects, constrain Issue to the exact original native exec leaf, and prevent redemption from the old image. They must establish the covered fresh bootstrap and successor-before-loader transition, and accept Complete only from that genuine successor after its real post-exec and frontend proofs. A same-birth pidfd, token, seal or digest is not proof of kernel exec. Socket qualification must compare against independently held launch objects; actual numeric ownership requires the qualified guest owner’s physical queries and final rechecks, never object equality alone. No request field is authority for any of these facts. These obligations belong to the trusted native launch chain, not to this opaque storage.

fn physical_ids(&self) -> Option<(i32, i32)>

Physical main-thread identity from the same retained watched birth. Missing proof refuses control RPCs. Implementations must never derive this identity from request IDs or unretained numerical PID equality.

Source

fn qualify_completion( &self, _ticket: ExecTicket, _binding: NativeExecBinding, ) -> bool

Revalidate the actual accepted successor’s held mappings, namespace, birth and binding immediately before Complete. Refuses by default. Called under the registry mutex; must never acquire scheduler/pending locks or recurse into the registry. This augments, and never replaces, the unsafe genuine-kernel-exec/lifecycle/consumer obligations above.

Expand description

The format of a record whose rows hold a --chaos-instruction-offset decision (ThreadHistory::preemption_instruction_offsets): the next number above STOPLESS_SLICE_ENDS_FORMAT on the record-format counter.

It is the record’s mandatory compatibility boundary. A Hermit that predates the offsets reads a thread’s rows without them, so it would stop each such slice at its branch target rather than the recorded instruction; it reads formats 1 to 5 only and refuses this one by name. So a record states it as soon as its rows hold one offset (raise_format, which the writer calls at the first, and every edit or copy that keeps such a row keeps), and validation refuses offset rows in a record of an older format (PreemptionRecord::validate_format). A record whose rows hold none is written in the newest format below it (format_without_instruction_offsets), readable as before.

A record of this format has every timing property of SWITCH_IN_CHARGE_FORMAT, even with an empty schedule trace, as a prefix of no events has. Rows alone, copied from a record without its schedule trace and jumps of global time (PreemptionRecord::clone_preemptions_only), say so (PreemptionRecord::rows_alone) and follow format 1’s timing rules, as the same rows without offsets state no format: they list no jumps of global time and charge no replayed switch-in. Every reader that keys timing on the format reads PreemptionRecord::timing_format, which decides that by the mark, not the number alone.

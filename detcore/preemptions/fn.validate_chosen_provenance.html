pub fn validate_chosen_provenance(config: &Config) -> Result<()>
Expand description

Early launch preflight. Each authoritative loader repeats the check on the same immutable decoded bytes it installs; this pathname check is not that final authority. Both Config inputs are checked independently. The run’s exclusive-loop rewrite must be the one each record states (super::rewrite_exclusives_mismatch against the final config), so every launch path – the CLI and the public library entries alike – refuses another rewrite before any backend starts the guest. The Chosen provenance half of validate_config_replay_inputs, with each record validated under its own recorded guest numbering. A CLI preflight that runs before the run adopts the recorded numbering uses this so a record failing provenance is refused for that specific reason, before identity admission, as the Detcore route refuses it; the launch still repeats the full check against the final config.

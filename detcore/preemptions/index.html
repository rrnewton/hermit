Module preemptions 

Source
Expand description

A datatype to abstract a record of thread preemptions, as generated during chaos mode execution.

Modules§

boundary_recording
File-format boundary between legacy editors and explicit slice records. The scheduler consumes the complete stream; legacy editors must refuse it. History-only replay and read-only inspection never rewrite that stream.

Software callback expirations in an otherwise unchanged legacy event replay. These coordinates do not program the PMU or select a runnable owner.

Structs§

BackgroundStart
The turn that began a kernel-run blocking call (ResourceID::is_kernel_run_blocking: a blocking read of an external descriptor, a binder call that waits for another process, a vfork, an rt_sigsuspend), committed as BACKGROUND: from then on the call runs in the kernel while other threads’ turns commit. The turn runs no guest code and so leaves no event; it is recorded after the global schedule’s first after events. When a call starts can decide what it sees: a binder read already waiting in the driver is the idle looper a later read on another thread finds, or not. A schedule replay starts the call at the same point, before the event that follows it.
InstructionOffset
Where a chaos timeslice with --chaos-instruction-offset ends (defined beside the schedule events, which record it too). Where a chaos timeslice with --chaos-instruction-offset ends: instructions single steps after the thread’s conditional-branch counter reaches rcb_target. Straight-line code can return to an address without a conditional branch (a repeated call, a backward jump, a rep instruction), so the step count, not an address, names the point.

RecordedTimedWaitSpread

RewriteExclusives
The exclusive-loop rewrite a record’s run applied: where it applied and the rewrite format that produced the rewritten instructions (crate::aarch64_lse::REWRITE_FORMAT_VERSION). The rewrite changes the instructions the guest retires while the files stay the same, so a replay must apply the same rewrite; another mode, or another format version under the same mode, cannot be shown to retire the same instructions and is refused (rewrite_exclusives_mismatch).
ThreadHistory
The record of priorities and preemptions for a particular thread.
ThreadHistoryIterator
An iterator over the preemption history of a thread. Does not include the final timeslice, which does not have an ending time.
TimeSkip
One jump of global time. A replay of the record makes it where the recording did, as replay drives context switches, and checks it: its target must still lie ahead, and no finite deadline the replay knows, then or later, may come before it, or the replay reports a desync (Scheduler::make_recorded_time_skip).

Constants§

BACKGROUND_STARTS_FORMAT
The first format whose records note every background start (BackgroundStart), so that a call such a record does not start at a point did not start there: the next number above SWITCH_IN_CHARGE_FORMAT on the record-format counter (PREEMPTION_RECORD_FORMAT_MAX).
INSTRUCTION_OFFSET_FORMAT
The format from which a record’s schedule trace (its global events) may carry an instruction offset on a batch of branches (SchedEvent::instruction_offset): above INSTRUCTION_OFFSET_ROWS_FORMAT, which only its rows may hold.
INSTRUCTION_OFFSET_ROWS_FORMAT
The format of a record whose rows hold a --chaos-instruction-offset decision (ThreadHistory::preemption_instruction_offsets): the next number above STOPLESS_SLICE_ENDS_FORMAT on the record-format counter.
PREEMPTION_RECORD_FORMAT_MAX
The newest preemption-record format this Hermit writes and reads (PreemptionRecord::format_version), one counter for every format change: a record of format N has every property of the formats before it.
PREEMPTION_RECORD_FORMAT_WITHOUT_OFFSETS
The format a fresh record states when its rows hold no instruction offset: the newest format below INSTRUCTION_OFFSET_ROWS_FORMAT, which is STOPLESS_SLICE_ENDS_FORMAT. Such a file is written exactly as before the offsets existed, so every Hermit still reads it; only a record whose rows hold an offset states PREEMPTION_RECORD_FORMAT_MAX. The writer stamps this format (format_without_instruction_offsets), and its first row with an offset raises it (PreemptionWriter::insert_reprioritization).
STOPLESS_SLICE_ENDS_FORMAT
The format from which a record may mark a lone thread’s timeslice end taken without a stop (SchedEvent::stopless): the next number above BACKGROUND_STARTS_FORMAT. A writer that notes its run’s background starts writes it (PreemptionWriter::noting_background_starts): a run that follows no record, and a preemption replay’s re-record. A record of an older format holds no mark: a writer below this format records such an end as an ordinary one (PreemptionWriter::insert_schedevent), and a record lowered below BACKGROUND_STARTS_FORMAT drops its marks with its starts (PreemptionRecord::forget_stopless_marks_below_their_format). A record read with a mark in an older format is refused (PreemptionRecord::validate_format).
SWITCH_IN_CHARGE_FORMAT
The format from which a schedule replay charges a scheduler turn for every replayed switch to a thread that then runs guest code (Scheduler::bump_global_time), as the run that wrote the record charged the yield turn the switch stands for. A run charges every such stretch when it follows no record, or follows one of this format. A replay of an older record charges as before: its writer cannot say whether its own run followed a schedule, and so left those stretches uncharged.
TIME_SKIPS_FORMAT
The format from which a record lists all its jumps of global time.

Both Config inputs are checked independently. A CLI preflight that runs before the run adopts the recorded numbering uses this so a record failing provenance is refused for that specific reason, before identity admission, as the Detcore route refuses it; the launch still repeats the full check against the final config.

detcore::aarch64_lse

Module rewrite 

Source
Expand description

Rewriting canonical load/store-exclusive retry loops into single FEAT_LSE atomics, in place and at the same length.

Why in place: every instruction keeps its address, so every PC-relative branch, return address, unwind table, symbol and signal PC in the image stays valid, and the rewrite needs no trampoline, no scratch page and no free register beyond the ones the loop itself already destroys.

The scratch registers are the loop’s own. A retry loop writes its status register unconditionally before anything can read it, and its load destination likewise, so both hold no live value at the loop’s entry: the replacement may use them to materialise an operand, and restores the exact value the original left in each one on every exit path.

Ordering is carried across exactly, pair to atomic (Arm ARM DDI 0487 L.a, C3.2.6 and C3.2.12):

loadstoreatomic
LDAXRSTLXRAL
LDAXRSTXRA
LDXRSTLXRL
LDXRSTXRplain

Only register-only instructions are allowed between the pair, so an acquire taken at the atomic rather than at the load, and a release taken at the atomic rather than at the store, order the same memory accesses.

Compare idioms (CasCompare, CasZero) are matched but never rewritten: they are always left alone as compare-exit. A CAS in their place would differ from the original exactly where the comparison fails, where the original never executes its store-exclusive: CASAL keeps its release semantics there, and its write-permission check faults on a read-only word the original only reads.

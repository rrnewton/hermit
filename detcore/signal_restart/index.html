What a syscall interrupted for a caught signal gives the guest, by Linux’s x86 table (A5 design 16.6 and D40, D43).

A wait that Detcore ends because a caught signal is pending ends with one of the kernel’s private restart codes. On ptrace the kernel applies the table itself when it builds the handler’s frame. Where Detcore ends the wait and the kernel never sees the code (an in-guest backend under its delivery gate, Config::in_guest_signal_delivery), Detcore applies the same table, with the action of the first caught delivery at that return, and the backend only writes the registers. Ignored instances ahead of it are discarded without touching the registers, and a later frame at the same return sees the result the first one left (-EINTR, or the call’s number to run again), which is no longer a restart code.

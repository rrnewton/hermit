Module watch 

Source
Expand description

hermit run --watch: arming the guest threads’ hardware watchpoints.

Debug registers are per thread and not inherited, so every thread arms its own. The scheduler decides when the watches are due: once it has recorded --watch-from events, its epoch is 1. It tells a thread the epoch in the replies a thread already receives at its stops (a WatchOrder on every TraceSchedEvent reply and on every reply after the thread waited for its turn), and the thread arms at the first such stop where Reverie accepts the watches. The thread whose event reached --watch-from arms at that event’s reply; every other thread arms before it next runs guest code, because it resumes only through one of those replies.

A thread reports its state with each event it records (WatchStatus), so the scheduler can say in the trace which threads armed and which never did. Each watch asks Reverie for the stacks of its first WATCH_HITS_WITH_STACKS hits on the thread, a budget Reverie spends at the hits, so a word the thread writes in a loop costs no unwinding after that. Hits reach GlobalTool::on_watchpoint_hit, which only appends to the access trace (crate::access_trace), unless the hit’s SIGTRAP may have changed the guest (hit_refusal).

Nothing here sends a request, moves virtual time or touches the guest beyond its debug registers.

Functions§

adopt
Act on the scheduler’s order at this stop (try_adopt), and stop the run if the thread cannot be watched as asked.
hit_refusal
Why the run stops at hit, if it must: Reverie says the hit’s SIGTRAP may have left the guest a SIGTRAP mask bit or action it did not set (it reset an ignored or caught-while-blocked SIGTRAP’s action to the default, or the backend could not tell its state). The guest could then run differently than it would without the watch, and a watch must only observe.
rearm_after_exec
At the post-exec stop, the new image’s first: Linux cleared the thread’s debug registers, and a thread the scheduler had told the watches are due arms again now (adopt), before the image runs. Its next order can come only after the image has run, at its first recorded event or turn.
specs
Reverie’s spelling of --watch’s watches, each asking for the stacks of its first WATCH_HITS_WITH_STACKS hits on the thread.
try_adopt
Arm the thread’s watches if order says they are due and it has not. A thread that blocks or ignores SIGTRAP stays as it is and tries again at its next stop. A thread whose hits could move a timer event, or whose watches cannot be written, is refused: a watch must not change the schedule, and a run that silently watched nothing would mislead.

Module boundary 

Source
Expand description

Explicit slice-boundary protocol. A complete typed stream keeps ordinary events and actual scheduling boundaries in one causal order.

A boundary is evidence of an existing scheduling request, not an instruction or permission to introduce a request. Its identity must come from the actual semantic callback, before the completed slice is reset. Replay expectations cannot supply observed identities. The controller must report any error here as a failed replay, irrespective of the legacy die_on_desync setting.

Plain Language Summary and Project Impact

Hermit schedules at retired-conditional-branch (RCB) coordinates. Histories did not identify their counter definition, so replay could consume incompatible coordinates. Reverie's taken-only event on seven Ice Lake-derived models was one mismatch. This PR pins that correction and checks standalone preemption/callback histories' RCB identity before guest launch:
- New histories are written in an `rcb_history` envelope that names the producer's identity (`rcb:cond-retired:user:v1`, or unqualified with a reason).
- A run qualifies its clock (backend contract + host PMU profile + installed PMU state, checked against the host's prepared claim), admits every executable input, pins the clock key once, and only then builds the scheduler and writer.
- A history with no identity, an unqualified identity, or a different metric is refused with a named reason. Analyze, minimize and bisect keep the source identity. The verifier compares inside the envelope.
- The record epoch, highest-shipped floor, history entry and current-version assertions move together from 0x186 to the reserved 0x187. Old-version refusal fixtures remain intentional.
- The capability handling adopts Reverie's first typed capability, `rcb_clock_contract`, without loosening any check. The v1 DBT envelope now refuses an omitted key, as its decoder already documented. The wire fingerprint carries the field's width. The golden table names ptrace's contract.

Availability restriction: history admission is limited to qualified ptrace producer clocks and a replay run with a qualified clock. Missing, unqualified or incompatible clock identities are refused before guest launch. Legacy history files without recorded clock identity are refused; qualified envelopes using the legacy scheduler mode remain admissible. This intentionally reduces the histories and backend/PMU combinations that can be replayed. The coordinator accepted this narrower availability scope; it is not a claim that every backend or PMU profile has been qualified.

Determinism

Qualification and admission read only the history file, the backend's stated contract, CPUID and the process PMU state, and publish nothing. The one mutation, recording the clock key with `commit_pin`, happens once before this run's scheduler, writer and guest are created. A refusal happens before guest launch. The guard checks compatibility before scheduling; the pinned Reverie change also corrects the underlying counter event and timer initialization, so this combined PR can change execution on affected hosts.

Linux Semantics

The new history refusals are Hermit policy applied before launch. The pinned counter fix remains `perf_event_open` PERF_TYPE_RAW, user mode only. This handoff does not claim that affected runs have unchanged timing or schedules.

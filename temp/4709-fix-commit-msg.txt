4709: resolve the auto CPU profile for direct Detcore test launches

[hermit2, musetrain, tbh-1005, devbig014, role=impl]

Plain Language Summary and Project Impact

The merge queue's privileged-cpuid.faulting node went red at
23ea511e: rdrand_rdseed_is_masked panicked with "--cpu-profile auto
reached Detcore unresolved". That test drives Detcore directly
through detcore/tests/testutils, and every Config::default() now
carries the clap default `auto`, which only a CLI launch view can
classify from a first image. Test preparation now resolves an
unresolved `auto` to x86-64-v2 — the profile `auto` itself selects
for an unmarked image — at the one preparation seam every Detcore
test launch funnels through, and the two direct callers that skipped
preparation now use it. Detcore's own refusal of an unresolved
`auto` is unchanged, so real launch paths keep their tripwire.

Determinism

Test-launch configuration only. The resolution is a constant named
profile, not derived from host state, wall time or the host CPU; a
guest image declaring a higher ISA level is still refused by name by
Detcore's per-exec check, exactly as under an explicit v2 launch.
No schedule, virtual-time or guest-visible product behaviour
changes: production code gains only a `CpuProfile` re-export.

Linux Semantics

No Linux behaviour Hermit presents changes. This chooses which
virtual CPU Detcore's own tests run under; the CPUID answers for the
named v2 profile are the table Detcore already served.

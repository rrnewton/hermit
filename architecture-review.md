## Recommended first implementation boundary

Adopt the existing `StatsSink` through the existing `DbtRunner::run_with_global` owner; do not introduce another runner, collector service, global protocol or backend-local comparison path.

1. **Make the existing capture result usable by every existing physical input shape.** R `output_with_global_and_stats:567` currently chooses Null and `status_with_global_and_stats:597` chooses Inherit. The Reader and inherited-output entry points at444/473 currently hardcode statistics DISABLED, although they already reach `run_with_global:622` with its stats argument. H `run_once:1800`, `run_once_with_terminal_input:1841` and `run_status:1875` call these exact routes. Extend that existing boundary so H obtains owned captured record bytes and a truthful presence/read outcome alongside the physical output/global. Choose the smallest concrete return/API change during implementation; no new execution abstraction is needed.
2. **Preserve the current acceptance distinction.** R `StatsSink::drain` deliberately maps a missing file to an empty snapshot. H `read_dbt_stats` refuses missing, empty, malformed/truncated, zero branches/syscalls and rewritten-greater-than-intercepted records for verification. Therefore the present `*_and_stats` result is not a drop-in replacement. Preserve absent versus present-empty versus malformed/read-error information; keep H's strict decision above the common capture. Optional instrumentation may retain its old empty behavior, but cannot convert verification's absent evidence into measured zero.
3. **Return capture failures as completion data until the current owner decides precedence.** Today H calls `clean_up_dbt_global` after the physical runner, before returning the serializable `DbtPhysicalOutput:1676`. R's current `sink.drain()?` occurs after it unwraps G; merely enabling that branch would let a stats failure prevent H from receiving/cleaning G and could move a stats error ahead of the existing evidence/latch refusal. Retain output/global cleanup and primary launch/wait/evidence error behavior. The capture result must survive long enough for the existing run-labelled completion boundary to classify it; do not add a second shutdown protocol.
4. **Move bytes, not paths, out of the container.** The R sink can be created inside the existing `DbtExecution::run` container and read after the current reaping boundary. Carry the owned raw result through the existing physical return representation. H's saved-run writer at `backends.rs:1429` must still persist exact `DBT_STATS` bytes; live/offline consumers continue through the same strict decoder/acceptance logic. This permits deleting H `DbtStatsCapture` and `DbtExecution.statistics`/`stats_capture` bind plumbing. Keep the codec, strict checks, evidence decoder and retained saved artifact. This is the concrete first deletion; it does not yet retire the native stats file.

This slice is bounded by D-owned R launcher/stats completion and H physical-run adapters. It needs no D2 deferred driver, T2 exec implementation, new T bootstrap or descriptor-protection API. It must still preserve the landed Reader lease, detached pump/EPIPE, terminal input, single physical-run ownership and shared container path. The public R result/interface change warrants normal cross-consumer review; it does not justify a new policy framework.

## Concrete design review before implementation

The author's selected API shape promotes the existing `StatsSink` to an owned public `DbtStatsSink`, constructed through its fallible constructor **inside H's existing container closure, before `G::init_global_state`**. H retains its current setup policy: strict/saved runs, summary or requested engagement refuse capture allocation failure; an ordinary run without those requests warns and continues once. Passing `Option<DbtStatsSink>` into the existing physical owner avoids inventing a second policy enum or a retry launch. The proposed completion distinguishes Missing, Unreadable (preserved message/raw OS error), and Records (including a present empty vector); private Option means not requested. Legacy source-return convenience methods explicitly retain their old missing-to-empty projection. New H callers receive capture data without a post-G `?` and keep the old strict policy at its existing completion boundary.

The whole-tree reaper and input pump are unchanged responsibilities. R `launcher.rs:840–915` drains stdout/stderr around `reap_tree` and preserves error output; `wait_with_output_and_input_writer:934–957` detaches a source-blocked pump, accepts BrokenPipe after child termination and preserves other completed pump errors. H `ChildInput:1709` is intentionally ManuallyDrop in the container's copy-on-write child; `DbtExecution::run:1634` uses the existing exit-after-publication path. The new stats sink must not be captured by or awaited through that detached pump. It is held by the physical runner through its existing reap boundary, drained once into owned completion data, and dropped before container publication. Failed spawn/wait/evidence errors retain their existing primary error and stderr; the capture cannot convert them into a successful physical output or replace them with missing-stats errors. No new input cancellation or child cleanup protocol is proposed.

**Container IPC assessment.** `RunOpts::launch_in_container:7059` calls the existing owned container path. R `reverie-process/src/container.rs:1416` serializes the child result with `bincode::config::legacy()` into an ordinary buffered pipe. The parent acquires bytes using `read_to_end` at2387 and decodes only after actual successful child termination, requiring exact consumption at2558. This is not JSON and has no fixed result frame cap; the separate 64-byte startup control frame and startup FD count are not result limits. Thus `Vec<u8>` does not introduce JSON decimal-byte expansion or a new stats-size refusal.

Native `reverie-dbt/native/client.c:6066–6164` appends one 144-byte statistics record per emitted image record; this stream does **not** include tracing logs. Protected evidence/logs remain on their current independent path. Native wire bytes, optional DR-stat presence and copied-child failure records remain unchanged. Exact bytes must be moved/borrowed, not sorted, deduplicated, re-encoded or cloned gratuitously. H previously read the full file too, but memory behavior is not identical: publication can coexist with the child's raw vector and parent's encoded buffer; parent decoding temporarily retains encoded plus decoded data; `owned_container.rs:341` additionally clones encoded bytes under no-namespace error-retention support. The new cost is linear in record bytes, not a measured bound or zero-overhead claim. No existing cap is weakened. A multi-record roundtrip through the actual physical result representation and exact saved `DBT_STATS` byte equality provide useful regression oracles without adding a custom transport.

Creating the sink inside the private container removes the need to bind an outer pathname. Its bytes are drained while that filesystem and the temporary-directory owner are alive; the parent receives owned data before its existing container backing guard is released. No parent reopening of an unpinned child path is required. Allocation failure may now acquire ordinary container error context, but required capture still refuses before G or guest starts. Preserve the literal H missing/empty/unreadable/inconsistent policy and output ordering, including evidence/latch precedence over stats. Existing aggregation accepts duplicate records; this refactor must not silently add identity rejection or change summation/XOR semantics.

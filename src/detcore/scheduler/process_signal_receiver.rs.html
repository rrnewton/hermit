8//! The thread of a multi-threaded process that takes a process-directed
9//! signal a guest sends (<https://github.com/rrnewton/hermit/issues/4034>).
10//!
11//! Linux queues such a signal on the process's shared queue
12//! (`__send_signal_locked`) and then `complete_signal` picks the thread it
13//! wakes to take it (kernel/signal.c:963-997 at v6.16):
14//!
15//! 1. the task the call names, `p` (the leader for a process id, the named
16//!    thread for one of its thread ids), if it `wants_signal`;
17//! 2. otherwise the first thread that does, walking the thread list from the
18//!    process's `signal->curr_target`, which then becomes that thread;
19//! 3. when no thread does, none: the signal waits in the shared queue, and the
20//!    first thread that unblocks it, or that finishes the signals it already
21//!    has pending, takes it.
22//!
23//! `wants_signal` (signal.c:946-961) asks that the thread not block the
24//! signal, not be exiting (`PF_EXITING`) and not be stopped or traced, and
25//! that it be running (`task_curr`) or have no signal pending
26//! (`task_sigpending`).
27//!
28//! Under ptrace every thread the scheduler holds is traced, so the kernel's
29//! own choice degenerates: `wants_signal` passes over every stopped thread,
30//! and the signal waits in the shared queue for whichever thread resumes
31//! first and does not block it (`ptrace_stop` ends with
32//! `recalc_sigpending_tsk`, signal.c:2491-2496). So Detcore makes the choice, by
33//! the same rule over its own model, and then keeps the call itself: it
34//! forwards the guest's `kill`, `rt_sigqueueinfo` or `pidfd_send_signal`
35//! unchanged, so the copy is the kernel's own, in the shared queue, with
36//! Linux's siginfo, coalescing, retargeting and visibility; and it resumes
37//! the chosen thread before any other that could take it, until it does
38//! (`process_signal_takers`, `Scheduler::first_process_signal_taker`).
39//!
40//! The model, in which the guest's threads share one CPU and only the sender
41//! runs:
42//!
43//! - The thread list is thread-ID order. `copy_process` appends each new
44//!   thread at the list's tail (kernel/fork.c:2396-2397), and in a PID
45//!   namespace `alloc_pid` hands out ids cyclically upward
46//!   (`idr_alloc_cyclic`, kernel/pid.c:237), so a later thread has the higher
47//!   id until the ids wrap.
48//! - `curr_target` starts at the leader (kernel/fork.c:1662) and moves to each
49//!   thread step 2 chooses, once the forwarded call has succeeded
50//!   (`Scheduler::process_signal_sent`): a call the kernel fails before it
51//!   queues anything, or one Detcore refuses, never reaches
52//!   `complete_signal`. That includes a send to the sender's own process
53//!   that Detcore forwards because Linux gives it to the sender
54//!   (`Scheduler::own_process_signal_choice`): when the call names another
55//!   thread, which blocks the signal, the walk is what reaches the sender.
56//!   Linux moves it on when that thread exits
57//!   (`__exit_signal`, kernel/exit.c:187-188); here the walk starts at the
58//!   first live thread at or after it, which is the same thread unless a
59//!   thread was created after the last thread in the list exited.
60//! - A thread is exiting once its exit is granted, it was killed at a turn, or
61//!   its exit waits for a delivery permit.
62//! - `task_curr` holds for the sender alone, and SIGKILL is wanted whatever is
63//!   pending (signal.c:954-955). A thread "has a signal pending" when its own
64//!   queue holds a signal it does not block, other than one a host-timed
65//!   source may have posted (`Scheduler::host_timed_signals`) or Reverie's
66//!   preemption marker. A copy in the shared queue does not count: Linux sets
67//!   `TIF_SIGPENDING` for it only on the thread it woke.
68//!
69//! Every input is the schedule's: the scheduler's committed records, and the
70//! `/proc` masks and private queues of threads stopped at a request or
71//! parked, which change only when they run, while the sender holds the turn.
72//!
73//! Two cases keep the fail-closed refusal they had before this choice existed
74//! (<https://github.com/rrnewton/hermit/issues/4034>), because the forwarded
75//! copy would not reach the chosen thread:
76//!
77//! - a thread sleeping outside the schedule (external I/O, a real
78//!   `rt_sigsuspend`) is not traced, so the kernel can wake it for the signal
79//!   at a moment host timing sets, whatever Detcore chose
80//!   (`ProcessSignalReceiver::OutOfSchedule`);
81//! - a thread that can take the copy outside its turn, whatever its own mask
82//!   says: its filed call installs a temporary mask that admits the signal
83//!   (`rt_sigsuspend`, `ppoll`, `pselect6`, `epoll_pwait`), a signalfd of the
84//!   process covers it, or a thread waits for it in `rt_sigtimedwait`
85//!   (`ProcessSignalReceiver::TakenOutOfTurn`);
86//! - a send to the sender's own process that Linux gives to another thread:
87//!   the sender is running, so `task_curr` makes it the one thread
88//!   `wants_signal` admits, and it takes the copy at its return to user mode
89//!   before any other thread runs (`ProcessSignalReceiver::SenderTakesIt`).
90//!   The sends Linux gives to the sender itself are forwarded, here and by
91//!   the earlier admission that holds the sender's turn
92//!   (`Detcore::own_process_signal`).
93//!
94//! A signal whose default action ends the process is exempt from all three:
95//! Linux ends the whole group with the same status whichever thread takes it
96//! (`get_signal` calls `do_group_exit(signr)`, signal.c:3034), and no thread
97//! runs further user code, so nothing the refusals protect is left to decide.
98//! A guest's own abort or fault (`raise(SIGABRT)` after a handler resets the
99//! disposition, a watchdog's `pidfd_send_signal(self, SIGSEGV)`) takes this
100//! path. Which thread carries the death out, and so how far a thread
101//! sleeping outside the schedule gets first, is the kernel's; the status and
102//! the death itself are not.
103//!
104//! A standard signal the shared queue already holds is queued no second time
105//! (`legacy_queue`, signal.c:1037-1040), so such a send reaches no
106//! `complete_signal`: it chooses nothing, marks nothing, and moves
107//! `curr_target` no further.
108//!
109//! Linux's group-exit shortcut at the send (signal.c:1003-1025) needs a
110//! thread that wants the signal, which no ptrace-stopped thread does, so for
111//! a fatal signal it is the receiver's delivery that ends the group, one turn
112//! later than native; the exit status is the same.

127/// Which thread takes a process-directed signal
128/// (`Scheduler::process_signal_receiver`).
129#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)]
130pub enum ProcessSignalReceiver {
131    /// The thread `complete_signal` gives the signal, which the scheduler
132    /// resumes first until it takes the forwarded copy
133    /// (`Scheduler::first_process_signal_taker`). `sole`: every other live
134    /// thread blocks the signal or is exiting, so no other thread can take
135    /// the copy before it anyway, and nothing is marked.
136    Thread { thread: DetTid, sole: bool },
137    /// No thread wants it: it waits in the process's shared queue.
138    SharedQueue,
139    /// This thread sleeps outside the schedule and does not block the
140    /// signal, so the kernel can wake it for the copy at a host-timed moment.
141    OutOfSchedule(DetTid),
142    /// This thread can take the copy from the shared queue outside its turn,
143    /// whatever its own mask says: its filed call installs a temporary mask
144    /// that admits the signal, or it reads a signalfd that covers it, or a
145    /// sibling waits for it in `rt_sigtimedwait`.
146    TakenOutOfTurn(DetTid),
147    /// The sender's own process, with the sender not blocking the signal and
148    /// another thread the receiver: the sender is the one thread Linux's
149    /// `wants_signal` admits (it is `task_curr`, and every other thread is
150    /// ptrace-stopped), so it takes the forwarded copy at its return to user
151    /// mode, before the receiver can run.
152    SenderTakesIt,
153    /// The choice depends on this thread, whose signal mask is unknown.
154    UnknownMask(DetTid),
155    /// The process's shared queue already holds the signal, so Linux queues
156    /// no second copy and chooses no thread (`legacy_queue`).
157    AlreadyQueued,
158    /// An exec is in flight in the process; its `de_thread` decides which
159    /// threads remain.
160    ExecInFlight,
161    /// This scheduler does not model signal targets (only ptrace does).
162    NotModeled,
163    /// A schedule replay chose `receiver`, as its recording did, but the
164    /// recorded schedule next runs `first`, another thread of the process
165    /// that could take the copy before it: the replay has left its recording.
166    ScheduleRunsFirst { receiver: DetTid, first: DetTid },
167}
168
169/// Whether one thread `wants_signal`, in the model above.
170#[derive(Clone, Copy, Debug, PartialEq, Eq)]
171pub(crate) enum Wants {
172    Yes,
173    /// It blocks the signal, or is exiting.
174    No,
175    /// It leaves the signal unblocked but already has one pending
176    /// (`task_sigpending`), so Linux passes it over; it can still take the
177    /// copy from the shared queue once it is done with those.
178    Busy,
179    /// Its mask is unknown.
180    Unknown,
181}
182
183/// A live thread of the process to read its shared queue through: the
184/// sender when it belongs to the process, else its first live thread.
185fn sender_or_member(threads: &[(DetTid, Wants)], sender: DetTid) -> DetTid {
186    if threads.iter().any(|(thread, _)| *thread == sender) {
187        sender
188    } else {
189        threads.first().map_or(sender, |(thread, _)| *thread)
190    }
191}

193/// `complete_signal`'s choice among `threads` (every live thread of the
194/// process in list order, with whether each wants the signal), trying `named`
195/// first and then walking from `curr_target`. Returns the receiver and, when
196/// the walk chose it, the process's new `curr_target`.
197///
198/// When no thread wants it, Linux leaves it in the shared queue for the first
199/// thread that can take it.
200pub(crate) fn complete_signal(
201    threads: &[(DetTid, Wants)],
202    named: DetTid,
203    curr_target: DetTid,
204) -> (ProcessSignalReceiver, Option<DetTid>) {
205    let chosen = |thread: DetTid| ProcessSignalReceiver::Thread {
206        thread,
207        sole: threads
208            .iter()
209            .all(|(tid, wants)| *tid == thread || *wants == Wants::No),
210    };
211    match threads.iter().find(|(tid, _)| *tid == named) {
212        Some((_, Wants::Yes)) => return (chosen(named), None),
213        Some((_, Wants::Unknown)) => return (ProcessSignalReceiver::UnknownMask(named), None),
214        Some((_, Wants::No | Wants::Busy)) | None => {}
215    }
216    let start = threads
217        .iter()
218        .position(|(tid, _)| *tid >= curr_target)
219        .unwrap_or(0);
220    let walk = || threads[start..].iter().chain(&threads[..start]);
221    for (tid, wants) in walk() {
222        match wants {
223            Wants::Yes => return (chosen(*tid), Some(*tid)),
224            Wants::Unknown => return (ProcessSignalReceiver::UnknownMask(*tid), None),
225            Wants::No | Wants::Busy => {}
226        }
227    }
228    (ProcessSignalReceiver::SharedQueue, None)
229}

231impl Scheduler {
232    /// The thread of `process` that takes the process-directed signal
233    /// `signo`, which `sender` sends naming `named` (module docs), decided in
234    /// `sender`'s turn. A chosen thread found by the walk becomes the
235    /// process's `curr_target`, and one that siblings could take the copy
236    /// before is marked as its taker (`process_signal_takers`).
237    pub(crate) fn process_signal_receiver(
238        &mut self,
239        process: DetPid,
240        named: DetTid,
241        sender: DetTid,
242        signo: i32,
243    ) -> ProcessSignalReceiver {
244        // Only this choice's own move can be committed by the call that
245        // follows it.
246        self.pending_signal_curr_target = None;
247        if !self.models_signal_targets {
248            return ProcessSignalReceiver::NotModeled;
249        }
250        if self.exec_teardowns.contains_key(&process) {
251            return ProcessSignalReceiver::ExecInFlight;
252        }
253        let bit = kernel_signal_bit(signo);
254        // Where a process signal control is installed (KVM), each thread is
255        // read under the mask Linux's `blocked` holds for it now, a call's
256        // temporary mask included, and the thread's state was decided by the
257        // admission in this turn, before any effect
258        // (`guest_send_admission`), which this choice repeats.
259        let controlled = self.signal_control_installed();
260        let threads: Vec<(DetTid, Wants)> = self
261            .process_signal_targets(process)
262            .into_iter()
263            .map(|thread| {
264                let wants = if controlled {
265                    self.controlled_wants(thread, sender, bit)
266                } else {
267                    self.wants_signal(thread, sender, bit)
268                };
269                (thread, wants)
270            })
271            .collect();
272        // A signal whose default action ends the process needs no choice at
273        // all: whichever thread takes it, Linux ends the whole thread group
274        // with the same status (`get_signal` calls `do_group_exit(signr)`,
275        // signal.c:3034; for a core-dumping signal `do_coredump` kills the
276        // others first, signal.c:3010-3020), and no thread runs further user
277        // code. So the two refusals below, which are about WHICH thread takes
278        // the copy, do not apply to it; the kernel's own choice under ptrace
279        // is as good as Linux's. The aborts and faults a guest raises in its
280        // own multi-threaded process take this path. Where the backend keeps
281        // its own queues the admission refused every such send but one an
282        // `rt_sigtimedwait` takes, which ends nothing, so the walk below
283        // chooses, as the admission's did.
284        if !controlled
285            && threads
286                .first()
287                .and_then(|(thread, _)| self.stopped_thread_signal_state(*thread).ok())
288                .is_some_and(|state| state.default_action_ends_process(signo))
289        {
290            // Every thread blocks it: Linux leaves it in the shared queue, and
291            // no thread takes it until one unblocks it.
292            let Some(thread) = threads
293                .iter()
294                .find(|(_, wants)| *wants != Wants::No)
295                .map(|(thread, _)| *thread)
296            else {
297                tracing::info!(
298                    "[scheduler] process-directed signal {} from {} to process {} would end its \
299                     thread group, but every thread blocks it: it waits in the shared queue",
300                    signo,
301                    sender,
302                    process,
303                );
304                return ProcessSignalReceiver::SharedQueue;
305            };
306            tracing::info!(
307                "[scheduler] process-directed signal {} from {} to process {} ends its thread \
308                 group whichever thread takes it; thread {} is named",
309                signo,
310                sender,
311                process,
312                thread,
313            );
314            return ProcessSignalReceiver::Thread { thread, sole: true };
315        }
316        // The kernel wakes such a thread itself, at a host-timed moment, so
317        // which thread takes the copy is not the schedule's. A backend that
318        // keeps its own queues wakes none; the admission refused a receiver
319        // in a host call.
320        if !controlled
321            && let Some((thread, _)) = threads
322                .iter()
323                .find(|(thread, wants)| *wants != Wants::No && self.out_of_schedule(*thread))
324        {
325            return ProcessSignalReceiver::OutOfSchedule(*thread);
326        }
327        // A thread whose turn is not where it takes the copy: its call's
328        // temporary mask admits the signal although its own mask blocks it, a
329        // signalfd it reads in the background covers it, or a sibling's
330        // `rt_sigtimedwait` set does. Each takes the copy at a moment host
331        // timing sets, as it does for the scheduler's own sends
332        // (`another_call_may_take_waiting_signal`), so no choice here holds.
333        // Where the backend keeps its own queues the admission settled each
334        // of these before this choice (`guest_send_admission`): a probe and
335        // an `rt_sigtimedwait` run in the thread's own turn, and the walk
336        // above read their masks; a signalfd that may cover the signal
337        // refuses a caught copy, and any send while a thread that can read
338        // the signalfd is in a host call.
339        if !controlled && let Some(thread) = self.may_take_out_of_turn(process, bit) {
340            return ProcessSignalReceiver::TakenOutOfTurn(thread);
341        }
342        // Linux does not queue a standard signal the shared queue already
343        // holds (`legacy_queue`, signal.c:1037-1040 through
344        // `__send_signal_locked`, signal.c:1063-1064), so the send reaches no
345        // `complete_signal`: the thread chosen for the copy already there
346        // keeps it, and this send decides nothing.
347        if bit & STANDARD_SIGNALS != 0
348            && self
349                .read_shared_pending(sender_or_member(&threads, sender))
350                .is_some_and(|pending| pending & bit != 0)
351        {
352            tracing::info!(
353                "[scheduler] process-directed signal {} from {} to process {} is already in its \
354                 shared queue; Linux queues no second copy",
355                signo,
356                sender,
357                process,
358            );
359            return ProcessSignalReceiver::AlreadyQueued;
360        }
361        let curr_target = self.signal_curr_target(process);
362        let (receiver, moved) = complete_signal(&threads, named, curr_target);
363        // A schedule replay decides as its recording did, from the same
364        // schedule, and resumes the threads in the recorded order, so the
365        // chosen thread, which the recording resumed before any other that
366        // could take the copy (`first_process_signal_taker`), is the next of
367        // them its schedule runs. If it is not, the replay has left its
368        // recording, and another thread could take the copy first.
369        if let ProcessSignalReceiver::Thread {
370            thread,
371            sole: false,
372        } = receiver
373            && thread != sender
374            && let Some(first) = self.replayer.as_ref().and_then(|replayer| {
375                let process_threads: Vec<DetTid> = threads.iter().map(|(tid, _)| *tid).collect();
376                replayer.next_thread_among(&process_threads, sender)
377            })
378            && first != thread
379        {
380            return ProcessSignalReceiver::ScheduleRunsFirst {
381                receiver: thread,
382                first,
383            };
384        }
385        // A signal Linux discards as it is sent never reaches
386        // `complete_signal` (`prepare_signal`, signal.c:1053-1054), so it
387        // moves nothing and takes no thread; its copy is dropped at the send.
388        let discarded = self.discarded_when_sent_to(named, signo, Some(sender));
389        // Under ptrace the sender is the only thread the kernel's own
390        // `complete_signal` admits, so a forwarded copy reaches it first.
391        // This refusal is decided before `curr_target` moves: Linux moves
392        // the pointer only on a successful walk choice, and a refused send
393        // chooses nothing.
394        // The sender's mask is read as the choice read every thread's: with
395        // a control installed, the controlled view (`controlled_mask`).
396        let sender_mask = if controlled {
397            self.controlled_mask(sender)
398        } else {
399            self.stopped_thread_mask(sender)
400        };
401        if let ProcessSignalReceiver::Thread { thread, .. } = receiver
402            && thread != sender
403            && process == self.sigchld_process(sender)
404            && sender_mask.is_none_or(|mask| mask & bit == 0)
405        {
406            return ProcessSignalReceiver::SenderTakesIt;
407        }
408        // The walk's choice becomes `curr_target` once the forwarded call has
409        // succeeded (`process_signal_sent`), as Linux moves it only for a send
410        // that reaches `complete_signal`.
411        self.pending_signal_curr_target = moved
412            .filter(|_| !discarded)
413            .map(|thread| (sender, process, thread));
414        if let ProcessSignalReceiver::Thread {
415            thread,
416            sole: false,
417        } = receiver
418            && !discarded
419        {
420            *self.process_signal_takers.entry(thread).or_default() |= bit;
421        }
422        tracing::info!(
423            "[scheduler] process-directed signal {} from {} naming {} to process {}: {:?} (curr_target {}, threads {:?})",
424            signo,
425            sender,
426            named,
427            process,
428            receiver,
429            curr_target,
430            threads
431        );
432        receiver
433    }

435    /// `process`'s `curr_target`: the thread the walk of `complete_signal` last
436    /// chose, or the leader, where Linux starts it.
437    pub(super) fn signal_curr_target(&self, process: DetPid) -> DetTid {
438        self.signal_curr_targets
439            .get(&process)
440            .copied()
441            .unwrap_or_else(|| DetTid::from_raw(process.as_raw()))
442    }
443
444    /// A send of `signo` that `sender` makes to its own process, naming
445    /// `named`, and that Detcore forwards as it is because Linux gives it to
446    /// the sender (`Detcore::own_process_signal`). Detcore chooses no receiver
447    /// for it, but Linux's `complete_signal` still runs, and when the named
448    /// task does not want the signal its walk reaches the sender, which then
449    /// becomes `curr_target`, as for any walk choice once the call has
450    /// succeeded (`process_signal_sent`). A later send from another process
451    /// starts its walk there (https://github.com/rrnewton/hermit/issues/4034).
452    /// As in `process_signal_receiver`, a standard signal the shared queue
453    /// already holds (`legacy_queue`) and one Linux discards as it is sent
454    /// (`prepare_signal`) reach no walk.
455    ///
456    /// It reads each thread under `wants_signal`'s stopped view alone:
457    /// `Detcore::own_process_signal` forwards such a send only where the
458    /// kernel's signal state is the guest's own
459    /// (`BackendCapabilities::kernel_signal_state_is_guests`), and no such
460    /// backend installs a process signal control
461    /// (`own_process_sends_never_meet_a_control` pins that), so the
462    /// controlled view never applies here.
463    pub(crate) fn own_process_signal_choice(&mut self, sender: DetTid, named: DetTid, signo: i32) {
464        self.pending_signal_curr_target = None;
465        if !self.models_signal_targets {
466            return;
467        }
468        let process = self.sigchld_process(sender);
469        let bit = kernel_signal_bit(signo);
470        if bit & STANDARD_SIGNALS != 0
471            && self
472                .read_shared_pending(sender)
473                .is_some_and(|pending| pending & bit != 0)
474        {
475            return;
476        }
477        if self.discarded_when_sent_to(named, signo, Some(sender)) {
478            return;
479        }
480        let threads: Vec<(DetTid, Wants)> = self
481            .process_signal_targets(process)
482            .into_iter()
483            .map(|thread| (thread, self.wants_signal(thread, sender, bit)))
484            .collect();
485        let (_, moved) = complete_signal(&threads, named, self.signal_curr_target(process));
486        self.pending_signal_curr_target = moved.map(|thread| (sender, process, thread));
487    }
488
489    /// `sender`'s forwarded process-directed send to `process` succeeded: the
490    /// thread the walk chose for it, if the walk chose one, becomes the
491    /// process's `curr_target` (`process_signal_receiver`). A send that failed
492    /// never reports, and the next choice discards its move.
493    pub(crate) fn process_signal_sent(&mut self, sender: DetTid, process: DetPid) {
494        if let Some((chooser, chosen_in, thread)) = self.pending_signal_curr_target.take()
495            && chooser == sender
496            && chosen_in == process
497        {
498            self.signal_curr_targets.insert(process, thread);
499        }
500    }

502    /// The thread step 3 resumes before any other because it is to take a
503    /// process-directed signal a guest sent (`process_signal_takers`,
504    /// `process_signal_receiver`), if any: the first whose mark still stands.
505    ///
506    /// A mark stands while the copy is still in its process's shared queue
507    /// and the thread still leaves the signal unblocked, so no stale mark can
508    /// let a thread run first for ever: the copy goes when the thread takes
509    /// it, when another thread does (which `/proc` shows), or when the signal
510    /// is flushed; and a thread that blocks the signal would not take it, so
511    /// another thread may, as Linux retargets a shared signal
512    /// (`retarget_shared_pending`, signal.c:3090). Only a thread queued to run
513    /// is chosen; one parked in a wait is woken by the ordinary path, and its
514    /// mark stands until then.
515    ///
516    /// Where a process signal control is installed (KVM), the thread's mask
517    /// is read as the admission and the choice read it (`controlled_mask`):
518    /// a call's temporary mask included, and that of a backend-served
519    /// `rt_sigsuspend` the drain woke and that has not run since
520    /// (`backend_suspend_woken`). Read as its own mask, a waiter that blocks
521    /// the signal outside the call lost its mark once the drain woke it, and
522    /// a sibling the same drain woke in the same wait, ahead of it in the run
523    /// queue, took the copy Linux gives the chosen thread alone (the Codex
524    /// review of https://github.com/rrnewton/hermit/pull/5415 at fcff78c8,
525    /// P1). Where that view cannot say (a thread readmitted from a call
526    /// outside the schedule whose mask its readmission could not record,
527    /// `BlockedPool::continuation_masks`), the mark stands: nothing shows the
528    /// thread blocks the signal. The claims audit does not refuse such a
529    /// state: it defers an unreadable claim to its next pass
530    /// (`Scheduler::audit_guest_send_claims`). Admission is what refuses an
531    /// unknown mask, at send time (`SendRefusal::UnknownState`).
532    pub(super) fn first_process_signal_taker(&mut self) -> Option<DetTid> {
533        let threads: Vec<DetTid> = self.process_signal_takers.keys().copied().collect();
534        let controlled = self.signal_control_installed();
535        for thread in threads {
536            let shared = self.read_shared_pending(thread).unwrap_or(0);
537            let mask = if controlled {
538                self.controlled_mask(thread)
539            } else {
540                self.stopped_thread_mask(thread)
541            };
542            // An unknown controlled mask (a readmission that could not
543            // record its call's mask) keeps the mark: it is no evidence the
544            // thread blocks the signal. The claims audit defers an
545            // unreadable claim to its next pass
546            // (`Scheduler::audit_guest_send_claims`); only admission refuses
547            // an unknown mask, at send time.
548            let unblocked = match mask {
549                Some(mask) => !mask,
550                None if controlled => !0,
551                None => 0,
552            };
553            let standing = self
554                .process_signal_takers
555                .get(&thread)
556                .copied()
557                .unwrap_or(0)
558                & shared
559                & unblocked;
560            if standing == 0 {
561                self.process_signal_takers.remove(&thread);
562            } else {
563                self.process_signal_takers.insert(thread, standing);
564            }
565        }
566        // With a control installed, a marked thread that polls a call whose
567        // probe takes the copy (`CatchReach::Probe`: `pselect6`, a masked
568        // `ppoll`, `rt_sigtimedwait`; never a raw `select`, which admission
569        // refuses, `SendRefusal::RawSelect`) is resumed first too: queue order
570        // alone let a sibling's probe, whose call Linux leaves asleep, take
571        // the copy first.
572        self.process_signal_takers.keys().copied().find(|thread| {
573            self.run_queue.contains_non_polling_tid(*thread)
574                || (controlled && self.run_queue.contains_tid(*thread))
575        })
576    }

578    /// A thread of `process` that can take a copy of the signal `bit` from
579    /// the shared queue outside the turn the scheduler gives it.
580    ///
581    /// Its filed call installs a temporary mask that admits the signal
582    /// (`Resources::blocked_signal_mask`: `rt_sigsuspend`, `ppoll`,
583    /// `pselect6`, `epoll_pwait`), or publishes none the scheduler can read
584    /// (`blocked_signal_mask_unknown`); or a signalfd of the process covers
585    /// the signal, which any thread's read can dequeue
586    /// (`signalfd_notify`, signal.c:1136); or a thread waits for it in
587    /// `rt_sigtimedwait`.
588    fn may_take_out_of_turn(&self, process: DetPid, bit: u64) -> Option<DetTid> {
589        if self.signalfd_may_read(bit) {
590            return self.process_signal_targets(process).into_iter().next();
591        }
592        self.process_signal_targets(process)
593            .into_iter()
594            .find(|thread| {
595                self.sigtimedwait_sets
596                    .get(thread)
597                    .is_some_and(|set| set & bit != 0)
598                    || self.filed_temporary_mask_admits(*thread, bit)
599            })
600    }

602    /// Whether `thread`'s filed request carries a temporary signal mask that
603    /// admits the signal `bit`, or one the scheduler cannot read.
604    fn filed_temporary_mask_admits(&self, thread: DetTid, bit: u64) -> bool {
605        self.next_turns
606            .get(&thread)
607            .and_then(|turn| turn.req.try_read())
608            .and_then(Result::ok)
609            .is_some_and(|request| {
610                request.blocked_signal_mask_unknown
611                    || request
612                        .blocked_signal_mask
613                        .is_some_and(|mask| mask & bit == 0)
614            })
615    }

617    /// Whether `thread` runs outside the schedule, where the kernel can wake
618    /// it for a signal at a moment host timing sets.
619    fn out_of_schedule(&self, thread: DetTid) -> bool {
620        self.blocked.external_io_blockers.contains_key(&thread)
621            || self.blocked.rt_sigsuspend_blockers.contains_key(&thread)
622    }

624    /// Whether `thread` wants the signal `bit` sent now by `sender`, in the
625    /// model of the module docs.
626    fn wants_signal(&self, thread: DetTid, sender: DetTid, bit: u64) -> Wants {
627        if self.parked.exit_fences.contains_key(&thread)
628            || self.logically_killed_threads.contains(&thread)
629            || self.filed_exit_request(thread)
630        {
631            return Wants::No;
632        }
633        let mask = if self.out_of_schedule(thread) {
634            match self.blocked.out_of_scheduler_masks.get(&thread) {
635                Some(Some(mask)) => *mask,
636                _ => return Wants::Unknown,
637            }
638        } else {
639            match self.stopped_thread_mask(thread) {
640                Some(mask) => mask,
641                None => return Wants::Unknown,
642            }
643        };
644        if mask & bit != 0 {
645            return Wants::No;
646        }
647        // Linux's `wants_signal` takes SIGKILL whatever else is pending, and
648        // the running sender is `task_curr`.
649        if bit == kernel_signal_bit(libc::SIGKILL) || thread == sender {
650            return Wants::Yes;
651        }
652        if self.out_of_schedule(thread) {
653            // Its own queue is not read: only the scheduler's own sends reach
654            // it there, and they are recorded.
655            return if self.blocked.signaled_background.contains(&thread) {
656                Wants::Busy
657            } else {
658                Wants::Yes
659            };
660        }
661        // A thread already chosen for a copy still in the shared queue has
662        // been woken for it, so Linux passes it over
663        // (`signal_wake_up`, signal.c:1027, sets `TIF_SIGPENDING`).
664        if self
665            .process_signal_takers
666            .get(&thread)
667            .is_some_and(|signals| *signals != 0)
668        {
669            return Wants::Busy;
670        }
671        match self.reliable_pending(thread, mask) {
672            Some(0) => Wants::Yes,
673            Some(_) => Wants::Busy,
674            None => Wants::Unknown,
675        }
676    }
677
678    /// Whether `thread` `wants_signal` for a signal the kernel itself generates
679    /// for its process between turns (a child's exit `SIGCHLD`, a timer's
680    /// expiry; `Scheduler::kernel_signal_choice`), where `mask` is the mask
681    /// Linux's `blocked` holds for it now (`None`: unreadable, so it is no
682    /// target), already less any set a `rt_sigtimedwait` waits for. The rule
683    /// is `wants_signal`'s, as for a guest's send, with no running sender:
684    /// not exiting, not blocking the signal, and, but for SIGKILL, no other
685    /// unblocked signal pending for it alone (`task_sigpending`) and not
686    /// already woken for another copy in the shared queue. A thread sleeping
687    /// outside the schedule is read only for its wake (`signaled_background`),
688    /// since host timing can post it a signal, except a vfork parent. A
689    /// thread the scheduler has woken for signals of its own and queued to
690    /// resume (`committed_own_signal_wake`) is busy only for any other
691    /// signal pending for it alone.
692    pub(super) fn kernel_sent_wants(&self, thread: DetTid, mask: Option<u64>, bit: u64) -> Wants {
693        if self.parked.exit_fences.contains_key(&thread)
694            || self.logically_killed_threads.contains(&thread)
695            || self.filed_exit_request(thread)
696        {
697            return Wants::No;
698        }
699        let Some(mask) = mask else {
700            return Wants::No;
701        };
702        if mask & bit != 0 {
703            return Wants::No;
704        }
705        if bit == kernel_signal_bit(libc::SIGKILL) {
706            return Wants::Yes;
707        }
708        // A vfork parent sleeps outside the schedule too, but no host timing
709        // ends its call (the child's exec or exit, which the schedule fixes,
710        // does) or posts it a signal, so its pending set is read like a
711        // stopped thread's: one with a signal pending is busy, which a caught
712        // signal does not wake there (`wait_for_vfork_done` sleeps killable).
713        if self.out_of_schedule(thread) && !self.vfork_barriers.contains_key(&thread) {
714            return if self.blocked.signaled_background.contains(&thread) {
715                Wants::Busy
716            } else {
717                Wants::Yes
718            };
719        }
720        if self
721            .process_signal_takers
722            .get(&thread)
723            .is_some_and(|signals| *signals != 0)
724        {
725            return Wants::Busy;
726        }
727        // Woken at a committed point for signals pending for it alone, and not
728        // yet resumed. Linux woke it when those signals were sent
729        // (`signal_wake_up`, kernel/signal.c:1027-1033 at v6.17) and, its
730        // wake latency far below the step between a send and the next
731        // expiry, it has dequeued them by the time the kernel generates this
732        // one: `dequeue_signal` takes the private queue first, then the
733        // shared one (lines 618-640), and returns to its interruptible wait
734        // with nothing pending. Here the wake is only committed, at the drain
735        // that also dispatches this expiry, so its private queue still holds
736        // those signals, and reading them as `task_sigpending` gave the copy
737        // to a sibling Linux does not choose (ptrace `busypause`:
738        // alarm_worker=1 worker_eintr=1 where Linux prints 0 and 0, the
739        // coord7 review of https://github.com/rrnewton/hermit/pull/5221,
740        // finding 2). It is busy only for a signal it was not woken for.
741        let woken_for = self.committed_own_signal_wake(thread).unwrap_or(0);
742        match self.reliable_pending(thread, mask) {
743            Some(pending) if pending & !woken_for != 0 => Wants::Busy,
744            _ => Wants::Yes,
745        }
746    }

748    /// The signals `thread` is queued to resume for, if the scheduler woke it
749    /// for signals pending for it alone at a committed point and it has not
750    /// run since: its filed request is that wake's one write-only resource,
751    /// the signal set the step-2 drain of cross-task signals files for an
752    /// interrupted `pause`, `nanosleep`, futex wait or poll (`WaitidSignals`,
753    /// `Scheduler::drain_sleep_signals`) or the signal a scheduler send files
754    /// for a sleeper or poller it wakes (`InboundSignal`,
755    /// `Scheduler::wake_signaled_guest_as`), and it waits in the run queue.
756    /// Not a delivery stop's own request, which asks for its signal
757    /// read-write after the kernel dequeued it.
758    fn committed_own_signal_wake(&self, thread: DetTid) -> Option<u64> {
759        if !self.run_queue.contains_tid(thread) {
760            return None;
761        }
762        let request = self.next_turns.get(&thread)?.req.try_read()?.ok()?;
763        if request.resources.len() != 1 {
764            return None;
765        }
766        match request.resources.iter().next()? {
767            (ResourceID::InboundSignal(signal), Permission::W) => {
768                Some(kernel_signal_bit(signal.raw()))
769            }
770            (ResourceID::WaitidSignals(signals), Permission::W) => Some(
771                signals
772                    .iter()
773                    .fold(0, |bits, signal| bits | kernel_signal_bit(signal.raw())),
774            ),
775            _ => None,
776        }
777    }

779    /// Whether `thread`'s filed request is its own exit, which Linux runs to
780    /// completion: `wants_signal` passes over an exiting thread (`PF_EXITING`,
781    /// signal.c:951-952).
782    pub(super) fn filed_exit_request(&self, thread: DetTid) -> bool {
783        self.next_turns
784            .get(&thread)
785            .and_then(|turn| turn.req.try_read())
786            .and_then(Result::ok)
787            .is_some_and(|request| {
788                request
789                    .resources
790                    .keys()
791                    .any(|rid| matches!(rid, ResourceID::Exit { .. }))
792            })
793    }

795    /// The mask of `thread`, stopped at a request or parked, as Linux's
796    /// `wants_signal` reads it: the guest's own while Detcore holds the thread
797    /// under a private one (`saved_guest_sigmasks`), less the set a polling
798    /// `rt_sigtimedwait` waits for, which Linux unblocks for the wait
799    /// (`do_sigtimedwait`, signal.c:3777).
800    fn stopped_thread_mask(&self, thread: DetTid) -> Option<u64> {
801        let mask = match self.saved_guest_sigmasks.get(&thread) {
802            Some(saved) => *saved,
803            None => self.stopped_thread_signal_state(thread).ok()?.blocked,
804        };
805        Some(mask & !self.sigtimedwait_sets.get(&thread).copied().unwrap_or(0))
806    }

808    /// The signals in `thread`'s own queue that the mask in force does not
809    /// block, when it is stopped at a request or parked, without those a
810    /// host-timed source may have posted (`host_timed_signals`) and
811    /// Reverie's preemption marker, which the schedule does not fix, and
812    /// without a copy Linux discarded as it was generated
813    /// (`discarded_bits`), which the kernel or the backend still holds (a
814    /// traced task's ignored signal is queued whatever its disposition) but
815    /// Linux never queued, so it sets no `TIF_SIGPENDING`. A copy that was
816    /// blocked when generated, and so queued although ignored, still counts
817    /// (the revastra2 review of SIGSHARE S3b's fix round, delta F2).
818    ///
819    /// `mask` is the one installed mask Linux's `blocked` holds for the
820    /// thread, already less any `rt_sigtimedwait` set: the same value the
821    /// caller tested the incoming signal against, so both halves of
822    /// `wants_signal` read one mask. A waiting call's temporary mask is
823    /// that mask; the thread's own mask alone would misread a private copy
824    /// the call blocks, or one it admits (the dual review of
825    /// https://github.com/rrnewton/hermit/pull/5259, P1).
826    fn reliable_pending(&self, thread: DetTid, mask: u64) -> Option<u64> {
827        let state = self.stopped_thread_signal_state(thread).ok()?;
828        let unreliable =
829            self.host_timed_signals(thread) | kernel_signal_bit(reverie::PERF_EVENT_SIGNAL as i32);
830        let discarded = self.discarded_bits(thread).0;
831        Some(state.thread_pending & !mask & !unreliable & !discarded)
832    }

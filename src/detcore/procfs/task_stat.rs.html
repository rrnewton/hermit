9//! A process's own `/proc/<pid>/stat` as Detcore renders it (package K slice
10//! D4c-1 of <https://github.com/rrnewton/hermit/issues/4213>), and the minimal
11//! record of task names it falls back on.
12//!
13//! Detcore renders every guest task's `stat`, by every spelling, from its
14//! process table, in Linux's 52 fields ([`render_stat`]): the caller's own
15//! process's since slice D4c-1, and since package K item 2b slice 2b-1
16//! (<https://github.com/rrnewton/hermit/issues/5063>) another process's in
17//! the caller's PID namespace too, as Linux serves it to every reader there
18//! (`proc_pid_lookup` and the world-readable `stat`, fs/proc/base.c), with
19//! `do_task_stat`'s `ptrace_may_access` gate on the fields it hides
20//! ([`TaskStat::permitted`]). Its second field,
21//! the task's name (Linux's `task_struct::comm`), comes from one of two
22//! sources, chosen by the backend's declared capability alone
23//! ([`CommSource::of_backend`]):
24//!
25//! - [`CommSource::Kernel`] where guest threads are host tasks the tool can
26//!   name (`procfs_inode::tool_can_name_guest_descriptors`: ptrace, DBT,
27//!   SaBRe, LiteInst): the kernel beneath's own name, which the tool reads
28//!   from the described task's `/proc/<pid>[/task/<tid>]/comm` in the
29//!   reader's turn (`Detcore::kernel_task_comm`). It follows every way Linux
30//!   renames a task, a write to a `comm` file by any spelling included, and
31//!   the host kernel's own rule for an exec by descriptor. The file must be
32//!   on a procfs. Where the tool shares the guest's root (DBT, SaBRe,
33//!   LiteInst) and the guest has changed it (`chroot`), nothing is read: the
34//!   path would go through a root the guest controls, where no check on the
35//!   opened file authenticates the task. Where the read is refused or fails
36//!   (that root change, the tool's own descriptors exhausted, a guest
37//!   seccomp filter), the read of `stat` is the failure policy's named
38//!   refusal, never the record. A tracer (ptrace) reads its own `/proc`,
39//!   which no guest `chroot` changes.
40//! - [`CommSource::Record`] where they are not (KVM): Detcore's record of the
41//!   name ([`TaskComm`], `ThreadTree::task_comms`), set at each exec from the
42//!   new image's `AT_EXECFN` ([`TaskComm::of_exec_filename`]), inherited at
43//!   clone, replaced by `prctl(PR_SET_NAME)`.
44//!
45//! The record would differ from Linux's name after a write to a `comm` file
46//! (by the task itself or another; glibc's `pthread_setname_np` of another
47//! thread writes `/proc/self/task/<tid>/comm`), and after
48//! `execveat(fd, "", AT_EMPTY_PATH)` on Linux 6.14 and later (named by the
49//! file's dentry, the record by `/dev/fd/<fd>`). Neither can happen where the
50//! record is used: Detcore refuses an open of the reader's own `comm` for
51//! writing (EACCES, below), and the KVM executor refuses that exec
52//! (ENOTSUP).
53//!
54//! The `comm` files (package K slice A+): where the name's source is the
55//! record (KVM), Detcore also renders every guest task's `/proc/<pid>/comm`
56//! (the reader's own process's since slice A+, another process's since
57//! slice 2b-1), by every spelling (`self`, a pid, `thread-self`,
58//! `task/<tid>`), from the same record ([`render_comm`],
59//! [`renders_task_comm`]), with the `stat` file's seq_file positioning and
60//! failure policy. Detcore does not write a name: it refuses an open of a
61//! rendered `comm` for writing itself, with EACCES and no injected call
62//! (`syscalls::files::rendered_procfs::asks_to_write_comm`), by its path,
63//! through a descriptor link, and through a `..` spelling, which Detcore
64//! walks itself where it models every component, checking each task it
65//! passes (`walk_comm_alias`), and refuses by name for writing where it does
66//! not (<https://github.com/rrnewton/hermit/issues/4263>), so the record
67//! cannot fall behind a write and the answer depends on neither the host nor
68//! the kernel beneath.
69//! DECLARED: Linux renames the task (`comm_write`), and refuses a write to
70//! another thread group's `comm` with EINVAL at the write; Detcore refuses
71//! the open of either with EACCES. Where the source is the kernel (ptrace,
72//! DBT, SaBRe, LiteInst), every `comm` file stays the kernel's, as before,
73//! unclassified.
74//!
75//! DECLARED, KVM: for the run's root image, the record (from `AT_EXECFN`,
76//! the path the root was launched by) names the task as Linux does, while
77//! the KVM executor, which still answers `PR_GET_NAME` there, names it by its
78//! resolved, canonical `argv[0]` (reverie-kvm `elf.rs`,
79//! `initial_thread_name`): for a `#!` script root, which Hermit's launcher
80//! rewrites to the interpreter, `stat` says `t.sh` where `PR_GET_NAME` says
81//! `sh`; for an ELF root launched through a symbolic link
82//! `/path/alias -> /path/actual`, `stat` says `alias` where `PR_GET_NAME`
83//! says `actual`. The record is the Linux-correct side and is kept; the
84//! executor's naming is the executor's
85//! (<https://github.com/rrnewton/reverie/issues/1106>). On ptrace and DBT
86//! every name is the kernel's. The rendered `comm` file and, since package K
87//! slice 2b-2, the rendered `status` (`task_status`, whose `Name` is this
88//! name) follow the record, so on KVM `stat`, `status` and `comm` agree, as
89//! Linux's do, and disagree only with `PR_GET_NAME` for those two roots, and
90//! in every descendant that has not renamed itself or exec'd since (cells
91//! `system-utils/stat-script-root` and `system-utils/stat-alias-root` check
92//! the three files against the native output; before 2b-2 their KVM rows
93//! said `status=bash`, the executor's name). A guest exec does not reopen
94//! the split: the executor names the new image by the filename the exec was
95//! given, as Linux does, so an exec of a symbolic link `alias -> actual` is
96//! `alias` to `PR_GET_NAME` and to the record alike. After `PR_SET_NAME`,
97//! both follow the same rule.
98//!
99//! The rules are Linux 6.17's (fs/proc/array.c `do_task_stat`, fs/exec.c
100//! `begin_new_exec`, kernel/sys.c `PR_SET_NAME`, fs/proc/base.c
101//! `comm_show`).

109/// Linux's `TASK_COMM_LEN`: a task's name and its terminating NUL.
110pub const TASK_COMM_LEN: usize = 16;
111
112/// `PF_EXITING` (include/linux/sched.h): the task is exiting, which a zombie's
113/// `stat` shows in its flags (`do_exit` sets it in `exit_signals`).
114const PF_EXITING: u64 = 0x0000_0004;
115
116/// `PF_FORKNOEXEC`: the task was forked and has not exec'd. `copy_process`
117/// sets it on every new task, threads included (kernel/fork.c:2061 in 6.17),
118/// and only the task that execs loses it (`begin_new_exec`).
119const PF_FORKNOEXEC: u64 = 0x0000_0040;
120
121/// `RLIM_INFINITY` as `stat`'s `rsslim` prints it.
122pub(crate) const RLIM_INFINITY: u64 = u64::MAX;

124/// A task's name, Linux's `task_struct::comm`: at most 15 bytes, none of them
125/// NUL, padded with NULs to [`TASK_COMM_LEN`], as `__set_task_comm` stores it
126/// (`strscpy_pad`).
127#[derive(
128    Clone,
129    Copy,
130    Debug,
131    Default,
132    PartialEq,
133    Eq,
134    Hash,
135    Serialize,
136    Deserialize
137)]
138pub struct TaskComm([u8; TASK_COMM_LEN]);
139
140impl TaskComm {
141    /// The name Linux stores from `bytes`: the bytes before the first NUL, at
142    /// most 15 (`strscpy_pad` into `TASK_COMM_LEN`). `PR_SET_NAME` reads at
143    /// most 15 bytes of the caller's string through its NUL
144    /// (`strncpy_from_user(comm, arg2, sizeof(me->comm) - 1)`), and the
145    /// kernel's `comm` file holds the name and a newline.
146    pub fn new(bytes: &[u8]) -> Self {
147        let length = bytes
148            .iter()
149            .take(TASK_COMM_LEN - 1)
150            .position(|byte| *byte == 0)
151            .unwrap_or_else(|| bytes.len().min(TASK_COMM_LEN - 1));
152        let mut name = [0; TASK_COMM_LEN];
153        name[..length].copy_from_slice(&bytes[..length]);
154        Self(name)
155    }
156
157    /// The name an exec of `filename` stores: its last component
158    /// (`kbasename(bprm->filename)`, fs/exec.c:1246 in 6.17), cut as
159    /// [`Self::new`] cuts it. A new image's `AT_EXECFN` points at a copy of
160    /// `bprm->filename` (`create_elf_tables`), so its last component is the
161    /// name the exec gave: the path as given for a direct, symbolic-link or
162    /// script exec. Only `execveat(fd, "", AT_EMPTY_PATH)` is named otherwise
163    /// in Linux 6.14 and later (by the file's dentry, `comm_from_dentry`),
164    /// and the backends that use this record do not support that exec.
165    pub fn of_exec_filename(filename: &[u8]) -> Self {
166        let start = filename
167            .iter()
168            .rposition(|byte| *byte == b'/')
169            .map_or(0, |slash| slash + 1);
170        Self::new(&filename[start..])
171    }
172
173    /// The name as the kernel's `/proc/<pid>/comm` holds it: the bytes before
174    /// its final newline (`comm_show` prints the name and `\n`).
175    pub fn from_comm_file(bytes: &[u8]) -> Self {
176        Self::new(bytes.strip_suffix(b"\n").unwrap_or(bytes))
177    }
178
179    /// The name's bytes, without the terminating NUL.
180    pub fn as_bytes(&self) -> &[u8] {
181        let length = self
182            .0
183            .iter()
184            .position(|byte| *byte == 0)
185            .unwrap_or(TASK_COMM_LEN);
186        &self.0[..length]
187    }
188}

190/// What Detcore's process table says about the task a per-process `stat`
191/// file describes (`Scheduler::task_stat_facts`): the thread below `task/`,
192/// else the task the top-level number names.
193#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
194pub struct TaskStatFacts {
195    /// The task's recorded name, `None` where Detcore recorded none (a task
196    /// of a process that has not exec'd an image Detcore saw).
197    pub comm: Option<TaskComm>,
198    /// The CPUs the task may run on and its home (`Scheduler::task_cpus`),
199    /// which place it on a CPU (`TaskStat::processor`).
200    pub cpus: crate::cpu_set::TaskCpus,
201    /// The task has exited and is not reaped: a zombie, whose state is `Z`.
202    pub exited: bool,
203    /// The task leads its thread group.
204    pub leads: bool,
205    /// The thread group leader's exit signal (`task_struct::exit_signal`), as
206    /// Detcore's wait model keeps it (`ProcessWaitMetadata::exit_signal`).
207    /// A thread that does not lead has -1 (`copy_process` for
208    /// `CLONE_THREAD`, kernel/fork.c:2328), whatever this is.
209    pub process_exit_signal: i32,
210    /// The thread group leader was forked and has not exec'd
211    /// (`ProcessWaitMetadata::forked_without_exec`).
212    pub forked_without_exec: bool,
213    /// The process's group and session, as `getpgid` and `getsid` answer
214    /// (`Scheduler::group_or_session_of`).
215    pub process_group: i32,
216    pub session: i32,
217    /// The tasks Linux counts in the process (`signal_struct::nr_threads`):
218    /// its live threads and its leader until the group is reaped, the tasks
219    /// its `task/` directory lists (`Scheduler::procfs_listing`).
220    pub num_threads: i32,
221    /// The process the task belongs to, by its leader's number; `None` for a
222    /// number no process of the table holds.
223    pub process: Option<i32>,
224    /// The process's parent as the guest sees it (`getppid`'s answer), from
225    /// Detcore's model (`Scheduler::guest_visible_parent`): its real parent's
226    /// process, the namespace's init (1) for an orphan given to it, and for a
227    /// process whose real parent is outside the guest's tree (the run's root,
228    /// and its `CLONE_PARENT` children) the parent its own `getppid` answered
229    /// when it first opened its rendered `stat`
230    /// (`Scheduler::record_external_parent`). `None` before that answer is
231    /// recorded.
232    pub parent: Option<i32>,
233    /// The process's virtual soft `RLIMIT_RSS` (`ThreadTree::rss_limits`),
234    /// `RLIM_INFINITY` unless it set another.
235    pub rsslim: u64,
236    /// The described task's CPU time as its process last published it
237    /// (`Scheduler::publish_cpu_time`): the process's own for a top-level
238    /// file, which counts every thread, exited ones included, one thread's
239    /// own for a file below `task/`, and the process's reaped children's in
240    /// both. Zero for a task that has published none (one that has not yet
241    /// made a request, and so has not run since its clone). What another
242    /// process's `stat` shows; the reader's own process's comes from its
243    /// own accounting, which is never behind.
244    pub cpu: TaskCpuTimes,
245    /// The zombie's exit code as Linux keeps it (fs/proc/array.c:484 and
246    /// :529-530 in 6.17): the wait status, recorded where Detcore learns how
247    /// the process ended (`Scheduler::record_exit_code`). An `exit_group`'s
248    /// status shifted left by 8; the leader's raw `exit` likewise, unless the
249    /// group later dies as a whole; a fatal signal, with `0x80` where the
250    /// death dumped core as the backend reports it; SIGKILL from another
251    /// process. 0 for a live task.
252    pub exit_code: i32,
253}

255/// Where a rendered `stat`'s name (field 2) comes from: decided by the
256/// backend's declared capability, never by which backend it is.
257#[derive(Clone, Copy, Debug, PartialEq, Eq)]
258pub(crate) enum CommSource {
259    /// The kernel beneath's own name (`Detcore::kernel_task_comm`).
260    Kernel,
261    /// Detcore's record of the name (`ThreadTree::task_comms`).
262    Record,
263}
264
265impl CommSource {
266    /// The source for a backend: the kernel's name where its guest threads
267    /// are host tasks the tool can name
268    /// (`procfs_inode::tool_can_name_guest_descriptors`, the capability
269    /// `namespace::guest_task_procfs` tests first, so the one
270    /// `Detcore::exec_image_at` and `mark_past_first_execve`'s `exe` read
271    /// depend on), Detcore's record elsewhere. The other conditions of
272    /// `guest_task_procfs` (an unchanged root, the tool's mount namespace)
273    /// decide whether a path through the guest's working directory or
274    /// descriptor links resolves, not whether a task's name can be read by
275    /// its number; after a guest `chroot` the source stays the kernel, whose
276    /// read succeeds through a tracer's own `/proc`, and where the tool
277    /// shares the guest's root, not at all: the read of `stat` is refused by
278    /// name (`Detcore::kernel_task_comm`).
279    ///
280    /// NOTE: `tool_can_name_guest_descriptors` is today the inverse of
281    /// `provides_process_signal_control`, which only KVM declares, so the
282    /// record is the source exactly where the backend owns signal delivery.
283    /// That capability describes signal ownership, not the absence of a host
284    /// task name: a future backend that owns signals but runs guest threads
285    /// as host tasks would need its own capability here. Writes do not depend
286    /// on this choice: Detcore refuses a write open of every `comm` it
287    /// renders.
288    pub(crate) fn of_backend(tool_can_name_guest_descriptors: bool) -> Self {
289        if tool_can_name_guest_descriptors {
290            Self::Kernel
291        } else {
292            Self::Record
293        }
294    }
295}

297/// The name a rendered `stat` shows, from its `source`: the kernel's name
298/// the tool read (`kernel`, `Err` naming why there is none), or Detcore's
299/// record (`record`). `Err` names why there is none, which the caller turns
300/// into the failure policy's named refusal: a failed kernel read is never
301/// answered with the record, which a host resource (the tool's descriptors)
302/// would then choose, and which can be stale where the kernel is the source.
303pub(crate) fn stat_comm(
304    source: CommSource,
305    kernel: Result<TaskComm, &'static str>,
306    record: Option<TaskComm>,
307) -> Result<TaskComm, &'static str> {
308    match source {
309        CommSource::Kernel => kernel,
310        CommSource::Record => record.ok_or("Detcore recorded no name for the task"),
311    }
312}

314/// Whether Detcore renders the `stat` of the task `facts` describe, whose
315/// name comes from `source`: any task of the guest's process table, the
316/// reader's own process's (package K slice D4c-1) and another process's
317/// (package K item 2b slice 2b-1), as Linux serves every task's `stat` to
318/// every reader in its PID namespace; and where the source is Detcore's
319/// record, only once a name is recorded (a process that has not exec'd an
320/// image Detcore saw has none), whose file stays the kernel beneath's. A
321/// number no process of the table holds is the kernel beneath's to answer
322/// (ENOENT).
323///
324/// Another process's file was the kernel beneath's before 2b-1: on KVM the
325/// provider's EACCES, which made ps and pgrep drop the process from their
326/// table without an error (procps 4.0.6 skips a process whose `stat` open
327/// fails, measured in the pinned root); on ptrace and DBT the kernel's,
328/// sanitized, which showed a zombie as `S` and every other process's CPU
329/// time as 0, where Linux shows `Z` and the time the process's own `stat`
330/// shows.
331pub(crate) fn renders_task_stat(facts: &TaskStatFacts, source: CommSource) -> bool {
332    facts.process.is_some() && (source == CommSource::Kernel || facts.comm.is_some())
333}

335/// Whether Detcore renders the `comm` of the task `facts` describe, whose
336/// name comes from `source` (package K slice A+): only where the source is
337/// Detcore's record (the same capability that chooses `stat`'s name, never a
338/// backend's identity), for any task of the guest's process table (the
339/// reader's own process's since slice A+, another process's since package K
340/// item 2b slice 2b-1), and only once a name is recorded. Elsewhere the file
341/// is the kernel beneath's: the host kernel's own name on ptrace and DBT,
342/// which Detcore leaves unclassified, and on KVM an unnamed task's, the
343/// executor's EACCES.
344pub(crate) fn renders_task_comm(facts: &TaskStatFacts, source: CommSource) -> bool {
345    source == CommSource::Record && facts.process.is_some() && facts.comm.is_some()
346}

348/// The name of Hermit's own init, pid 1 of the run's PID namespace where no
349/// guest holds it: Hermit's process, forked by Hermit without an exec, so
350/// its `comm` is Hermit's (`hermit`), as the container contract pins it
351/// (the isolation matrix's `pid.private_init`, hermit-cli's
352/// `dbt_guest_runs_in_the_common_container`).
353pub(crate) const HERMIT_INIT_COMM: &[u8] = b"hermit";
354
355/// The facts of the task `task` names for its `stat` and `comm`
356/// (package K item 2b, pid 1): Detcore's process table's (`facts`), except
357/// for Hermit's own init where the name's source is Detcore's record
358/// (`source`, KVM's capability), whose files Detcore then renders from a
359/// fixed model of that process instead of leaving them to the kernel
360/// beneath, whose `/proc/1` there is not Hermit's init (KVM's provider
361/// refuses every procfs object, so procps left pid 1 out of its table).
362///
363/// Hermit's init is the task `procfs::listing::task_exists` finds for pid 1
364/// and its one thread 1 where no process of the table holds the number
365/// (`facts.process` is `None`); `Scheduler::procfs_task` already models it
366/// as live. Its model, every field a constant or Linux's rule for that
367/// process, nothing read from the host or the supervisor:
368///
369/// - name [`HERMIT_INIT_COMM`], parent 0 (its parent is outside the PID
370///   namespace), the contract's `PID1 name=hermit, pid=1, parent=0`;
371/// - process group and session 0: both are outside the namespace, which
372///   numbers them 0 (`pid_vnr`);
373/// - one thread, the listing's (`/proc/1/task` lists 1 alone);
374/// - forked without an exec (`PF_FORKNOEXEC`), exit signal `SIGCHLD`, the
375///   default `RLIMIT_RSS`, and no CPU time: it runs no guest code, and
376///   Detcore accounts virtual CPU time to guest tasks only.
377///
378/// Where the source is the kernel's (ptrace, DBT, SaBRe, LiteInst) the
379/// kernel beneath's `/proc/1` is Hermit's init itself, whose sanitized file
380/// stays as before: `facts` unchanged.
381pub(crate) fn with_hermit_init(
382    task: crate::procfs::BoundTask,
383    facts: TaskStatFacts,
384    source: CommSource,
385) -> TaskStatFacts {
386    let names_init = task.process == 1 && task.thread.is_none_or(|thread| thread == 1);
387    if source != CommSource::Record || facts.process.is_some() || !names_init {
388        return facts;
389    }
390    TaskStatFacts {
391        comm: Some(TaskComm::new(HERMIT_INIT_COMM)),
392        cpus: facts.cpus,
393        exited: false,
394        leads: true,
395        process_exit_signal: libc::SIGCHLD,
396        forked_without_exec: true,
397        process_group: 0,
398        session: 0,
399        num_threads: 1,
400        process: Some(1),
401        parent: Some(0),
402        rsslim: RLIM_INFINITY,
403        cpu: TaskCpuTimes::default(),
404        exit_code: 0,
405    }
406}

409/// name as `proc_task_name(m, p, false)` prints it, raw, through its first

412pub(crate) fn render_comm(comm: &TaskComm) -> Vec<u8> {

433/// One rendering of a `stat` file, with what its reader adds to the
434/// process table's facts.
435#[derive(Clone, Copy, Debug, PartialEq, Eq)]
436pub(crate) struct TaskStat {
437    /// The number the file's path names its task by: field 1
438    /// (`pid_nr_ns(pid, ns)` of the inode's pid, the thread's number below
439    /// `task/`).
440    pub(crate) pid: i32,
441    /// The task's name: the kernel's, or Detcore's record ([`stat_comm`]).
442    pub(crate) comm: TaskComm,
443    pub(crate) facts: TaskStatFacts,
444    /// The reading thread is the task the file describes, which is running.
445    pub(crate) reader_is_task: bool,
446    /// The process's parent: as `getppid` answers its reader for its own
447    /// process, or for another process's file read by this one,
448    /// [`TaskStatFacts::parent`], numbered as that process's `getppid`
449    /// answers it (`Detcore::getppid_numbered_parent`).
450    pub(crate) ppid: i32,
451    /// The process's `RLIMIT_RSS` soft limit ([`TaskStatFacts::rsslim`]),
452    /// whoever reads it.
453    pub(crate) rsslim: u64,
454    /// The CPU the task runs on, field 39: its place on the run's virtual
455    /// CPUs ([`TaskStatFacts::cpus`], `TaskCpus::current`), 0 on the single
456    /// CPU without `--virtual-cpus`.
457    pub(crate) processor: u32,
458    /// The task's CPU time as of this read: from its reader's own
459    /// accounting for its own process's file, and for another process's,
460    /// what that process last published ([`TaskStatFacts::cpu`]), which,
461    /// with threads sequentialized, is its time where it last stopped.
462    pub(crate) cpu: TaskCpuTimes,
463    /// Linux's `ptrace_may_access(task, PTRACE_MODE_READ_FSCREDS)` for the
464    /// reader (`do_task_stat`'s `permitted`, fs/proc/array.c:490 in 6.17):
465    /// always for the reader's own thread group, and for another, Detcore's
466    /// model of that check (`Detcore::io_read_allowed`). Where it refuses,
467    /// Linux prints `startcode` and `endcode` as 1 for a task with memory
468    /// and the exit code as 0 ([`render_stat`]).
469    pub(crate) permitted: bool,
470}
471
472/// `stat`'s state letter for a task: `R` for the reader itself, which runs
473/// while it reads; `Z` for a zombie; `S` for every other task. With threads
474/// sequentialized no other task runs while the file is read, and Detcore
475/// does not model a task's kernel wait states (`D`, `t`, `T`): a fixed `S`.
476pub(crate) fn state(stat: &TaskStat) -> char {
477    if stat.facts.exited {
478        'Z'
479    } else if stat.reader_is_task {
480        'R'
481    } else {
482        'S'
483    }
484}
485
486/// `stat`'s `flags` (field 9): only the bits Detcore models.
487/// `PF_FORKNOEXEC` for a task forked without an exec since (every thread
488/// that does not lead, and a leader by Detcore's wait model), and
489/// `PF_EXITING` for a zombie. Never `PF_RANDOMIZE`: every launcher Hermit
490/// execs a guest through sets `ADDR_NO_RANDOMIZE`, and KVM's loader does not
491/// randomize. Never `PF_SUPERPRIV` or the kernel's other bits, which
492/// describe host privilege use and kernel state.
493fn flags(stat: &TaskStat) -> u64 {
494    let mut flags = 0;
495    if !stat.facts.leads || stat.facts.forked_without_exec {
496        flags |= PF_FORKNOEXEC;
497    }
498    if stat.facts.exited {
499        flags |= PF_EXITING;
500    }
501    flags
502}

504/// A task's `stat` line in Linux's 52 fields (`do_task_stat`,
505/// fs/proc/array.c:467-669 in 6.17), from Detcore's state:
506///
507/// | field | name | value |
508/// | --- | --- | --- |
509/// | 1 | pid | the number the path names the task by |
510/// | 2 | comm | the task's name ([`TaskStat::comm`]), raw bytes, in parentheses |
511/// | 3 | state | `R` for the reader, `Z` for a zombie, else `S` ([`state`]) |
512/// | 4 | ppid | the process's parent |
513/// | 5, 6 | pgrp, session | Detcore's model, as `getpgid` and `getsid` answer |
514/// | 7, 8 | tty_nr, tpgid | 0, -1: no controlling terminal |
515/// | 9 | flags | [`flags`] |
516/// | 14, 15 | utime, stime | the task's user and system time ([`TaskCpuTimes`]), in clock ticks; another process's as it last published them ([`TaskStatFacts::cpu`]) |
517/// | 16, 17 | cutime, cstime | its process's reaped children's, in clock ticks; another process's as it last published them |
518/// | 18, 19 | priority, nice | 20, 0: nice is inert under Detcore |
519/// | 20 | num_threads | the process's tasks |
520/// | 25 | rsslim | the process's `RLIMIT_RSS` soft limit |
521/// | 26, 27 | startcode, endcode | 0; 1 where the reader is not [`TaskStat::permitted`] and the task has memory (not a zombie), as Linux prints them |
522/// | 38 | exit_signal | the leader's, -1 for another thread |
523/// | 39 | processor | the task's virtual CPU, [`TaskStat::processor`] |
524/// | 40, 41 | rt_priority, policy | 0, 0 (`SCHED_OTHER`) |
525/// | 52 | exit_code | a zombie's recorded exit code ([`TaskStatFacts::exit_code`]) to a permitted reader, else 0 |
526///
527/// Every other field is 0: the fault counts (10-13), the guest time (43, 44),
528/// `itrealvalue` (21, always 0 in Linux), the start time (22), the memory
529/// sizes and addresses (23, 24, 28-30, 45-51), the four obsolete signal
530/// words (31-34, which the sanitizer zeroed on every backend before this),
531/// `wchan` (35), `nswap` and `cnswap` (36, 37) and the block-I/O delay
532/// (42). These are the fields `sanitize_stat` zeroed in the kernel's file
533/// before Detcore rendered it, with the last CPU (39), which is 0 on the
534/// single virtual CPU.
535pub(crate) fn render_stat(stat: &TaskStat) -> Vec<u8> {
536    let facts = &stat.facts;
537    let mut line = format!("{} (", stat.pid).into_bytes();
538    line.extend_from_slice(stat.comm.as_bytes());
539    let exit_signal = if facts.leads {
540        facts.process_exit_signal
541    } else {
542        -1
543    };
544    // `do_task_stat` (fs/proc/array.c:616-617, :660-661 in 6.17): a reader
545    // that may not trace the task sees 1 for the code bounds of a task with
546    // memory, and no exit code. Detcore shows no real address to anyone.
547    let code_bound = if !stat.permitted && !facts.exited {
548        "1"
549    } else {
550        "0"
551    };
552    let exit_code = if stat.permitted { facts.exit_code } else { 0 };
553    let fields: [String; 50] = [
554        // 3 state
555        state(stat).to_string(),
556        // 4 ppid, 5 pgrp, 6 session, 7 tty_nr, 8 tpgid
557        stat.ppid.to_string(),
558        facts.process_group.to_string(),
559        facts.session.to_string(),
560        "0".to_owned(),
561        "-1".to_owned(),
562        // 9 flags
563        flags(stat).to_string(),
564        // 10 minflt .. 13 cmajflt
565        "0".to_owned(),
566        "0".to_owned(),
567        "0".to_owned(),
568        "0".to_owned(),
569        // 14 utime .. 17 cstime
570        clock_ticks(stat.cpu.user).to_string(),
571        clock_ticks(stat.cpu.system).to_string(),
572        clock_ticks(stat.cpu.children_user).to_string(),
573        clock_ticks(stat.cpu.children_system).to_string(),
574        // 18 priority, 19 nice, 20 num_threads
575        "20".to_owned(),
576        "0".to_owned(),
577        facts.num_threads.to_string(),
578        // 21 itrealvalue, 22 starttime, 23 vsize, 24 rss
579        "0".to_owned(),
580        "0".to_owned(),
581        "0".to_owned(),
582        "0".to_owned(),
583        // 25 rsslim
584        stat.rsslim.to_string(),
585        // 26 startcode, 27 endcode, 28 startstack .. 37 cnswap
586        code_bound.to_owned(),
587        code_bound.to_owned(),
588        "0".to_owned(),
589        "0".to_owned(),
590        "0".to_owned(),
591        "0".to_owned(),
592        "0".to_owned(),
593        "0".to_owned(),
594        "0".to_owned(),
595        "0".to_owned(),
596        "0".to_owned(),
597        "0".to_owned(),
598        // 38 exit_signal, 39 processor, 40 rt_priority, 41 policy
599        exit_signal.to_string(),
600        stat.processor.to_string(),
601        "0".to_owned(),
602        "0".to_owned(),
603        // 42 delayacct_blkio_ticks .. 51 env_end
604        "0".to_owned(),
605        "0".to_owned(),
606        "0".to_owned(),
607        "0".to_owned(),
608        "0".to_owned(),
609        "0".to_owned(),
610        "0".to_owned(),
611        "0".to_owned(),
612        "0".to_owned(),
613        "0".to_owned(),
614        // 52 exit_code
615        exit_code.to_string(),
616    ];
617    line.extend_from_slice(b") ");
618    line.extend_from_slice(fields.join(" ").as_bytes());
619    line.push(b'\n');
620    line
621}

1034    /// has no name is a refusal: a failed kernel read is never answered with
1035    /// the record, which can be stale there (a write to a `comm` file

1038    fn a_failed_kernel_comm_read_is_refused_not_answered_with_the_record() {

1044            stat_comm(CommSource::Kernel, Ok(kernel), Some(record)),

1050            stat_comm(CommSource::Record, Err("none"), Some(record)),

1054            stat_comm(CommSource::Record, Ok(kernel), Some(record)),

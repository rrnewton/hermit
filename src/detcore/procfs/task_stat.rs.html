9//! A process's own `/proc/<pid>/stat` as Detcore renders it (package K slice
10//! D4c-1 of <https://github.com/rrnewton/hermit/issues/4213>), and the minimal
11//! record of task names it falls back on.
12//!
13//! Detcore renders the caller's own process's `stat`, by every spelling, from
14//! its process table, in Linux's 52 fields ([`render_stat`]). Its second field,
15//! the task's name (Linux's `task_struct::comm`), comes from one of two
16//! sources, chosen by the backend's declared capability alone
17//! ([`CommSource::of_backend`]):
18//!
19//! - [`CommSource::Kernel`] where guest threads are host tasks the tool can
20//!   name (`procfs_inode::tool_can_name_guest_descriptors`: ptrace, DBT,
21//!   SaBRe, LiteInst): the kernel beneath's own name, which the tool reads
22//!   from the described task's `/proc/<pid>[/task/<tid>]/comm` in the
23//!   reader's turn (`Detcore::kernel_task_comm`). It follows every way Linux
24//!   renames a task, a write to a `comm` file by any spelling included, and
25//!   the host kernel's own rule for an exec by descriptor. The file must be
26//!   on a procfs. Where the tool shares the guest's root (DBT, SaBRe,
27//!   LiteInst) and the guest has changed it (`chroot`), nothing is read: the
28//!   path would go through a root the guest controls, where no check on the
29//!   opened file authenticates the task. Where the read is refused or fails
30//!   (that root change, the tool's own descriptors exhausted, a guest
31//!   seccomp filter), the read of `stat` is the failure policy's named
32//!   refusal, never the record. A tracer (ptrace) reads its own `/proc`,
33//!   which no guest `chroot` changes.
34//! - [`CommSource::Record`] where they are not (KVM): Detcore's record of the
35//!   name ([`TaskComm`], `ThreadTree::task_comms`), set at each exec from the
36//!   new image's `AT_EXECFN` ([`TaskComm::of_exec_filename`]), inherited at
37//!   clone, replaced by `prctl(PR_SET_NAME)`.
38//!
39//! The record would differ from Linux's name after a write to a `comm` file
40//! (by the task itself or another; glibc's `pthread_setname_np` of another
41//! thread writes `/proc/self/task/<tid>/comm`), and after
42//! `execveat(fd, "", AT_EMPTY_PATH)` on Linux 6.14 and later (named by the
43//! file's dentry, the record by `/dev/fd/<fd>`). Neither can happen where the
44//! record is used: Detcore refuses an open of the reader's own `comm` for
45//! writing (EACCES, below), and the KVM executor refuses that exec
46//! (ENOTSUP).
47//!
48//! The `comm` files (package K slice A+): where the name's source is the
49//! record (KVM), Detcore also renders the reader's own process's
50//! `/proc/<pid>/comm`, by every spelling (`self`, its pid, `thread-self`,
51//! `task/<tid>`), from the same record ([`render_comm`],
52//! [`renders_task_comm`]), with the `stat` file's seq_file positioning and
53//! failure policy. Detcore does not write a name: it refuses an open of a
54//! rendered `comm` for writing itself, with EACCES and no injected call
55//! (`syscalls::files::rendered_procfs::asks_to_write_comm`), by its path,
56//! through a descriptor link, and through a `..` spelling, which Detcore
57//! walks itself where it models every component, checking each task it
58//! passes (`walk_comm_alias`), and refuses by name for writing where it does
59//! not (<https://github.com/rrnewton/hermit/issues/4263>), so the record
60//! cannot fall behind a write and the answer depends on neither the host nor
61//! the kernel beneath.
62//! DECLARED: Linux renames the task (`comm_write`). Another process's
63//! `comm` stays the kernel beneath's (the executor's). Where the source is
64//! the kernel (ptrace, DBT, SaBRe, LiteInst), every `comm` file stays the
65//! kernel's, as before, unclassified.
66//!
67//! DECLARED, KVM: for the run's root image, the record (from `AT_EXECFN`,
68//! the path the root was launched by) names the task as Linux does, while
69//! the KVM executor, which still answers `PR_GET_NAME` and
70//! `/proc/<pid>/status` there, names it by its resolved, canonical
71//! `argv[0]` (reverie-kvm `elf.rs`, `initial_thread_name`): for a `#!`
72//! script root, which Hermit's launcher rewrites to the interpreter, `stat`
73//! says `t.sh` where `status` says `sh`; for an ELF root launched through a
74//! symbolic link `/path/alias -> /path/actual`, `stat` says `alias` where
75//! `status` says `actual`. The record is the Linux-correct side and is kept;
76//! the executor's naming is the executor's
77//! (<https://github.com/rrnewton/reverie/issues/1106>; cells
78//! `system-utils/stat-script-root` and `system-utils/stat-alias-root` record
79//! it). On ptrace and DBT all three are the kernel's. The rendered `comm`
80//! file follows the record, so on KVM it agrees with `stat` and disagrees
81//! with `PR_GET_NAME` and `status` for those two roots in the same way, and
82//! in every descendant that has not renamed itself or exec'd since. The same
83//! split can follow a guest exec by a spelling the executor canonicalizes: a
84//! slashless `execve("alias", ...)` of a symbolic link `alias -> actual` can
85//! be named `actual` by the executor while the record, `stat` and `comm` say
86//! `alias`, as Linux does. After `PR_SET_NAME`, both follow the same rule.
87//!
88//! The rules are Linux 6.17's (fs/proc/array.c `do_task_stat`, fs/exec.c
89//! `begin_new_exec`, kernel/sys.c `PR_SET_NAME`, fs/proc/base.c
90//! `comm_show`).

98/// Linux's `TASK_COMM_LEN`: a task's name and its terminating NUL.
99pub const TASK_COMM_LEN: usize = 16;
100
101/// `PF_EXITING` (include/linux/sched.h): the task is exiting, which a zombie's
102/// `stat` shows in its flags (`do_exit` sets it in `exit_signals`).
103const PF_EXITING: u64 = 0x0000_0004;
104
105/// `PF_FORKNOEXEC`: the task was forked and has not exec'd. `copy_process`
106/// sets it on every new task, threads included (kernel/fork.c:2061 in 6.17),
107/// and only the task that execs loses it (`begin_new_exec`).
108const PF_FORKNOEXEC: u64 = 0x0000_0040;
109
110/// `RLIM_INFINITY` as `stat`'s `rsslim` prints it.
111pub(crate) const RLIM_INFINITY: u64 = u64::MAX;

113/// A task's name, Linux's `task_struct::comm`: at most 15 bytes, none of them
114/// NUL, padded with NULs to [`TASK_COMM_LEN`], as `__set_task_comm` stores it
115/// (`strscpy_pad`).
116#[derive(
117    Clone,
118    Copy,
119    Debug,
120    Default,
121    PartialEq,
122    Eq,
123    Hash,
124    Serialize,
125    Deserialize
126)]
127pub struct TaskComm([u8; TASK_COMM_LEN]);
128
129impl TaskComm {
130    /// The name Linux stores from `bytes`: the bytes before the first NUL, at
131    /// most 15 (`strscpy_pad` into `TASK_COMM_LEN`). `PR_SET_NAME` reads at
132    /// most 15 bytes of the caller's string through its NUL
133    /// (`strncpy_from_user(comm, arg2, sizeof(me->comm) - 1)`), and the
134    /// kernel's `comm` file holds the name and a newline.
135    pub fn new(bytes: &[u8]) -> Self {
136        let length = bytes
137            .iter()
138            .take(TASK_COMM_LEN - 1)
139            .position(|byte| *byte == 0)
140            .unwrap_or_else(|| bytes.len().min(TASK_COMM_LEN - 1));
141        let mut name = [0; TASK_COMM_LEN];
142        name[..length].copy_from_slice(&bytes[..length]);
143        Self(name)
144    }
145
146    /// The name an exec of `filename` stores: its last component
147    /// (`kbasename(bprm->filename)`, fs/exec.c:1246 in 6.17), cut as
148    /// [`Self::new`] cuts it. A new image's `AT_EXECFN` points at a copy of
149    /// `bprm->filename` (`create_elf_tables`), so its last component is the
150    /// name the exec gave: the path as given for a direct, symbolic-link or
151    /// script exec. Only `execveat(fd, "", AT_EMPTY_PATH)` is named otherwise
152    /// in Linux 6.14 and later (by the file's dentry, `comm_from_dentry`),
153    /// and the backends that use this record do not support that exec.
154    pub fn of_exec_filename(filename: &[u8]) -> Self {
155        let start = filename
156            .iter()
157            .rposition(|byte| *byte == b'/')
158            .map_or(0, |slash| slash + 1);
159        Self::new(&filename[start..])
160    }
161
162    /// The name as the kernel's `/proc/<pid>/comm` holds it: the bytes before
163    /// its final newline (`comm_show` prints the name and `\n`).
164    pub fn from_comm_file(bytes: &[u8]) -> Self {
165        Self::new(bytes.strip_suffix(b"\n").unwrap_or(bytes))
166    }
167
168    /// The name's bytes, without the terminating NUL.
169    pub fn as_bytes(&self) -> &[u8] {
170        let length = self
171            .0
172            .iter()
173            .position(|byte| *byte == 0)
174            .unwrap_or(TASK_COMM_LEN);
175        &self.0[..length]
176    }
177}

179/// What Detcore's process table says about the task a per-process `stat`
180/// file describes (`Scheduler::task_stat_facts`): the thread below `task/`,
181/// else the task the top-level number names.
182#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Serialize, Deserialize)]
183pub struct TaskStatFacts {
184    /// The task's recorded name, `None` where Detcore recorded none (a task
185    /// of a process that has not exec'd an image Detcore saw).
186    pub comm: Option<TaskComm>,
187    /// The CPUs the task may run on and its home (`Scheduler::task_cpus`),
188    /// which place it on a CPU (`TaskStat::processor`).
189    pub cpus: crate::cpu_set::TaskCpus,
190    /// The task has exited and is not reaped: a zombie, whose state is `Z`.
191    pub exited: bool,
192    /// The task leads its thread group.
193    pub leads: bool,
194    /// The thread group leader's exit signal (`task_struct::exit_signal`), as
195    /// Detcore's wait model keeps it (`ProcessWaitMetadata::exit_signal`).
196    /// A thread that does not lead has -1 (`copy_process` for
197    /// `CLONE_THREAD`, kernel/fork.c:2328), whatever this is.
198    pub process_exit_signal: i32,
199    /// The thread group leader was forked and has not exec'd
200    /// (`ProcessWaitMetadata::forked_without_exec`).
201    pub forked_without_exec: bool,
202    /// The process's group and session, as `getpgid` and `getsid` answer
203    /// (`Scheduler::group_or_session_of`).
204    pub process_group: i32,
205    pub session: i32,
206    /// The tasks Linux counts in the process (`signal_struct::nr_threads`):
207    /// its live threads and its leader until the group is reaped, the tasks
208    /// its `task/` directory lists (`Scheduler::procfs_listing`).
209    pub num_threads: i32,
210    /// The process the task belongs to, by its leader's number; `None` for a
211    /// number no process of the table holds.
212    pub process: Option<i32>,
213    /// The process's parent as the guest sees it (`getppid`'s answer), from
214    /// Detcore's model (`Scheduler::guest_visible_parent`): its real parent's
215    /// process, the namespace's init (1) for an orphan given to it, and for a
216    /// process whose real parent is outside the guest's tree (the run's root,
217    /// and its `CLONE_PARENT` children) the parent its own `getppid` answered
218    /// when it first opened its rendered `stat`
219    /// (`Scheduler::record_external_parent`). `None` before that answer is
220    /// recorded.
221    pub parent: Option<i32>,
222    /// The process's virtual soft `RLIMIT_RSS` (`ThreadTree::rss_limits`),
223    /// `RLIM_INFINITY` unless it set another.
224    pub rsslim: u64,
225}

227/// Where a rendered `stat`'s name (field 2) comes from: decided by the
228/// backend's declared capability, never by which backend it is.
229#[derive(Clone, Copy, Debug, PartialEq, Eq)]
230pub(crate) enum CommSource {
231    /// The kernel beneath's own name (`Detcore::kernel_task_comm`).
232    Kernel,
233    /// Detcore's record of the name (`ThreadTree::task_comms`).
234    Record,
235}
236
237impl CommSource {
238    /// The source for a backend: the kernel's name where its guest threads
239    /// are host tasks the tool can name
240    /// (`procfs_inode::tool_can_name_guest_descriptors`, the capability
241    /// `namespace::guest_task_procfs` tests first, so the one
242    /// `Detcore::exec_image_at` and `mark_past_first_execve`'s `exe` read
243    /// depend on), Detcore's record elsewhere. The other conditions of
244    /// `guest_task_procfs` (an unchanged root, the tool's mount namespace)
245    /// decide whether a path through the guest's working directory or
246    /// descriptor links resolves, not whether a task's name can be read by
247    /// its number; after a guest `chroot` the source stays the kernel, whose
248    /// read succeeds through a tracer's own `/proc`, and where the tool
249    /// shares the guest's root, not at all: the read of `stat` is refused by
250    /// name (`Detcore::kernel_task_comm`).
251    ///
252    /// NOTE: `tool_can_name_guest_descriptors` is today the inverse of
253    /// `provides_process_signal_control`, which only KVM declares, so the
254    /// record is the source exactly where the backend owns signal delivery.
255    /// That capability describes signal ownership, not the absence of a host
256    /// task name: a future backend that owns signals but runs guest threads
257    /// as host tasks would need its own capability here. Writes do not depend
258    /// on this choice: Detcore refuses a write open of every `comm` it
259    /// renders.
260    pub(crate) fn of_backend(tool_can_name_guest_descriptors: bool) -> Self {
261        if tool_can_name_guest_descriptors {
262            Self::Kernel
263        } else {
264            Self::Record
265        }
266    }
267}

269/// The name a rendered `stat` shows, from its `source`: the kernel's name
270/// the tool read (`kernel`, `Err` naming why there is none), or Detcore's
271/// record (`record`). `Err` names why there is none, which the caller turns
272/// into the failure policy's named refusal: a failed kernel read is never
273/// answered with the record, which a host resource (the tool's descriptors)
274/// would then choose, and which can be stale where the kernel is the source.
275pub(crate) fn stat_comm(
276    source: CommSource,
277    kernel: Result<TaskComm, &'static str>,
278    record: Option<TaskComm>,
279) -> Result<TaskComm, &'static str> {
280    match source {
281        CommSource::Kernel => kernel,
282        CommSource::Record => record.ok_or("Detcore recorded no name for the task"),
283    }
284}

286/// Whether Detcore renders the `stat` of the task `facts` describe for a
287/// reader in process `own`, whose name comes from `source`: only the
288/// reader's own process's (package K slice D4c-1), and where the source is
289/// Detcore's record, only once a name is recorded (a process that has not
290/// exec'd an image Detcore saw has none). Another process's file is the
291/// kernel beneath's: the host kernel's on ptrace and DBT, the provider's
292/// EACCES on KVM.
293pub(crate) fn renders_task_stat(facts: &TaskStatFacts, own: i32, source: CommSource) -> bool {
294    facts.process == Some(own) && (source == CommSource::Kernel || facts.comm.is_some())
295}

297/// Whether Detcore renders the `comm` of the task `facts` describe for a
298/// reader in process `own`, whose name comes from `source` (package K slice
299/// A+): only where the source is Detcore's record (the same capability that
300/// chooses `stat`'s name, never a backend's identity), only the reader's own
301/// process's, and only once a name is recorded. Elsewhere the file is the
302/// kernel beneath's: the host kernel's own name on ptrace and DBT, which
303/// Detcore leaves unclassified, and on KVM another process's, or an unnamed
304/// task's, the executor's EACCES.
305pub(crate) fn renders_task_comm(facts: &TaskStatFacts, own: i32, source: CommSource) -> bool {
306    source == CommSource::Record && facts.process == Some(own) && facts.comm.is_some()
307}

309/// A task's `comm` file (fs/proc/base.c:1750-1765 `comm_show` in 6.17): its
310/// name as `proc_task_name(m, p, false)` prints it, raw, through its first

334/// One rendering of a `stat` file, with what its reader adds to the
335/// process table's facts.
336#[derive(Clone, Copy, Debug, PartialEq, Eq)]
337pub(crate) struct TaskStat {
338    /// The number the file's path names its task by: field 1
339    /// (`pid_nr_ns(pid, ns)` of the inode's pid, the thread's number below
340    /// `task/`).
341    pub(crate) pid: i32,
342    /// The task's name: the kernel's, or Detcore's record ([`stat_comm`]).
343    pub(crate) comm: TaskComm,
344    pub(crate) facts: TaskStatFacts,
345    /// The reading thread is the task the file describes, which is running.
346    pub(crate) reader_is_task: bool,
347    /// The process's parent: as `getppid` answers its reader for its own
348    /// process, or for another process's file read by this one,
349    /// [`TaskStatFacts::parent`], numbered as that process's `getppid`
350    /// answers it (`Detcore::getppid_numbered_parent`).
351    pub(crate) ppid: i32,
352    /// The process's `RLIMIT_RSS` soft limit ([`TaskStatFacts::rsslim`]),
353    /// whoever reads it.
354    pub(crate) rsslim: u64,
355    /// The CPU the task runs on, field 39: its place on the run's virtual
356    /// CPUs ([`TaskStatFacts::cpus`], `TaskCpus::current`), 0 on the single
357    /// CPU without `--virtual-cpus`.
358    pub(crate) processor: u32,
359    /// The task's CPU time as of this read, its reader's own process's;
360    /// zero for another process's file, whose accounting Detcore keeps in
361    /// that process's own threads.
362    pub(crate) cpu: TaskCpuTimes,
363}

365/// `stat`'s state letter for a task: `R` for the reader itself, which runs
366/// while it reads; `Z` for a zombie; `S` for every other task. With threads
367/// sequentialized no other task runs while the file is read, and Detcore
368/// does not model a task's kernel wait states (`D`, `t`, `T`): a fixed `S`.
369fn state(stat: &TaskStat) -> char {
370    if stat.facts.exited {
371        'Z'
372    } else if stat.reader_is_task {
373        'R'
374    } else {
375        'S'
376    }
377}

379/// `stat`'s `flags` (field 9): only the bits Detcore models.
380/// `PF_FORKNOEXEC` for a task forked without an exec since (every thread
381/// that does not lead, and a leader by Detcore's wait model), and
382/// `PF_EXITING` for a zombie. Never `PF_RANDOMIZE`: every launcher Hermit
383/// execs a guest through sets `ADDR_NO_RANDOMIZE`, and KVM's loader does not
384/// randomize. Never `PF_SUPERPRIV` or the kernel's other bits, which
385/// describe host privilege use and kernel state.
386fn flags(stat: &TaskStat) -> u64 {
387    let mut flags = 0;
388    if !stat.facts.leads || stat.facts.forked_without_exec {
389        flags |= PF_FORKNOEXEC;
390    }
391    if stat.facts.exited {
392        flags |= PF_EXITING;
393    }
394    flags
395}

397/// A task's `stat` line in Linux's 52 fields (`do_task_stat`,
398/// fs/proc/array.c:467-669 in 6.17), from Detcore's state:
399///
400/// | field | name | value |
401/// | --- | --- | --- |
402/// | 1 | pid | the number the path names the task by |
403/// | 2 | comm | the task's name ([`TaskStat::comm`]), raw bytes, in parentheses |
404/// | 3 | state | `R` for the reader, `Z` for a zombie, else `S` ([`state`]) |
405/// | 4 | ppid | the process's parent |
406/// | 5, 6 | pgrp, session | Detcore's model, as `getpgid` and `getsid` answer |
407/// | 7, 8 | tty_nr, tpgid | 0, -1: no controlling terminal |
408/// | 9 | flags | [`flags`] |
409/// | 14, 15 | utime, stime | the task's user and system time ([`TaskCpuTimes`]), in clock ticks; 0 for another process's file |
410/// | 16, 17 | cutime, cstime | its process's reaped children's, in clock ticks; 0 for another process's file |
411/// | 18, 19 | priority, nice | 20, 0: nice is inert under Detcore |
412/// | 20 | num_threads | the process's tasks |
413/// | 25 | rsslim | the process's `RLIMIT_RSS` soft limit |
414/// | 38 | exit_signal | the leader's, -1 for another thread |
415/// | 39 | processor | the task's virtual CPU, [`TaskStat::processor`] |
416/// | 40, 41 | rt_priority, policy | 0, 0 (`SCHED_OTHER`) |
417/// | 52 | exit_code | 0 |
418///
419/// Every other field is 0: the fault counts (10-13), the guest time (43, 44),
420/// `itrealvalue` (21, always 0 in Linux), the start time (22), the memory
421/// sizes and addresses (23, 24, 26-30, 45-51), the four obsolete signal
422/// words (31-34, which the sanitizer zeroed on every backend before this),
423/// `wchan` (35), `nswap` and `cnswap` (36, 37) and the block-I/O delay
424/// (42). These are the fields `sanitize_stat` zeroed in the kernel's file
425/// before Detcore rendered it, with the last CPU (39), which is 0 on the
426/// single virtual CPU.
427pub(crate) fn render_stat(stat: &TaskStat) -> Vec<u8> {
428    let facts = &stat.facts;
429    let mut line = format!("{} (", stat.pid).into_bytes();
430    line.extend_from_slice(stat.comm.as_bytes());
431    let exit_signal = if facts.leads {
432        facts.process_exit_signal
433    } else {
434        -1
435    };
436    let fields: [String; 50] = [
437        // 3 state
438        state(stat).to_string(),
439        // 4 ppid, 5 pgrp, 6 session, 7 tty_nr, 8 tpgid
440        stat.ppid.to_string(),
441        facts.process_group.to_string(),
442        facts.session.to_string(),
443        "0".to_owned(),
444        "-1".to_owned(),
445        // 9 flags
446        flags(stat).to_string(),
447        // 10 minflt .. 13 cmajflt
448        "0".to_owned(),
449        "0".to_owned(),
450        "0".to_owned(),
451        "0".to_owned(),
452        // 14 utime .. 17 cstime
453        clock_ticks(stat.cpu.user).to_string(),
454        clock_ticks(stat.cpu.system).to_string(),
455        clock_ticks(stat.cpu.children_user).to_string(),
456        clock_ticks(stat.cpu.children_system).to_string(),
457        // 18 priority, 19 nice, 20 num_threads
458        "20".to_owned(),
459        "0".to_owned(),
460        facts.num_threads.to_string(),
461        // 21 itrealvalue, 22 starttime, 23 vsize, 24 rss
462        "0".to_owned(),
463        "0".to_owned(),
464        "0".to_owned(),
465        "0".to_owned(),
466        // 25 rsslim
467        stat.rsslim.to_string(),
468        // 26 startcode .. 37 cnswap
469        "0".to_owned(),
470        "0".to_owned(),
471        "0".to_owned(),
472        "0".to_owned(),
473        "0".to_owned(),
474        "0".to_owned(),
475        "0".to_owned(),
476        "0".to_owned(),
477        "0".to_owned(),
478        "0".to_owned(),
479        "0".to_owned(),
480        "0".to_owned(),
481        // 38 exit_signal, 39 processor, 40 rt_priority, 41 policy
482        exit_signal.to_string(),
483        stat.processor.to_string(),
484        "0".to_owned(),
485        "0".to_owned(),

527    fn fields(line: &[u8]) -> (String, Vec<String>) {
528        let text = String::from_utf8_lossy(line).into_owned();
529        assert!(text.ends_with('\n'), "{text:?}");
530        let open = text.find(" (").unwrap();
531        let close = text.rfind(") ").unwrap();
532        let comm = text[open + 2..close].to_owned();
533        let mut fields = vec![text[..open].to_owned(), format!("({comm})")];
534        fields.extend(text[close + 2..].split_whitespace().map(str::to_owned));
535        (comm, fields)
536    }

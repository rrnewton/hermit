9//! Which rows of the kernel's `/proc/locks` belong to the guest.
10//!
11//! Detcore renders `/proc/locks` from the kernel's file, read through the
12//! guest's own descriptor. In the guest's PID namespace Linux hides every
13//! POSIX, flock and lease row whose owner the namespace cannot see
14//! (`locks_show` drops a row whose `locks_translate_pid` is 0), but it cannot
15//! hide an open file description (OFD) lock: such a lock has no owning task,
16//! and Linux prints it as owner `-1` from every namespace. Any process on the
17//! host that holds an OFD lock, on any file, therefore added rows to the
18//! guest's snapshot, at moments the host decided.
19//!
20//! The guest's own OFD and flock locks belong to its open file descriptions,
21//! not to its tasks, and the kernel lists exactly the locks held through one
22//! description in that description's `/proc/<pid>/fdinfo/<fd>` `lock:` lines,
23//! spelled as `/proc/locks` spells them. After every `F_OFD_SETLK`,
24//! `F_OFD_SETLKW`, `flock` and `pidfd_getfd` call, and for a descriptor
25//! received over `SCM_RIGHTS` that Detcore models, Detcore reads that
26//! descriptor's fdinfo through the recorder ([`held_locks_in_fdinfo`]). Its
27//! global state keeps a [`LockLedger`]: which locks each such description
28//! holds and which guest descriptor tables reference it, with a slot count
29//! per table, kept as Linux keeps the references (close, replacement, fork,
30//! `CLONE_FILES`, a successful exec, exit). A description's locks are the
31//! guest's while some table it knows references it. If the fdinfo cannot be
32//! opened or read (a full descriptor table, no `/proc` in a chroot, a seccomp
33//! filter), the description's locks are unknown rather than taken to be none:
34//! the call itself goes on as Linux runs it, and a `/proc/locks` read made
35//! while a guest table still references that description stops the run by
36//! name ([`LockLedger::unknown`]), since its rows could not be told from a
37//! host's. A run that never reads `/proc/locks` is not stopped.
38//!
39//! Before the snapshot's identities are numbered, Detcore keeps only the
40//! groups of rows the guest owns ([`guest_lock_rows`]). A group is a granted
41//! lock and the waiters queued behind it, which share one sequence number. A
42//! group stays when its granted row stays:
43//! - an OFD row whose class, mode, access, object and range are, field for
44//!   field, a lock a guest description some guest table references holds, at
45//!   most one row per distinct such lock. An OFD row has no owning task (owner
46//!   `-1` from every namespace), so this field match is the only way to tell
47//!   the guest's from a host's;
48//! - a row owned by a positive pid that names a process of the guest, as the
49//!   container's `/proc` lists it (a live process, or a zombie until it is
50//!   reaped), translated from the kernel's numbering where a backend's differs
51//!   (`Scheduler::procfs_ids`). This is the ONLY rule that keeps a POSIX or a
52//!   flock row: Linux prints a flock row with the pid of the process that took
53//!   it, so a flock row is kept when that pid is a guest process's. This is
54//!   guest-pid membership, not proof of identity: a pid says who holds that
55//!   number now, not who took the lock (see the host-row cases below). A
56//!   field match against a description's recorded flock is not
57//!   used: that record can go stale where Detcore does not see the unlock (a
58//!   copied DBT `vfork` child runs `LOCK_UN` natively), and a stale record
59//!   would admit a host process's identical flock where the guest's procfs is
60//!   not namespace-private (`--no-namespace`). This also hides another
61//!   process's POSIX and flock rows there;
62//! - TEMPORARY EXEMPTION, for KVM only in practice: a row whose object is on
63//!   device `00:00`. KVM keeps a backend-local copy of `/proc/locks`, built
64//!   from the supervisor's fdinfo `lock:` lines for the guest's own files, and
65//!   prints every row there as `00:00:N` with owner `-1`, so no guest
66//!   description's lock line (which names the real device) matches it, and
67//!   this filter would otherwise drop all of them. Linux itself never prints
68//!   `00:00` for a lockable object (an anonymous device's minor starts at 1),
69//!   so no kernel row is kept by this rule. This is not Linux behaviour being
70//!   modelled: it is an exemption for one backend's local file, to be removed
71//!   when package K replaces KVM's local `/proc/locks` with Detcore's own
72//!   rendering (slice K8).
73//!
74//! Within a group that stays, a waiter row stays only when a guest process
75//! owns it. A group whose granted row goes, goes whole, as Linux drops a whole
76//! group whose granted row's owner it cannot see.
77//!
78//! What still differs from Linux, named rather than hidden. Three cases can
79//! show a host row (the first, and the two pid-identity cases right after
80//! it); every other case hides a row of the guest's own, and none shows a
81//! host row:
82//! - a host OFD lock whose row is, field for field, an OFD lock a guest
83//!   description holds now (in practice a shared read lock on the same range
84//!   of the same file, or a file in another btrfs subvolume, whose rows print
85//!   the one superblock device, with the same inode number, range and access)
86//!   takes the place of the guest's row, at most once per distinct such lock:
87//!   the row shown is the same either way;
88//! - a host flock whose taker has exited, its description kept by another
89//!   host process, prints the taker's freed pid under `--no-namespace`; when
90//!   that number is later given to a guest process, the row is kept as the
91//!   guest's. When the timing of that reuse is the host's, so is the row;
92//! - on DBT, when a guest process is killed from outside and reaped
93//!   automatically before Detcore retires its pid, a host process can take
94//!   that number while it is still in Detcore's list of guest processes, and
95//!   that host process's POSIX or flock rows are kept until it is retired;
96//! - two guest descriptions holding identical shared read OFD locks (same
97//!   file, range and access) show one row, where Linux shows two;
98//! - the guest's own OFD waiter rows (`->` with owner -1) are not shown:
99//!   fdinfo lists no waiters, so Detcore cannot tell them from a host's;
100//! - an OFD lock the guest's descriptions held before Detcore read it is not
101//!   shown until a call through a modelled descriptor of it: a description
102//!   inherited already locked at the start; one received over `SCM_RIGHTS`
103//!   where Detcore keeps no model of the receiver's descriptor (ptrace), once
104//!   the sender's tables let go of it; one received through `recvmmsg`; one an
105//!   in-guest backend's exec rebuilds under a new identity;
106//! - a flock whose taker is not a guest process, while a guest description
107//!   holds it: a taker that has exited (its descriptor was inherited), or one
108//!   outside the guest from the start (a launcher that took the flock and
109//!   handed the guest that description). Linux keeps the original taker's
110//!   pid in the row, even after the guest itself takes the same mode on the
111//!   description (a same-mode flock changes nothing), so the row names no
112//!   guest process and is hidden, whatever call the guest makes. Inside a
113//!   PID namespace Linux hides such a row itself (the taker is outside the
114//!   namespace, or reaped), so the visible difference is only under
115//!   `--no-namespace`; a zombie taker, which the guest's `/proc` still lists,
116//!   stays shown;
117//! - fork before lock, for OFD locks: a table that referenced a description
118//!   before Detcore first read its locks (the parent of a child that then
119//!   locks it) is not followed, so once the tables Detcore did see let go of
120//!   it (the child exits), its lock is hidden though Linux keeps it. A flock
121//!   taken that way is shown while its taker lives, by its pid; after the
122//!   taker is reaped, Linux hides it too under a PID namespace;
123//! - a process whose descriptor table the ledger cannot follow contributes no
124//!   lock while it lives, nor does a process forked from it: one sharing its
125//!   table with another process (`CLONE_FILES` without `CLONE_THREAD`, whose
126//!   slots in-guest backends also count in separate per-process copies), and
127//!   one with a thread that has a private table (`CLONE_THREAD` without
128//!   `CLONE_FILES`), whose calls the ledger cannot tell from the leader's;
129//! - once a lock or unlock goes through a descriptor whose description the
130//!   ledger may know under another identity (one Detcore keeps no model of,
131//!   such as a descriptor received over `SCM_RIGHTS` on ptrace, or one an
132//!   in-guest backend registered on reception), no lock on that inode number,
133//!   on any device, is shown again; if that descriptor's fdinfo cannot be
134//!   read, no OFD or flock lock is shown again;
135//! - a lease set by a process that was then reaped, under `--no-namespace`,
136//!   is not shown; leases are kept by their owner's pid only;
137//! - the guest's own `F_GETLK`, `F_OFD_GETLK` and conflicting lock calls still
138//!   see host locks on files it shares with the host: this filter changes only
139//!   what `/proc/locks` shows.
140//!
141//! Remaining ways a host row can still appear, until `/proc/locks` is decided
142//! from the kernel's state at the snapshot: a description an in-guest
143//! backend's exec rebuilds under a new identity, whose lock changes through
144//! the new identity leave the old one's entry stale in a table forked before
145//! the exec; and an OFD lock change the guest makes without Detcore seeing the
146//! call at all. DBT refuses the one known case, a copied `vfork` child's
147//! `F_OFD_SETLK`/`F_OFD_SETLKW`, at the call, and also refuses the `vfork`
148//! up front while the parent's own descriptions may hold an OFD lock. A
149//! flock change Detcore does not see (a copied child's native `LOCK_UN` or
150//! `LOCK_NB`) can leave a description's recorded flock stale, but that record
151//! admits no row: flock rows are kept by their taker's pid.

162/// One row of `/proc/locks`, split into fields:
163///     `SEQ: [->] CLASS MODE RW PID MAJOR:MINOR:INODE START END`
164#[derive(Clone)]
165pub(super) struct LockLine {
166    pub(super) sequence: String,
167    pub(super) waiter: bool,
168    pub(super) fields: Vec<String>,
169    pub(super) owner_index: usize,
170    pub(super) object_index: usize,
171}
172
173/// `line` as a `/proc/locks` row, or `None` when it is not one. The owner is
174/// a signed integer and the object has three `:`-separated parts.
175pub(super) fn parse_line(line: &str) -> Option<LockLine> {
176    let fields = line
177        .split_whitespace()
178        .map(str::to_owned)
179        .collect::<Vec<_>>();
180    let waiter = fields.get(1).is_some_and(|field| field == "->");
181    let details = usize::from(waiter) + 1;
182    let owner_index = details + 3;
183    let object_index = details + 4;
184    let sequence = fields
185        .first()
186        .and_then(|field| field.strip_suffix(':'))
187        .filter(|field| !field.is_empty() && field.bytes().all(|byte| byte.is_ascii_digit()))?
188        .to_owned();
189    if fields.len() != details + 7
190        || fields[owner_index].parse::<i64>().is_err()
191        || fields[object_index].split(':').count() != 3
192    {
193        return None;
194    }
195    Some(LockLine {
196        sequence,
197        waiter,
198        fields,
199        owner_index,
200        object_index,
201    })
202}

204/// One granted lock as `/proc/locks` and fdinfo spell it, its owner aside:
205/// class (`OFDLCK`, `FLOCK`, `POSIX`, ...), mode (`ADVISORY`), access
206/// (`READ`, `WRITE`), object (`MAJOR:MINOR:INODE`, hexadecimal device numbers
207/// and a decimal inode, `%02x:%02x:%lu`) and range.
208#[derive(Clone, Debug, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
209pub struct HeldLock {
210    /// The lock's class.
211    pub class: String,
212    /// The lock's mode.
213    pub mode: String,
214    /// The lock's access.
215    pub access: String,
216    /// The locked object, as the kernel prints it.
217    pub object: String,
218    /// The range's first byte.
219    pub start: String,
220    /// The range's last byte, or `EOF`.
221    pub end: String,
222}
223
224impl HeldLock {
225    fn from_line(row: &LockLine) -> Self {
226        let first = usize::from(row.waiter) + 1;
227        let field = |index: usize| row.fields[index].clone();
228        Self {
229            class: field(first),
230            mode: field(first + 1),
231            access: field(first + 2),
232            object: field(row.object_index),
233            start: field(row.object_index + 1),
234            end: field(row.object_index + 2),
235        }
236    }
237
238    /// Whether the object is on device `00:00`: the temporary KVM exemption
239    /// (see the module comment), removed when package K slice K8 replaces
240    /// KVM's local `/proc/locks`. Linux never prints that device for a
241    /// lockable object.
242    fn on_null_device(&self) -> bool {
243        let mut parts = self.object.split(':');
244        let number = |part: Option<&str>| part.and_then(|part| u32::from_str_radix(part, 16).ok());
245        number(parts.next()) == Some(0) && number(parts.next()) == Some(0)
246    }
247
248    /// Whether Linux ties this lock to an open file description rather than
249    /// to a task: an OFD lock or a flock.
250    fn belongs_to_a_description(&self) -> bool {
251        self.class == "OFDLCK" || self.is_flock()
252    }
253
254    /// Whether this is a flock, which Linux prints with its taker's pid.
255    fn is_flock(&self) -> bool {
256        self.class == "FLOCK"
257    }
258
259    /// Whether a row of this lock is kept by matching it, field for field,
260    /// against a lock a guest description holds: an OFD lock only, whose row
261    /// has no owner to decide by. A flock row is kept only by its taker's pid
262    /// (see the module comment).
263    fn kept_by_field_match(&self) -> bool {
264        self.belongs_to_a_description() && !self.is_flock()
265    }
266}

268/// The fields of one `/proc/locks` row that decide whether the guest owns it.
269#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
270pub struct LockRowFacts {
271    /// The group's sequence number, which a granted lock and its waiters share.
272    pub sequence: String,
273    /// Whether this is a waiter (`->`) row.
274    pub waiter: bool,
275    /// The owner field: a pid, `-1` for an OFD lock, `0` for a task the
276    /// reader's PID namespace cannot see, or a remote lock's own value.
277    pub owner: i64,
278    /// The lock, its owner aside.
279    pub lock: HeldLock,
280}

282/// The facts of every row of `contents`, in row order, or `None` when any row
283/// is not a `/proc/locks` row (the sanitizer then refuses the whole snapshot).
284pub(crate) fn lock_rows(contents: &[u8]) -> Option<Vec<LockRowFacts>> {
285    let text = std::str::from_utf8(contents).ok()?;
286    text.lines()
287        .map(|line| {
288            let row = parse_line(line)?;
289            Some(LockRowFacts {
290                owner: row.fields[row.owner_index].parse().ok()?,
291                lock: HeldLock::from_line(&row),
292                sequence: row.sequence,
293                waiter: row.waiter,
294            })
295        })
296        .collect()
297}

299/// The OFD and flock locks a description holds, from its
300/// `/proc/<pid>/fdinfo/<fd>` text: its `lock:` lines, which the kernel spells
301/// as `/proc/locks` rows. Lines of other classes (a POSIX lock this process
302/// took on the same file) and lines that do not parse are left out.
303pub(crate) fn held_locks_in_fdinfo(contents: &[u8]) -> Vec<HeldLock> {
304    let text = String::from_utf8_lossy(contents);
305    text.lines()
306        .filter_map(|line| line.strip_prefix("lock:"))
307        .filter_map(|row| parse_line(row.trim()))
308        .filter(|row| !row.waiter)
309        .map(|row| HeldLock::from_line(&row))
310        .filter(HeldLock::belongs_to_a_description)
311        .collect()
312}

314/// Which of `rows` the guest owns (see the module comment). `held` is every
315/// lock a guest description some guest table references holds; each distinct
316/// lock admits at most one row, so a lock listed by two descriptions the
317/// ledger cannot tell are one (an in-guest backend's receiver registers a
318/// description it received under an identity of its own) admits no host row
319/// beside the guest's. `guest_process` answers for a positive owner.
320pub(crate) fn guest_lock_rows(
321    rows: &[LockRowFacts],
322    mut guest_process: impl FnMut(i64) -> bool,
323    held: &[HeldLock],
324) -> Vec<bool> {
325    let mut unclaimed: BTreeMap<&HeldLock, usize> = BTreeMap::new();
326    for lock in held {
327        unclaimed.insert(lock, 1);
328    }
329    // A granted row a guest process owns is the guest's whatever it matches,
330    // and it claims its match first, so that a row another owner holds with
331    // the same fields cannot claim it too. Only an OFD lock is kept by field
332    // match, and an OFD row has no owner, so in practice this claims nothing;
333    // it keeps the rule whole should another field-matched class appear.
334    let owned = rows
335        .iter()
336        .map(|row| !row.waiter && row.owner > 0 && guest_process(row.owner))
337        .collect::<Vec<_>>();
338    for (row, owned) in rows.iter().zip(&owned) {
339        if *owned
340            && row.lock.kept_by_field_match()
341            && let Some(count) = unclaimed.get_mut(&row.lock)
342        {
343            *count = count.saturating_sub(1);
344        }
345    }
346    let mut kept_groups = BTreeSet::new();
347    let mut keep = vec![false; rows.len()];
348    for (index, row) in rows.iter().enumerate() {
349        if row.waiter {
350            continue;
351        }
352        // TEMPORARY EXEMPTION for KVM's backend-local `/proc/locks`
353        // (`HeldLock::on_null_device`); removed with package K slice K8.
354        keep[index] = row.lock.on_null_device()
355            || owned[index]
356            || (row.lock.kept_by_field_match()
357                && unclaimed.get_mut(&row.lock).is_some_and(|count| {
358                    let available = *count > 0;
359                    *count = count.saturating_sub(1);
360                    available
361                }));
362        if keep[index] {
363            kept_groups.insert(row.sequence.as_str());
364        }
365    }
366    for (index, row) in rows.iter().enumerate() {
367        if row.waiter {
368            keep[index] = kept_groups.contains(row.sequence.as_str())
369                && (row.lock.on_null_device() || (row.owner > 0 && guest_process(row.owner)));
370        }
371    }
372    keep
373}

375/// A descriptor table, as the ledger names it: a token it hands out, not the
376/// kernel's `files_struct` or Detcore's local `FilesId`, so that nothing in
377/// the ledger depends on a guest process computing a table's identity the
378/// same way the global state does.
379type Table = u64;
380
381/// Which guest descriptor tables reference each open file description whose
382/// OFD or flock locks Detcore has read, and which locks it holds
383/// (`GlobalState::lock_ledger`).
384///
385/// A description's locks count for `/proc/locks` only while some table
386/// references it. Every change comes from the guest's own turns:
387/// - a call through a descriptor that reads its fdinfo
388///   ([`LockLedger::note_locks`]) records the description's locks and how many
389///   slots of the caller's table name it;
390/// - a close, `dup2`/`dup3` over a slot or `close_range` of a description
391///   Detcore has read the locks of reports how many slots of that table still
392///   name it ([`LockLedger::release`]);
393/// - a fork copies the parent's table, and `CLONE_FILES` shares it
394///   ([`LockLedger::fork`]);
395/// - a successful exec leaves the process's table ([`LockLedger::exec`]) and
396///   then names the descriptions that survived it ([`LockLedger::exec_kept`]);
397///   a failed exec changes nothing;
398/// - a table any of whose processes has exited, reaped or not, is dropped
399///   ([`LockLedger::prune`]).
400///
401/// A description whose fdinfo could not be read is followed the same way,
402/// with its locks unknown ([`LockLedger::note_unknown`]) until a later read
403/// succeeds or no table references it.
404///
405/// Where it cannot follow a reference exactly, the ledger forgets it, which
406/// hides the guest's own row; it never keeps one it has not seen, which would
407/// show a host's.
408#[derive(Debug, Default)]
409pub(crate) struct LockLedger {
410    next_table: Table,
411    process_table: BTreeMap<DetPid, Table>,
412    owners: BTreeMap<Table, BTreeSet<DetPid>>,
413    references: BTreeMap<OpenFileId, BTreeMap<Table, u32>>,
414    locks: BTreeMap<OpenFileId, DescriptionLocks>,
415    after_exec: BTreeMap<DetPid, BTreeMap<OpenFileId, DescriptionLocks>>,
416    /// Processes whose descriptor table the ledger cannot follow
417    /// ([`LockLedger::mark_opaque`]): a description any of their tables
418    /// references contributes no lock.
419    opaque: BTreeSet<DetPid>,
420    /// Inode numbers, as `/proc/locks` prints them, on which no lock counts
421    /// ([`LockLedger::alias_inode`]).
422    aliased_inodes: BTreeSet<String>,
423    /// No lock counts at all ([`LockLedger::alias_inode`] without an inode).
424    aliased_everything: bool,
425    /// Why no `/proc/locks` snapshot can be decided for the rest of the run
426    /// ([`LockLedger::refuse`]): set once, never cleared.
427    refused: Option<String>,
428}

430/// The locks a description holds, as its fdinfo last showed them, or why
431/// that fdinfo could not be read.
432type DescriptionLocks = Result<Vec<HeldLock>, String>;
433
434impl LockLedger {
435    /// The table `process` uses, made for it if it has none yet.
436    fn table_of(&mut self, process: DetPid) -> Table {
437        if let Some(table) = self.process_table.get(&process) {
438            return *table;
439        }
440        let table = self.next_table;
441        self.next_table += 1;
442        self.process_table.insert(process, table);
443        self.owners.entry(table).or_default().insert(process);
444        table
445    }
446
447    fn set_references(&mut self, open_file: OpenFileId, table: Table, slots: u32) {
448        let references = self.references.entry(open_file).or_default();
449        if slots == 0 {
450            references.remove(&table);
451        } else {
452            references.insert(table, slots);
453        }
454        if references.is_empty() {
455            self.references.remove(&open_file);
456            self.locks.remove(&open_file);
457        }
458    }
459
460    /// `open_file` holds `locks` (perhaps none), as its fdinfo showed them
461    /// after a call through a descriptor of `process`'s table, `slots` of
462    /// which name it.
463    pub(crate) fn note_locks(
464        &mut self,
465        process: DetPid,
466        open_file: OpenFileId,
467        locks: Vec<HeldLock>,
468        slots: u32,
469    ) {
470        self.note(process, open_file, Ok(locks), slots);
471    }
472
473    /// As [`Self::note_locks`], for a description whose fdinfo could not be
474    /// read, for `reason`: which locks it holds is unknown.
475    pub(crate) fn note_unknown(
476        &mut self,
477        process: DetPid,
478        open_file: OpenFileId,
479        reason: String,
480        slots: u32,
481    ) {
482        self.note(process, open_file, Err(reason), slots);
483    }
484
485    fn note(
486        &mut self,
487        process: DetPid,
488        open_file: OpenFileId,
489        locks: DescriptionLocks,
490        slots: u32,
491    ) {
492        let table = self.table_of(process);
493        self.set_references(open_file, table, slots);
494        if self.references.contains_key(&open_file) {
495            self.locks.insert(open_file, locks);
496        }
497    }
498
499    /// `remaining` slots of `process`'s table name `open_file` after a close
500    /// or replacement there. A table the ledger has no record of has no
501    /// reference to drop.
502    pub(crate) fn release(&mut self, process: DetPid, open_file: OpenFileId, remaining: u32) {
503        if let Some(table) = self.process_table.get(&process).copied() {
504            self.set_references(open_file, table, remaining);
505        }
506    }
507
508    /// A new process `child` starts with a copy of `parent`'s table, or,
509    /// with `shares_table` (`CLONE_FILES`), with that table itself. Whatever an
510    /// earlier process with the same number left is not the child's.
511    ///
512    /// A table two processes share is one the ledger cannot follow (in-guest
513    /// backends count its slots in separate per-process copies), so both
514    /// become opaque, as does a child of an opaque process, whose copy may
515    /// hold the wrong slots ([`Self::mark_opaque`]).
516    pub(crate) fn fork(&mut self, parent: DetPid, child: DetPid, shares_table: bool) {
517        self.forget_process(child);
518        self.after_exec.remove(&child);
519        self.opaque.remove(&child);
520        if shares_table {
521            self.opaque.insert(parent);

527            return;
528        };

531            self.process_table.insert(child, table);
532            return;

535        for references in self.references.values_mut() {
536            if let Some(slots) = references.get(&table).copied() {
537                references.insert(copy, slots);
538            }
539        }

542    /// `process` completed an exec: it leaves its table (Linux unshares it
543    /// and closes its close-on-exec slots), and only the descriptions
544    /// [`Self::exec_kept`] names next remain referenced through it.
545    pub(crate) fn exec(&mut self, process: DetPid) {
546        let mut kept = BTreeMap::new();
547        if let Some(table) = self.process_table.get(&process).copied() {
548            for (open_file, references) in &self.references {
549                if references.contains_key(&table)
550                    && let Some(locks) = self.locks.get(open_file)
551                {
552                    kept.insert(*open_file, locks.clone());
553                }
554            }
555        }
556        self.forget_process(process);
557        self.after_exec.insert(process, kept);
558    }

561    /// after the exec [`Self::exec`] recorded, with their slot counts.
562    pub(crate) fn exec_kept(&mut self, process: DetPid, surviving: &[(OpenFileId, u32)]) {
563        let kept = self.after_exec.remove(&process).unwrap_or_default();
564        for (open_file, slots) in surviving {
565            let Some(locks) = self
566                .locks
567                .get(open_file)
568                .or_else(|| kept.get(open_file))
569                .cloned()
570            else {
571                continue;
572            };
573            let table = self.table_of(process);
574            self.set_references(*open_file, table, *slots);
575            if self.references.contains_key(open_file) {
576                self.locks.insert(*open_file, locks);
577            }
578        }

582    /// exited, reaped or not; a process blocked in a call is alive). A
583    /// table processes share (`CLONE_FILES`) goes when the first of them
584    /// exits, which can only hide a row the survivors still hold.
585    pub(crate) fn prune(&mut self, mut alive: impl FnMut(DetPid) -> bool) {
586        self.opaque.retain(|process| alive(*process));
587        let gone = self
588            .owners
589            .iter()
590            .filter(|(_, owners)| owners.iter().any(|process| !alive(*process)))
591            .map(|(table, _)| *table)
592            .collect::<Vec<_>>();
593        for table in gone {
594            self.drop_table(table);
595        }
596        let processes = self.after_exec.keys().copied().collect::<Vec<_>>();
597        for process in processes {
598            if !alive(process) {
599                self.after_exec.remove(&process);
600            }
601        }

605        let Some(table) = self.process_table.remove(&process) else {
606            return;
607        };
608        let empty = self.owners.get_mut(&table).is_none_or(|owners| {
609            owners.remove(&process);
610            owners.is_empty()
611        });
612        if empty {

714/// The smallest buffer a kernel `seq_file` such as `/proc/locks` fills in one
715/// `read`: one page (`seq_read_iter` starts with `PAGE_SIZE` and only grows).
716/// 4096 is the smallest page Linux uses, so a larger one only makes the rule
717/// in [`locks_capture_without_repeats`] keep more.
718const SEQ_FILE_MIN_BUFFER_BYTES: usize = 4096;
719
720/// A `/proc/locks` capture, `contents`, without the records that the kernel
721/// printed again after the end of its list, given the lengths of the
722/// capture's nonzero reads, in order, each through a buffer of `chunk` bytes,
723/// and the read that returned 0 after them.
724///
725/// After the first read whose length shows it reached the end of the
726/// kernel's list in its own walk, each record a later read returned is
727/// dropped, its waiter lines with it, when its granted lock is a lock already
728/// in the capture ([`lock_identity`]). Every other record is kept, where it
729/// came. When no read passes the length test, or the bytes after it are not
730/// whole records, the capture is returned as the kernel gave it.
731///
732/// Why repeats appear. Each `read` of a `seq_file` restarts the walk of the
733/// kernel's global lock list at the index where the last one stopped
734/// (`start(m->index)`). The list is a list per CPU, walked in CPU order, each
735/// newest lock first. When the host adds locks ahead of that index between
736/// two reads, the restarted walk prints the records that slid past it: the
737/// last records the previous read returned, renumbered, and any added lock
738/// that landed between the index and them (a lock added on the same CPU as
739/// the guest's, ahead of the guest's own rows). The added locks are real and
740/// stay; the repeats go. A repeat need not be byte for byte the record it
741/// repeats: between the reads the host can queue a waiter behind the lock or
742/// give one up, a lease can start breaking, and a waiter's owner can leave
743/// the reader's view. None of that moves the list's index, and it is still
744/// the one lock, so a repeat is recognized by its granted lock alone, and
745/// the earlier record, which one walk printed, is the one kept.
746///
747/// The length test. One read stops before the end of the list only when the
748/// caller's buffer is full (it returns `chunk` bytes) or when the next record
749/// does not fit in the kernel's buffer of at least
750/// [`SEQ_FILE_MIN_BUFFER_BYTES`]. A record is a granted lock and every waiter
751/// queued behind it, so it has no fixed bound; but that record is the first
752/// thing the next read prints, so while the list stays still, the reads after
753/// a read of `n < chunk` bytes that stopped there return at least
754/// `SEQ_FILE_MIN_BUFFER_BYTES - n` bytes.
755///
756/// Why the length test alone is not enough. The list does not stay still: the
757/// record that stopped a read can lose its waiters or go between the reads,
758/// and a removal ahead of the index moves the walk. The next read then
759/// returns records nobody has read yet, few enough bytes to pass the length
760/// test. So only repeats are dropped.
761///
762/// What this can still get wrong, named. A later record whose granted lock
763/// prints the same identity as a lock already captured, and which is
764/// genuinely another lock, is dropped, whenever the bytes after the end are
765/// shorter than the length test allows: either the list changed between the
766/// reads in a way the length test cannot see and the record was never read,
767/// or the host added it. Identical identities of distinct locks exist
768/// natively, per class:
769/// - POSIX: one owner's locks on two files in two btrfs subvolumes with the
770///   same inode number (every subvolume prints its one superblock device);
771///   two descriptor tables of one thread group (identical shared locks);
772/// - FLOCK: two descriptions under one pid holding identical shared flocks,
773///   and the btrfs case;
774/// - OFD: two descriptions holding identical shared ranges (the guest filter
775///   already shows such a lock once), and the btrfs case;
776/// - LEASE and DELEG: two descriptions under one pid holding identical
777///   leases, and the btrfs case.
778///
779/// The snapshot then shows one of two identical rows. A record added by the
780/// host that matches a guest lock is the host's, and the guest filter would
781/// keep at most one row for it anyway. Content the kernel returns over
782/// several reads stays exposed to the host's changes at every boundary before
783/// the last, and duplicates are kept whenever no read passes the length test.
784///
785/// Matching only the records that could have slid past the index (the last
786/// few of the capture) would narrow the residual, but it is not provably
787/// enough: a removal between the reads can drop one of those records and let
788/// an earlier one slide in, so the whole capture is searched.
789pub(crate) fn locks_capture_without_repeats(
790    contents: &[u8],
791    reads: &[usize],
792    chunk: usize,
793) -> Vec<u8> {
794    if reads.iter().sum::<usize>() != contents.len() {
795        return contents.to_vec();
796    }
797    let mut later = contents.len();
798    let mut end = 0;
799    for &read in reads {
800        end += read;
801        later -= read;
802        if later > 0 && read < chunk && read + later < SEQ_FILE_MIN_BUFFER_BYTES {
803            return without_repeats(contents, end).unwrap_or_else(|| contents.to_vec());
804        }
805    }
806    contents.to_vec()
807}

809/// `contents` with each record past `end` dropped whose granted lock is one
810/// an earlier record holds; `None` when the bytes are not whole records.
811fn without_repeats(contents: &[u8], end: usize) -> Option<Vec<u8>> {
812    let mut seen = lock_records(&contents[..end])?
813        .into_iter()
814        .map(|(identity, _)| identity)
815        .collect::<BTreeSet<_>>();
816    let mut out = contents[..end].to_vec();
817    for (identity, bytes) in lock_records(&contents[end..])? {
818        if seen.insert(identity) {
819            out.extend_from_slice(bytes.as_bytes());
820        }
821    }
822    Some(out)
823}

825/// `contents` as whole `/proc/locks` records, each a granted lock's line and
826/// the lines of the waiters queued behind it: the identity of the record's
827/// granted lock ([`lock_identity`]) and the record's bytes. A waiter's line is
828/// `SEQ: -> ...`, indented between the colon and the arrow by its depth in the
829/// waiter tree (`lock_get_status`). `None` when the bytes are not whole lines
830/// that each begin with a sequence number, or begin with a waiter.
831fn lock_records(contents: &[u8]) -> Option<Vec<(Vec<String>, &str)>> {
832    let text = std::str::from_utf8(contents).ok()?;
833    if !text.is_empty() && !text.ends_with('\n') {
834        return None;
835    }
836    let mut records: Vec<(Vec<String>, std::ops::Range<usize>)> = Vec::new();
837    let mut offset = 0;
838    for line in text.split_inclusive('\n') {
839        let (sequence, rest) = line.split_once(':')?;
840        if sequence.is_empty() || !sequence.bytes().all(|byte| byte.is_ascii_digit()) {
841            return None;
842        }
843        let span = offset..offset + line.len();
844        offset = span.end;
845        if rest.trim_start().starts_with("->") {
846            records.last_mut()?.1.end = span.end;
847        } else {
848            records.push((lock_identity(rest), span));
849        }
850    }
851    Some(
852        records
853            .into_iter()
854            .map(|(identity, bytes)| (identity, &text[bytes]))
855            .collect(),
856    )
857}

859/// The fields of a granted lock's `/proc/locks` line, its `SEQ:` removed,
860/// that stay the same while it is the one lock: every field
861/// (`CLASS MODE ACCESS PID MAJOR:MINOR:INODE START END`) for POSIX, OFD,
862/// FLOCK and the rest; for a lease or delegation (`LEASE`/`DELEG`), all but
863/// its state (`ACTIVE`, `BREAKING`, `BREAKER`) and its access, which a break
864/// changes to the type it is breaking to (`target_leasetype`).
865fn lock_identity(line: &str) -> Vec<String> {
866    let mut fields = line
867        .split_whitespace()
868        .map(str::to_owned)
869        .collect::<Vec<_>>();
870    if matches!(fields.first().map(String::as_str), Some("LEASE" | "DELEG")) && fields.len() > 3 {
871        fields.drain(1..3);
872    }
873    fields
874}

876/// The rows of `contents` that `kept` keeps, in order. With no decision (a
877/// snapshot whose rows do not parse, which the sanitizer refuses anyway, or a
878/// caller that made none) every row is kept. A decision for a different
879/// number of rows keeps none.
880pub(crate) fn keep_lock_rows(contents: &[u8], kept: Option<&[bool]>) -> Vec<u8> {
881    let Some(kept) = kept else {
882        return contents.to_vec();
883    };
884    let Ok(text) = std::str::from_utf8(contents) else {
885        return Vec::new();
886    };
887    let lines = text.lines().collect::<Vec<_>>();
888    if lines.len() != kept.len() {
889        return Vec::new();
890    }
891    let mut out = Vec::new();
892    for (line, keep) in lines.into_iter().zip(kept) {
893        if *keep {
894            out.extend_from_slice(line.as_bytes());
895            out.push(b'\n');
896        }
897    }
898    if !text.ends_with('\n') && !out.is_empty() {
899        out.pop();
900    }
901    out
902}

1515        // A read that filled the caller's buffer may have stopped anywhere.
1516        let contents = format!("{GUEST}{REPEAT}");
1517        assert_eq!(
1518            capture(&contents, &[GUEST.len(), REPEAT.len()], GUEST.len()),
1519            contents
1520        );
1521        // A host list over several pages, each read stopping at a page, whose
1522        // last read reached the end, followed by a repeat of its last row.
1523        let (one, two) = (filler(1, 81), filler(82, 81));
1524        let three = format!("{}{GUEST}", filler(163, 70));
1525        let all = format!("{one}{two}{three}");
1526        assert_eq!(kept(&[&one, &two, &three, REPEAT]), all);
1527        assert_eq!(kept(&[&one, &two, &three]), all);
1528        // A burst of additions too large for the length test, in one closing
1529        // read with the repeat: all kept.
1530        let burst = format!("{}{REPEAT}", filler(400, 80));
1531        assert_eq!(kept(&[GUEST, &burst]), format!("{GUEST}{burst}"));
1532        // Lengths that disagree with the bytes decide nothing.
1533        assert_eq!(capture(&contents, &[GUEST.len()], CHUNK), contents);
1534        // Bytes that are not whole lock rows are never dropped.
1535        assert_eq!(kept(&[GUEST, "garbage\n"]), format!("{GUEST}garbage\n"));
1536        let unterminated = REPEAT.trim_end();
1537        assert_eq!(
1538            kept(&[GUEST, unterminated]),
1539            format!("{GUEST}{unterminated}")
1540        );
1541    }

81/*
82NOTE [Blocking Syscalls via Internal Polling]
83---------------------------------------------
84
85A system like hermit which sequentializes execution must have the ability to detect
86blocking operations, so as not to deadlock the system. (This remains true irrespective of
87whether sequentialization is relaxed to admit some parallelism.)
88
89One option is for hermit to *precisely* model everything that may cause a syscall to
90block, and run the syscall only when it is certain that it can complete.  This is the
91approach with the precise implementation of futexes, for example, but it is tricky in
92general and requires hermit recapitulate a lot of the logic in the Linux kernel.
93
94Hence the need for this quick-and-dirty alternative of polling for internal blocking
95operations. The idea is that many potentially-blocking syscalls have the option to be run
96in a non-blocking fashion. This concept is captured by the `NonBlockableSyscall` trait.
97
98The way the polling strategy works is that the handler inside the guest converts the
99syscall to its nonblocking form (or ensures it runs nonblocking via file descriptor
100configuration).  The handler executes the syscall in a loop, while increasing the
101`poll_attempt` to make it visible to the scheduler that these are retries of a [logically]
102blocking operation, rather than new operations.
103
104The scheduler can then interleave these polling operations into the deterministic
105linearization of all guest side effects, just like any other operations.  However, it is a
106good idea to have some form of "backoff" when polling, because this strategy can
107asymptotically increase the total number of syscalls performed. For example, there are a
108large number of threads polling, and one thread productively running, we don't want to
109poll every thread once for every step of productive work. Conversely, we want to guarantee
110that no poller is starved indefinitely, because that could lead to live lock in the
111presence of any kind of "busy waiting".
112
113Determinism And linearization assumptions
114-----------------------------------------
115
116Why is this strategy deterministic?  How can we guarantee that on two separate executions,
117the same syscall `S` will retry exactly `N` times at times `T_1 ... T_n`?
118
119The assumption we make here is that all syscalls, even across multiple cores, act as
120atomic operations on the kernel state --- from the guest's perspective.  That is, halfway
121through executing a guest, we can describe the prior history of system as the linear
122series of syscalls committed to the kernel. Does this actually hold for Linux?  It doesn't
123seem to be documented anywhere, and Linux doesn't have anything like a formal semantics.
124For most syscalls we treat their man pages as the spec, and they don't answer questions
125like this.
126
127If we execute a guest entirely on one core, then only a weaker form of the assumption
128needs to hold.
129
130The upshot is, because we make this "linearizability of syscalls" assumption, each polling
131attempt for a given syscall is assumed to deterministically succeed or fail based on the
132history of syscalls that committed before it.
133
134The troublesome race
135--------------------
136
137One may wonder why not simply implement polling by *letting* the operation block,
138backgrounding the thread, and then checking in at each polling point to see if the
139operation has completed *without* incurring a user/kernel context switch and executing the
140syscall again. This would indeed be great, but it would require an oracle that can answer
141the question: "has thread X unblocked yet"?
142
143### A non-solution dead-end:
144
145We can recapture control flow immediately after any blocking syscall (in the handler), but
146that "posthook" won't run until (1) the syscall unblocks, and (2) the OS gets around to
147actually scheduling the thread.  Thus, inside the scheduler, we are racing with threads
148like this that are unblocked and in the process of attempting to report for duty.  Such
149threads can signal their readiness by tweaking the scheduler data structures, but those
150updates arrive completely asynchronously.  For example, if a syscall unblocks on scheduler
151turn 100 in one run, how can we know it won't arrive late at turn 101 on the next run?  We
152can't determinize the point that the formerly-blocked thread rejoins the scheduler pool.
153Not unless we do some huge (realtime) wait at each scheduler turn to ensure the OS has had
154a chance to run any recently-unblocked threads!
155
156### Future work: efficient oracle
157
158This nondeterministic-rejoining-the-pool strategy is exactly what we do for *externally*
159blocked syscalls.  But for internally-blocked ones that we want to determinize, then we
160would need a more efficient "has-unblocked?" oracle.  For example, if we had a kernel
161module exposing a safe predicate function that reveals this information to userspace. It's
162possible that the /proc file system exposes enough information to synchronously poll a
163threads status.
164
165But solving this may be extremely difficult, or impossible.  If the syscall that ran
166before us unblocked a thread, how long does that status update take to propogate through
167the kernel itself?  If one futex wake syscall unblocks 1000 other threads, their status
168would have to atomically change immediately by the time the futex wake returns to the
169guest, or at least by the start of the next syscall (or oracle call).
170
171This atomicity property seems hard to guarantee for the OS. Instead, the current polling
172strategy that uses nonblocking syscalls is much more localized.  It doesn't treat the
173kernel state as monolithic and require atomic updates from the guest perspective, but
174rather it only requires atomic treatment of whatever state is relevant to syscalls
175operating on that individual resource (futex, file descriptor etc) --- a much less
176stringent requirement.
177
178*/

180/// Identify a resource which is subject to side effects by actions
181/// (system calls) taken by the detcore guest.  Some actions may affect multiple resources.
182///
183/// Some resources may be entangled or aliased, as when address spaces share pages.
184///
185/// Resource requests may also be asking simply for permission to proceed, as with exit or
186/// sleep.
187#[derive(PartialEq, Debug, Eq, Clone, Serialize, Deserialize, Hash)]
188pub enum ResourceID {
189    /// File contents identified by inode.
190    FileContents(DetInode),
191
192    /// File and directory Metadata.  These correspond to inodes, because hardlinks to the same file
193    /// still share metadata such as modtimes and permissions.
194    FileMetadata(DetInode),
195
196    /// Directory contents (entries) identified by inode.
197    DirectoryContents(DetInode),
198
199    /// Memory address space identified by process id.  Note that these may be
200    /// connected/aliased via shared memory. TODO(T78055411)
201    ///
202    /// This resource is not typically released/returned, and rather is associated with
203    /// the thread on each time slice it runs for the lifetime of the thread.  (However,
204    /// it is in principle possible to support unmapping shared mappings that would
205    /// dynamically *decrease* the conflicts for scheduling a given thread/process.)
206    MemAddrSpace(DetPid),
207
208    /// Permission to change the single resource at this path (file, directory, pipe etc), via
209    /// renaming, unlinking etc.  Holding this resource does not grant permission to change the
210    /// contents.  Read permission on the path is required just for resolving the path to inode
211    /// mapping, but the global method `resolve_path` can be used to abstract this.
212    Path(PathBuf),
213
214    /// NB: unstable:
215    ///
216    /// Transitive permission to all paths underneath a given directory, i.e., all paths that share
217    /// this path as a prefix.
218    PathsTransitive(PathBuf),
219
220    /// Permission to a device, which behaves like a predefined "inode".
221    Device(Device),
222
223    /// Wait for go-ahead to Exit or ExitGroup.  True indicates "group".
224    /// Does not need to be released/returned once granted.
225    Exit {
226        /// Whether this is `exit_group` rather than `exit`.
227        group: bool,
228        /// Process whose lifecycle state is affected.
229        process: DetPid,
230        /// Address space used by clear-child-tid futex wakeups.
231        mm: MmId,
232    },
233
234    /// A thread checks in with the scheduler before it continues executing after cloning
235    /// a child thread.  This allows it to be prioritized correctly vis-a-vis its child
236    /// thread.
237    ParentContinue { parent: DetTid, child: DetTid },
238
239    /// Wait for permission to wake up. This is parameterized by an *absolute* time
240    /// (i.e. global time).
241    SleepUntil(LogicalTime),
242
243    /// A guest-internal internal IO op which is guaranteed to be nonblocking,
244    /// i.e. converted into a polling strategy.
245    InternalIOPolling,
246
247    /// An internal event that is only used when implementing context switches under tracereplay.
248    /// It should not bump global time.
249    TraceReplay,
250
251    /// A guest is blocking on a futex wait, which means it's out of the runqueue.
252    FutexWait,
253
254    /// Permission to perform blocking IO with an endpoint outside the deterministic container.
255    /// In general these should be recorded if strict reproducibility is to be achieved.
256    BlockingExternalIO(ExternalOpId),
257
258    // TODO-HUMAN-REVIEW(PR-868): Review the vfork registration scheduler token.
259    /// A `CLONE_VFORK` parent entering the kernel. The scheduler must not admit
260    /// another guest turn until the child has registered or the clone has failed.
261    BlockingVfork(ExternalOpId),
262
263    // TODO-HUMAN-REVIEW(PR-1152): Review failed deferred-vfork cancellation.
264    /// A clone operation governed by [`ResourceID::BlockingVfork`] failed before a child could
265    /// register. This is a continuation outcome rather than a new blocking operation: it lets the
266    /// scheduler cancel the pending vfork barrier, re-admit the parent, and preserve the original
267    /// injected syscall error.
268    VforkFailed(ExternalOpId),
269
270    /// Permission to CONTINUE execution after returning from a potentially-blocking
271    /// operation that reaches outside the container.
272    BlockedExternalContinue(ExternalOpId),
273
274    /// Permission to continue beyond a priority change point. Used for chaotic
275    /// scheduling. Could also be considered less of a resource and more of a
276    /// "request" to the scheduler to alter priority of the requesting thread.
277    /// The contained value should be a random u64 from the deterministic PRNG.
278    /// No guarantees are made about how it will be used.
279    ///
280    /// Also includes the local time at which the guest observed the preemption point.
281    // AUTONOMOUS-BOT-IMPLEMENTED
282    // TODO-HUMAN-REVIEW(PR-1151)
283    PriorityChangePoint(u64, LogicalTime, u64, Vec<ChaosEpochTransition>),
284
285    /// Park until an exact or any-child process wait has a logical exit to reap.
286    WaitChild {
287        /// The process issuing the wait.
288        parent: DetPid,
289        /// Child population selected by the syscall.
290        spec: ChildWaitSpec,
291    },
292
293    /// Park until a backend reports that a logically exited child is physically waitable.
294    WaitPhysicalChild(DetPid),
295
296    /// A physical signal has been received by the thread, request to continue delivering it and
297    /// invoking the signal handler as the next thing to run.
298    InboundSignal(SigWrapper),
299
300    /// A scheduler notification that one or more guest-generated signals are
301    /// physically pending. An unmarked request wakes waitid polling; a request
302    /// carrying `signal_interrupt_errno` wakes internal IO polling. Kept as one
303    /// resource because scheduler requests currently admit one resource only.
304    WaitidSignals(Vec<SigWrapper>),
305
306    /// Relinquish the current scheduler turn without changing the thread's
307    /// persistent priority.
308    SchedYield,
309
310    /// A guest thread checking in with the scheduler at a happens-before anchor
311    /// point, carrying the thread's running syscall count. The scheduler
312    /// consults the configured `HappensBeforeProgram`: it fires any anchors this
313    /// checkpoint reaches, and parks the thread (removing it from the run queue)
314    /// when the checkpoint is the AFTER endpoint of a Hard edge whose BEFORE
315    /// endpoint has not yet fired. The contained value is the post-increment
316    /// syscall count observed by the guest.
317    HappensBeforeCheckpoint(u64),
318
319    /// A real `rt_sigsuspend` executing outside the runnable set while the kernel
320    /// atomically installs its temporary signal mask. Unlike arbitrary external
321    /// IO, this operation cannot complete without a signal.
322    BlockingRtSigsuspend(ExternalOpId),
323}

346/// `Resources` is a request to lock zero or more resources so that the thread can perform an action.
347///
348/// There can only be one outstanding request at a time for a given TID.
349#[derive(PartialEq, Eq, Clone, Serialize, Deserialize)]
350pub struct Resources {
351    /// The thread ID requesting the resources.
352    pub tid: DetTid,
353    /// The set of resources requested.
354    pub resources: HashMap<ResourceID, Permission>,
355    /// If the guest thread is polling the resource, retrying until success, it should
356    /// increment this field after each attempt, as a hint to the scheduler to deprioritize it.
357    /// That is, requests with a nonzero value will be deprioritized. Zero values will be treated
358    /// normally.
359    pub poll_attempt: u32,
360    /// A bit of metadata (just for debugging), about what the thread is trying to do with the
361    /// resources.
362    pub fyi: String,
363    /// Errno returned when an established signal interruption happens before a
364    /// syscall makes progress. Its presence also asks the caller to classify a
365    /// signal wake after partial progress, when Linux returns the byte count
366    /// instead. `None` does not make an `InternalIOPolling` request eligible
367    /// for the scheduler's cross-task signal wakeup.
368    #[serde(default)]
369    pub(crate) signal_interrupt_errno: Option<i32>,
370}
371
372impl fmt::Debug for Resources {
373    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
374        let mut debug = f.debug_struct("Resources");
375        debug
376            .field("tid", &self.tid)
377            .field("resources", &self.resources)
378            .field("poll_attempt", &self.poll_attempt)
379            .field("fyi", &self.fyi);
380        if let Some(errno) = self.signal_interrupt_errno {
381            debug.field("signal_interrupt_errno", &errno);
382        }
383        debug.finish()
384    }
385}
386
387impl Resources {
388    /// Allocate a new, empty Resources request.
389    pub fn new(tid: DetTid) -> Resources {
390        Resources {
391            tid,
392            resources: HashMap::new(),
393            poll_attempt: 0,
394            fyi: String::new(),
395            signal_interrupt_errno: None,
396        }
397    }
398
399    /// Similar to extend, but union all permissions within the intersection.
400    /// Union can only be called on resources with matching `tid`.
401    /// (NB: equivalent to Haskell `Data.Map.unionWith perm_union`)
402    pub fn union(&mut self, other: &Resources) {
403        assert_eq!(self.tid, other.tid);
404        for (id, perm2) in other.resources.iter() {
405            match self.resources.entry(id.clone()) {
406                Entry::Occupied(mut e) => {
407                    let perm1 = e.get_mut();
408                    *perm1 = perm1.union(perm2)
409                }
410                Entry::Vacant(e) => {
411                    e.insert(perm2.clone());
412                }
413            }
414        }
415        match (self.signal_interrupt_errno, other.signal_interrupt_errno) {
416            (None, interrupt) => self.signal_interrupt_errno = interrupt,
417            (Some(left), Some(right)) => assert_eq!(left, right),
418            (Some(_), None) => {}
419        }
420    }
421
422    pub fn set_signal_interrupt_errno(&mut self, errno: Errno) {
423        self.signal_interrupt_errno = Some(errno.into_raw());
424    }
425
426    pub fn signal_interrupt_errno(&self) -> Option<i32> {
427        self.signal_interrupt_errno
428    }
429
430    /// Insert a new individual resource into a set of resources.
431    /// Panics if that resource is already present.
432    pub fn insert(&mut self, new: ResourceID, perm: Permission) {
433        let old = self.resources.insert(new, perm);
434        assert_eq!(old, None);
435    }
436
437    /// Add some metadata, typically a short tag, to the FYI.
438    pub fn fyi(&mut self, s: &str) {
439        if !self.fyi.is_empty() {
440            self.fyi.push_str(", ");
441        }
442        self.fyi.push_str(s);
443    }
444
445    // Test if the request corresponds to an exit or exit_group.
446    // If it does, return a synthetic copy of the syscall which would generate this resource request.
447    pub fn as_exit_syscall(&self) -> Option<Syscall> {
448        let exit = self.resources.keys().find_map(|resource| match resource {
449            ResourceID::Exit { group, process, mm } => Some((*group, *process, *mm)),
450            _ => None,
451        });
452        if exit.is_some() && self.resources.len() > 1 {
453            panic!(
454                "is_polling_turn: not expecting an InternalIOPolling mixed in with other resource requests: {:?}",
455                self
456            );
457        }
458        if exit.is_some_and(|(group, _, _)| group) {
459            Some(Syscall::ExitGroup(Default::default())) // This status code is dummy.
460        } else if exit.is_some() {
461            Some(Syscall::Exit(Default::default())) // This status code is dummy.
462        } else {
463            None
464        }
465    }
466
467    /// Return lifecycle identity when this is an exit request.
468    pub fn exit_identity(&self) -> Option<(bool, DetPid, MmId)> {
469        self.resources.keys().find_map(|resource| match resource {
470            ResourceID::Exit { group, process, mm } => Some((*group, *process, *mm)),
471            _ => None,
472        })
473    }
474}

476/// Is the resource to be used for writing, reading or both?
477#[derive(PartialEq, Debug, Eq, Clone, Serialize, Deserialize, Hash)]
478pub enum Permission {
479    /// Read permission.
480    R,
481    /// Write permission.
482    W,
483    /// Read+Write permission.
484    RW,
485}
486
487impl Permission {
488    /// Take the union of requested permissions.
489    pub fn union(&self, other: &Permission) -> Permission {
490        use Permission::*;
491        match (self, other) {
492            (R, R) => R,
493            (R, W) => RW,
494            (W, R) => RW,
495            (W, W) => W,
496            (RW, _) => RW,
497            (_, RW) => RW,
498        }
499    }
500}

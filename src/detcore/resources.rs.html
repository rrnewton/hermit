118/*
119NOTE [Blocking Syscalls via Internal Polling]
120---------------------------------------------
121
122A system like hermit which sequentializes execution must have the ability to detect
123blocking operations, so as not to deadlock the system. (This remains true irrespective of
124whether sequentialization is relaxed to admit some parallelism.)
125
126One option is for hermit to *precisely* model everything that may cause a syscall to
127block, and run the syscall only when it is certain that it can complete.  This is the
128approach with the precise implementation of futexes, for example, but it is tricky in
129general and requires hermit recapitulate a lot of the logic in the Linux kernel.
130
131Hence the need for this quick-and-dirty alternative of polling for internal blocking
132operations. The idea is that many potentially-blocking syscalls have the option to be run
133in a non-blocking fashion. This concept is captured by the `NonBlockableSyscall` trait.
134
135The way the polling strategy works is that the handler inside the guest converts the
136syscall to its nonblocking form (or ensures it runs nonblocking via file descriptor
137configuration).  The handler executes the syscall in a loop, while increasing the
138`poll_attempt` to make it visible to the scheduler that these are retries of a [logically]
139blocking operation, rather than new operations.
140
141The scheduler can then interleave these polling operations into the deterministic
142linearization of all guest side effects, just like any other operations.  However, it is a
143good idea to have some form of "backoff" when polling, because this strategy can
144asymptotically increase the total number of syscalls performed. For example, there are a
145large number of threads polling, and one thread productively running, we don't want to
146poll every thread once for every step of productive work. Conversely, we want to guarantee
147that no poller is starved indefinitely, because that could lead to live lock in the
148presence of any kind of "busy waiting".
149
150Determinism And linearization assumptions
151-----------------------------------------
152
153Why is this strategy deterministic?  How can we guarantee that on two separate executions,
154the same syscall `S` will retry exactly `N` times at times `T_1 ... T_n`?
155
156The assumption we make here is that all syscalls, even across multiple cores, act as
157atomic operations on the kernel state --- from the guest's perspective.  That is, halfway
158through executing a guest, we can describe the prior history of system as the linear
159series of syscalls committed to the kernel. Does this actually hold for Linux?  It doesn't
160seem to be documented anywhere, and Linux doesn't have anything like a formal semantics.
161For most syscalls we treat their man pages as the spec, and they don't answer questions
162like this.
163
164If we execute a guest entirely on one core, then only a weaker form of the assumption
165needs to hold.
166
167The upshot is, because we make this "linearizability of syscalls" assumption, each polling
168attempt for a given syscall is assumed to deterministically succeed or fail based on the
169history of syscalls that committed before it.
170
171The troublesome race
172--------------------
173
174One may wonder why not simply implement polling by *letting* the operation block,
175backgrounding the thread, and then checking in at each polling point to see if the
176operation has completed *without* incurring a user/kernel context switch and executing the
177syscall again. This would indeed be great, but it would require an oracle that can answer
178the question: "has thread X unblocked yet"?
179
180### A non-solution dead-end:
181
182We can recapture control flow immediately after any blocking syscall (in the handler), but
183that "posthook" won't run until (1) the syscall unblocks, and (2) the OS gets around to
184actually scheduling the thread.  Thus, inside the scheduler, we are racing with threads
185like this that are unblocked and in the process of attempting to report for duty.  Such
186threads can signal their readiness by tweaking the scheduler data structures, but those
187updates arrive completely asynchronously.  For example, if a syscall unblocks on scheduler
188turn 100 in one run, how can we know it won't arrive late at turn 101 on the next run?  We
189can't determinize the point that the formerly-blocked thread rejoins the scheduler pool.
190Not unless we do some huge (realtime) wait at each scheduler turn to ensure the OS has had
191a chance to run any recently-unblocked threads!
192
193### Future work: efficient oracle
194
195This nondeterministic-rejoining-the-pool strategy is exactly what we do for *externally*
196blocked syscalls.  But for internally-blocked ones that we want to determinize, then we
197would need a more efficient "has-unblocked?" oracle.  For example, if we had a kernel
198module exposing a safe predicate function that reveals this information to userspace. It's
199possible that the /proc file system exposes enough information to synchronously poll a
200threads status.
201
202But solving this may be extremely difficult, or impossible.  If the syscall that ran
203before us unblocked a thread, how long does that status update take to propogate through
204the kernel itself?  If one futex wake syscall unblocks 1000 other threads, their status
205would have to atomically change immediately by the time the futex wake returns to the
206guest, or at least by the start of the next syscall (or oracle call).
207
208This atomicity property seems hard to guarantee for the OS. Instead, the current polling
209strategy that uses nonblocking syscalls is much more localized.  It doesn't treat the
210kernel state as monolithic and require atomic updates from the guest perspective, but
211rather it only requires atomic treatment of whatever state is relevant to syscalls
212operating on that individual resource (futex, file descriptor etc) --- a much less
213stringent requirement.
214
215*/

217/// Identify a resource which is subject to side effects by actions
218/// (system calls) taken by the detcore guest.  Some actions may affect multiple resources.
219///
220/// Some resources may be entangled or aliased, as when address spaces share pages.
221///
222/// Resource requests may also be asking simply for permission to proceed, as with exit or
223/// sleep.
224#[derive(PartialEq, Debug, Eq, Clone, Serialize, Deserialize, Hash)]
225pub enum ResourceID {
226    /// File contents identified by inode.
227    FileContents(DetInode),
228
229    /// File and directory Metadata.  These correspond to inodes, because hardlinks to the same file
230    /// still share metadata such as modtimes and permissions.
231    FileMetadata(DetInode),
232
233    /// Directory contents (entries) identified by inode.
234    DirectoryContents(DetInode),
235
236    /// Memory address space identified by process id.  Note that these may be
237    /// connected/aliased via shared memory. TODO(T78055411)
238    ///
239    /// This resource is not typically released/returned, and rather is associated with
240    /// the thread on each time slice it runs for the lifetime of the thread.  (However,
241    /// it is in principle possible to support unmapping shared mappings that would
242    /// dynamically *decrease* the conflicts for scheduling a given thread/process.)
243    MemAddrSpace(DetPid),
244
245    /// Permission to change the single resource at this path (file, directory, pipe etc), via
246    /// renaming, unlinking etc.  Holding this resource does not grant permission to change the
247    /// contents.  Read permission on the path is required just for resolving the path to inode
248    /// mapping, but the global method `resolve_path` can be used to abstract this.
249    Path(PathBuf),
250
251    /// NB: unstable:
252    ///
253    /// Transitive permission to all paths underneath a given directory, i.e., all paths that share
254    /// this path as a prefix.
255    PathsTransitive(PathBuf),
256
257    /// Permission to a device, which behaves like a predefined "inode".
258    Device(Device),
259
260    /// Wait for go-ahead to Exit or ExitGroup.  True indicates "group".
261    /// Does not need to be released/returned once granted.
262    Exit {
263        /// Whether this is `exit_group` rather than `exit`.
264        group: bool,
265        /// Process whose lifecycle state is affected.
266        process: DetPid,
267        /// Address space used by clear-child-tid futex wakeups.
268        mm: MmId,
269    },
270
271    /// A thread checks in with the scheduler before it continues executing after cloning
272    /// a child thread.  This allows it to be prioritized correctly vis-a-vis its child
273    /// thread.
274    ParentContinue { parent: DetTid, child: DetTid },
275
276    /// Wait for permission to wake up. This is parameterized by an *absolute* time
277    /// (i.e. global time).
278    SleepUntil(LogicalTime),
279
280    /// A guest-internal internal IO op which is guaranteed to be nonblocking,
281    /// i.e. converted into a polling strategy.
282    InternalIOPolling,
283
284    /// An internal event that is only used when implementing context switches under tracereplay.
285    /// It should not bump global time.
286    TraceReplay,
287
288    /// A guest is blocking on a futex wait, which means it's out of the runqueue.
289    FutexWait,
290
291    /// Permission to perform blocking IO with an endpoint outside the deterministic container.
292    /// In general these should be recorded if strict reproducibility is to be achieved.
293    BlockingExternalIO(ExternalOpId),
294
295    // TODO-HUMAN-REVIEW(PR-868): Review the vfork registration scheduler token.
296    /// A `CLONE_VFORK` parent entering the kernel. The scheduler must not admit
297    /// another guest turn until the child has registered or the clone has failed.
298    BlockingVfork(ExternalOpId),
299
300    // TODO-HUMAN-REVIEW(PR-1152): Review failed deferred-vfork cancellation.
301    /// A clone operation governed by [`ResourceID::BlockingVfork`] failed before a child could
302    /// register. This is a continuation outcome rather than a new blocking operation: it lets the
303    /// scheduler cancel the pending vfork barrier, re-admit the parent, and preserve the original
304    /// injected syscall error.
305    VforkFailed(ExternalOpId),
306
307    /// Permission to CONTINUE execution after returning from a potentially-blocking
308    /// operation that reaches outside the container.
309    BlockedExternalContinue(ExternalOpId),
310
311    /// Permission to continue beyond a priority change point. Used for chaotic
312    /// scheduling. Could also be considered less of a resource and more of a
313    /// "request" to the scheduler to alter priority of the requesting thread.
314    /// The contained value should be a random u64 from the deterministic PRNG.
315    /// No guarantees are made about how it will be used.
316    ///
317    /// Also includes the local time at which the guest observed the preemption point.
318    // AUTONOMOUS-BOT-IMPLEMENTED
319    // TODO-HUMAN-REVIEW(PR-1151)
320    PriorityChangePoint(u64, LogicalTime, u64, Vec<ChaosEpochTransition>),
321
322    /// Park until an exact or any-child process wait has a logical exit to reap.
323    WaitChild {
324        /// The process issuing the wait.
325        parent: DetPid,
326        /// Child population selected by the syscall.
327        spec: ChildWaitSpec,
328    },
329
330    /// Park until a backend reports that a logically exited child is physically waitable.
331    WaitPhysicalChild(DetPid),
332
333    /// A physical signal has been received by the thread, request to continue delivering it and
334    /// invoking the signal handler as the next thing to run.
335    InboundSignal(SigWrapper),
336
337    /// A scheduler notification that one or more guest-generated signals are
338    /// physically pending. An unmarked request wakes waitid polling; a request
339    /// carrying `signal_interrupt_errno` wakes internal IO polling. Kept as one
340    /// resource because scheduler requests currently admit one resource only.
341    WaitidSignals(Vec<SigWrapper>),
342
343    /// Relinquish the current scheduler turn without changing the thread's
344    /// persistent priority.
345    SchedYield,
346
347    /// A guest thread checking in with the scheduler at a happens-before anchor
348    /// point, carrying the thread's running syscall count. The scheduler
349    /// consults the configured `HappensBeforeProgram`: it fires any anchors this
350    /// checkpoint reaches, and parks the thread (removing it from the run queue)
351    /// when the checkpoint is the AFTER endpoint of a Hard edge whose BEFORE
352    /// endpoint has not yet fired. The contained value is the post-increment
353    /// syscall count observed by the guest.
354    HappensBeforeCheckpoint(u64),
355
356    /// A happens-before checkpoint at a syscall that is the `nth` occurrence of
357    /// one or more syscall-occurrence anchors on this thread (a named syscall,
358    /// optionally on one file descriptor, counted by the guest per thread).
359    /// Carries the post-increment syscall count, so count anchors at the same
360    /// syscall are evaluated too, and the names of the anchors reached. The
361    /// scheduler fires those that resolve to this thread.
362    HappensBeforeSyscallCheckpoint {
363        /// The post-increment syscall count observed by the guest.
364        count: u64,
365        /// The syscall-occurrence anchors this syscall is the `nth` occurrence
366        /// of, in name order.
367        anchors: Vec<String>,
368    },
369
370    /// A syscall entry that reached posthook happens-before anchors returned an
371    /// internal restart code, so whether it completes is decided by the kernel
372    /// after Hermit's checkpoint. The scheduler refuses the run
373    /// (`HERMIT_HB_POSTHOOK_INTERRUPTED`) and fires nothing
374    /// (<https://github.com/rrnewton/hermit/issues/3929>).
375    HappensBeforePosthookInterrupted {
376        /// The post-increment syscall count observed by the guest.
377        count: u64,
378        /// The posthook anchors the entry reached, in name order.
379        anchors: Vec<String>,
380        /// The restart code, by name.
381        code: String,
382    },
383
384    /// A real `rt_sigsuspend` executing outside the runnable set while the kernel
385    /// atomically installs its temporary signal mask. Unlike arbitrary external
386    /// IO, this operation cannot complete without a signal.
387    BlockingRtSigsuspend(ExternalOpId),
388
389    /// A one-shot SIGALRM consumed while its single-threaded in-guest target
390    /// was parked at a qualified emulated sleep. This authorizes only the
391    /// original sleep's typed fatal response, not a generic physical signal.
392    InGuestFatalAlarm,
393}

416/// `Resources` is a request to lock zero or more resources so that the thread can perform an action.
417///
418/// There can only be one outstanding request at a time for a given TID.
419#[derive(PartialEq, Eq, Clone, Serialize, Deserialize)]
420pub struct Resources {
421    /// The thread ID requesting the resources.
422    pub tid: DetTid,
423    /// The set of resources requested.
424    pub resources: HashMap<ResourceID, Permission>,
425    /// If the guest thread is polling the resource, retrying until success, it should
426    /// increment this field after each attempt, as a hint to the scheduler to deprioritize it.
427    /// That is, requests with a nonzero value will be deprioritized. Zero values will be treated
428    /// normally.
429    pub poll_attempt: u32,
430    /// A bit of metadata (just for debugging), about what the thread is trying to do with the
431    /// resources.
432    pub fyi: String,
433    /// Errno returned when an established signal interruption happens before a
434    /// syscall makes progress. Its presence also asks the caller to classify a
435    /// signal wake after partial progress, when Linux returns the byte count
436    /// instead. `None` does not make an `InternalIOPolling` request eligible
437    /// for the scheduler's cross-task signal wakeup.
438    #[serde(default)]
439    pub(crate) signal_interrupt_errno: Option<i32>,
440    /// Set by `tool_global::resource_request` when this request is made while
441    /// the thread is handling a syscall whose cost is withheld because it
442    /// belongs to a backend-runtime bootstrap window (see
443    /// `ThreadState::charge_syscall_time`). The scheduler withholds the
444    /// per-turn scheduler time of such a turn, unless it is an IO-polling
445    /// retry, for the same reason the syscall cost is withheld: the turn
446    /// exists only because the backend's runtime made the syscall, so charging
447    /// it would make guest-visible virtual time depend on the backend. `false`
448    /// for every request from a backend without such a runtime, and for
449    /// requests that do not go through `resource_request`.
450    #[serde(default)]
451    pub(crate) backend_runtime_bootstrap: bool,
452    /// The signal mask a thread sleeps under in the blocking call this request
453    /// begins (`BlockingExternalIO`, `BlockingRtSigsuspend`), when the call
454    /// installs its own: the mask argument of `rt_sigsuspend`, `ppoll` or
455    /// `pselect6`, read in the thread's turn, without `SIGKILL` and `SIGSTOP`,
456    /// which Linux never blocks. `None` for a call that sleeps under the
457    /// thread's own mask; the scheduler then reads that mask when it commits
458    /// the request, while the thread is still stopped at it. The scheduler
459    /// records the mask either way, because once the thread runs the call its
460    /// live mask is no longer ordered by the schedule, and a `SIGCHLD` target
461    /// must be chosen from masks that are
462    /// (<https://github.com/rrnewton/hermit/issues/3146>).
463    #[serde(default)]
464    pub(crate) blocked_signal_mask: Option<u64>,
465    /// Set on a `BlockingExternalIO` request whose call installs a temporary
466    /// signal mask that the thread's turn cannot vouch for: a record/replay
467    /// pselect6 whose mask Hermit could not read through the kernel at entry,
468    /// which keeps the guest's `{ sigmask, sigsetsize }` wrapper. A masked
469    /// record/replay pselect6, ppoll or epoll_pwait that may wait sleeps under
470    /// a private copy Hermit read at entry
471    /// (<https://github.com/rrnewton/hermit/issues/4095>), and sets it too, so
472    /// that recording and replay, which serves the call from the log without
473    /// the kernel installing anything, schedule the call alike. The scheduler
474    /// then records no sleeping mask for the thread
475    /// (`BlockedPool::out_of_scheduler_masks` holds `None`), so it neither arms
476    /// the thread for a committed signal nor chooses it as a `SIGCHLD` target,
477    /// as for every call outside the schedule before the scheduler modelled
478    /// signal targets (review of <https://github.com/rrnewton/hermit/pull/3989>).
479    #[serde(default)]
480    pub(crate) blocked_signal_mask_unknown: bool,
481    /// Set on a `BlockingExternalIO` request whose call `hermit replay` serves
482    /// from the recording. Such a call runs in the background as it did during
483    /// recording, so the schedule matches the recording's, but it cannot
484    /// block. The scheduler therefore commits no other turn until it has
485    /// finished, and readmits such calls before any other background call, so
486    /// that neither its effects nor when it rejoins depend on host timing.
487    /// `false` outside replay.
488    #[serde(default)]
489    pub(crate) replay_served_from_log: bool,
490    /// Set on a `BlockingExternalIO` request whose call reads a descriptor
491    /// Detcore records as a signalfd (`read`, `readv`, `preadv2`): run outside
492    /// the schedule, it can dequeue a pending signal of its own process at a
493    /// host-timed moment (`signalfd_dequeue` reads the calling task's queues).
494    /// The scheduler then does not arm another thread of that process for a
495    /// shared-queue signal the signalfd may read
496    /// (`Scheduler::another_call_may_take_waiting_signal`). Detcore's
497    /// descriptor table follows close, dup and close-on-exec, so a closed
498    /// signalfd sets nothing. `false` for every other request.
499    #[serde(default)]
500    pub(crate) reads_signalfd: bool,
501    /// The descriptor a `BlockingExternalIO` request's `read`, `readv` or
502    /// `preadv2` reads, whatever it is, with the identity of the descriptor
503    /// table it is in; `None` for every other request. Under
504    /// record and replay the scheduler asks the kernel, as it grants the
505    /// request, whether that descriptor is a signalfd and which signals it
506    /// reads, so that a signalfd Detcore's table does not record as one (one
507    /// received over `SCM_RIGHTS`) counts too, and a descriptor changed by
508    /// another thread's turn while this request waited is read as it is when
509    /// the call runs (`Scheduler::background_kernel_signalfd_reads`).
510    #[serde(default)]
511    pub(crate) read_fd: Option<(detcore_model::fd::FilesId, i32)>,
512    /// Set on a polling request whose attempts fail or succeed only through
513    /// guest actions: a retry on a container-internal descriptor (a pipe, a
514    /// socketpair end, or a FIFO polled as a pipe), or a FIFO open waiting for
515    /// a guest peer. Such a poller cannot make progress on its own, which is
516    /// what `Scheduler::nothing_else_can_run` asks
517    /// (<https://github.com/rrnewton/hermit/issues/2203>). `false` for a poll
518    /// whose outcome a host can change.
519    #[serde(default)]
520    pub(crate) polls_guest_state_only: bool,
521    /// Set by a blocking FIFO open waiting for a guest peer. When this polling
522    /// turn commits and nothing else can run (`Scheduler::nothing_else_can_run`),
523    /// the answer is `ResumeStatus::NothingElseCanRun`, and the open then waits
524    /// in the kernel holding the turn, as without the poll.
525    #[serde(default)]
526    pub(crate) waits_until_nothing_else_can_run: bool,
527    /// Set on a retry (`poll_attempt > 0`) whose previous attempt moved data
528    /// (a partial pipe write). Every other retry follows an attempt that would
529    /// have blocked and moved nothing, which `Scheduler::nothing_else_can_run`
530    /// needs to know: a guest-state poll grant is progress unless the thread's
531    /// next request is a retry without this flag.
532    #[serde(default)]
533    pub(crate) previous_attempt_made_progress: bool,
534    /// The `poll_attempt` a skipped retry had when the scheduler replaced it
535    /// with a runnable copy whose `poll_attempt` is 0
536    /// (`Scheduler::upgrade_polled_to_runnable`): the request is still that
537    /// retry, for `Scheduler::nothing_else_can_run`.
538    #[serde(default)]
539    pub(crate) upgraded_from_attempt: u32,
540    /// The pipe or FIFO this polling request waits on, and what it waits
541    /// for, under `--pipe-wake-latency` (`crate::pipe_wake`): an action of
542    /// another thread that can satisfy it hands this thread the turn. `None`
543    /// for every other request, and always with the option unset. Boxed:
544    /// inline, its 32 bytes in every request a handler future holds grew
545    /// `handle_syscall_event`'s debug-build stack past the 2 MiB test thread
546    /// that runs ptrace record through the library (`record_replay`'s
547    /// `public_record_*` tests).
548    #[serde(default)]
549    pub(crate) polls_channel: Option<Box<(crate::pipe_wake::ChannelId, crate::pipe_wake::Wants)>>,
550    /// The absolute virtual deadline of the timed wait that a polling request
551    /// (`poll_attempt > 0`) retries: `ppoll`, `poll`, `epoll_wait`,
552    /// `epoll_pwait`, `rt_sigtimedwait`, `select`, `pselect6` or a polling
553    /// `FUTEX_WAIT` with a timeout. Once committed virtual time passes it, the
554    /// scheduler restores the backed-off poller's normal priority so its next
555    /// retry can return the timeout
556    /// (`Scheduler::step2b_restore_due_pollers`,
557    /// <https://github.com/rrnewton/hermit/issues/3952>). `None` for every other
558    /// request, and always under record/replay.
559    #[serde(default)]
560    pub(crate) poll_deadline: Option<LogicalTime>,
561    /// The action and guest mask read in this exact emulated sleep's own turn.
562    /// Only its singleton SleepUntil request may use this snapshot.
563    #[serde(default)]
564    pub(crate) in_guest_sleep_sigalrm: Option<InGuestSleepSigalrm>,
565    /// The filing thread's process and thread as the backend names them for
566    /// `/proc` (`guest.pid()`, `guest.tid()`, as a futex wait's
567    /// `FutexSignalWatch` records them), on a restartable internal IO poll
568    /// (`retry_nonblocking_syscall_helper`, `execute_blocking_pipe_write`).
569    /// The scheduler reads that thread's live signal state there to decide
570    /// which pending signals end the poll
571    /// (`Scheduler::restartable_internal_io_interrupting_signals`). `None`
572    /// for every other request; a marked poll without it is not filtered.
573    #[serde(default)]
574    pub(crate) signal_state_task: Option<(i32, i32)>,
575    /// Set on a restartable internal IO poll that decides for itself whether
576    /// a `Signaled` wake interrupts it: a parked pipe `writev`
577    /// (`pipe_writev_resources`) polls with every ordinary signal blocked and
578    /// reads the target's disposition after the wake
579    /// (`wait_signal_disposition`). The scheduler's drain therefore does not
580    /// filter its signals by the thread's kernel state, whose mask it would
581    /// read as all-blocked, dropping every signal
582    /// (<https://github.com/rrnewton/hermit/issues/4187>).
583    #[serde(default)]
584    pub(crate) decides_signal_interruption_itself: bool,
585}

641impl Resources {
642    /// The runnable copy of a skipped retry that
643    /// `Scheduler::upgrade_polled_to_runnable` puts in its place:
644    /// `poll_attempt` 0, with the retry number kept in `upgraded_from_attempt`.
645    pub(crate) fn upgraded_to_runnable(&self) -> Resources {
646        let mut runnable = self.clone();
647        runnable.upgraded_from_attempt = runnable.upgraded_from_attempt.max(runnable.poll_attempt);
648        runnable.poll_attempt = 0;
649        runnable
650    }

652    /// Allocate a new, empty Resources request.
653    pub fn new(tid: DetTid) -> Resources {
654        Resources {
655            tid,
656            resources: HashMap::new(),
657            poll_attempt: 0,
658            fyi: String::new(),
659            signal_interrupt_errno: None,
660            backend_runtime_bootstrap: false,
661            blocked_signal_mask: None,
662            blocked_signal_mask_unknown: false,
663            replay_served_from_log: false,
664            reads_signalfd: false,
665            read_fd: None,
666            polls_guest_state_only: false,
667            waits_until_nothing_else_can_run: false,
668            previous_attempt_made_progress: false,
669            upgraded_from_attempt: 0,
670            polls_channel: None,
671            poll_deadline: None,
672            in_guest_sleep_sigalrm: None,
673            signal_state_task: None,
674            decides_signal_interruption_itself: false,
675        }
676    }
677
678    /// Similar to extend, but union all permissions within the intersection.
679    /// Union can only be called on resources with matching `tid`.
680    /// (NB: equivalent to Haskell `Data.Map.unionWith perm_union`)
681    pub fn union(&mut self, other: &Resources) {
682        assert_eq!(self.tid, other.tid);
683        // Union describes a combined operation, not the exact wait whose owner
684        // captured the snapshot. Never promote either operand's authority.
685        self.in_guest_sleep_sigalrm = None;
686        for (id, perm2) in other.resources.iter() {
687            match self.resources.entry(id.clone()) {
688                Entry::Occupied(mut e) => {
689                    let perm1 = e.get_mut();
690                    *perm1 = perm1.union(perm2)
691                }
692                Entry::Vacant(e) => {
693                    e.insert(perm2.clone());
694                }
695            }
696        }
697        match (self.signal_interrupt_errno, other.signal_interrupt_errno) {
698            (None, interrupt) => self.signal_interrupt_errno = interrupt,
699            (Some(left), Some(right)) => assert_eq!(left, right),
700            (Some(_), None) => {}
701        }
702        self.backend_runtime_bootstrap |= other.backend_runtime_bootstrap;
703        match (self.blocked_signal_mask, other.blocked_signal_mask) {
704            (None, mask) => self.blocked_signal_mask = mask,
705            (Some(left), Some(right)) => assert_eq!(left, right),
706            (Some(_), None) => {}
707        }
708        self.blocked_signal_mask_unknown |= other.blocked_signal_mask_unknown;
709        if self.signal_state_task.is_none() {
710            self.signal_state_task = other.signal_state_task;
711        }
712        self.decides_signal_interruption_itself |= other.decides_signal_interruption_itself;
713        self.replay_served_from_log |= other.replay_served_from_log;
714        self.polls_guest_state_only |= other.polls_guest_state_only;
715        self.waits_until_nothing_else_can_run |= other.waits_until_nothing_else_can_run;
716        self.previous_attempt_made_progress |= other.previous_attempt_made_progress;
717        self.upgraded_from_attempt = self.upgraded_from_attempt.max(other.upgraded_from_attempt);
718        // A merged request waits for the earlier of two deadlines.
719        self.poll_deadline = match (self.poll_deadline, other.poll_deadline) {
720            (Some(left), Some(right)) => Some(left.min(right)),
721            (left, right) => left.or(right),
722        };
723    }
724
725    /// The deadline at which this request, still queued for a turn, would
726    /// time out: a sleep's wake-up time or a backed-off poll's timeout.
727    pub(crate) fn queued_deadline(&self) -> Option<LogicalTime> {
728        let sleep = self.resources.keys().find_map(|resource| match resource {
729            ResourceID::SleepUntil(deadline) if !deadline.is_indefinite() => Some(*deadline),
730            _ => None,
731        });
732        match (sleep, self.poll_deadline) {
733            (Some(a), Some(b)) => Some(a.min(b)),
734            (a, b) => a.or(b),
735        }
736    }
737
738    /// Return the owner snapshot only for an unmodified singleton sleep.
739    pub(crate) fn in_guest_sigalrm_sleep(&self) -> Option<(InGuestSleepSigalrm, LogicalTime)> {
740        if self.resources.len() != 1
741            || self.poll_attempt != 0
742            || self.signal_interrupt_errno.is_some()
743            || self.blocked_signal_mask.is_some()
744            || self.replay_served_from_log
745            || self.backend_runtime_bootstrap
746            || self.poll_deadline.is_some()
747        {
748            return None;
749        }
750        let (ResourceID::SleepUntil(deadline), Permission::W) = self.resources.iter().next()?
751        else {
752            return None;
753        };
754        if !(self.fyi == PAUSE_FYI && deadline.is_indefinite() || self.fyi == NANOSLEEP_FYI) {
755            return None;
756        }
757        Some((self.in_guest_sleep_sigalrm?, *deadline))
758    }

783    // Test if the request corresponds to an exit or exit_group.
784    // If it does, return a synthetic copy of the syscall which would generate this resource request.
785    pub fn as_exit_syscall(&self) -> Option<Syscall> {
786        let exit = self.resources.keys().find_map(|resource| match resource {
787            ResourceID::Exit { group, process, mm } => Some((*group, *process, *mm)),
788            _ => None,
789        });
790        if exit.is_some() && self.resources.len() > 1 {
791            panic!(
792                "is_polling_turn: not expecting an InternalIOPolling mixed in with other resource requests: {:?}",
793                self
794            );
795        }
796        if exit.is_some_and(|(group, _, _)| group) {
797            Some(Syscall::ExitGroup(Default::default())) // This status code is dummy.
798        } else if exit.is_some() {
799            Some(Syscall::Exit(Default::default())) // This status code is dummy.
800        } else {
801            None
802        }
803    }

809            _ => None,

814/// Is the resource to be used for writing, reading or both?
815#[derive(PartialEq, Debug, Eq, Clone, Serialize, Deserialize, Hash)]
816pub enum Permission {
817    /// Read permission.
818    R,
819    /// Write permission.
820    W,
821    /// Read+Write permission.
822    RW,
823}
824
825impl Permission {
826    /// Take the union of requested permissions.
827    pub fn union(&self, other: &Permission) -> Permission {
828        use Permission::*;
829        match (self, other) {
830            (R, R) => R,
831            (R, W) => RW,
832            (W, R) => RW,
833            (W, W) => W,
834            (RW, _) => RW,
835            (_, RW) => RW,
836        }
837    }
838}

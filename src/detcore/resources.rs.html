117/*
118NOTE [Blocking Syscalls via Internal Polling]
119---------------------------------------------
120
121A system like hermit which sequentializes execution must have the ability to detect
122blocking operations, so as not to deadlock the system. (This remains true irrespective of
123whether sequentialization is relaxed to admit some parallelism.)
124
125One option is for hermit to *precisely* model everything that may cause a syscall to
126block, and run the syscall only when it is certain that it can complete.  This is the
127approach with the precise implementation of futexes, for example, but it is tricky in
128general and requires hermit recapitulate a lot of the logic in the Linux kernel.
129
130Hence the need for this quick-and-dirty alternative of polling for internal blocking
131operations. The idea is that many potentially-blocking syscalls have the option to be run
132in a non-blocking fashion. This concept is captured by the `NonBlockableSyscall` trait.
133
134The way the polling strategy works is that the handler inside the guest converts the
135syscall to its nonblocking form (or ensures it runs nonblocking via file descriptor
136configuration).  The handler executes the syscall in a loop, while increasing the
137`poll_attempt` to make it visible to the scheduler that these are retries of a [logically]
138blocking operation, rather than new operations.
139
140The scheduler can then interleave these polling operations into the deterministic
141linearization of all guest side effects, just like any other operations.  However, it is a
142good idea to have some form of "backoff" when polling, because this strategy can
143asymptotically increase the total number of syscalls performed. For example, there are a
144large number of threads polling, and one thread productively running, we don't want to
145poll every thread once for every step of productive work. Conversely, we want to guarantee
146that no poller is starved indefinitely, because that could lead to live lock in the
147presence of any kind of "busy waiting".
148
149Determinism And linearization assumptions
150-----------------------------------------
151
152Why is this strategy deterministic?  How can we guarantee that on two separate executions,
153the same syscall `S` will retry exactly `N` times at times `T_1 ... T_n`?
154
155The assumption we make here is that all syscalls, even across multiple cores, act as
156atomic operations on the kernel state --- from the guest's perspective.  That is, halfway
157through executing a guest, we can describe the prior history of system as the linear
158series of syscalls committed to the kernel. Does this actually hold for Linux?  It doesn't
159seem to be documented anywhere, and Linux doesn't have anything like a formal semantics.
160For most syscalls we treat their man pages as the spec, and they don't answer questions
161like this.
162
163If we execute a guest entirely on one core, then only a weaker form of the assumption
164needs to hold.
165
166The upshot is, because we make this "linearizability of syscalls" assumption, each polling
167attempt for a given syscall is assumed to deterministically succeed or fail based on the
168history of syscalls that committed before it.
169
170The troublesome race
171--------------------
172
173One may wonder why not simply implement polling by *letting* the operation block,
174backgrounding the thread, and then checking in at each polling point to see if the
175operation has completed *without* incurring a user/kernel context switch and executing the
176syscall again. This would indeed be great, but it would require an oracle that can answer
177the question: "has thread X unblocked yet"?
178
179### A non-solution dead-end:
180
181We can recapture control flow immediately after any blocking syscall (in the handler), but
182that "posthook" won't run until (1) the syscall unblocks, and (2) the OS gets around to
183actually scheduling the thread.  Thus, inside the scheduler, we are racing with threads
184like this that are unblocked and in the process of attempting to report for duty.  Such
185threads can signal their readiness by tweaking the scheduler data structures, but those
186updates arrive completely asynchronously.  For example, if a syscall unblocks on scheduler
187turn 100 in one run, how can we know it won't arrive late at turn 101 on the next run?  We
188can't determinize the point that the formerly-blocked thread rejoins the scheduler pool.
189Not unless we do some huge (realtime) wait at each scheduler turn to ensure the OS has had
190a chance to run any recently-unblocked threads!
191
192### Future work: efficient oracle
193
194This nondeterministic-rejoining-the-pool strategy is exactly what we do for *externally*
195blocked syscalls.  But for internally-blocked ones that we want to determinize, then we
196would need a more efficient "has-unblocked?" oracle.  For example, if we had a kernel
197module exposing a safe predicate function that reveals this information to userspace. It's
198possible that the /proc file system exposes enough information to synchronously poll a
199threads status.
200
201But solving this may be extremely difficult, or impossible.  If the syscall that ran
202before us unblocked a thread, how long does that status update take to propogate through
203the kernel itself?  If one futex wake syscall unblocks 1000 other threads, their status
204would have to atomically change immediately by the time the futex wake returns to the
205guest, or at least by the start of the next syscall (or oracle call).
206
207This atomicity property seems hard to guarantee for the OS. Instead, the current polling
208strategy that uses nonblocking syscalls is much more localized.  It doesn't treat the
209kernel state as monolithic and require atomic updates from the guest perspective, but
210rather it only requires atomic treatment of whatever state is relevant to syscalls
211operating on that individual resource (futex, file descriptor etc) --- a much less
212stringent requirement.
213
214*/

217/// (system calls) taken by the detcore guest.  Some actions may affect multiple resources.

394impl ResourceID {
395    /// Whether a granted request for this resource makes its thread's call a
396    /// kernel-run blocking call: the call runs outside the schedule, in the
397    /// kernel, where it may sleep for as long as the kernel decides, while
398    /// the scheduler commits other threads' turns. The thread rejoins with a
399    /// [`ResourceID::BlockedExternalContinue`] request (a failed vfork with
400    /// [`ResourceID::VforkFailed`]), filed at a moment host timing chooses.
401    /// So, in committed state, the call is running from the grant of this
402    /// resource until the grant of that request.
403    ///
404    /// This is the published list of kernel-run blocking calls of the A5
405    /// signal-delivery design (dev-hermit
406    /// `ai_docs/2026-10-16-a5-signal-delivery-design.md`, 16.11). Step 3c.1
407    /// refuses by name a caught or default-fatal signal that a committed send
408    /// makes pending for a thread in one of them, because the in-guest
409    /// runtime's mask keeps the signal pending where Linux would interrupt
410    /// the call. The request names the call: its `fyi` is the syscall's name,
411    /// or `clone_vfork`.
412    ///
413    /// That reason holds for a call that sleeps under the thread's own mask.
414    /// Three forms instead hand the kernel the guest's temporary mask
415    /// (`Resources::blocked_signal_mask`): `rt_sigsuspend` as
416    /// `BlockingRtSigsuspend`, `rt_sigsuspend` with a signal already pending
417    /// as `BlockingExternalIO`, and a masked `pselect6` with `nfds` above 64.
418    /// The kernel installs that mask for the call, so a caught signal it
419    /// unblocks interrupts the call and is delivered on the return into
420    /// runtime code. That is the temporary-mask problem of 16.11 (step 3c.w),
421    /// not a signal kept pending.
422    ///
423    /// A call that may block inside its own turn is not one. The scheduler
424    /// commits no other turn until that thread files its next request, so no
425    /// committed send and no expiry can make a signal pending for it
426    /// meanwhile.
427    ///
428    /// Which calls file these requests is decided by their handlers, from
429    /// Detcore's descriptor model and configuration. The list applies to a
430    /// sequentialized `hermit run`, the configuration in which the in-guest
431    /// backends run (record and replay run on ptrace). Without sequentialized
432    /// threads, `resource_request` sends no request to the scheduler, so
433    /// nothing is granted in the background and there is no committed state
434    /// to key on. In a sequentialized `hermit run` they are:
435    /// - `rt_sigsuspend`, always, except on a backend whose `rt_sigsuspend`
436    ///   never sleeps (`rt_sigsuspend_never_sleeps`, KVM);
437    /// - `vfork`, and `clone` or `clone3` with `CLONE_VFORK` (the in-guest
438    ///   runtime refuses those two before they run);
439    /// - `read` and `readv` of an inherited external input;
440    /// - `read`, `recvfrom`, `recvmsg`, `recvmmsg`, `sendto`, `sendmsg`,
441    ///   `sendmmsg`, `connect`, `accept` and `accept4` on a descriptor that is
442    ///   blocking both logically and physically, or that Detcore cannot
443    ///   classify (`execute_nonblockable_fd_syscall`). Detcore makes the
444    ///   sockets, pipes and eventfds it creates physically nonblocking, and
445    ///   its timerfds while time is virtual, so these are, for example,
446    ///   inotify and signalfd descriptors and sockets Detcore did not create;
447    /// - `select` and `pselect6` with `nfds` above 64 and a timeout that is
448    ///   not zero (a zero timeout runs in the turn first);
449    /// - `futex` under `--debug-futex-mode=external`. (A `restart_syscall`
450    ///   never resumes such a wait: Detcore keeps a futex restart record only
451    ///   in the precise and polling modes, which external mode returns
452    ///   before.)
453    ///
454    /// The scheduler grants exactly these resources in its background arm
455    /// (`Scheduler::block_for_one_resource`, which asserts it). The work-span
456    /// report also counts the continuation (`BlockedExternalContinue`) as a
457    /// wait outside the schedule, though the kernel call has returned by then.
458    ///
459    /// `write`, `writev` and `readv` on a physically blocking descriptor
460    /// (for `readv`, one that is not an inherited input), `preadv2` and
461    /// `pwritev2` at offset -1 on a stream, and a masked
462    /// `epoll_pwait` or `epoll_pwait2` on a backend without
463    /// `supports_blocked_wait_signal_interruption`, run in the turn instead.
464    ///
465    /// Exhaustive, so that a new variant has to be classified.
466    pub(crate) fn is_kernel_run_blocking(&self) -> bool {
467        match self {
468            ResourceID::BlockingExternalIO(_)
469            | ResourceID::BlockingVfork(_)
470            | ResourceID::BlockingRtSigsuspend(_) => true,
471            ResourceID::FileContents(_)
472            | ResourceID::FileMetadata(_)
473            | ResourceID::DirectoryContents(_)
474            | ResourceID::MemAddrSpace(_)
475            | ResourceID::Path(_)
476            | ResourceID::PathsTransitive(_)
477            | ResourceID::Device(_)
478            | ResourceID::Exit { .. }
479            | ResourceID::ParentContinue { .. }
480            | ResourceID::SleepUntil(_)
481            | ResourceID::InternalIOPolling
482            | ResourceID::TraceReplay
483            | ResourceID::FutexWait
484            | ResourceID::VforkFailed(_)
485            | ResourceID::BlockedExternalContinue(_)
486            | ResourceID::PriorityChangePoint(..)
487            | ResourceID::WaitChild { .. }
488            | ResourceID::WaitPhysicalChild(_)
489            | ResourceID::InboundSignal(_)
490            | ResourceID::WaitidSignals(_)
491            | ResourceID::SchedYield
492            | ResourceID::HappensBeforeCheckpoint(_)
493            | ResourceID::HappensBeforeSyscallCheckpoint { .. }
494            | ResourceID::HappensBeforePosthookInterrupted { .. }
495            | ResourceID::InGuestFatalAlarm => false,
496        }
497    }
498}

521/// `Resources` is a request to lock zero or more resources so that the thread can perform an action.
522///
523/// There can only be one outstanding request at a time for a given TID.
524#[derive(PartialEq, Eq, Clone, Serialize, Deserialize)]

527    pub tid: DetTid,
528    /// The set of resources requested.
529    pub resources: HashMap<ResourceID, Permission>,
530    /// If the guest thread is polling the resource, retrying until success, it should
531    /// increment this field after each attempt, as a hint to the scheduler to deprioritize it.
532    /// That is, requests with a nonzero value will be deprioritized. Zero values will be treated
533    /// normally.
534    pub poll_attempt: u32,
535    /// A bit of metadata (just for debugging), about what the thread is trying to do with the
536    /// resources.
537    pub fyi: String,
538    /// Errno returned when an established signal interruption happens before a
539    /// syscall makes progress. Its presence also asks the caller to classify a
540    /// signal wake after partial progress, when Linux returns the byte count
541    /// instead. `None` does not make an `InternalIOPolling` request eligible
542    /// for the scheduler's cross-task signal wakeup.
543    #[serde(default)]
544    pub(crate) signal_interrupt_errno: Option<i32>,
545    /// Set by `tool_global::resource_request` when this request is made while
546    /// the thread is handling a syscall whose cost is withheld because it
547    /// belongs to a backend-runtime bootstrap window (see
548    /// `ThreadState::charge_syscall_time`). The scheduler withholds the
549    /// per-turn scheduler time of such a turn, unless it is an IO-polling
550    /// retry, for the same reason the syscall cost is withheld: the turn
551    /// exists only because the backend's runtime made the syscall, so charging
552    /// it would make guest-visible virtual time depend on the backend. `false`
553    /// for every request from a backend without such a runtime, and for
554    /// requests that do not go through `resource_request`.
555    #[serde(default)]
556    pub(crate) backend_runtime_bootstrap: bool,

921    /// Similar to extend, but union all permissions within the intersection.
922    /// Union can only be called on resources with matching `tid`.
923    /// (NB: equivalent to Haskell `Data.Map.unionWith perm_union`)
924    pub fn union(&mut self, other: &Resources) {
925        assert_eq!(self.tid, other.tid);
926        assert!(
927            self.slice_boundary.is_none() && other.slice_boundary.is_none(),
928            "slice-boundary protocol refuses merging an annotated operation"
929        );
930        // Union describes a combined operation, not the exact wait whose owner
931        // captured the snapshot. Never promote either operand's authority.
932        self.in_guest_sleep_sigalrm = None;
933        for (id, perm2) in other.resources.iter() {
934            match self.resources.entry(id.clone()) {
935                Entry::Occupied(mut e) => {
936                    let perm1 = e.get_mut();
937                    *perm1 = perm1.union(perm2)
938                }
939                Entry::Vacant(e) => {
940                    e.insert(perm2.clone());
941                }
942            }
943        }
944        match (self.signal_interrupt_errno, other.signal_interrupt_errno) {
945            (None, interrupt) => self.signal_interrupt_errno = interrupt,
946            (Some(left), Some(right)) => assert_eq!(left, right),
947            (Some(_), None) => {}
948        }
949        self.backend_runtime_bootstrap |= other.backend_runtime_bootstrap;
950        match (self.blocked_signal_mask, other.blocked_signal_mask) {
951            (None, mask) => self.blocked_signal_mask = mask,
952            (Some(left), Some(right)) => assert_eq!(left, right),
953            (Some(_), None) => {}
954        }
955        self.blocked_signal_mask_unknown |= other.blocked_signal_mask_unknown;
956        // Both parts are the same thread's, stopped at the same request.
957        match (self.guest_signal_mask, other.guest_signal_mask) {
958            (None, mask) => self.guest_signal_mask = mask,
959            (Some(left), Some(right)) => assert_eq!(left, right),
960            (Some(_), None) => {}
961        }
962        if self.signal_state_task.is_none() {
963            self.signal_state_task = other.signal_state_task;
964        }
965        self.decides_signal_interruption_itself |= other.decides_signal_interruption_itself;
966        // A combined operation is a continuation only if both parts are.
967        self.continues_sigreturn &= other.continues_sigreturn;
968        self.private_sigchld_decides |= other.private_sigchld_decides;
969        self.replay_served_from_log |= other.replay_served_from_log;
970        self.polls_guest_state_only |= other.polls_guest_state_only;
971        self.relies_on_guest_held_marks |= other.relies_on_guest_held_marks;
972        self.passes_descriptors_out |= other.passes_descriptors_out;
973        self.waits_until_nothing_else_can_run |= other.waits_until_nothing_else_can_run;
974        // A combined operation is a zero-length sleep only if both parts are.
975        self.zero_length_sleep &= other.zero_length_sleep;
976        self.previous_attempt_made_progress |= other.previous_attempt_made_progress;
977        self.upgraded_from_attempt = self.upgraded_from_attempt.max(other.upgraded_from_attempt);
978        // A merged request waits for the earlier of two deadlines.
979        self.poll_deadline = match (self.poll_deadline, other.poll_deadline) {
980            (Some(left), Some(right)) => Some(left.min(right)),
981            (left, right) => left.or(right),
982        };
983    }

985    /// The deadline at which this request, still queued for a turn, would
986    /// time out: a sleep's wake-up time or a backed-off poll's timeout.
987    pub(crate) fn queued_deadline(&self) -> Option<LogicalTime> {
988        let sleep = self.resources.keys().find_map(|resource| match resource {
989            ResourceID::SleepUntil(deadline) if !deadline.is_indefinite() => Some(*deadline),
990            _ => None,
991        });
992        match (sleep, self.poll_deadline) {
993            (Some(a), Some(b)) => Some(a.min(b)),
994            (a, b) => a.or(b),
995        }
996    }

1021            return None;
1022        }
1023        let (ResourceID::SleepUntil(deadline), Permission::W) = self.resources.iter().next()?
1024        else {
1025            return None;
1026        };
1027        if !(self.fyi == PAUSE_FYI && deadline.is_indefinite() || self.fyi == NANOSLEEP_FYI) {
1028            return None;
1029        }
1030        Some((self.in_guest_sleep_sigalrm?, *deadline))
1031    }

1056    // Test if the request corresponds to an exit or exit_group.
1057    // If it does, return a synthetic copy of the syscall which would generate this resource request.
1058    pub fn as_exit_syscall(&self) -> Option<Syscall> {
1059        let exit = self.resources.keys().find_map(|resource| match resource {
1060            ResourceID::Exit { group, process, mm } => Some((*group, *process, *mm)),
1061            _ => None,
1062        });
1063        if exit.is_some() && self.resources.len() > 1 {
1064            panic!(
1065                "is_polling_turn: not expecting an InternalIOPolling mixed in with other resource requests: {:?}",
1066                self
1067            );
1068        }
1069        if exit.is_some_and(|(group, _, _)| group) {
1070            Some(Syscall::ExitGroup(Default::default())) // This status code is dummy.
1071        } else if exit.is_some() {
1072            Some(Syscall::Exit(Default::default())) // This status code is dummy.
1073        } else {
1074            None
1075        }
1076    }

1087/// Is the resource to be used for writing, reading or both?
1088#[derive(PartialEq, Debug, Eq, Clone, Serialize, Deserialize, Hash)]
1089pub enum Permission {
1090    /// Read permission.
1091    R,
1092    /// Write permission.
1093    W,
1094    /// Read+Write permission.
1095    RW,
1096}
1097
1098impl Permission {
1099    /// Take the union of requested permissions.
1100    pub fn union(&self, other: &Permission) -> Permission {
1101        use Permission::*;
1102        match (self, other) {
1103            (R, R) => R,
1104            (R, W) => RW,
1105            (W, R) => RW,
1106            (W, W) => W,
1107            (RW, _) => RW,
1108            (_, RW) => RW,
1109        }
1110    }
1111}

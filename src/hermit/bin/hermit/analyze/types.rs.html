40/// Repeat a run multiple times in a controlled search to find concurrency bugs.
41///
42/// Hermit analyze searches over runs of `hermit run`, and its primary input is a set of CLI flags
43/// that constitute a hermit run, i.e., ARGS in `hermit run ARGS`.  These arguments are passed to
44/// all runs that analyze considers (but some options may be overwritten by the settings varied by
45/// analyze's search process).
46///
47/// The analyzer is interested in programs with some *target* property (such as non-zero exit code
48/// due to crashing).  Analyze must have, or find, a `hermit run` execution that exhibits this
49/// target property. If the target "run1" is not explicitly provided, the tool can search for it
50/// (--search).
51///
52/// Analyze must also have a second (baseline) one that does not. If a "run2" is not provided,
53/// analyze assumes that a hermit run without chaos is the baseline.
54///
55/// Finally, given a target and a baseline run, the job of analyze is to search between them and
56/// find the critical events: instructions which, when reordered, cause the target property to hold
57/// or not.  This is evidence of an order violation or race condition bug, and means the the program
58/// has at least one concurrency bug.
59///
60/// The critical events are identified to the user by printing their stack traces, optionally into a
61/// separate report file.
62#[derive(Debug, Parser, Clone)]

104    /// Before searching, minimize the target run's chaos-mode interventions (its preemptions
105    /// and priority changes) to those it needs to meet the target criteria, by knocking them out
106    /// a batch at a time. This may accelerate the subsequent binary search.
107    ///
108    /// The baseline is then the minimized record with its latest intervention knocked out, and
109    /// knocked out again while the replay still meets the target. When no intervention is left,
110    /// there is no baseline to bisect against and the analysis ends with that error, as it does
111    /// with the run's own error for a knocked-out run that does not finish; `--prefix-search`
112    /// needs no baseline. So `--minimize` finds its own baseline and does not
113    /// take `--run2-seed`, `--run2-preemptions` or `--run2-schedule`. To search between a given
114    /// pair of runs, omit `--minimize`.
115    #[clap(
116        long,
117        conflicts_with = "run2_seed",
118        conflicts_with = "run2_preemptions",

123    /// Search within the target run's schedule instead of between it and a baseline run.
124    ///
125    /// Each trial replays the first K events of the target schedule and then lets the
126    /// scheduler continue without chaos. Replaying none of it gives the baseline outcome and
127    /// replaying all of it the target outcome; a binary search finds the K at which the
128    /// outcome flips. Event #K is the scheduling decision that commits the run to the target:
129    /// the report shows the stack of the thread the target schedule runs there and of the
130    /// thread the scheduler would run instead. Each stack is taken where the trial's replay
131    /// consumes the recorded event at position K, however many polling retries the trial
132    /// made before it.
133    ///
134    /// Unlike the default search, it needs no baseline schedule, so events that only one of
135    /// two unrelated runs executed (timeslices that end at other points, iterations of a
136    /// polling loop) cannot stop it. It takes about log2(schedule length) trials, two more for
137    /// each continuation (`--continuation-timeslice`) it tries, and two to recheck the
138    /// boundary.
139    #[clap(
140        long,
141        conflicts_with = "minimize",
142        conflicts_with = "run2_seed",
143        conflicts_with = "run2_preemptions",
144        conflicts_with = "run2_schedule",
145        conflicts_with = "run_needleman"
146    )]

149    /// The timeslice, in virtual nanoseconds, with which `--prefix-search` trials continue
150    /// without chaos after their replayed prefix: `auto` (the default) or a number.
151    ///
152    /// A race found only at a short timeslice often shows without chaos at that timeslice too:
153    /// the scheduler alone, replaying none of the target schedule, already meets the target,
154    /// and the search has nothing to bisect against. With `auto` the search continues at the
155    /// run's own `--max-timeslice`, and when that cannot serve (the scheduler alone meets the
156    /// target, or replaying the whole schedule misses it) at hermit's default 200 ms. This also
157    /// applies to the prefix search the default search falls back to. The report names the
158    /// timeslice the search used.
159    ///
160    /// The value is the trials' `--max-timeslice`, which also ends the replayed prefix's
161    /// slices that its schedule does not end, so it may not be shorter than the run's own, and
162    /// a run whose arguments disable PMU timeslices takes none.
163    #[clap(long, value_name = "NANOS|auto", default_value = "auto")]
164    pub continuation_timeslice: ContinuationTimeslice,

310    /// Wall-clock bound on each run after the initial target attempt (and, when explicit, on the
311    /// replay of a `--run1-preemptions` record): a positive number of seconds, `auto` (the
312    /// default), or `off`.
313    ///
314    /// With `auto`, the initial run and completed target/baseline endpoint runs are measured.
315    /// Later runs are bounded at max(60 s, 10 times the slowest measured run), rounded up to
316    /// whole seconds. With `--run1-preemptions`, the initial run is a replay of the record: it
317    /// is measured like a seed's, and an explicit number bounds it too.
318    /// A trial that reaches its bound stops analysis with exit 124: it establishes no outcome
319    /// and cannot support a successful report. Retry with a larger bound if the guest can
320    /// finish. A `--timeout` in the run arguments also bounds the initial run and wins wherever
321    /// it is shorter. `off` removes only analyze's bounds, not the run arguments' timeout.
322    ///
323    /// The bound needs a backend on which `hermit run --timeout` is qualified; elsewhere `auto`
324    /// gives no bound and an explicit number is refused. Use an outer timeout there.
325    /// While trials are bounded, the log files they write under `--trial-log` above warn or
326    /// `--selfcheck` are capped at max(64 MiB, 10 times the largest measured endpoint log),
327    /// within HERMIT_LOG_MAX_BYTES.
328    /// HERMIT_LOG_MAX_BYTES=0 lifts both file caps; `off` lifts analyze's file cap.

343    /// Keep the workspace (see --tmp-dir) when analyze exits.
344    ///
345    /// The workspace holds every run's schedules, logs, output and reproducer command, and the
346    /// paths analyze prints name it. By default analyze removes it when it exits after its
347    /// report, and when SIGTERM, SIGINT or SIGHUP stops it; after an error it keeps it, since
348    /// the error can name trial files in it. A stop signal ends the run in progress and starts
349    /// no other; analyze then removes the workspace and dies of that signal (a shell reports
350    /// 128 plus its number, 143 for SIGTERM). --verbose, and --trial-log above warn, keep the
351    /// workspace too. The report file (--report-file) is never removed. Without --keep-tmp, even
352    /// with --verbose, a bisection trial's schedules are removed as soon as its outcome is read,
353    /// and every run's recording with event times once analyze has written it without them.
354    ///
355    /// Analyze cannot clean up after SIGKILL, nor after a stop signal it does not handle: one it
356    /// inherits as ignored stays ignored, and an analyze that is PID 1 of its PID namespace
357    /// (`docker run IMAGE hermit analyze ...` without --init) leaves the stop signals at their
358    /// default actions, which Linux discards for a namespace's init. Neither does it handle
359    /// them, so that they kill it at once as before, when /proc is not its own PID namespace's
360    /// (analyze started by another process inside `unshare -pf` without --mount-proc), when
361    /// it inherited more than 64 children, or where it cannot open, signal through or wait on
362    /// a pidfd (Linux before 5.4, or a seccomp filter), through which alone it signals the run.
363    /// A stop it cannot pass on to the run (no file descriptor left) makes it die of the
364    /// signal as without its handler, saying why; the run dies with it, and the workspace and
365    /// the running trial's private temporary directory stay.
366    #[clap(long)]
367    pub keep_tmp: bool,

369    /// Wall-clock time this invocation may spend before it reports what it has found so far:
370    /// `off` (the default), or a whole number of seconds, minutes or hours (`1800`, `30m`,
371    /// `2h`).
372    ///
373    /// The budget is checked before every run, and each run's `--timeout` is shortened to the
374    /// time left. A run the budget cuts short is thrown away, not counted as not meeting the
375    /// target, so the budget decides only when analyze stops, never what it finds. When it runs
376    /// out, analyze reports its best answer so far and exits 120 (a partial result): the
377    /// default search's current pair of schedules, whose replays miss and meet the target, and
378    /// the first event at which they differ; or `--prefix-search`'s bracket, the longest prefix
379    /// known to miss the target and the shortest known to meet it. The report says that it is
380    /// partial, why, and which phase was running, after the stderr line
381    /// `HERMIT_ANALYZE_PARTIAL class=time-budget`. The workspace is then kept, even without
382    /// --keep-tmp, and the report gives the command that continues the analysis (--resume).
383    /// The default search's report replays its two schedules for their stacks only when two
384    /// such runs fit min(120 s, 5% of the budget) after it ran out; the report says when they
385    /// did not. A budget that runs out after the search finished, during its final replays,
386    /// reports no decision: analyze names one only once those replays repeat the search's
387    /// outcomes.
388    /// Computation between runs (the default search's schedule distances) is not
389    /// interrupted, so analyze may overrun the budget by that much; an outer kill bound should
390    /// sit above the budget plus that grace, so that analyze stops itself first.

635impl EndpointMeasurements {

638        if let Some(bytes) = log_bytes {
639            self.largest_log = self.largest_log.max(Some(bytes));

652#[derive(Debug, Eq, PartialEq, Clone)]
653pub enum ExitStatusConstraint {
654    /// Accept only a specific exit code.
655    Exact(i32),
656    /// Accept any nonzero exit code.
657    NonZero,
658    /// Accept any exit code.  No filter.
659    Any,
660}
661
662/// The exit code a shell reports for a run that ended with `status`: the
663/// guest's own code, or 128 plus the signal number for a signal death. Not
664/// the raw wait status, which shifts an exit code left by eight bits.
665pub fn run_exit_code(status: ExitStatus) -> i32 {
666    match status {
667        ExitStatus::Exited(code) => code,
668        ExitStatus::Signaled(signal, _) => detcore_model::signal_exit_status(signal as i32),
669        ExitStatus::SignaledRaw(signal, _) => detcore_model::signal_exit_status(signal),
670    }
671}
672
673impl ExitStatusConstraint {
674    /// Is the constraint met for a run that ended with `exit_status`
675    /// ([`run_exit_code`])?
676    pub fn is_match(&self, exit_status: ExitStatus) -> bool {
677        let exit_code = run_exit_code(exit_status);
678        match self {
679            ExitStatusConstraint::Exact(code) => exit_code == *code,
680            ExitStatusConstraint::NonZero => exit_code != 0,
681            ExitStatusConstraint::Any => true,
682        }
683    }
684}
685
686impl FromStr for ExitStatusConstraint {
687    type Err = String;
688
689    fn from_str(s: &str) -> Result<Self, Self::Err> {
690        if let Ok(n) = s.parse::<i32>() {
691            if !(0..=255).contains(&n) {
692                return Err(format!(
693                    "Exit code constraint {n} is out of range: an exit code is 0 to 255 (128 plus \
694                     the signal number for a signal death)"
695                ));
696            }
697            Ok(ExitStatusConstraint::Exact(n))
698        } else {
699            match s.to_lowercase().as_str() {
700                "nonzero" => Ok(ExitStatusConstraint::NonZero),
701                "none" | "any" => Ok(ExitStatusConstraint::Any),
702                _ => Err(format!(
703                    "Unable to parse string as exit code constraint, expected a number, 'none'/'any', or 'nonzero'.  Received: {}",
704                    s
705                )),
706            }
707        }
708    }
709}
710
711/// `--success-exit-code`: an exit status, 0 to 255, but those that already
712/// mean something else for analyze (see the exit-code allocation table in
713/// `hermit::lib`). A process exits with the low 8 bits of the value it
714/// passes (`exit`, `exit_group`: `(error_code & 0xff) << 8`,
715/// <https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git/tree/kernel/exit.c?h=v6.9#n992>),
716/// so a value outside that range is refused before the reserved ones are
717/// checked: 258 would exit 2 and 378 or -134 would exit 122.
718fn parse_success_exit_code(text: &str) -> Result<i32, String> {
719    let code: i32 = text
720        .parse()
721        .map_err(|error| format!("{text:?} is not a 32-bit integer: {error}"))?;
722    if !(0..=255).contains(&code) {
723        return Err(format!(
724            "{code} is not an exit status: a process exits with the low 8 bits of the value it \
725             passes, 0 to 255, so a process exiting with {code} exits {}",
726            code & 0xff
727        ));
728    }
729    match code {
730        hermit::HERMIT_ANALYZE_PRECONDITION_EXIT => Err(format!(
731            "{code} is the status analyze exits with when its inputs do not give it what it \
732             needs (HERMIT_ANALYZE_PRECONDITION), so a success could not be told apart from it"
733        )),
734        120..=127 => Err(format!(
735            "{code} is in 120 to 127, which Hermit reserves for its own statuses (122 a refusal, \
736             123 the log cap, 124 a deadline, 125 an internal failure, 126 and 127 a program \
737             that cannot run), so a success could not be told apart from them"
738        )),
739        _ => Ok(code),
740    }
741}

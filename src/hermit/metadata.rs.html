25/// Hermit record version. Recorded as part of hermit-record, hermit-replay

40impl RecordVersion {
41    /// Check if the recorder/replayer version is compatible with a given

48/// hermit record/replay version.
49// NB: Increase the version number when there are breaking changes, i.e.:
50// when new syscalls or event schemas are added.
51//
52// AUTONOMOUS-BOT-IMPLEMENTED
53// TODO-HUMAN-REVIEW(#2373)
54// 0x10b -> 0x10c: flock(2) stopped being a Detcore no-op and now reaches
55// `record_or_replay`, so a post-fix run emits a `Return` event per flock call.
56// Replay re-issues calls for materialized descriptors and fails closed when it
57// cannot reproduce the lock side effect. A 0x10b recording contains NO flock
58// event at all -- the old handler returned Ok(0) before ever reaching the
59// recorder, even though flock was already classified Determinized -- so
60// replaying one under this build would read the next thread event for every
61// flock and desynchronize the stream. The version gate must refuse it.
62//
63// TODO-HUMAN-REVIEW(#2370)
64// 0x10d -> 0x10e: record/replay now carries successful exec image/path state and
65// an explicit ppoll timeout-pointer shape. Older readers cannot interpret those
66// events without desynchronizing the stream, so the format advances once.
67//
68// TODO-HUMAN-REVIEW(#2272)
69// 0x10c -> 0x10d: `Ppoll` becomes its OWN event rather than sharing `Poll`'s,
70// because ppoll additionally copies out a timeout and must preserve it on
71// EINTR and on a partial EFAULT copy-out; and `Poll` itself now records the
72// partial `revents` copy-out an error return leaves behind. The recorded
73// stream therefore carries a different event shape for both syscalls.
74//
75// ONE increment covers BOTH halves deliberately. This branch bumped twice --
76// once per format change -- but a reader either understands the new stream or
77// it does not, so what matters is that the version differs from every stream
78// a different shape was written under. Landing two increments would imply a
79// 0x10d recording exists that this build can read and it cannot: no build
80// ever wrote one.
81//
82// ⚠️ THIS BUMP IS WHY THE REBASE COULD NOT SIMPLY TAKE EITHER SIDE. This
83// change was authored against 0x10a and bumped to 0x10b; main has since gone
84// to 0x10c for the unrelated flock work. Keeping the branch's 0x10b would
85// move the version BACKWARDS and let a 0x10c flock recording be replayed by a
86// build whose ppoll events have a different shape. Keeping main's 0x10c
87// unchanged would be worse: the format would change with no bump at all, so a
88// recording made here would claim 0x10c while containing a `Ppoll` event the
89// 0x10c reader does not know -- exactly the desynchronization the paragraph
90// above exists to prevent. The version must go FORWARD once more.
91//
92// AUTONOMOUS-BOT-IMPLEMENTED
93// TODO-HUMAN-REVIEW(#2407)
94// 0x10e -> 0x10f: pidfd_getfd(2) is now explicitly subscribed and recorded.
95// Earlier builds let the syscall bypass the recorder, so a successful call
96// changed the guest descriptor table without a corresponding stream event.
97// The replayer now consumes one exact pidfd_getfd event and reissues the
98// syscall to reproduce the kernel side effect; accepting a 0x10e stream would
99// therefore consume the next event at every pidfd_getfd call.
100//
101// 0x10f -> 0x110: metadata now carries the recording namespace's proven
102// Hermit-owned mount IDs. Detcore applies that map after both the recorder's
103// raw read and the replayer's ReadV2 copyout. An older recording has no map and
104// would replay different guest-visible mountinfo bytes under this sanitizer,
105// so accepting it would violate replay fidelity even though the event enum did
106// not change.
107//
108// 0x110 -> 0x111: metadata now also carries the recording namespace's full
109// raw mount-ID order. That makes fdinfo's mnt_id use the same canonical identity
110// as mountinfo during replay instead of consulting the unrelated replay
111// namespace or collapsing all descriptors to one mount.
112// 0x111 -> 0x113: fdinfo mount identities are now keyed by each observed raw
113// mount ID rather than broad descriptor classes. Metadata carries only the
114// completed namespace's mountinfo row/parent order; pseudo-filesystem IDs that
115// are absent from mountinfo are allocated afterward in deterministic guest
116// observation order. Replay must rebuild that mapping from recording-time raw
117// bytes, or pidfs/nsfs/anon_inodefs can be collapsed or rejected. The draft
118// 0x112 format was never shipped.
119//
120// 0x113 -> 0x114: recordings persist the completed guest's mountinfo order and
121// unlisted fdinfo mount-ID order, and event streams use stable recording-local
122// thread IDs rather than host PID allocation. An older reader cannot rebuild
123// either mapping reliably for a plain public record API recording.
124//
125// 0x114 -> 0x115: event stream filenames now encode deterministic process-tree
126// pedigrees instead of process-local allocation order. Older readers look for
127// integer filenames and cannot replay a recording containing child streams.
128//
129// 0x115 -> 0x116: event stream filenames are fixed-size SHA-256 names and each
130// data/debug stream begins with its complete process-tree identity. Older
131// readers cannot skip or validate these headers.
132// 0x116 -> 0x119: nonpositioned random-device readv now uses Detcore's
133// shared canonical cursor and no longer emits or consumes recorder ReadvV2
134// events. Old event streams cannot be replayed under this routing.
135// 0x117 and 0x118 identify incompatible retained RNG, clock, and network
136// recordings from parallel development; do not reinterpret those identities.
137// 0x119 -> 0x11a: random-device preadv/preadv2 now use Detcore's canonical
138// generator, including the shared cursor for preadv2(-1). They no longer emit
139// or consume ReadvV2 events; accepting an older recording would desynchronize
140// the event stream and replace its recorded random bytes.
141// Early rejection of invalid negative offsets also stops emitting ReadvV2
142// error events for non-random descriptors.
143// 0x11a -> 0x11b: sysinfo uptime rounds exact elapsed logical time up, removing
144// dependence on the calendar epoch's fraction. Detcore recomputes sysinfo during
145// recording/replay, even with virtualize_time=false; replaying an older stream
146// under the new projection could change guest control flow and event consumption.
147// Sysinfo remains determinized rather than gaining a recorded event.
148// 0x11b -> 0x11c: /proc/uptime renders the floor of exact elapsed logical time
149// instead of the difference of the separately truncated clock and epoch, so a
150// fractional epoch no longer moves it (or /proc/stat's idle ticks derived from
151// it) by one second. /proc/stat btime is now derived from the fixed boot
152// instant rather than from the clock minus uptime. Detcore recomputes these
153// fields over the recorded procfs bytes during recording and replay, so an older
154// stream replayed under the new projection could show the guest different bytes.
155// 0x11c -> 0x11d: with time not virtualized, which is always the case for
156// record/replay, detcore passes clock reads to record/replay instead of refusing
157// them. Streams now carry Timespec and Timeofday events for clock_gettime,
158// gettimeofday and time, and clock_getres gains a recorder event (Timespec, or
159// Return for a NULL `res`). An older reader would desynchronize on these events.
160// 0x11d -> 0x11e: guest-semantic madvise advice, which detcore used to refuse
161// with ENOSYS, now reaches the recorder and replayer and emits a Madvise event.
162// 0x11e -> 0x11f: faccessat, faccessat2, chdir, getcwd and the legacy path
163// mutations (rename, link, symlink, chmod, chown, lchown, mknod, rmdir) are
164// recorded instead of running live. A successful chdir or fchdir carries a
165// Bytes event naming the directory it entered. An older reader would
166// desynchronize on these events.
167// 0x11f -> 0x120: descriptor syncs and metadata changes (fsync, fdatasync,
168// syncfs, fchmod, fchown, fsetxattr, fremovexattr) record a Return event, the
169// xattr queries (getxattr, lgetxattr, fgetxattr and the listxattr family)
170// record a Bytes event (Return for a zero-size query), and zero-count read and
171// pread64 calls are recorded instead of running live. An older reader would
172// desynchronize on these events.
173// 0x120 -> 0x121: splice and tee refuse with EINVAL instead of ENOSYS; vmsplice
174// keeps ENOSYS. Record and replay always fail closed, and Detcore computes this
175// refusal itself rather than recording it, so replay recomputes the errno. The
176// guest can branch on it: GNU grep falls back to read/write on EINVAL but
177// reports a read error and exits 2 on ENOSYS. Replaying an older stream under
178// the new errno could change guest control flow and event consumption, although
179// no event shape changed.
180// 0x121 -> 0x122: Detcore numbers raw mount IDs in the order the guest first
181// observes them through mountinfo or fdinfo, instead of by row position in the
182// run's starting mountinfo. Metadata carries that order as
183// `mount_id_assignment_order`, replacing `fdinfo_unlisted_mount_ids`, and
184// replay numbers every raw ID from it. An older recording's metadata cannot
185// rebuild the mapping its guest saw, so replaying it could change the mount IDs
186// the guest reads and its control flow.
187// 0x122 -> 0x123: Detcore's inode pool starts at 9000 instead of 1 and every
188// numbering request consumes a number, so the deterministic inode numbers
189// differ (https://github.com/rrnewton/hermit/issues/2897). Even with
190// virtualize_metadata off, as record/replay runs, the procfs sanitizer renders
191// pool numbers into /proc/*/fdinfo `ino:` lines and /proc/*/maps and smaps
192// inode columns over the recorded raw bytes, during recording and again during
193// replay. An older recording replayed under the new numbering could show the
194// guest different bytes, although no event shape changed.
195// 0x123 -> 0x124: accept and accept4 record an `Accept` event, and bind, listen
196// and shutdown record a `Return` event, instead of running live during replay
197// (https://github.com/rrnewton/hermit/issues/3864). An older recording has no
198// events for these calls, so this replayer would consume another call's event.
199// 0x124 -> 0x125: a blocking accept on a listener the container created runs in
200// the caller's turn (https://github.com/rrnewton/hermit/issues/3880). It
201// records one `Accept` event per nonblocking attempt, where an older recording
202// has a single `Accept` event for the backgrounded call. (Its timeout comes
203// from Detcore's model of `setsockopt`, not from a recorded event.) Connections accepted under record
204// are no longer made nonblocking. An older recording would hand this replayer
205// the wrong number of events. A recording also carries a `rejoins` file, the
206// turns at which backgrounded calls rejoined the run queue, which replay
207// requires.
208// 0x125 -> 0x126: in the precise futex mode a FUTEX_WAKE that wakes fewer
209// waiters than are waiting takes the longest waiters first, as Linux does,
210// instead of the most recent ones, and a FUTEX_WAKE_BITSET leaves the waiters
211// it skips in arrival order (https://github.com/rrnewton/hermit/issues/3917).
212// Futex waits and wakes are not recorded events; replay recomputes which thread
213// each wake takes, so an older recording replayed under the new order could run
214// a different schedule, although no event shape changed. Schedule and
215// preemption files written by `--record-preemptions-to` carry no version and
216// are likewise tied to the old order.
217// 0x126 -> 0x127: a vfork barrier ends at the child's release edge (its exec
218// or `Exit` grant) whether or not the parent's death has been seen. With a
219// live parent, the scheduler then commits no turn until the parent's
220// continuation is posted, where the child used to keep running alone for a
221// host-timed number of turns (https://github.com/rrnewton/hermit/issues/3984).
222// Turn selection is not recorded; replay recomputes it, so an older recording
223// containing a vfork replayed under the new rule could run a different
224// schedule, although no event shape changed.
225// 0x127 -> 0x128: on ptrace, `prctl(PR_SET_CHILD_SUBREAPER)` and
226// `PR_GET_CHILD_SUBREAPER` run live in record and replay alike instead of
227// failing with ENOSYS, and the scheduler re-parents orphans to a child
228// subreaper (https://github.com/rrnewton/hermit/issues/3997). An older
229// recording saw ENOSYS for both calls; this replayer would run them and could
230// take another branch and a different schedule, although no event shape
231// changed.
232// 0x128 -> 0x129: record and replay set
233// `backend_supports_blocked_wait_signal_interruption`, so the scheduler models
234// signal targets as `hermit run` does on ptrace
235// (https://github.com/rrnewton/hermit/issues/3963). A thread that a committed
236// signal wakes out of a backgrounded call rejoins at the release barrier, a
237// precise FUTEX_WAIT or an rt_sigtimedwait ends only for a signal that would end
238// it on Linux, and an emulated pause or nanosleep ends for another thread's
239// signal. (poll, epoll_wait, select and pselect6 are logged background calls
240// here, which the kernel itself ends.) Replay recomputes all of these, so an
241// older recording replayed here could run a different schedule, although no
242// event shape changed.
243// 0x129 -> 0x12a: a SIGCHLD the scheduler sends at a commit point (a child's
244// child-exit timer, or a POSIX timer) ends a precise FUTEX_WAIT that catches
245// it, as on Linux, where it was held until the call returned
246// (https://github.com/rrnewton/hermit/issues/4005). Replay recomputes precise
247// futex results, so an older recording replayed here could take the other
248// branch, although no event shape changed (Codex review of
249// https://github.com/rrnewton/hermit/pull/4039).
250pub(crate) const RECORD_VERSION: RecordVersion = RecordVersion(0x12a);
251
252/// The highest RECORD_VERSION this project has ever shipped.
253///
254/// RECORD_VERSION must never move BACKWARD onto it. This is a COMPILE-TIME
255/// assertion rather than a test on purpose: it is decidable from two constants,
256/// so it should break the build rather than a test run, and it cannot be
257/// skipped, filtered or left unrun.
258///
259/// WHY IT EXISTS AT ALL. The rejection set in `record_version_requires_an_exact_match`
260/// used to be a list of specific versions, and `!compatible_with(0x10a)` was
261/// catching a backward move BY ACCIDENT. Replacing that list with a window derived
262/// from RECORD_VERSION fixes its silent narrowing but cannot catch a regression,
263/// because a derived window re-derives from whatever the constant currently says.
264/// Dropping the list without this floor would have traded a stale check for a
265/// weaker one.
266///
267/// The failure it guards is near, not hypothetical: a long-stale branch that bumped
268/// 0x109 -> 0x10a while main advanced to 0x10e regresses the constant the moment its
269/// conflict is resolved by taking the branch side. The build would then stamp the
270/// current schema with a label an older reader already claims, and the exact-match
271/// gate would accept a stream whose shape it does not know -- the desynchronization
272/// the version exists to prevent.
273///
274/// RAISE THIS IN THE SAME COMMIT THAT RAISES RECORD_VERSION.
275const HIGHEST_SHIPPED_RECORD_VERSION: u32 = 0x12a;
276
277const _: () = assert!(
278    RECORD_VERSION.0 >= HIGHEST_SHIPPED_RECORD_VERSION,
279    "RECORD_VERSION is BELOW HIGHEST_SHIPPED_RECORD_VERSION. A recording made by this \
280     build would carry a label an older reader already claims. If this fired during a \
281     rebase, the version constant was resolved BACKWARD -- merge it forward."
282);

284/// Metadata associated with the recording. This is serialized as a JSON file.
285#[derive(Debug, Serialize, Deserialize)]
286pub struct Metadata {
287    /// The real path to the program.
288    pub exe: PathBuf,
289    /// The name of the program.
290    pub program: String,
291    /// The first argument passed to the program.
292    pub arg0: String,
293    /// Program arguments (not including arg0).
294    pub args: Vec<String>,
295    /// The working directory of the program.
296    pub current_dir: PathBuf,
297    /// The hostname in the UTS namespace used by the program.
298    pub hostname: Option<String>,
299    /// The domainname in the UTS namespace used by the program.
300    pub domainname: Option<String>,
301    /// The environment variables used by the program.
302    pub envs: BTreeMap<String, String>,
303    /// Hermit record/replay version.
304    pub version: RecordVersion,
305    /// Actual guest proc mount mode after setup. Missing in older recordings or
306    /// when the guest's proc mount could not be inspected; diagnostic only.
307    #[serde(default)]
308    pub proc_readonly: Option<bool>,
309    /// Recording-namespace mount roots proven to be Hermit-owned.
310    ///
311    /// Replay consumes the recorder's raw syscall buffers, so it must apply the
312    /// recording-time raw mount IDs rather than IDs from the fresh replay
313    /// namespace.  Older recordings default to no private-root rewrites.
314    #[serde(default)]
315    pub mountinfo_root_rewrites: Vec<MountInfoRootRewrite>,
316    /// Recording-namespace raw mount IDs in canonical row order.
317    #[serde(default)]
318    pub mountinfo_mount_ids: Vec<u64>,
319    /// Whether `mountinfo_mount_ids` is a producer-owned snapshot, including a
320    /// valid empty snapshot.
321    #[serde(default)]
322    pub mountinfo_mount_ids_captured: bool,
323    /// Recording-time raw mount IDs in the order Detcore numbered them, which
324    /// is the order the guest first observed them through mountinfo or fdinfo.
325    /// Replay numbers each raw ID by its position in this list.
326    #[serde(default)]
327    pub mount_id_assignment_order: Vec<u64>,
328    /// Whether the recording ran in an isolated network namespace with only
329    /// loopback (`record start --network local`). `None` means the recorder
330    /// did not say, which is every recording made before this field existed;
331    /// those recordings ran on the host network. An autopilot replay uses the
332    /// same network, so syscalls the replayer re-executes see the same
333    /// interfaces and ports they were recorded against.
334    #[serde(default)]
335    pub local_networking: Option<bool>,
336}

338impl Metadata {
339    /// Creates a new metadata object, populating it with information about a
340    /// command.
341    pub fn new(command: &Command) -> Result<Self, Error> {
342        let exe = command.find_program()?;
343
344        let program = command.get_program().to_string_lossy().into_owned();
345        let arg0 = command.get_arg0().to_string_lossy().into_owned();
346
347        let args = command
348            .get_args()
349            .map(|arg| arg.to_string_lossy().into_owned())
350            .collect();
351
352        let envs = command
353            .get_captured_envs()
354            .into_iter()
355            .map(|(k, v)| {
356                (
357                    k.to_string_lossy().into_owned(),
358                    v.to_string_lossy().into_owned(),
359                )
360            })
361            .collect();
362
363        let current_dir = command
364            .get_current_dir()
365            .map_or_else(|| env::current_dir().unwrap(), ToOwned::to_owned);
366
367        let hostname = command
368            .get_hostname()
369            .map(|s| s.to_string_lossy().into_owned());
370        let domainname = command
371            .get_domainname()
372            .map(|s| s.to_string_lossy().into_owned());
373
374        Ok(Self {
375            exe,
376            program,
377            arg0,
378            args,
379            current_dir,
380            hostname,
381            domainname,
382            envs,
383            version: RECORD_VERSION,
384            proc_readonly: None,
385            mountinfo_root_rewrites: Vec::new(),
386            mountinfo_mount_ids: Vec::new(),
387            mountinfo_mount_ids_captured: false,
388            mount_id_assignment_order: Vec::new(),
389            local_networking: None,
390        })
391    }
392
393    /// Reads the metadata of the recording stored in `dir`.
394    pub fn load(dir: &Path) -> Result<Self, Error> {
395        let metadata_path = dir.join(METADATA_NAME);
396        serde_json::from_reader(
397            fs::File::open(&metadata_path)
398                .with_context(|| format!("Failed to open {:?}", metadata_path))?,
399        )
400        .with_context(|| format!("Failed to parse {:?}", metadata_path))
401    }
402
403    /// Constructs a command from the metadata.
404    pub fn command(&self) -> Command {
405        // NOTE: We bypass the normal $PATH search here by passing in the
406        // absolute path to the program directly.
407        let mut command = Command::new(&self.exe);
408        command.arg0(&self.arg0);
409        command.args(&self.args);
410        command.env_clear();
411        command.envs(&self.envs);
412        command.current_dir(&self.current_dir);
413
414        if let Some(hostname) = &self.hostname {
415            command.hostname(hostname);
416        }
417
418        if let Some(domainname) = &self.domainname {
419            command.domainname(domainname);
420        }
421
422        command
423    }
424}

426pub fn record_or_replay_config(data: &Path) -> detcore::Config {
427    // NOTE: Record and replay should use the exact same Detcore configuration.
428    // Callers add the completed producer namespace's mountinfo order and
429    // mount-ID assignment order after this common base is built, so replay
430    // uses recording-time raw IDs rather than IDs from its fresh container.
431    //
432    // WHY THIS IS NOT `hermit run --strict`, WRITTEN HERE ON PURPOSE.
433    //
434    // `virtualize_time: false` below is DELIBERATE, and the rationale used to live only
435    // in the separate dev-hermit workspace -- not in this repository, beside the code it
436    // governs. The cost of that was measured: three agents in one night read this line,
437    // searched this repo's source, git log, docs/ and issues, found nothing, and could
438    // not tell a design decision from a determinism bug; two coordinators then spent
439    // hours treating it as a candidate defect. A decision recorded in a different
440    // repository from the code it governs is, in practice, undocumented. Hence this
441    // comment. See rrnewton/hermit#2295.
442    //
443    // WHAT RECORD/REPLAY ACTUALLY GUARANTEES. Replay re-executes a recording against the
444    // recorded syscall data, so what must be reproducible is THIS recording's replay --
445    // not agreement between two independent recordings. Time is therefore left real: the
446    // recording captures what the guest actually observed, and replay returns those
447    // recorded values. `hermit record start --verify` records once, replays that
448    // recording, and compares the two; its success message says exactly that ("replay
449    // matched recording") and does not claim more.
450    //
451    // WHAT IT DOES NOT GUARANTEE, which is the part that misleads readers. Because time
452    // is not virtualized, two INDEPENDENT recordings of the same program observe
453    // different clock values. Demonstrated: `hermit run -- date` twice returns the
454    // identical virtual epoch, while `hermit record start -- date` twice returns real
455    // wall-clock times seconds apart. Replay fidelity says nothing about that, and
456    // the focused `independent_mountinfo_recordings_are_canonical` test compares
457    // two independent mountinfo recordings after replacing exactly field 3, the
458    // major:minor device column. With `virtualize_metadata: false`, Linux may
459    // legitimately allocate a different anonymous-block-device minor for the
460    // private procfs mount in each container. That test still compares mount ID,
461    // parent ID, root, mountpoint, options, optional fields, separator,
462    // filesystem type, source, and superblock options byte-for-byte. It does not
463    // establish general cross-recording determinism, and a green `--verify`
464    // remains only a replay-fidelity result.
465    //
466    // This configuration differs from `hermit run --strict` on four of the five
467    // properties that define it (see run.rs: only `sequentialize_threads` matches).
468    // Any claim that recording is "strict" in that sense is wrong; the `--strict` flag
469    // on `hermit record` is accepted for command-line compatibility, and its only effect
470    // is to refuse a host whose retired-branch counter is inexact
471    // (https://github.com/rrnewton/hermit/issues/3810).
472    let default_config: detcore::Config = Default::default();
473    let mut config = detcore::Config {
474        // Record and replay are determinism claims, so an unsupported syscall
475        // must invalidate the operation instead of being recorded from or
476        // replayed against the live host.
477        panic_on_unsupported_syscalls: true,
478        // Return a typed error through Reverie rather than unwinding across the
479        // backend callback. The tracer owns process-tree cleanup on that error.
480        exit_on_unsupported_syscall: true,
481        shutdown_on_unsupported_syscall: false,
482        unsupported_syscall_report_fd: None,
483        panic_on_rcb_overshoot: false,
484        sequentialize_threads: true,
485        runs_post_fork: default_config.runs_post_fork,
486        // Record/replay keeps a partial Detcore subscription. Complete coverage
487        // of the Determinized classification begins in v0x10a; madvise policy
488        // semantics begin in v0x102.
489        passthru_opt: true,
490        deterministic_io: false,
491        virtualize_time: crate::RECORD_REPLAY_VIRTUALIZES_TIME,
492        virtualize_metadata: false,
493        mountinfo_root_rewrites: Vec::new(),
494        mountinfo_device_rewrites: Vec::new(),
495        mountinfo_mount_ids: Vec::new(),
496        mountinfo_mount_ids_captured: false,
497        mount_id_assignment_order: Vec::new(),
498        virtualize_cpuid: true,
499        // Record and replay run under the ptrace backend.
500        backend: <reverie_ptrace::PtraceBackend as reverie::Backend>::capabilities(),
501        // As `hermit run` sets it for ptrace (`prepare_backend_config` in
502        // lib.rs). With it off, the scheduler did not model signal targets, so
503        // a thread asleep in a backgrounded rt_sigsuspend that a child-exit

586/// Whether this host can arm Reverie's ptrace timer for a record or replay:
587/// working perf counters AND a PMU profile for its CPU. Without a profile,
588/// Reverie gives no task a timer, so a timeslice would be configured and never
589/// delivered.
590fn record_timer_support() -> Result<(), String> {
591    timer_support_from(
592        reverie_ptrace::is_perf_supported(),
593        reverie_ptrace::host_pmu_profile(),
594    )
595}
596
597/// [`record_timer_support`] from what the host answered: whether perf works,
598/// and whether Reverie has a PMU profile for its CPU.
599fn timer_support_from(
600    perf_supported: bool,
601    profile: Result<(), reverie_ptrace::PmuValidationError>,
602) -> Result<(), String> {
603    if !perf_supported {
604        return Err("hardware perf counters are not supported on this machine".to_owned());
605    }
606    profile.map_err(|error| error.to_string())
607}

609/// Turn off `config`'s timeslice, which this host cannot deliver (`reason`).
610fn disable_timeslice_without_a_timer(config: &mut detcore::Config, reason: &str) {
611    if config.max_timeslice.is_some() {
612        tracing::warn!("{reason}; Records/Replays run without a timeslice and may randomly fail!");
613        config.max_timeslice = None;
614    }
615}

654    fn record_version_requires_an_exact_match() {
655        assert!(RECORD_VERSION.compatible_with(&RECORD_VERSION));
656
657        // DERIVED FROM THE COMPATIBILITY RULE, NOT ENUMERATED.
658        //
659        // This assertion used to be a list of specific versions -- 0x10a, 0x10c,
660        // 0x105, 0x110. A list SILENTLY NARROWS every time RECORD_VERSION
661        // advances: the named values drift away from the boundary that matters,
662        // and the test keeps passing while checking less and less. It cannot
663        // fail for the reason its name gives once the value has moved past the
664        // range someone happened to write down.
665        //
666        // `compatible_with` is exact equality, so the property to assert is
667        // "every OTHER version is refused". Re-deriving the cases from
668        // RECORD_VERSION itself means the window travels with the constant and
669        // cannot go stale.
670        let current = RECORD_VERSION.0;
671        for delta in 1..=16u32 {
672            let older = RecordVersion(current - delta);
673            assert!(
674                !RECORD_VERSION.compatible_with(&older),
675                "recorder at {current:#x} must refuse a recording made at {:#x}",
676                older.0
677            );
678            let newer = RecordVersion(current + delta);
679            assert!(
680                !RECORD_VERSION.compatible_with(&newer),
681                "recorder at {current:#x} must refuse a recording made at {:#x}",
682                newer.0
683            );
684        }
685    }

737    fn record_and_replay_subscribe_every_determinized_syscall() {
738        let config = record_or_replay_config(Path::new("replay-data"));
739        let record = <detcore::Detcore<crate::recorder::Recorder> as Tool>::subscriptions(&config);
740        let replay = <detcore::Detcore<crate::replayer::Replayer> as Tool>::subscriptions(&config);
741
742        for (phase, subscriptions) in [("record", record), ("replay", replay)] {
743            let delivered = subscriptions.iter_syscalls().collect::<Vec<_>>();
744            let missing = detcore::all_pinned_syscalls()
745                .filter(|sysno| detcore::is_determinized_syscall(*sysno))
746                .filter(|sysno| !delivered.contains(sysno))
747                .collect::<Vec<_>>();
748            assert!(
749                missing.is_empty(),
750                "{phase} lets Determinized syscalls bypass Detcore: {}",
751                missing
752                    .iter()
753                    .map(|sysno| sysno.to_string())
754                    .collect::<Vec<_>>()
755                    .join(" ")
756            );
757            assert!(
758                delivered.contains(&Sysno::syslog),
759                "{phase} must deliver syslog to its deterministic Detcore handler"
760            );
761            // chdir is PassThrough for Detcore but its result depends on the
762            // replay chroot, so record/replay subscribes it (hermit#3598);
763            // umask, from the same PassThrough group, stays the sentinel that
764            // record/replay does not subscribe everything.
765            assert!(
766                delivered.contains(&Sysno::chdir) && delivered.contains(&Sysno::getcwd),
767                "{phase} must deliver chdir and getcwd so replay uses recorded results"
768            );
769            // A replayed descriptor may be a placeholder, so these must
770            // return recorded results rather than run
771            // (https://github.com/rrnewton/hermit/issues/3591).
772            for sysno in [
773                Sysno::fsync,
774                Sysno::fdatasync,
775                Sysno::syncfs,
776                Sysno::fchmod,
777                Sysno::fchown,
778                Sysno::fsetxattr,
779                Sysno::fremovexattr,
780                Sysno::setxattr,
781                Sysno::lsetxattr,
782                Sysno::removexattr,
783                Sysno::lremovexattr,
784                Sysno::getxattr,
785                Sysno::lgetxattr,
786                Sysno::fgetxattr,
787                Sysno::listxattr,
788                Sysno::llistxattr,
789                Sysno::flistxattr,
790            ] {
791                assert!(
792                    delivered.contains(&sysno),
793                    "{phase} must deliver {sysno} so replay uses its recorded result"
794                );
795            }
796            assert!(
797                !delivered.contains(&Sysno::umask),
798                "{phase} must leave unlisted PassThrough umask unsubscribed"
799            );
800        }

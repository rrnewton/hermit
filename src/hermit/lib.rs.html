33/// Whether record/replay verification hashes syscall output buffers, and
34/// therefore whether its log comparison can see buffer CONTENT at all.
35///
36/// ONE CONSTANT BECAUSE TWO INDEPENDENT SWITCHES HAD TO AGREE AND SILENTLY DID
37/// NOT MATTER. Record/replay carried this decision twice: `metadata.rs`'s
38/// `record_or_replay_config` decided whether the recorder EMITS the hash, and
39/// `record_start.rs`'s `ComparisonOptions` decided whether the comparator READS
40/// it. Both were hard-coded `false`, neither was reachable from the command
41/// line, and nothing related them. Setting either alone achieves nothing: hash
42/// without compare is dead weight, compare without hash finds nothing. Naming
43/// the decision once makes the pair impossible to desynchronize, and makes
44/// changing it a one-line edit in a place a reader can find.
45pub const RECORD_REPLAY_HASHES_IO_BUFFERS: bool = true;

47/// Whether record/replay virtualizes time. FALSE, DELIBERATELY, AND THAT IS WHY
48/// A GREEN RECORD/REPLAY VERDICT IS NOT A DETERMINISM RESULT.
49///
50/// Named for the same reason as [`RECORD_REPLAY_HASHES_IO_BUFFERS`] directly
51/// above: the decision was about to be carried twice. `metadata.rs`'s
52/// `record_or_replay_config` sets the config the recorder and replayer run
53/// under, and `record_start.rs`'s `ComparisonOptions` now discloses that setting
54/// in the verdict. If those two disagreed, the report would describe a time
55/// policy the run did not use — which is precisely the class of defect the
56/// disclosure exists to close, reintroduced one layer up.
57///
58/// `hermit run --verify` reads its value from the live `det_config` instead,
59/// because `--no-virtualize-time` makes it a genuine runtime choice there. Only
60/// the record/replay path is a fixed decision, so only it gets a constant.

70/// Exit status for a failure of HERMIT ITSELF, as distinct from the guest's.
71///
72/// ⚠️ EVERY CLI ERROR USED TO BE `Exited(1)`, WHICH IS THE SINGLE MOST COMMON
73/// GUEST FAILURE CODE. A tracer panic and a guest that exited 1 of its own
74/// accord were therefore INDISTINGUISHABLE from `$?` alone — and every harness,
75/// gate and script on this project decides pass/fail from exactly that value.
76/// The information was not missing, only discarded: reverie's container reports
77/// the child's real status as a typed `ExitStatus`, and hermit collapsed it to
78/// prose and then to `1`.
79///
80/// WHY THIS DOES NOT BREAK THE "hermit's exit IS the guest's exit" CONTRACT.
81/// That contract describes the case where the guest RAN AND EXITED, and it is
82/// untouched: a guest status still flows through `raise_or_exit` unchanged, and
83/// only the `Err` arm — where there is NO guest exit code, because hermit failed
84/// before or instead of producing one — uses this value. The contract did not
85/// cover that case; it does now.
86///
87/// WHY 125. It is the established convention for "the wrapper tool itself
88/// failed" — GNU `env`, `chroot` and `timeout` all reserve 125 for exactly this,
89/// leaving 126/127 for exec-level problems. It is not a value hermit emits
90/// anywhere else.
91///
92/// ⚠️ THIS REDUCES A COLLISION, IT DOES NOT REMOVE ONE. A guest is free to exit
93/// 125 deliberately, and every value in 0..=255 is a legal guest status, so no
94/// code can be reserved outright. What it removes is the GUARANTEED collision
95/// with the most common failure code. For an unambiguous signal, read the
96/// `HERMIT_TASK_PANIC` marker on stderr or the verification JSON; this makes the
97/// cheap check — `$?` — stop actively lying.
98///
99/// ⚠️ IT LIVES IN THE LIBRARY, NOT IN `main.rs`, AND THAT PLACEMENT IS THE FIX
100/// FOR HOW IT WENT STALE. It was a private `const` inside the binary, so
101/// `tests/cli.rs` — the only thing that asserts on it — could not name it and
102/// wrote the number out by hand instead. When hermit#2558 moved the value from
103/// `1` to `125`, the definition moved and the sixteen copies did not: eight cli
104/// tests went red on main and stayed red, each failing an assertion about the
105/// exit code rather than about the behaviour it exists to check. Same shape as
106/// [`RECORD_REPLAY_HASHES_IO_BUFFERS`] above — a decision carried in two places
107/// that had to agree and had no way to. Exported here, the tests move with it.
108///
109/// ⚠️ DO NOT FLIP EVERY `Some(1)` YOU FIND. `tests/stress_suite.rs`
110/// asserts `Some(1)` as THE GUEST'S OWN SIGNAL, not as a stale copy of this
111/// constant: there `Some(1) => GuestOutcome::Exposed`, and
112/// `status.code() == Some(1)` IS the `exposes_bug` predicate. It is
113/// pattern-identical to the tests that DID go stale, and it is the OPPOSITE
114/// case -- the assertion is CORRECT and must not move with this constant.
115///
116/// ⚠️ ITS FAILURE MODE IS SILENT SUCCESS. Changing it to 125 would not
117/// turn the stress suite red; it would make `exposes_bug` NEVER FIRE, so the
118/// suite would report no bug exposed forever and pass while blind. A red is
119/// recoverable; a green that cannot fail is not.
120///
121/// REVIEWER RULE: a change to `tests/stress_suite.rs` inside an exit-code head
122/// SHOULD BE REFUSED ON SIGHT AND QUESTIONED.
123pub const HERMIT_INTERNAL_FAILURE_EXIT: i32 = 125;

164// ⚠️ THE VALUES THEMSELVES ARE PINNED, NOT ONLY THEIR NAMES.
165//
166// Naming a constant makes every consumer agree with the definition; it does not
167// make the definition right. Once `tests/cli.rs` asserts `Some(THE_CONSTANT)`
168// everywhere, the whole suite is self-consistent and completely unanchored -- a
169// one-character edit here would move all sixteen assertions with it and nothing
170// would fail. That is the exact shape of the defect this scheme exists to close,
171// displaced one level up, and it is why these are compile-time assertions rather
172// than a comment: a deliberate edit "would be noticed" is the argument that
173// already failed once, when hermit#2558 moved 1 -> 125 and sixteen copies went
174// stale.
175//
176// WHY EACH VALUE AND NOT ANOTHER. GNU `env`, `chroot` and `timeout` reserve 125
177// for "the wrapper itself failed", 127 for "command not found" and 126 for
178// "found but not executable". Borrowing the whole scheme rather than one number
179// is what keeps the three answers distinguishable from each other.
180//
181// ⚠️ THE EXIT-CODE ALLOCATION FOR THE `hermit` BINARY. ONE TABLE, HERE.
182//
183// Five separate exit-code defects were found in one evening and every one of
184// them came from a value being chosen, copied or rewritten somewhere that could
185// not see the others. This is the single place the space is allocated; anything
186// that emits or rewrites a hermit exit status is a consumer OF this table and
187// must not invent its own reading of it.
188//
189//   0          success.
190//   1          HERMIT_VERIFICATION_DIVERGENCE_EXIT, matching `diff`; also a
191//              legal guest status. Read the verification JSON to distinguish.
192//   2 ..= 121  THE GUEST'S OWN STATUS, passed through untouched. (The range
193//              stops at 121 because 122 is reserved below; a guest may still
194//              CHOOSE any value, see the caveat at the end.)
195//   122        HERMIT_POLICY_REFUSAL_EXIT -- hermit REFUSED the run under a
196//              fail-closed policy. Hermit WORKED; the run was stopped on
197//              purpose and the reason was printed. Distinct from 125 because
198//              "hermit refused" and "hermit broke" demand opposite responses:
199//              read the refusal and change your program or flags, versus file a
200//              bug. Defined in `detcore-model` because `detcore` emits it and
201//              this crate recognises it, and that is the only crate both
202//              depend on.
203//   123        DO NOT USE. dev-hermit's `bin/safehermit` LOG BYTE CAP kill.
204//              It moved here FROM 125 so it would stop colliding with the line
205//              below; taking 123 back would undo that.
206//   124        DO NOT USE. GNU `timeout`'s deadline, and dev-hermit's
207//              `bin/safehermit` WALL DEADLINE kill. `tests/cli.rs` asserts
208//              `assert_ne!(code, Some(124))` on the awk-mincore probe.
209//   125        HERMIT_INTERNAL_FAILURE_EXIT -- hermit itself failed, no guest
210//              ran. Sole meaning as of 2026-08-25: `bin/safehermit` previously
211//              also emitted 125 for its byte-cap kill, so a run through that
212//              wrapper produced one number for two faults with opposite
213//              remedies. SAFEHERMIT MOVED, NOT HERMIT, because that wrapper is
214//              the only layer that knows which happened -- it relays hermit's
215//              status otherwise -- and because 125/126/127 is one GNU scheme
216//              that cannot be broken up. Tracked as `hermit_s_125_collides`.
217//   126        GUEST_PROGRAM_NOT_EXECUTABLE_EXIT.
218//   127        GUEST_PROGRAM_NOT_FOUND_EXIT -- the ABSOLUTE-PATH form. The
219//              bare-name-on-guest-PATH form currently exits 125 instead, which
220//              is an inconsistency tracked as `hermit_reports_a_missing`, not a
221//              second meaning for 127.
222//   128 + N    killed by signal N (shell convention). Hermit does not emit these
223//              deliberately; a wrapper reporting a signal death must use them
224//              rather than borrow a code that already means something.
225//
226// ⚠️ NO CODE IS EXCLUSIVELY HERMIT'S. Every value in 0..=255 is a legal guest
227// status, so a guest may return 125 or 127 of its own accord and this table
228// cannot stop it. The table removes GUARANTEED collisions, not possible ones.
229// The only unambiguous discriminator is the `HERMIT_INTERNAL_FAILURE` marker on
230// stderr, present exactly when hermit itself failed. Any consumer deciding on
231// `$?` alone is guessing, and should say so.
232//
233// ⚠️ THE SAME ARGUMENT APPLIES TO 124, AND MORE SHARPLY, BECAUSE FIVE
234// MECHANISMS PRODUCE IT. `hermit run --timeout`, its unwind fallback, `hermit
235// record --record-timeout`, the `timeout(1)` wrapped around a manifest cell, and
236// `safehermit`'s wall deadline all exit 124, and GNU `timeout` uses it for the
237// same event. They demand different responses -- a slow guest, a wedged
238// teardown inside hermit, a cell bound set too low, a run that escaped every
239// inner bound -- so `$?` cannot route the reader to any of them.
240//
241// The discriminator is again the marker on stderr, and it is a CONTRACT rather
242// than a diagnostic nicety: `class=run-timeout` for hermit's own bound (which
243// also states the bound in seconds), `HERMIT_RUN_TIMEOUT_FALLBACK` for the
244// unwind failing to complete, `safehermit: bound.wall=` for the cgroup reap.
245// EXIT 124 WITH NO MARKER AT ALL MEANS NO INNER BOUND FIRED -- something outside
246// hermit killed the run -- which is a configuration error and not a slow guest.
247// The full picture, including which rung bounds which quantity and the
248// strict-inequality invariant between them, is docs/TIMEOUT_LADDER.md.
249//
250// ⚠️ DO NOT CLAMP INTO THIS RANGE. `scripts/hermit-code-coverage.rs` used
251// `clamp(1, 125)` and so rewrote 127 and 126 into 125 -- turning "your program is
252// missing" into "hermit broke" and pointing the reader at the wrong project.
253// Truncating a status does not lose information here, it MANUFACTURES a false
254// attribution, because the ceiling is itself a meaning.
255//
256// ⚠️ WHAT EACH VALUE MUST NOT COLLIDE WITH -- AND 125 ALREADY DOES.
257//
258//   0    success. Never a failure code; see the nonzero pin below.
259//   1    the commonest guest exit status. Sharing it is the collision
260//        hermit#2558 introduced 125 to escape, so 125 must never drift back.
261//   124  GNU `timeout`'s "deadline fired", and dev-hermit's `bin/safehermit`
262//        uses it for its WALL DEADLINE kill. `tests/cli.rs` asserts
263//        `assert_ne!(code, Some(124))` on the awk-mincore probe for that reason.
264//   126  hermit's own GUEST_PROGRAM_NOT_EXECUTABLE_EXIT.
265//   127  hermit's own GUEST_PROGRAM_NOT_FOUND_EXIT -- already in use for the
266//        ABSOLUTE-PATH form of a missing guest program. Note the bare-name form
267//        resolved against the guest PATH exits 125 instead, which is an
268//        inconsistency filed separately, not a licence to reuse 127.
269//
270//   125  ⚠️ NOT FREE. dev-hermit's `bin/safehermit` exits 125 to mean "the LOG
271//        BYTE CAP fired: safehermit killed the run through its cgroup"
272//        (`demos/lib/demo_common.py`'s SAFEHERMIT_EXIT_REASON). Any hermit run
273//        launched through that wrapper -- which is how the demos and the repeat
274//        harness run it -- can therefore produce 125 for two unrelated reasons:
275//        hermit refused, or the wrapper killed it for log volume. They demand
276//        opposite responses (fix the invocation vs raise the cap), and `$?`
277//        cannot tell them apart. This is a LIVE ambiguity, not a hypothetical:
278//        demo 5 has been observed reporting `exited with status 125` when the
279//        cap fired. It is recorded here rather than resolved because changing
280//        either value is a cross-repository decision.
281//
282//        The discriminator meanwhile is the same one that separates hermit's 125
283//        from a guest's own 125: the `HERMIT_INTERNAL_FAILURE` marker on stderr,
284//        present only when hermit itself failed. safehermit writes its verdict
285//        to its `--sh-report` file instead. Read one of those, never the number
286//        alone.
287//
288// ⚠️ 0 IS THE DANGEROUS DRIFT, NOT 126 OR 127. Every one of these is asserted as
289// `assert_eq!(code, Some(CONST))`. At 0 those assertions would stop demanding a
290// FAILURE and start demanding a SUCCESS, and would still pass -- sixteen tests
291// silently inverted. `tests/cli.rs` also asserts `!status.success()` beside the
292// code for that reason; this pin is the second of the two locks.
293const _: () = assert!(
294    HERMIT_VERIFICATION_DIVERGENCE_EXIT == 1,
295    "1 is the established diff-style result for a completed comparison that diverged"
296);
297const _: () = assert!(
298    HERMIT_INTERNAL_FAILURE_EXIT == 125,
299    "125 is the GNU wrapper-failed convention; 1 is the commonest guest status and 0 is success"
300);
301const _: () = assert!(
302    GUEST_PROGRAM_NOT_FOUND_EXIT == 127,
303    "127 is the GNU command-not-found convention and must stay distinct from 125 and 126"
304);
305const _: () = assert!(
306    GUEST_PROGRAM_NOT_EXECUTABLE_EXIT == 126,
307    "126 is the GNU found-but-not-executable convention and must stay distinct from 125 and 127"
308);
309const _: () = assert!(
310    HERMIT_VERIFICATION_DIVERGENCE_EXIT != 0
311        && HERMIT_INTERNAL_FAILURE_EXIT != 0
312        && GUEST_PROGRAM_NOT_FOUND_EXIT != 0
313        && GUEST_PROGRAM_NOT_EXECUTABLE_EXIT != 0,

403fn read_iovecs<M: reverie::syscalls::MemoryAccess>(
404    memory: &M,
405    message: &libc::msghdr,
406) -> Result<Vec<libc::iovec>, reverie::Errno> {
407    if message.msg_iovlen == 0 {
408        return Ok(Vec::new());
409    }
410    let address = reverie::syscalls::Addr::from_raw(message.msg_iov as usize)
411        .ok_or(reverie::Errno::EFAULT)?;
412    let mut iovecs = vec![
413        libc::iovec {
414            iov_base: std::ptr::null_mut(),
415            iov_len: 0,
416        };
417        message.msg_iovlen
418    ];
419    memory.read_values(address, &mut iovecs)?;
420    Ok(iovecs)
421}

438/// Saves stdin captured before Rust's process startup can reuse a closed fd 0.
439pub fn reserve_kvm_stdin(stdin: Option<fs::File>) -> io::Result<()> {
440    let mut reservation = KVM_STDIN_RESERVATION
441        .lock()
442        .map_err(|_| io::Error::other("KVM stdin reservation lock is poisoned"))?;
443    if reservation.is_some() {
444        return Err(io::Error::new(
445            io::ErrorKind::AlreadyExists,
446            "KVM stdin is already reserved",
447        ));
448    }
449    *reservation = Some(match stdin {
450        Some(file) => KvmStdinReservation::Open(file),
451        None => KvmStdinReservation::Closed,
452    });
453    Ok(())
454}

456fn duplicate_current_stdin() -> io::Result<Option<fs::File>> {
457    // SAFETY: F_DUPFD_CLOEXEC duplicates fd 0 without taking ownership of it.
458    let duplicate = unsafe { libc::fcntl(libc::STDIN_FILENO, libc::F_DUPFD_CLOEXEC, 3) };
459    if duplicate >= 0 {
460        // SAFETY: F_DUPFD_CLOEXEC returned a new owned descriptor.
461        return Ok(Some(unsafe { fs::File::from_raw_fd(duplicate) }));
462    }
463    let error = io::Error::last_os_error();
464    if error.raw_os_error() == Some(libc::EBADF) {
465        Ok(None)
466    } else {
467        Err(error)
468    }
469}

471fn ensure_kvm_stdin_reserved() -> io::Result<()> {
472    let mut reservation = KVM_STDIN_RESERVATION
473        .lock()
474        .map_err(|_| io::Error::other("KVM stdin reservation lock is poisoned"))?;
475    if reservation.is_none() {
476        *reservation = Some(match duplicate_current_stdin()? {
477            Some(file) => KvmStdinReservation::Open(file),
478            None => KvmStdinReservation::Closed,
479        });
480    }
481    Ok(())
482}
483
484fn reserved_kvm_stdin() -> Result<Option<fs::File>, Error> {
485    ensure_kvm_stdin_reserved()?;
486    let reservation = KVM_STDIN_RESERVATION
487        .lock()
488        .map_err(|_| io::Error::other("KVM stdin reservation lock is poisoned"))?;
489    match reservation.as_ref() {
490        Some(KvmStdinReservation::Open(file)) => Ok(Some(file.try_clone()?)),
491        Some(KvmStdinReservation::Closed) => Ok(None),
492        None => unreachable!("stdin reservation was initialized above"),
493    }
494}

496/// A replayable snapshot of the guest's stdin for the output-capturing backends.
497///
498/// `hermit run --verify` executes the guest twice and compares the two runs. The
499/// output-capturing backends historically fed the guest `Stdio::null()`, so any
500/// data piped into hermit (`echo prog | hermit run --strict --verify -- ...`)
501/// was silently dropped. Both runs then saw identical *empty* input and hermit
502/// reported a false "deterministic" success even though the guest never received
503/// its input. `Seekable` holds a read-only, rewindable file so both runs receive
504/// the exact same bytes without being able to modify the caller's input; `None`
505/// means stdin should be `/dev/null` (nothing to replay, or a terminal that
506/// cannot be replayed identically to two runs).
507enum StdinSnapshot {
508    Seekable(fs::File),
509    None,
510}
511
512static OUTPUT_STDIN_SNAPSHOT: Mutex<Option<StdinSnapshot>> = Mutex::new(None);
513
514/// Records a rewindable snapshot of the process stdin so the output-capturing
515/// backends can replay identical input to each run of `hermit run --verify`.
516///
517/// `stdin` is the descriptor captured before Rust startup could reuse a closed
518/// fd 0 (see the binary's `startup_stdin`). A regular-file redirect is reopened
519/// read-only; a pipe/fifo/socket is drained once into a seekable temporary file
520/// and that file is reopened read-only. A terminal (or absent stdin) is treated
521/// as `/dev/null` because a live terminal cannot be replayed identically to two
522/// runs.
523pub fn reserve_output_stdin_snapshot(stdin: Option<fs::File>) -> io::Result<()> {
524    let snapshot = match stdin {
525        None => StdinSnapshot::None,
526        Some(mut file) => {
527            // SAFETY: as_raw_fd borrows the descriptor without taking ownership.
528            let is_tty = unsafe { libc::isatty(file.as_raw_fd()) } == 1;
529            if is_tty {
530                StdinSnapshot::None
531            } else {
532                let replay = if file.stream_position().is_ok() {
533                    // Already seekable (e.g. `< file`): retain it below through
534                    // a read-only descriptor with an independent file offset.
535                    file
536                } else {
537                    // Non-seekable (pipe/fifo/socket): buffer once into a
538                    // seekable temporary file so both --verify runs receive
539                    // identical input.
540                    //
541                    // NAME THE WAIT BEFORE ENTERING IT. This `io::copy` reads to
542                    // EOF, so a stdin that never reaches EOF -- an inherited socket,
543                    // a fifo whose writer stays open -- blocks here FOREVER, before
544                    // the guest has started. Measured: the process wedges with ZERO
545                    // bytes on stdout and stderr and is only cleared by killing it,
546                    // which is indistinguishable from a slow run. That
547                    // indistinguishability is the whole harm; an unbounded wait that
548                    // says what it is waiting for is merely slow, and a reader can
549                    // act on it.
550                    //
551                    // Deliberately UNCONDITIONAL rather than emitted after a delay:
552                    // a message that appears only once N seconds have passed makes
553                    // hermit's own stderr depend on timing, and this project does
554                    // not accept timing-dependent output. Deliberately NOT a
555                    // deadline either -- a 12s slow producer is legitimate and
556                    // delivers, and nothing can separate "slow" from "never" except
557                    // by waiting. This changes no control flow: every input that
558                    // worked before still works, byte for byte, on stdout.
559                    eprintln!(
560                        "hermit: --verify is buffering stdin from a non-seekable stream so both \
561                         runs receive identical input. If this appears to hang, stdin has not \
562                         reached end-of-file; pass `< /dev/null` when the guest needs no input."
563                    );
564                    let mut buffered = tempfile::tempfile()?;
565                    io::copy(&mut file, &mut buffered)?;
566                    buffered.seek(SeekFrom::Start(0))?;
567                    buffered
568                };
569
570                // A duplicate would keep the original access mode. Reopen the
571                // reserved descriptor read-only so neither verification run
572                // can modify the caller's stdin or the next run's input.
573                let replay_path = format!("/proc/self/fd/{}", replay.as_raw_fd());
574                StdinSnapshot::Seekable(fs::File::open(replay_path)?)
575            }
576        }
577    };
578    let mut reservation = OUTPUT_STDIN_SNAPSHOT
579        .lock()
580        .map_err(|_| io::Error::other("output stdin snapshot lock is poisoned"))?;
581    if reservation.is_some() {
582        return Err(io::Error::new(
583            io::ErrorKind::AlreadyExists,
584            "output stdin snapshot is already reserved",
585        ));
586    }
587    *reservation = Some(snapshot);
588    Ok(())
589}
590
591/// Returns a rewound descriptor for the reserved stdin snapshot, if any.
592///
593/// Each call rewinds the snapshot and hands back a fresh descriptor, so
594/// repeated `--verify` runs read identical input from the start. Returns `None`
595/// when no snapshot was reserved or the reserved stdin is a terminal/absent
596/// (nothing to replay). Runs are sequential (each executes in its own forked
597/// container child), so resetting the shared open file description's offset here
598/// is safe.
599fn output_backend_stdin_reservation() -> Result<(bool, Option<fs::File>), Error> {
600    let mut reservation = OUTPUT_STDIN_SNAPSHOT
601        .lock()
602        .map_err(|_| io::Error::other("output stdin snapshot lock is poisoned"))?;
603    match reservation.as_mut() {
604        Some(StdinSnapshot::Seekable(file)) => {
605            file.seek(SeekFrom::Start(0))?;
606            Ok((true, Some(file.try_clone()?)))
607        }
608        Some(StdinSnapshot::None) => Ok((true, None)),
609        None => Ok((false, None)),
610    }
611}
612
613fn output_backend_stdin_file() -> Result<Option<fs::File>, Error> {
614    Ok(output_backend_stdin_reservation()?.1)
615}
616
617/// Returns the stdin to hand a guest run in an output-capturing backend.
618///
619/// When [`reserve_output_stdin_snapshot`] has stored a replayable snapshot the
620/// file is rewound and a fresh descriptor handed to the guest, so each
621/// `--verify` run reads identical input. Otherwise (no snapshot reserved, or a
622/// terminal/absent stdin) the guest gets `/dev/null`, matching the previous
623/// behavior for callers that do not reserve a snapshot.
624fn output_backend_stdin() -> Result<Stdio, Error> {
625    match output_backend_stdin_file()? {
626        Some(file) => Ok(Stdio::from(file)),
627        None => Ok(Stdio::null()),
628    }
629}

642enum CapabilityProbe {
643    Namespaces,
644    Ptrace,
645    Seccomp,
646}
647
648fn run_capability_probe(probe: CapabilityProbe) -> Result<bool, Error> {
649    // SAFETY: The child calls only async-signal-safe syscalls and exits immediately.
650    let pid = unsafe { libc::fork() };
651    if pid == -1 {
652        return Err(std::io::Error::last_os_error()).context("Failed to fork capability probe");
653    }
654    if pid == 0 {
655        let supported = match probe {
656            CapabilityProbe::Namespaces => unsafe {
657                libc::unshare(libc::CLONE_NEWUSER | libc::CLONE_NEWPID) == 0
658            },
659            CapabilityProbe::Ptrace => {
660                // SAFETY: PTRACE_TRACEME ignores the pid and address arguments.
661                unsafe {
662                    libc::ptrace(
663                        libc::PTRACE_TRACEME,
664                        0,
665                        std::ptr::null_mut::<libc::c_void>(),
666                        std::ptr::null_mut::<libc::c_void>(),
667                    ) != -1
668                }
669            }
670            CapabilityProbe::Seccomp => {
671                let mut filter = libc::sock_filter {
672                    code: 0x06, // BPF_RET | BPF_K
673                    jt: 0,
674                    jf: 0,
675                    k: 0x7fff0000, // SECCOMP_RET_ALLOW
676                };
677                let program = libc::sock_fprog {
678                    len: 1,
679                    filter: &mut filter,
680                };
681                // SAFETY: The filter is an allow-all program with a valid one-element lifetime.
682                unsafe {
683                    libc::prctl(libc::PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) == 0
684                        && libc::syscall(
685                            libc::SYS_seccomp,
686                            1, // SECCOMP_SET_MODE_FILTER
687                            0,
688                            &program,
689                        ) == 0
690                }
691            }
692        };
693        // SAFETY: Avoid running Rust destructors after fork.
694        unsafe { libc::_exit(i32::from(!supported)) }
695    }
696
697    let mut status = 0;
698    loop {
699        // SAFETY: pid is the child created above and status points to valid storage.
700        let result = unsafe { libc::waitpid(pid, &mut status, 0) };
701        if result == pid {
702            return Ok(libc::WIFEXITED(status) && libc::WEXITSTATUS(status) == 0);
703        }
704        if result == -1 {
705            let error = std::io::Error::last_os_error();
706            if error.kind() == std::io::ErrorKind::Interrupted {
707                continue;
708            }
709            return Err(error).context("Failed to wait for capability probe");
710        }
711    }
712}

714fn validate_tracing_environment() -> Result<(), Error> {
715    if !run_capability_probe(CapabilityProbe::Namespaces)? {
716        anyhow::bail!(
717            "Hermit cannot create its required user and PID namespaces: \
718             unshare(CLONE_NEWUSER | CLONE_NEWPID) was denied. Allow unprivileged user namespaces \
719             and the unshare syscall in the host/container policy."
720        );
721    }
722    if !run_capability_probe(CapabilityProbe::Ptrace)? {
723        anyhow::bail!(
724            "Hermit cannot use ptrace in this environment: a child PTRACE_TRACEME probe was \
725             denied. Allow same-UID parent-child ptrace in the container seccomp and host \
726             Yama/LSM policy; CAP_SYS_PTRACE is normally not required. Use --namespace-only for \
727             a sandbox smoke test without syscall interception."
728        );
729    }
730    if !run_capability_probe(CapabilityProbe::Seccomp)? {
731        anyhow::bail!(
732            "Hermit cannot install its tracee seccomp filter: \
733             seccomp(SECCOMP_SET_MODE_FILTER) was denied. Allow seccomp and \
734             prctl(PR_SET_NO_NEW_PRIVS) in the container policy, or use --namespace-only for a \
735             sandbox smoke test without syscall interception."
736        );
737    }
738    Ok(())
739}

814    // `libreverie_liteinst.so.so.revision` and refuse a correctly staged runtime.
815    let marker = PathBuf::from(format!("{}.revision", path.display()));

817        Ok(text) => text.trim().to_owned(),
818        Err(error) if error.kind() == io::ErrorKind::NotFound => {
819            return Err(io::Error::new(

823                     shown to match the pin this binary was built from ({expected}). It was staged \
824                     by a build that predates revision recording, which is exactly the case where a \
825                     stale runtime went unnoticed. Restage it with `cargo build --release -p \
826                     hermit-install` -- staging is release-only.",
827                    path.display()
828                ),
829            ));
830        }
831        Err(error) => return Err(error),
832    };
833    if staged != expected {
834        return Err(io::Error::new(
835            io::ErrorKind::InvalidData,
836            format!(
837                "the staged LiteInst runtime {} was built from Reverie {staged}, but this binary \
838                 was built from {expected}. Running it would measure the OLD runtime and report a \
839                 verdict about the NEW pin. Restage with `cargo build --release -p hermit-install`.",

847fn validate_liteinst_runtime_library(path: &Path) -> io::Result<PathBuf> {
848    liteinst_runtime_pin_matches(path)?;
849    let bytes = fs::read(path).map_err(|error| {
850        io::Error::new(
851            error.kind(),
852            format!(
853                "failed to read LiteInst runtime {}: {error}",
854                path.display()
855            ),
856        )
857    })?;
858    let elf = Elf::parse(&bytes).map_err(|error| {
859        io::Error::new(
860            io::ErrorKind::InvalidData,
861            format!(
862                "LiteInst runtime {} is not an ELF DSO: {error}",
863                path.display()
864            ),
865        )
866    })?;
867    if elf.header.e_type != header::ET_DYN || elf.header.e_machine != header::EM_X86_64 {
868        return Err(io::Error::new(
869            io::ErrorKind::InvalidData,
870            format!(
871                "LiteInst runtime {} is not an x86-64 shared object",
872                path.display()
873            ),
874        ));
875    }
876
877    let required = [
878        "reverie_liteinst_initialize",
879        "reverie_liteinst_site_trap_count",
880        "reverie_liteinst_site_hook_count",
881    ];
882    for name in required {
883        if !elf
884            .dynsyms
885            .iter()
886            .any(|symbol| elf.dynstrtab.get_at(symbol.st_name) == Some(name))
887        {
888            return Err(io::Error::new(
889                io::ErrorKind::InvalidData,
890                format!(
891                    "LiteInst runtime {} is missing required export {name}",
892                    path.display()
893                ),
894            ));
895        }
896    }
897    let (initializer_index, initializer) = elf
898        .dynsyms
899        .iter()
900        .enumerate()
901        .find(|(_, symbol)| {
902            elf.dynstrtab.get_at(symbol.st_name) == Some("reverie_liteinst_initialize")
903        })
904        .ok_or_else(|| io::Error::other("checked LiteInst initializer disappeared"))?;
905    let init_array = elf
906        .section_headers
907        .iter()
908        .find(|section| section.sh_type == section_header::SHT_INIT_ARRAY)
909        .ok_or_else(|| {
910            io::Error::new(
911                io::ErrorKind::InvalidData,
912                format!(
913                    "LiteInst runtime {} has no constructor array",
914                    path.display()
915                ),
916            )
917        })?;
918    let init_start = init_array.sh_addr;
919    let init_end = init_start.saturating_add(init_array.sh_size);
920    let relocated_initializer = elf
921        .dynrelas
922        .iter()
923        .chain(elf.dynrels.iter())
924        .any(|relocation| {
925            (init_start..init_end).contains(&relocation.r_offset)
926                && relocation.r_sym == initializer_index
927        });
928    let init_bytes = usize::try_from(init_array.sh_offset)
929        .ok()
930        .and_then(|start| {
931            usize::try_from(init_array.sh_size)
932                .ok()
933                .and_then(|size| bytes.get(start..start.checked_add(size)?))
934        })
935        .unwrap_or_default();
936    let direct_initializer = init_bytes
937        .as_chunks::<8>()
938        .0
939        .iter()
940        .any(|entry| u64::from_le_bytes(*entry) == initializer.st_value);
941    if !relocated_initializer && !direct_initializer {
942        return Err(io::Error::new(
943            io::ErrorKind::InvalidData,
944            format!(
945                "LiteInst runtime {} does not register reverie_liteinst_initialize as a preload constructor",
946                path.display()
947            ),
948        ));
949    }
950    path.canonicalize()
951}

1192fn take_skid_overshoot_error() -> Option<SkidOvershootError> {

1197impl SkidOvershootReport {
1198    fn begin(enabled: bool) -> Self {
1199        if enabled {
1200            // A previous invocation in this process must not qualify this one.
1201            let _ = reverie::take_skid_overshoot_count();
1202        }
1203        Self { enabled }
1204    }
1205
1206    fn finish<T>(self, result: Result<T, Error>) -> Result<T, Error> {
1207        if !self.enabled {
1208            return result;
1209        }
1210
1211        let Some(overshoot) = take_skid_overshoot_error() else {
1212            return result;
1213        };
1214        match result {
1215            Ok(_) => Err(Error::new(overshoot)),
1216            Err(error) => Err(error.context(overshoot)),
1217        }
1218    }
1219
1220    fn finish_with_count<T>(self, result: Result<T, Error>) -> Result<(T, u64), Error> {
1221        if !self.enabled {
1222            return result.map(|value| (value, 0));
1223        }
1224
1225        let count = reverie::take_skid_overshoot_count();
1226        match result {
1227            Ok(value) => Ok((value, count)),
1228            Err(error) if count > 0 => Err(error.context(SkidOvershootError::new(count))),
1229            Err(error) => Err(error),
1230        }
1231    }
1232}

1288// TODO-HUMAN-REVIEW(PR-739): Review SaBRe loader discovery and executable validation.
1289fn resolve_sabre_binary_from(
1290    override_path: Option<&OsStr>,
1291    packaged_path: Option<&Path>,
1292    executable: &Path,
1293    path_env: &OsStr,
1294) -> Result<PathBuf, Error> {
1295    if let Some(requested) = override_path {
1296        if requested.is_empty() {
1297            return Err(anyhow!("{SABRE_BINARY_ENV} is empty"));
1298        }
1299        let path = PathBuf::from(requested);
1300        return is_executable_file(&path)
1301            .then_some(path.clone())
1302            .ok_or_else(|| {
1303                anyhow!(
1304                    "{SABRE_BINARY_ENV}={} is not an executable file",
1305                    path.display()
1306                )
1307            });
1308    }
1309
1310    if let Some(path) = packaged_path
1311        && is_executable_file(path)
1312    {
1313        return Ok(path.to_path_buf());
1314    }
1315
1316    let directory = executable
1317        .parent()
1318        .ok_or_else(|| anyhow!("Hermit executable has no parent directory"))?;
1319    let sibling = directory.join("sabre");
1320    let target_build = directory.parent().map(|target| target.join("sabre/sabre"));
1321
1322    if is_executable_file(&sibling) {
1323        return Ok(sibling);
1324    }
1325    if let Some(candidate) = &target_build
1326        && is_executable_file(candidate)
1327    {
1328        return Ok(candidate.clone());
1329    }
1330    if !path_env.is_empty()
1331        && let Some(candidate) = std::env::split_paths(path_env)
1332            .map(|directory| directory.join("sabre"))
1333            .find(|candidate| is_executable_file(candidate))
1334    {
1335        return Ok(candidate);
1336    }
1337
1338    Err(anyhow!(
1339        "SaBRe executable was not found in the Hermit installation, beside {}, or in PATH; set {} or {SABRE_BINARY_ENV}",
1340        executable.display(),
1341        hermit_resources::INSTALL_DIR_ENV
1342    ))
1343}

1471    global: &Arc<T>,
1472    timeout: Duration,
1473) -> Result<(), usize> {
1474    let disconnected = tokio::time::timeout(timeout, async {
1475        while Arc::strong_count(global) > 1 {

1486    if live_references == 0 {
1487        Ok(())
1488    } else {
1489        Err(live_references)
1490    }
1491}

1550/// Run one command with the Detcore tool executing inside a SaBRe plugin and
1551/// the single GlobalState held by this Hermit coordinator process.
1552// AUTONOMOUS-BOT-IMPLEMENTED
1553// TODO-HUMAN-REVIEW(PR-738): Review SaBRe coordinator lifetime and artifact loading.
1554async fn run_sabre(
1555    mut command: Command,
1556    config: DetConfig,
1557    print_summary: bool,
1558    print_summary_to_json_file: &Option<PathBuf>,
1559    capture_output: bool,
1560) -> Result<Output, Error> {
1561    let path_evidence_file = std::env::var_os(SABRE_PATH_EVIDENCE_ENV).map(PathBuf::from);
1562    let sabre = resolve_sabre_binary()?;
1563    let plugin = sabre_runtime_library_path()
1564        .map_err(|error| anyhow!("failed to locate the Detcore SaBRe plugin: {error}"))?;
1565    let program = command.find_program().map_err(|error| {
1566        anyhow!(
1567            "failed to resolve SaBRe guest executable {:?}: {error}",
1568            command.get_program()
1569        )
1570    })?;
1571    let staged_program = stage_sabre_program_in(&program, Path::new(SABRE_STAGING_DIRECTORY))?;
1572    let launch_program = staged_program
1573        .as_ref()
1574        .map_or(program.as_path(), |staged| staged.path.as_path());
1575
1576    // This runs after Hermit enters the guest mount namespace, where `/tmp`
1577    // names the container-visible temporary filesystem. Do not inherit a
1578    // host-side nested TMPDIR: validation commonly sets TMPDIR=/tmp/<run>/tmp,
1579    // but that parent path is hidden once the private `/tmp` mount is active.
1580    // The SaBRe plugin and coordinator must name the socket through the same
1581    // namespace-visible path.
1582    let socket_dir = tempfile::Builder::new()
1583        .prefix("hermit-sabre-rpc-")
1584        .tempdir_in(Path::new("/tmp"))?;
1585    let socket_path = socket_dir.path().join("coordinator.sock");
1586    let fallback_ready = Arc::new(AtomicBool::new(false));
1587    let global = Arc::new(detcore::GlobalState::init_global_state(&config).await);
1588    let server = reverie_rpc_transport::RpcServer::bind_with_readiness(
1589        &socket_path,
1590        global.clone(),
1591        config.clone(),
1592        fallback_ready.clone(),
1593    )
1594    .map_err(|error| anyhow!("failed to start SaBRe coordinator RPC: {error}"))?;
1595    let server_task = tokio::spawn(async move { server.serve().await });
1596
1597    command.prepend_args([
1598        plugin.as_os_str(),
1599        OsStr::new("--"),
1600        launch_program.as_os_str(),
1601    ]);
1602    command.program(&sabre);
1603    command.env(SABRE_RPC_SOCKET_ENV, &socket_path);
1604    // Publish the shape of the Config this coordinator will send. The plugin is a
1605    // separate artifact in the same target directory, so it can be stale without
1606    // looking it; comparing here turns an opaque decode failure at connect into a
1607    // message that names the mismatch. See detcore_model::config_wire_fingerprint.
1608    command.env(
1609        detcore::CONFIG_FINGERPRINT_ENV,
1610        detcore::config_wire_fingerprint(),
1611    );
1612    command.env_remove(SABRE_PATH_EVIDENCE_ENV);
1613    command.env_remove(SABRE_DETLOG_FORWARD_ENV);
1614    if tracing::enabled!(target: "detcore", tracing::Level::INFO) {
1615        command.env(SABRE_DETLOG_FORWARD_ENV, "1");
1616    }
1617    command.env_remove("SABRE_BINARY");
1618    command.env_remove("SABRE_PLUGIN");
1619
1620    // THE SOCKET PATH IS DELIBERATELY RANDOM AND MUST NOT BE COMPARED.
1621    //
1622    // `tempfile` appends a random 6-character suffix to the directory above, so
1623    // the absolute path differs on every launch by design -- that is what keeps
1624    // concurrent hermit invocations on a shared host from binding the same
1625    // coordinator socket. Emitting it at INFO put per-launch randomness into the
1626    // INFO stream, which `--verify-strict` compares:
1627    //
1628    //   Mismatch at log messages 2 (run 1) and 2 (run 2):
1629    //   < socket=/tmp/hermit-sabre-rpc-Gw6tUi/coordinator.sock
1630    //   > socket=/tmp/hermit-sabre-rpc-7SZ94p/coordinator.sock
1631    //
1632    // That fails EVERY SaBRe verify cell before the guest executes an
1633    // instruction, for a host-side value with no guest-visible content. The
1634    // defect was in the oracle, not the backend.
1635    //
1636    // WHY THE VALUE IS DROPPED FROM INFO RATHER THAN MADE DETERMINISTIC: the two
1637    // `--verify` runs execute in SEPARATE CHILD PROCESSES, so any path stable
1638    // across both would have to be derived from state shared between them. That
1639    // trades `tempfile`'s guaranteed-fresh directory for a reused one, and a
1640    // run1 that dies holding the socket would then make run2 fail to bind -- a
1641    // real new failure mode in exchange for a cosmetic field. The path keeps its
1642    // randomness; only the compared stream stops carrying it.
1643    //
1644    // This is NOT a comparator relaxation. No normalization envelope is widened,
1645    // so any future randomness leaking into this banner still fails the
1646    // comparison. The full path remains available one level down.
1647    tracing::debug!(
1648        target: "hermit::sabre",
1649        socket = %socket_path.display(),
1650        "SaBRe coordinator RPC socket (per-launch temp path, deliberately not at INFO)",
1651    );
1652    tracing::info!(
1653        target: "hermit::sabre",
1654        guest = %program.display(),
1655        plugin = %plugin.display(),
1656        "launching Detcore guest through SaBRe with coordinator RPC",
1657    );
1658
1659    let supervised = match sabre_ptrace::run(
1660        command.into_std_lossy(),
1661        PathBuf::from(&sabre),
1662        plugin.clone(),
1663        fallback_ready,
1664        global.clone(),
1665        capture_output,
1666    )
1667    .await
1668    {
1669        Ok(supervised) => supervised,
1670        Err(error) => {
1671            global.release_all_physical_process_exits();
1672            global.force_shutdown_with_error();
1673            let _ = shutdown_sabre_rpc(server_task, &global, SABRE_RPC_DISCONNECT_TIMEOUT).await;
1674            return Err(error);
1675        }
1676    };
1677    // The supervisor returns only after every tracee reached a final kernel wait status. Release
1678    // the root process's barrier (and any intentionally unreaped child barriers) before scheduler
1679    // shutdown; no guest thread remains that could race timer fast-forward here.
1680    global.release_all_physical_process_exits();
1681    // A SaBRe execution in which no guest thread ever reached the coordinator
1682    // is an execution in which Detcore was never loaded as a Reverie tool: the
1683    // guest ran on bare Linux. Treat it exactly like a failed run so the
1684    // scheduler is torn down here instead of blocking forever in `clean_up`
1685    // below, waiting for a guest thread that will never register.
1686    let detcore_never_engaged = !supervised.path_evidence.guest_rpc_observed;
1687    let requires_forced_shutdown = !supervised.status.success() || detcore_never_engaged;
1688    if requires_forced_shutdown {
1689        global.force_shutdown_with_error();
1690    }
1691    // Emit one unconditional, machine-readable per-run fact instead of a
1692    // free-form warning. SaBRe loads the guest interpreter before the Detcore
1693    // plugin, so pre-plugin loader syscalls are structurally absent from its
1694    // observation envelope. Versioning that fact lets scorecard consumers
1695    // reject old or incomplete records rather than infer coverage from silence.
1696    //
1697    // Keep this in the controller-diagnostic stream rather than writing
1698    // directly to the process stderr that also carries captured guest stderr.
1699    // WARN is Hermit's default tracing level, and `--log-file` can therefore
1700    // separate the unconditional controller fact from guest output without a
1701    // comparator exception. A missing record remains distinct from a record
1702    // whose counters are zero.
1703    let backend_evidence = sabre_backend_evidence_line(&supervised.path_evidence);
1704    tracing::warn!(target: "hermit::sabre", "{backend_evidence}");
1705    if let Some(path) = path_evidence_file {
1706        let mut file = fs::OpenOptions::new()
1707            .create(true)
1708            .append(true)
1709            .mode(0o600)
1710            .open(&path)
1711            .map_err(|error| {
1712                anyhow!(
1713                    "failed to open SaBRe path evidence {}: {error}",
1714                    path.display()
1715                )
1716            })?;
1717        serde_json::to_writer(&mut file, &supervised.path_evidence)?;
1718        writeln!(file)?;
1719    }
1720    let output = Output {
1721        status: supervised.status.into(),
1722        stdout: supervised.stdout,
1723        stderr: supervised.stderr,
1724    };
1725
1726    shutdown_sabre_rpc(server_task, &global, SABRE_RPC_DISCONNECT_TIMEOUT).await?;
1727    let mut global = Arc::try_unwrap(global).map_err(|global| {
1728        anyhow!(
1729            "SaBRe coordinator stopped with {} live RPC reference(s)",
1730            Arc::strong_count(&global) - 1
1731        )
1732    })?;
1733    if requires_forced_shutdown {
1734        global.cancel_internal_scheduler().await;
1735    }
1736    global
1737        .clean_up(print_summary, print_summary_to_json_file)
1738        .await;
1739    tracing::info!(
1740        target: "hermit::sabre::fallback",
1741        ptrace_fallback_sites = supervised.path_evidence.ptrace_fallback_sites,
1742        trusted_shared_object_sites = supervised.path_evidence.trusted_shared_object_sites,
1743        guest_rpc_observed = supervised.path_evidence.guest_rpc_observed,
1744        "SaBRe ptrace fallback completed",
1745    );
1746    if detcore_never_engaged {
1747        return Err(anyhow!(
1748            "{}",
1749            sabre_uninstrumented_guest_message(&output.status)
1750        ));
1751    }
1752    Ok(output)
1753}

1790/// Explain a SaBRe run whose guest never reached the Detcore coordinator.
1791///
1792/// `guest_rpc_observed` is set by the coordinator RPC listener the first time a
1793/// SaBRe-loaded guest connects. When it stays false the guest completed without
1794/// Detcore intercepting anything, so the run carries no determinism guarantee
1795/// whatsoever -- its timing, scheduling, PIDs, and clock reads all came from the
1796/// host. Reporting that as a successful `hermit run` would be a fail-open
1797/// determinism hole, so the caller turns it into a hard error and this function
1798/// supplies the diagnosis.
1799///
1800/// The dominant cause is a guest whose syscall sites SaBRe never rewrote. A
1801/// statically linked ELF is the sharp edge: it has no dynamic loader and no
1802/// shared library through which SaBRe could regain control, so an unrewritten
1803/// static client runs entirely on bare Linux with no second chance.
1804fn sabre_uninstrumented_guest_message(status: &ExitStatus) -> String {
1805    format!(
1806        "the SaBRe backend finished ({status:?}) without the guest ever reaching the Detcore \
1807         coordinator: no syscall was intercepted, so this run applied no determinization at all \
1808         and its result is not a Hermit guarantee. This means SaBRe rewrote no syscall site in \
1809         the guest -- most often a statically linked ELF, whose syscall sites SaBRe must patch \
1810         in the client image itself because there is no dynamic loader to intercept."
1811    )
1812}

1819/// Maximum `#!` interpreter indirection levels, matching the Linux kernel's
1820/// `BINPRM_MAX_RECURSION` limit for chained script interpreters.
1821const MAX_SHEBANG_DEPTH: usize = 4;
1822
1823/// Resolve `#!` interpreter scripts before the reverie-kvm ELF loader runs.
1824///
1825/// The KVM ELF loader can only map ELF images, so a guest program that is
1826/// actually a `#!`-script (for example `/usr/local/bin/file` -> `#!/bin/bash`,
1827/// or `/usr/bin/pkg-config` -> `#!/usr/bin/sh`) must be rewritten to launch its
1828/// interpreter, exactly as the kernel's `execve(2)` `binfmt_script` handler
1829/// does. On success the returned image is an ELF and `argv` has the interpreter,
1830/// its shebang arguments, and the script path prepended in kernel order:
1831/// `[interp, shebang_args.., script_path, <original argv[1..]>]`.
1832///
1833/// The interpreter line is parsed with hermit's shared [`Shebang`] so the KVM
1834/// backend matches how the ptrace backend and recorder treat `#!`-scripts.
1835fn resolve_kvm_shebang(
1836    resolved_program: &Path,
1837    mut argv: Vec<String>,
1838) -> Result<(PathBuf, Vec<String>, Vec<u8>), Error> {
1839    let mut load_path = resolved_program.to_path_buf();
1840    let mut image = fs::read(&load_path)
1841        .map_err(|error| anyhow!("failed to read KVM guest executable {load_path:?}: {error}"))?;
1842
1843    let mut depth = 0;
1844    while image.starts_with(b"#!") {
1845        depth += 1;
1846        if depth > MAX_SHEBANG_DEPTH {
1847            return Err(anyhow!(
1848                "too many levels of `#!` interpreter indirection loading {resolved_program:?}"
1849            ));
1850        }
1851        let (interpreter, shebang_args) = Shebang::from_buf(&image)
1852            .ok_or_else(|| anyhow!("malformed `#!` interpreter line in {load_path:?}"))?
1853            .into_parts();
1854        let interpreter_str = interpreter
1855            .to_str()
1856            .ok_or_else(|| anyhow!("non-UTF-8 `#!` interpreter path in {load_path:?}"))?
1857            .to_owned();
1858
1859        // Rewrite argv in kernel order. The prior argv[0] (the script's own
1860        // name) is dropped on the first level; on deeper levels the previous
1861        // interpreter path is preserved as a positional argument, matching
1862        // `binfmt_script`.
1863        let mut rewritten = Vec::with_capacity(argv.len() + shebang_args.len() + 2);
1864        rewritten.push(interpreter_str);
1865        for arg in &shebang_args {
1866            rewritten.push(
1867                arg.to_str()
1868                    .ok_or_else(|| anyhow!("non-UTF-8 `#!` interpreter argument in {load_path:?}"))?
1869                    .to_owned(),
1870            );
1871        }
1872        rewritten.push(load_path.to_string_lossy().into_owned());
1873        rewritten.extend_from_slice(&argv[1..]);
1874        argv = rewritten;
1875
1876        load_path = interpreter;
1877        image = fs::read(&load_path).map_err(|error| {
1878            anyhow!(
1879                "failed to read `#!` interpreter {load_path:?} for {resolved_program:?}: {error}"
1880            )
1881        })?;
1882    }
1883
1884    Ok((load_path, argv, image))
1885}

1887/// The container replaces this host directory with a private, empty tmpfs, so
1888/// nothing beneath it is visible to the guest. Kept next to the diagnostic that
1889/// depends on it; `run.rs` has its own `TMP_DIR` for the mount itself.
1890const CONTAINER_REPLACED_TMP: &str = "/tmp";
1891
1892/// Explain why a working directory that plainly exists on the host could not be
1893/// resolved for the guest.
1894///
1895/// ⚠️ THIS FUNCTION EXISTS BECAUSE THE BARE ERROR CAUSED A MISDIAGNOSIS, not to
1896/// be tidy. `fs::canonicalize` runs after the container's mounts are applied, and
1897/// the container bind-mounts a fresh empty tmpfs over `/tmp`
1898/// (`bin/hermit/container.rs`). So a cwd beneath `/tmp` is genuinely absent from
1899/// the guest's mount namespace and `canonicalize` returns a perfectly correct
1900/// `NotFound` -- for a directory the user can `ls`.
1901///
1902/// Reported 2026-08-25 as "run_kvm_ cli tests fail from a git worktree". They do
1903/// not. Measured across five working directories with one binary: a PLAIN
1904/// directory under `/tmp` with no git in it FAILS, and a linked git worktree
1905/// under `/home` WORKS. The only property that tracks the failure is "the cwd is
1906/// under /tmp"; `/tmp` itself resolves because the mount POINT exists. The git
1907/// hypothesis cost real investigation time, and it came from this message saying
1908/// only "No such file or directory".
1909///
1910/// It mattered more than a stray report because the historical landing recipe
1911/// placed detached worktrees below `/tmp`, exactly where this fires. Current
1912/// dev-hermit worktrees are created through wrkslots below `worktrees/`, but the
1913/// diagnostic remains necessary for arbitrary callers and older checkouts.
1914///
1915/// The message names the mechanism and both ways out. It deliberately does NOT
1916/// silently fall back to `/`: changing the guest's working directory out from
1917/// under a caller who asked for a specific one would trade a loud, correct
1918/// failure for a quiet, wrong success.
1919fn kvm_cwd_resolution_error(requested_cwd: &Path, error: &std::io::Error) -> Error {
1920    let under_replaced_tmp = requested_cwd.starts_with(CONTAINER_REPLACED_TMP)
1921        && requested_cwd != Path::new(CONTAINER_REPLACED_TMP);
1922    if error.kind() == std::io::ErrorKind::NotFound && under_replaced_tmp {
1923        anyhow!(
1924            "failed to resolve KVM guest working directory {:?}: {error}\n\
1925             \n\
1926             This directory may well exist on the host. The container replaces \
1927             {CONTAINER_REPLACED_TMP} with a private, empty tmpfs, so nothing beneath \
1928             {CONTAINER_REPLACED_TMP} is visible to the guest, and resolving the working \
1929             directory happens inside that mount namespace.\n\
1930             Either run from a directory outside {CONTAINER_REPLACED_TMP}, or pass \
1931             --workdir with a path that exists inside the guest.",
1932            requested_cwd
1933        )
1934    } else {
1935        anyhow!(
1936            "failed to resolve KVM guest working directory {:?}: {error}",
1937            requested_cwd
1938        )
1939    }
1940}

1942/// Dispatch a command onto the real reverie-kvm Tool runtime.
1943async fn run_kvm(
1944    command: &Command,
1945    mut config: DetConfig,
1946    print_summary: bool,
1947    print_summary_to_json_file: &Option<PathBuf>,
1948    capture_output: bool,
1949) -> Result<Output, Error> {
1950    let dispatch_started = Instant::now();
1951    // KVM does not expose the outer container's procfs. Its executor serves a
1952    // synthetic `/proc/self/mountinfo` containing one deterministic rootfs row
1953    // (`reverie-kvm/src/executor.rs::synthetic_proc_content`). Consequently
1954    // none of the outer namespace's Hermit-owned bind mounts, or their raw
1955    // mount IDs, can appear in the bytes Detcore receives. The exact provenance
1956    // set for KVM's guest-visible mount table is therefore empty. Keeping outer
1957    // IDs here is not conservative: it makes the shared sanitizer reject a
1958    // valid synthetic row because those IDs name a different namespace.
1959    config.mountinfo_root_rewrites.clear();
1960    // reverie-kvm's synthetic mountinfo row spells the root filesystem device
1961    // as 0:1, while pathname metadata for `/` comes from the host root.  Record
1962    // that backend-proven equivalence explicitly so mountinfo and stat/statx
1963    // enter Detcore's shared DevicePool under the same raw identity.  This is
1964    // not a DevicePool ordinal: the guest-visible number remains allocated by
1965    // the same first-observation policy as every other filesystem device.
1966    let root_device = fs::metadata("/")
1967        .context("failed to inspect the KVM guest root filesystem device")?
1968        .dev();
1969    config.mountinfo_device_rewrites.clear();
1970    config
1971        .mountinfo_device_rewrites
1972        .push((libc::makedev(0, 1), root_device));
1973    // reverie-kvm supplies its own synthetic raw mount IDs. The shared
1974    // sanitizer derives their canonical order from that synthetic snapshot;
1975    // outer-container IDs describe a different namespace and must not leak in.
1976    // The current executor denies `/proc/self/fdinfo/*`, so KVM provides no
1977    // fdinfo/mountinfo cross-file assurance; tests pin mountinfo output/status
1978    // only and must not promote that result to L2 parity.
1979    config.mountinfo_mount_ids.clear();
1980    config.mountinfo_mount_ids_captured = false;
1981    config.fdinfo_unlisted_mount_ids.clear();
1982    let stdin = if capture_output {
1983        let (snapshot_reserved, snapshot) = output_backend_stdin_reservation()?;
1984        if snapshot_reserved {
1985            snapshot
1986        } else {
1987            // Public KVM output-capture callers do not pass through the CLI's
1988            // verify setup. Preserve their existing stdin behavior instead of
1989            // silently replacing it with /dev/null merely because output is
1990            // captured.
1991            reserved_kvm_stdin()?
1992        }
1993    } else {
1994        reserved_kvm_stdin()?
1995    };
1996    let requested_cwd = command
1997        .get_current_dir()
1998        .map(Path::to_owned)
1999        .unwrap_or(std::env::current_dir()?);
2000    let cwd = fs::canonicalize(&requested_cwd)
2001        .map_err(|error| kvm_cwd_resolution_error(&requested_cwd, &error))?;
2002    let program = command
2003        .get_program()
2004        .to_str()
2005        .ok_or_else(|| anyhow!("KVM guest executable path is not valid UTF-8"))?
2006        .to_owned();
2007    if !cwd.is_dir() {
2008        return Err(anyhow!(
2009            "KVM guest working directory is not a directory: {:?}",
2010            cwd
2011        ));
2012    }
2013    let resolved_program = command.find_program().map_err(|error| {
2014        anyhow!("failed to resolve KVM guest executable {program:?} in the guest PATH: {error}")
2015    })?;
2016    let mut argv = Vec::with_capacity(1 + command.get_args().count());
2017    argv.push(program.clone());
2018    for argument in command.get_args() {
2019        argv.push(
2020            argument
2021                .to_str()
2022                .ok_or_else(|| anyhow!("KVM guest argument is not valid UTF-8"))?
2023                .to_owned(),
2024        );
2025    }
2026
2027    // Rewrite `#!`-scripts to their interpreter before the ELF loader sees them.
2028    let (_interpreter_path, argv, image) = resolve_kvm_shebang(&resolved_program, argv)?;
2029    // After shebang resolution the executable is the interpreter (argv[0]).
2030    let program = argv.first().cloned().unwrap_or(program);
2031    let envp = command
2032        .get_captured_envs()
2033        .into_iter()
2034        .map(|(key, value)| {
2035            let key = key
2036                .to_str()
2037                .ok_or_else(|| anyhow!("KVM guest environment key is not valid UTF-8"))?;
2038            let value = value
2039                .to_str()
2040                .ok_or_else(|| anyhow!("KVM guest environment value is not valid UTF-8"))?;
2041            Ok(format!("{key}={value}"))
2042        })
2043        .collect::<Result<Vec<_>, Error>>()?;
2044    tracing::info!(
2045        target: "hermit::kvm",
2046        program = %program,
2047        argv = ?argv,
2048        cwd = %cwd.display(),
2049        env_count = envp.len(),
2050        "launching guest through reverie-kvm",
2051    );
2052    let argv = argv.iter().map(String::as_str).collect::<Vec<_>>();
2053    let envp = envp.iter().map(String::as_str).collect::<Vec<_>>();
2054
2055    let setup_started = Instant::now();
2056    config.cpuid_virtualized_by_backend = true;
2057    config.backend_supports_madvise = false;
2058    // KVM does not enter Hermit's UTS namespace, so Detcore must provide the
2059    // same synthetic identity that the namespace-backed ptrace path exposes.
2060    // TODO-HUMAN-REVIEW(PR-998): Review KVM UTS namespace parity.
2061    config.has_uts_namespace = false;
2062    let random_seed = config.rng_seed();
2063    let mut backend = reverie_kvm::KvmBackend::new_with_stdin(KVM_GUEST_MEMORY_BYTES, stdin)
2064        .map_err(|error| anyhow!("failed to initialize reverie-kvm: {error}"))?;
2065    // AUTONOMOUS-BOT-IMPLEMENTED
2066    // TODO-HUMAN-REVIEW(PR-1120): Review KVM's canonical Detcore root identity.
2067    backend
2068        .set_root_pid(detcore::ROOT_DETPID.as_raw())
2069        .map_err(|error| anyhow!("failed to configure KVM root PID: {error}"))?;
2070    backend
2071        .install_static_elf_with_context(&image, &argv, &envp, &cwd)
2072        .map_err(|error| anyhow!("failed to load KVM guest executable {program:?}: {error}"))?;
2073    backend
2074        .set_random_seed(random_seed)
2075        .map_err(|error| anyhow!("failed to configure KVM guest random seed: {error}"))?;
2076    // The KVM backend now defaults to Tool-owned guest threads: CLONE_THREAD
2077    // workers are driven through the Detcore tool loop and their futex/CLEARTID
2078    // synchronization routes to Detcore, matching the golden ptrace model
2079    // ("follow children"). Detcore's own clone logic treats a CLONE_THREAD as
2080    // backend-uninstrumented iff `backend_dispatches_thread_tools` is false (see
2081    // detcore/src/syscalls/threads.rs), so in exactly that case opt the backend
2082    // out to host-owned threads to keep worker execution and futex ownership in
2083    // one synchronization domain (mixing them deadlocks pthread_join). In the
2084    // default (true) case the backend already follows children, so no call is
2085    // needed.
2086    if !config.backend_dispatches_thread_tools {
2087        backend.unmonitored_threads();
2088    }
2089
2090    let execution_started = Instant::now();
2091    let (global_state, code, stdout, stderr) = backend
2092        .run_static_elf_with_tool::<Detcore>(config, capture_output)
2093        .await
2094        .map_err(|error| anyhow!("KVM guest execution failed: {error}"))?;
2095    let cleanup_started = Instant::now();
2096    global_state
2097        .clean_up(print_summary, print_summary_to_json_file)
2098        .await;
2099    let teardown_started = Instant::now();
2100    // Drop explicitly so the host's KVM VM teardown cost remains observable.
2101    drop(backend);
2102    let teardown_finished = Instant::now();
2103
2104    // Every field below is a host wall-clock duration. Keep this diagnostic at
2105    // DEBUG so it remains available for backend profiling without entering the
2106    // INFO stream exposed to canonical comparison. KVM's built-in verification
2107    // is still output/status-only; this classification does not claim KVM L2.
2108    tracing::debug!(
2109        target: "hermit::kvm",
2110        prepare_us = setup_started.duration_since(dispatch_started).as_micros() as u64,
2111        setup_us = execution_started.duration_since(setup_started).as_micros() as u64,
2112        execution_us = cleanup_started.duration_since(execution_started).as_micros() as u64,
2113        cleanup_us = teardown_started.duration_since(cleanup_started).as_micros() as u64,
2114        teardown_us = teardown_finished.duration_since(teardown_started).as_micros() as u64,
2115        lifecycle_us = teardown_finished.duration_since(dispatch_started).as_micros() as u64,
2116        "reverie-kvm lifecycle phase timings",
2117    );
2118
2119    if !capture_output {
2120        std::io::stdout().write_all(&stdout)?;
2121        std::io::stderr().write_all(&stderr)?;
2122    }
2123
2124    Ok(Output {
2125        status: ExitStatus::Exited(code),
2126        stdout,
2127        stderr,
2128    })
2129}

2365// to move together, because both readers derive it from the same fact. When the reserved set grew to include the signal
2366// band, `Exited(130)` fell outside `122..=127` and is NOT `Signaled(_, _)` --

2377// COMMENT SAID THEY WERE. agent(hermit-007)'s codex lane caught the overclaim.

2379//
2380//   this predicate            122..=127  +  signal band  +  real Signaled
2381//   classify_container_result 122        +  signal band
2382//
2383// 123..=127 force a LiteInst shutdown and are classified as NEITHER a refusal
2384// nor a signal death -- 123 is safehermit's log cap, 124 a deadline, 125 hermit
2385// itself, 126/127 exec-level, and each has a different producer. Only the signal
2386// half is shared, and only the signal half is protected from drift. Do not
2387// "simplify" this by assuming the two agree; the `122..=127` bound here is still
2388// hard-coded and still needs a human to widen it if the reserved set grows

2396            // "killed by signal N".
2397            (122..=127).contains(&code) || detcore_model::signal_from_exit_status(code).is_some()
2398        }

2425/// How long the unwind gets before the hard fallback fires.
2426///
2427/// The fallback exists because the gentle path can itself wedge: if the guest
2428/// is stopped in a way that keeps a tracer task from completing, dropping the
2429/// future never returns and the deadline would be as inert as the mechanisms
2430/// this replaces. Ten seconds is the same grace the per-cell
2431/// `timeout --kill-after=10s` already uses, so the two tiers agree rather than
2432/// racing on different numbers.
2433const RUN_TIMEOUT_UNWIND_GRACE: Duration = Duration::from_secs(10);
2434
2435/// Bound `guest` by `timeout`, preferring an unwind over a kill.
2436///
2437/// ⚠️ THE UNWIND IS THE POINT. `tokio::time::timeout` DROPS the guest future on
2438/// expiry, and dropping it is what runs every `Drop` in the async stack:
2439/// reverie detaches and reaps its tracees, detcore's global state is dropped,
2440/// and the error then propagates out through `with_container`, so the container
2441/// init returns NORMALLY instead of `_exit`ing. The mounts and the guest go away
2442/// because the namespace is torn down in order, not because the kernel demolished
2443/// it under us.
2444///
2445/// Contrast `record_start.rs`'s `recording_timeout_handler`, which this follows
2446/// in SHAPE but deliberately not in ACTION: it `_exit(124)`s from a signal
2447/// handler, skipping every destructor, because a signal handler may only call
2448/// async-signal-safe functions and cannot unwind. That remains the right answer
2449/// for the FALLBACK tier below and the wrong one for the primary path.
2450///
2451/// ⚠️ WHY A FALLBACK IS STILL REQUIRED. The primary path depends on the runtime
2452/// reaching the timer, and on the dropped future actually completing its own
2453/// teardown. Neither is guaranteed for an arbitrary wedged guest. A bound that
2454/// works only when the run was healthy enough not to need it is the inert
2455/// mechanism this exists to remove, so the alarm below is armed FIRST and is
2456/// disarmed by RAII only once the unwind has finished.
2457async fn with_run_deadline<F>(timeout: Option<Duration>, guest: F) -> Result<ExitStatus, Error>
2458where
2459    F: std::future::Future<Output = Result<ExitStatus, Error>>,
2460{
2461    let Some(limit) = timeout else {
2462        return guest.await;
2463    };
2464
2465    // Armed before the guest starts and dropped after it finishes, so the
2466    // window it covers is exactly the window the bound applies to.
2467    let _fallback = RunTimeoutFallback::arm(limit + RUN_TIMEOUT_UNWIND_GRACE)?;
2468
2469    match tokio::time::timeout(limit, guest).await {
2470        Ok(result) => result,
2471        // The future has already been dropped by `timeout` at this point; every
2472        // destructor in the guest stack has run before we get here.
2473        Err(_elapsed) => {
2474            stall_the_unwind_if_asked();
2475            Err(Error::new(GuestTimedOut { limit }))
2476        }
2477    }
2478}

2480/// Test-only: hold the post-expiry path open past the grace so the SIGALRM
2481/// fallback is the thing that ends the run.
2482///
2483/// ⚠️ THIS EXISTS BECAUSE THE FALLBACK COULD NOT BE MADE TO FIRE ANY OTHER WAY,
2484/// AND AN UNEXERCISED SAFETY PATH IS THE FAILURE MODE THIS PROJECT KEEPS
2485/// FINDING. Measured 2026-08-26 at this commit: the primary path fired at
2486/// exactly the bound for a userspace spinner, a guest blocked reading a pipe
2487/// with no writer, a guest that `SIGSTOP`s itself, an eight-thread guest
2488/// ignoring `SIGTERM`, and a multi-process guest ignoring `SIGTERM` -- five
2489/// shapes, five clean unwinds, no wedge. That is a good result for the primary
2490/// path and it leaves the fallback with zero executions, which is exactly the
2491/// mechanism-that-has-never-run shape.
2492///
2493/// ⚠️ WHAT THIS DOES AND DOES NOT REPRODUCE, stated precisely rather than
2494/// implied. It reproduces the CONDITION the fallback is specified against --
2495/// the post-expiry path not completing within `RUN_TIMEOUT_UNWIND_GRACE` -- and
2496/// it exercises the real alarm, the real inherited-mask handling, the real
2497/// handler, the real message and the real `_exit`. It does NOT reproduce any
2498/// particular upstream CAUSE of a slow unwind, because none is known; the delay
2499/// is here, after the drop, rather than inside a wedged destructor. A future
2500/// reader must not read a passing fallback test as evidence that some specific
2501/// teardown hang is handled.
2502///
2503/// Deliberately keyed off an environment variable named like the existing
2504/// `HERMIT_INTERNAL_LITEINST_ACTIVATION_PROBE` rather than a `cfg(test)` gate:
2505/// the fallback lives in the shipped binary and must be exercised there, not in
2506/// a differently-compiled one.
2507fn stall_the_unwind_if_asked() {
2508    const STALL_ENV: &str = "HERMIT_INTERNAL_RUN_TIMEOUT_STALL_UNWIND";
2509    if std::env::var_os(STALL_ENV).as_deref() != Some(std::ffi::OsStr::new("1")) {
2510        return;
2511    }
2512    // Comfortably past the grace, so the alarm -- not this sleep -- ends the
2513    // process. If the fallback is broken this returns and the caller sees an
2514    // ordinary timeout, which is what makes the test able to fail.
2515    std::thread::sleep(RUN_TIMEOUT_UNWIND_GRACE + Duration::from_secs(5));
2516}

2518static RUN_TIMEOUT_MESSAGE: AtomicPtr<u8> = AtomicPtr::new(std::ptr::null_mut());
2519static RUN_TIMEOUT_MESSAGE_LEN: AtomicUsize = AtomicUsize::new(0);

2521/// The hard fallback: fires only if the unwind above did not finish in time.
2522///
2523/// Identical in construction to `record_start.rs`'s `recording_timeout_handler`
2524/// -- non-blocking stderr so a full pipe cannot wedge the handler, then
2525/// `_exit` -- and identical in exit code, because "a deadline fired" is one
2526/// meaning and 124 already carries it for GNU `timeout`, for `safehermit`'s wall
2527/// bound, and for `hermit record`'s own deadline. Reusing it here adds no new
2528/// collision; inventing a fourth number for the same event would.
2529extern "C" fn run_timeout_fallback_handler(_signal: libc::c_int) {
2530    let len = RUN_TIMEOUT_MESSAGE_LEN.load(Ordering::Acquire);
2531    let message = RUN_TIMEOUT_MESSAGE.load(Ordering::Acquire);
2532    if !message.is_null() && len != 0 {
2533        // SAFETY: the message is leaked before the timer is armed, and
2534        // fcntl(2), write(2) and _exit(2) are async-signal-safe.
2535        unsafe {
2536            let flags = libc::fcntl(libc::STDERR_FILENO, libc::F_GETFL);
2537            if flags != -1 {
2538                libc::fcntl(libc::STDERR_FILENO, libc::F_SETFL, flags | libc::O_NONBLOCK);
2539            }
2540            libc::write(libc::STDERR_FILENO, message.cast(), len);
2541        }
2542    }
2543    // Exiting the namespace init tears down the container and its tracees.
2544    // SAFETY: _exit(2) is async-signal-safe and runs no Rust destructors --
2545    // which is precisely why this is the fallback and not the primary path.
2546    unsafe { libc::_exit(HERMIT_DEADLINE_EXIT) }
2547}

2549struct RunTimeoutFallback {
2550    previous_handler: SigAction,
2551    reblock_sigalrm: bool,
2552}
2553
2554impl RunTimeoutFallback {
2555    fn arm(after: Duration) -> Result<Self, Error> {
2556        let seconds: libc::c_uint = after
2557            .as_secs()
2558            .try_into()
2559            .map_err(|_| Error::msg("--timeout exceeds the platform alarm limit"))?;
2560        let message = Box::leak(
2561            format!(
2562                "HERMIT_RUN_TIMEOUT_FALLBACK: the --timeout unwind did not complete within {} seconds; \
2563                 the container was terminated without a clean teardown\n",
2564                RUN_TIMEOUT_UNWIND_GRACE.as_secs()
2565            )
2566            .into_boxed_str(),
2567        );
2568        RUN_TIMEOUT_MESSAGE.store(message.as_mut_ptr(), Ordering::Release);
2569        RUN_TIMEOUT_MESSAGE_LEN.store(message.len(), Ordering::Release);
2570
2571        let action = SigAction::new(
2572            SigHandler::Handler(run_timeout_fallback_handler),
2573            SaFlags::SA_RESETHAND,
2574            SigSet::empty(),
2575        );
2576        // SAFETY: the handler uses only async-signal-safe operations and stays
2577        // installed until this guard disarms it.
2578        let previous_handler = unsafe { sigaction(Signal::SIGALRM, &action) }?;
2579
2580        // A blocked SIGALRM stays pending forever and the handler never runs,
2581        // silently disabling the fallback. `record_start.rs` learned this too.
2582        let mut alarm = SigSet::empty();
2583        alarm.add(Signal::SIGALRM);
2584        let reblock_sigalrm = SigSet::thread_get_mask()
2585            .map(|mask| mask.contains(Signal::SIGALRM))
2586            .unwrap_or(false);
2587        if reblock_sigalrm {
2588            let _ = alarm.thread_unblock();
2589        }
2590
2591        // SAFETY: `seconds` fits c_uint.
2592        unsafe { libc::alarm(seconds) };
2593        Ok(Self {
2594            previous_handler,
2595            reblock_sigalrm,
2596        })
2597    }
2598}

2600impl Drop for RunTimeoutFallback {
2601    fn drop(&mut self) {
2602        // SAFETY: disarm the alarm before restoring the inherited handler.
2603        unsafe {
2604            libc::alarm(0);
2605            let _ = sigaction(Signal::SIGALRM, &self.previous_handler);
2606        }
2607        if self.reblock_sigalrm {
2608            let mut alarm = SigSet::empty();
2609            alarm.add(Signal::SIGALRM);
2610            let _ = alarm.thread_block();
2611        }
2612        RUN_TIMEOUT_MESSAGE_LEN.store(0, Ordering::Release);
2613        RUN_TIMEOUT_MESSAGE.store(std::ptr::null_mut(), Ordering::Release);
2614    }
2615}

2642    print_summary: bool,

2644    backend: Backend,
2645) -> Result<ExitStatus, Error> {

2652            false,

2654        .await?
2655        .status);
2656    }
2657    if backend == Backend::Dbt {
2658        #[cfg(feature = "dbt")]
2659        {
2660            return Ok(run_dbt(command, config, print_summary, false).await?.status);
2661        }
2662        #[cfg(not(feature = "dbt"))]
2663        {
2664            backend.ensure_available()?;
2665            unreachable!("DBT availability must fail when the feature is disabled");
2666        }
2667    }
2668    if backend == Backend::Sabre {
2669        return Ok(run_sabre(
2670            command,
2671            config,
2672            print_summary,
2673            print_summary_to_json_file,
2674            false,
2675        )
2676        .await?
2677        .status);
2678    }
2679    if backend == Backend::Liteinst {
2680        let preload = liteinst_runtime_library_path()?;
2681        let (exit_status, mut global_state) =
2682            reverie_liteinst::LiteinstBackend::run_host_with_preload::<Detcore>(
2683                command, config, preload,
2684            )
2685            .await?;
2686        if liteinst_requires_forced_shutdown(exit_status) {
2687            global_state.force_shutdown_with_error();
2688            global_state.cancel_internal_scheduler().await;
2689        }
2690        global_state
2691            .clean_up(print_summary, print_summary_to_json_file)
2692            .await;
2693        return Ok(exit_status);
2694    }
2695    ensure_backend_dispatch(backend)?;
2696
2697    let stats_request = backend_stats::request();
2698    let mut builder = reverie_ptrace::TracerBuilder::<Detcore>::new(command).config(config.clone());
2699    if config.gdbserver {
2700        builder = builder.gdbserver(config.gdbserver_port);
2701        if config.sequentialize_threads {

2703            // done by detcore already. Without this the gdbserver freezes
2704            // the other threads around a breakpoint stop and waits for each
2705            // to report, but under detcore they are parked in its scheduler
2706            // rather than blocked in the kernel, so they cannot answer until
2707            // the scheduler runs them -- which it cannot while the stopped
2708            // thread holds its turn. The replay path already does this.
2709            builder = builder.sequentialized_guest();
2710        }
2711    }

2713    global_state
2714        .clean_up(print_summary, print_summary_to_json_file)
2715        .await; // Before it's dropped by this function.
2716    backend_stats::report(backend, stats_request, &backend_stats::PtraceStatsSource);
2717    Ok(exit_status)
2718}

2851async fn dispatch_output_backend(
2852    mut command: Command,
2853    config: DetConfig,
2854    print_summary: bool,
2855    print_summary_to_json_file: &Option<PathBuf>,
2856    backend: Backend,
2857) -> Result<Output, Error> {
2858    if backend == Backend::Kvm {
2859        return run_kvm(
2860            &command,
2861            config,
2862            print_summary,
2863            print_summary_to_json_file,
2864            true,
2865        )
2866        .await;
2867    }
2868    if backend == Backend::Dbt {
2869        #[cfg(feature = "dbt")]
2870        {
2871            return run_dbt(command, config, print_summary, true).await;
2872        }
2873        #[cfg(not(feature = "dbt"))]
2874        {
2875            backend.ensure_available()?;
2876            unreachable!("DBT availability must fail when the feature is disabled");
2877        }
2878    }
2879    if backend == Backend::Sabre {
2880        command.stdin(output_backend_stdin()?);
2881        command.stdout(Stdio::piped());
2882        command.stderr(Stdio::piped());
2883        return run_sabre(
2884            command,
2885            config,
2886            print_summary,
2887            print_summary_to_json_file,
2888            true,
2889        )
2890        .await;
2891    }
2892    if backend == Backend::Liteinst {
2893        command.stdin(output_backend_stdin()?);
2894        let preload = liteinst_runtime_library_path()?;
2895        let (output, mut global_state) =
2896            reverie_liteinst::LiteinstBackend::run_host_with_output_and_preload::<Detcore>(
2897                command, config, preload,
2898            )
2899            .await?;
2900        let status = output.status;
2901        if liteinst_requires_forced_shutdown(status) {
2902            global_state.force_shutdown_with_error();
2903            global_state.cancel_internal_scheduler().await;
2904        }
2905        global_state
2906            .clean_up(print_summary, print_summary_to_json_file)
2907            .await;
2908        return Ok(Output {
2909            status,
2910            stdout: output.stdout,
2911            stderr: output.stderr,
2912        });
2913    }
2914    ensure_backend_dispatch(backend)?;
2915
2916    let stats_request = backend_stats::request();
2917    command.stdin(output_backend_stdin()?);
2918    command.stdout(Stdio::piped());
2919    command.stderr(Stdio::piped());
2920    let mut builder = reverie_ptrace::TracerBuilder::<Detcore>::new(command).config(config.clone());
2921    if config.gdbserver {
2922        builder = builder.gdbserver(config.gdbserver_port);
2923        if config.sequentialize_threads {
2924            // Inform gdbserver not to serialize guests because this is
2925            // done by detcore already. Without this the gdbserver freezes
2926            // the other threads around a breakpoint stop and waits for each
2927            // to report, but under detcore they are parked in its scheduler
2928            // rather than blocked in the kernel, so they cannot answer until
2929            // the scheduler runs them -- which it cannot while the stopped
2930            // thread holds its turn. The replay path already does this.
2931            builder = builder.sequentialized_guest();
2932        }
2933    }
2934    let (output, global_state) = builder.spawn().await?.wait_with_output().await?;
2935    global_state
2936        .clean_up(print_summary, print_summary_to_json_file)
2937        .await;
2938    backend_stats::report(backend, stats_request, &backend_stats::PtraceStatsSource);
2939    Ok(output)
2940}

2949fn collect_recording_ids(

3175/// Capture the current mount namespace's raw IDs in the exact row/parent order
3176/// used by Detcore's canonical mountinfo mapping.
3177pub fn capture_mountinfo_identity_order() -> Result<Vec<u64>, Error> {
3178    use std::collections::BTreeSet;
3179
3180    let contents = fs::read("/proc/self/mountinfo")?;
3181    let rows = detcore_model::procfs::parse_mountinfo(&contents)
3182        .ok_or_else(|| anyhow!("malformed /proc/self/mountinfo"))?;
3183    let mut visible = Vec::new();
3184    let mut parents = Vec::new();
3185    let mut seen = BTreeSet::new();
3186    for row in rows {
3187        seen.insert(row.raw_mount_id);
3188        visible.push(row.raw_mount_id);
3189        parents.push(row.raw_parent_id);
3190    }
3191    for parent in parents {
3192        if seen.insert(parent) {
3193            visible.push(parent);
3194        }
3195    }
3196    Ok(visible)
